# Правила разработки LacEditor

## Общение и границы задачи

- Общаться с пользователем на русском языке. Объяснять просто; специальные термины сопровождать кратким пояснением.
- Перед изменениями изучить текущий код и состояние `git status`. Сохранять чужие и незакоммиченные изменения.
- Для задачи из нескольких шагов сначала изложить краткий план и способ проверки результата. Существенные неоднозначности уточнять до реализации.
- Всегда выбирать минимальное решение. Без отдельного разрешения не добавлять режимы, инфраструктуру, защитные механизмы, зависимости, рефакторинг и соседние улучшения вне согласованного плана.
- Менять только необходимые участки, соблюдать существующий стиль. Не переформатировать соседний код и не удалять ранее существовавший неиспользуемый код.
- При изменении поведения кода в рамках той же задачи актуализировать соответствующие правила и описания в `AGENTS.md`, чтобы они отражали фактическую реализацию.
- Не создавать коммиты, не публиковать и не выпускать приложение без явного запроса пользователя.

## Устройство проекта

- Приложение для macOS 26+ на SwiftUI и AppKit; редактор использует TextKit, предпросмотр Markdown — WebKit и cmark-gfm, разбор кода — Tree-sitter.
- `LacEditor/App` — состояние приложения, окна, команды и настройки; `Views` — интерфейс; `Editor` — редактирование; `Models` — модели; `Services` — операции с файлами и текстом; `Preview` — предпросмотр.
- `LacEditorTests` содержит тесты XCTest, `Verification` — дополнительные проверки, `Scripts` — команды сборки и приёмки.
- Поддерживать сборку через Swift Package Manager (`Package.swift`) и Xcode (`LacEditor.xcodeproj`). При добавлении исходников или ресурсов обновлять необходимые списки сборки, включая прямые вызовы `swiftc` в скриптах проверок.
- Не менять содержимое пользовательских документов, правила сохранения, восстановления и совместимость существующих настроек ради несвязанной задачи.
- Текущая основа редактора — TextKit 1. Переход на TextKit 2, `NSDocument` или другую модель окон не считать обычной частью исправления ошибки. `docs/ROADMAP.md` и `NEXT_OPTIMIZATIONS.md` содержат также будущие работы: сверять их статус с кодом, не описывать планы как реализованные возможности.

## Окна, вкладки и владение документами

- Начинать изменения жизненного цикла с `App/WindowManager.swift`, `App/LacEditorApp.swift` и `App/AppState.swift`. Окна редактора, включая первое, создаёт и удерживает AppKit через `WindowManager`; сцена SwiftUI используется для настроек. Не добавлять второй независимый путь создания окна редактора.
- В обычном интерфейсе системная вкладка — отдельное `NSWindow` со своим `AppState`. При этом модель `AppState.documents` остаётся массивом для существующих операций и переноса; не заменять это предположением, что массив всегда содержит ровно один документ.
- Окна редактора восстанавливаются через `WindowManager` и снимки сессии; системное AppKit state restoration для создаваемых вручную окон отключено, чтобы не запускать второй путь восстановления.
- Сохранять общий экземпляр `AppPreferences` для состояний окон и направлять команды в активное состояние через `WindowManager`. Не подменять его состоянием первого созданного окна.
- Открытие файла проверяет `DocumentFileIdentity` среди окон и активирует уже открытый документ. Сохранять эти проверки также для «Сохранить как» и сохранения при закрытии. Идентичность определяется ресурсом файла либо каноническим путём с разрешением символических ссылок, а не одним отображаемым именем.
- Перенос между окнами передаёт существующий объект `EditorDocument`; не создавать его заново только из строки текста. Сохранять идентификатор документа, несохранённые изменения и связанное состояние редактора.
- Сохранять различие между закрытием документа, окна и завершением приложения. При закрытии последнего заполненного документа в единственной системной вкладке окно заменяет его пустым документом; пустая вкладка либо вкладка в группе может закрыть своё окно. Повторное открытие через Dock и открытие файла через Finder проходят существующую координацию окна.
- Закрытие и выход ожидают текущие сохранения. Подтверждения несохранённых документов обрабатываются последовательно, отмена останавливает дальнейшее закрытие; не обходить эти пути прямым удалением состояния или вызовом завершения приложения.

## Актуальный текст и фоновые операции

- `EditorDocument` — модель документа, но во время набора актуальный текст может ещё находиться в `NSTextView`: перенос в модель отложен. Перед сохранением, снимком сессии и операцией, требующей актуального содержимого, использовать `synchronizedText()` или `synchronizedSnapshot()`. Не читать `document.text` как безусловно актуальную копию ввода.
- Сохранять механизм `attachLiveTextProvider` / `detachLiveTextProvider` и подтверждение версии после синхронизации. Не копировать весь большой документ в модель на каждое нажатие клавиши.
- Менять интерфейс и состояние редактора на основном потоке; в фон передавать снимок текста и необходимые значения. `@unchecked Sendable` означает ответственность существующего кода за согласованность доступа, а не разрешение свободно менять модель из любой очереди.
- Для фоновой работы сохранять проверки идентификатора документа, `textRevision` (версии текста), поколения задачи (номера её запуска) и отмены, предусмотренные соответствующим путём. Использовать существующий `DocumentTaskCoordinator`; не применять результат только потому, что вычисление завершилось.
- При новом запуске операции того же вида предыдущая работа отменяется. При изменении текста, закрытии документа или удалении сессии сохранять соответствующую отмену, снятие наблюдателей и очистку отложенной работы.
- Проверять актуальность также после возвращения на основной поток. Отмена некоторых вызовов Foundation не прерывает сам системный вызов: это не отменяет обязательную проверку перед применением результата.
- Завершение сохранения помечает сохранённым именно записанный снимок и его версию. Правки, сделанные во время записи, должны остаться несохранёнными; не сбрасывать `isDirty` безусловно после успешной записи.

## Редактирование, диапазоны и разметка

- Диапазоны AppKit, поиска и подсветки используют `NSRange` и UTF-16 — единицы строки `NSString`. Не подменять их `String.count`, числом отображаемых символов или количеством байтов UTF-8. Проверять китайский текст, emoji и составные символы.
- В `DocumentEditDelta` поле `editedRange` задаёт заменяемый диапазон до изменения, а `replacementLength` — длину вставленного текста в UTF-16. Накопленные диапазоны переводятся в координаты обновлённого документа. Tree-sitter получает байтовые координаты своего входа: текущий `SyntaxParser` использует UTF-16 и преобразует смещение умножением на два. Не смешивать их с ограничениями размера по UTF-8.
- Программную замену в существующем пути редактора проводить через согласованный цикл AppKit `shouldChangeText` → изменение → `didChangeText`, сохраняя отмену, название действия и выделение. Для замены результата преобразования проверять исходный диапазон, текст и версию. Не обходить редактор прямым присваиванием модели, если требуется сохранить историю отмены.
- Во время `marked text` — незавершённого ввода через системный способ ввода, например китайский — не подменять строку, её атрибуты и параметры абзаца. Сохранять существующие проверки в `EditorTextView` и `LacTextView`; реальный ввод проверять на macOS.
- При внешней смене документа или версии согласованно обновлять индекс строк, сворачивание и выделение, ограничивая диапазоны новой длиной текста. Не перезаписывать незавершённый ввод.
- Подсветка меняет временные атрибуты `NSLayoutManager`, а не содержимое, метрики шрифта, атрибуты ввода и историю отмены. Обновление ограничивать соответствующим диапазоном, не стирать цвета вне него.
- Сворачивание в `FoldLayoutManager` скрывает отображение и высоту строк без удаления текста. Текущая реализация хранит один свёрнутый диапазон; не предполагать поддержку произвольного дерева сворачиваний. Сохранять раскрытие при редактировании и показе пересекающегося выделения.
- Для Markdown доступно переключение исходного и оформленного представлений одного редактора. `isMarkdownFormatted` относится к объекту документа и не записывается в сессию; после восстановления используется исходное представление. Переключение не должно менять строку, несохранённость, выделение или историю отмены.
- `MarkdownPresentationParser` получает структуру cmark и переводит позиции UTF-8 в UTF-16. Встроенные маркеры раскрывать по точному выделению и подтверждённому владельцу элемента: соседний элемент на той же строке остаётся оформленным. Заголовки, списки и сложные блоки сохраняют раскрытие по строке. Неоднозначная разметка остаётся исходником. Подтверждённые обычные маркеры списков оформляются отдельно; таблицы используют нативную сетку, описанную ниже. Локальные, data URI и HTTP(S) изображения поддерживают отдельные абзацы, inline, контейнеры и ячейки; загрузка в фоне сверяет документ, версию, путь и видимую область. Уже установленные изображения удерживать до смены документа, правки или выключения оформления, чтобы прокрутка не меняла высоту текста и не запускала цикл выгрузки и повторной загрузки. Системную проверку орфографии и грамматики отключать для документа с `data:image`, чтобы Base64-содержимое не попадало в spell server. Выделение раскрывает исходник, строка документа не меняется. Скрытие маркеров независимо от сворачивания строк; высоту заголовков считать по пересечению фрагмента строки с заголовком, включая отступы и цитаты.
- `MarkdownPresentationController` разбирает снимок в фоне с отменой и проверкой поколения, версии редактора, документа и активности. Оформлять только ещё не оформленную часть видимой области, не переустанавливать атрибуты уже оформленного текста и не раскладывать весь документ при вводе или прокрутке. Видимый диапазон получать из уже готовой TextKit-разметки без её принудительного достраивания. Во время незавершённого системного ввода отложить оформление до его окончания. При возврате к исходнику восстановить шрифты, параметры нового ввода и ранее скрытые глифы, включая область за экраном. Не применять к оформлению пороги других подсистем и не добавлять новые ограничения без отдельной задачи.
- Меню «Формат Markdown» использует актуальный NSTextView в обоих представлениях. `MarkdownFormattingService` возвращает одну замену и итоговое выделение в UTF-16; применение проходит обычный цикл AppKit и отдельную группу отмены. Не снимать экранированные или неоднозначные маркеры, не создавать встроенное оформление через несколько абзацев и не менять блоки кода блочными командами. Во время marked text и для недоступного редактирования команды не применяются.
- Команды создания списков, fenced-блока и горизонтального разделителя используют тот же путь форматирования и одну отмену. Для списков добавлено преобразование подтверждённых однострочных siblings общего cmark list: bullet/ordered/task, сохранность source content и UTF-16 selection, same-type без изменений. Многострочные родители пока не преобразуются, чтобы изменение ширины marker не разрушило вложенность; fenced/разделитель продолжают работать с обычными строками. В оформленном виде подтверждённый task-флажок рисуется поверх исходного маркера; щелчок меняет только пробел/x через обычный цикл отмены с проверкой версии, документа, доступности, IME и единственного выделения. Клик по флажку при запрещённой операции не передаётся обычной обработке и не сбрасывает множественное выделение. В этих новых блочных преобразованиях границы Markdown-строк — CR, LF и CRLF; U+2028/U+2029 остаются содержимым по правилам cmark, а индекс строк редактора сохраняет собственную обработку Unicode-разделителей. Проверка кода учитывает пересечение диапазона и незакрытое ограждение в конце файла; не ослаблять её ради новых команд.
- Оглавление — раскрываемый раздел существующей боковой панели, не индекс файлов библиотеки. Один результат Markdown-разбора обслуживает оформление и видимое оглавление; в исходном виде оглавление не меняет атрибуты редактора. `markdownHeadings` и `isMarkdownOutlineCurrent` временные: правка и внешняя замена текста немедленно отменяют актуальность. Переход проверяет выбранный документ и принадлежность текущему списку, раскрывает сворачивание также для позиции курсора без выделения. Раскрытие оглавления не записывается в сессию.
- Встроенный `[toc]` пока распознаётся как точный отдельный абзац верхнего уровня. Использовать заголовки того же разбора, не записывать развёрнутый список в текст. Выделение показывает исходный маркер, клик проверяет текущий документ/версию/IME и использует обычный revealSelection. Геометрия и hit-test ограничены видимой областью; не раскладывать все удалённые маркеры при каждом клике. HTML и нативный PDF получили отдельную подготовленную реализацию по тому же дереву cmark; допустимы только сгенерированные известные ID текущей страницы, unsafe HTML не включать. Для Pandoc подготовлена подстановка подтверждённых TOC-маркеров через существующее дерево вывода; PDF-ссылки/закладки требуют проверки фактической пагинации и сложных заголовков на Mac.
- `MarkdownTableEditingService` изменяет GFM-таблицы, включая неполные строки и таблицы внутри цитат/списков: строки, столбцы и выравнивание. Нативная сетка использует один NSTextView активной ячейки, поддерживает Tab/Shift-Tab, перенос строк/столбцов мышью и многострочный текст через подтверждённые `<br>`. Отображаемый текст и исходные диапазоны переводятся в обе стороны в UTF-16; неизменённые фрагменты сохраняются дословно. Одна подтверждённая операция — одна замена основного текста и одна отмена. Незавершённый системный ввод попадает в существующий live provider через составной снимок и не подменяется текстом модели. Для отсутствующих ячеек разделители создаются только после принятия ввода; отмена диалога ничего не добавляет. Ссылки и изображения проверяют идентификатор активной ячейки, документ, версию и выделение после диалога. При вводе переразбирать активную строку, смещая остальные диапазоны без копирования всех строк таблицы. Сохранность соседнего оформления проверять сразу, до фонового разбора. Полная клавиатурная матрица, буфер обмена, сложная разметка и приёмка Mac остаются в работе.
- Cmd-клик по подтверждённой ссылке использует общий cmark-результат; при отсутствии готового результата допустим один отменяемый разбор по явному клику. Клик без Cmd сохраняет редактирование. Проверять объект документа, текущий ввод, версию и смену выделения, в том числе уход и возврат. До переходов по сноскам и ссылкам обрабатывать выход из активной ячейки; незавершённый ввод дочернего NSTextView нельзя обойти проверкой только родителя. Ячейки используют одинаковую локальную TextKit-разметку для рисования и попадания, диапазон ссылки хранится относительно исходника ячейки; картинки формул не меняют исходные координаты.
- `MarkdownHeadingAnchors` задаёт единые ID и псевдонимы заголовков для редактора и HTML. Сохранять прежние правила Unicode и конфликтов имён. `MarkdownLinkNavigationService` декодирует фрагмент один раз, разрешает относительный файл от URL документа и не выбирает рабочий каталог для несохранённого файла. Внешние http/https/mailto открываются системным приложением только по явному действию. Открытие другого поддерживаемого файла идёт через существующий WindowManager с проверкой идентичности и ожиданием чтения; перед переходом проверяются исходный запрос, активное целевое окно и точный снимок назначения. Диапазоны голых GFM email восстанавливаются общим захватом исходных TEXT-узлов до autolink; неоднозначное соответствие не угадывается. Именованные HTML-якоря сравниваются по точным UTF-8, без объединения канонически эквивалентных Unicode-строк. Ссылки предпросмотра проходят текущий DOM nonce и существующий путь открытия; отсутствующий Markdown создаётся только после подтверждения и повторных проверок актуальности.
- Сноски используют `CMARK_OPT_FOOTNOTES` в общем разборе и предпросмотре; заголовки внутри определений не попадают в оглавление. Подсказки и Cmd-переходы временные, проверяют актуальность и очищаются при смене документа/представления. HTML-предпросмотр допускает только свои якоря fn-/fnref- без ослабления остальных правил URL.
- Подтверждённые общим cmark HTML-блоки разбираются SwiftSoup; исходные позиции остаются у cmark и последовательного HTMLContext. Локальные и HTTP(S) audio/video воспроизводятся системным AVPlayerView без автозапуска. Iframe использует отдельный непостоянный WebKit с ограниченным sandbox и разрешёнными HTTP(S)-адресами. После ожидания проверяются документ, версия, поколение, URL, видимость и IME; раскрытие исходника, сворачивание, деактивация и уход с экрана останавливают и удаляют media view. Изменение высоты блоков обновляет frame видимых дочерних представлений. Скрипты и обработчики событий из документа не исполняются. Фактическое воспроизведение, геометрия и VoiceOver требуют Mac.
- Фокус текущего абзаца и режим печатной машинки — временные настройки окна. Затемнение не меняет атрибуты текста. Центрирование после ввода проверяет версию и выделение, отменяется ручной прокруткой/выбором и откладывается при IME; не раскладывать целиком большой документ.
- Автоматические пары скобок/кавычек и Markdown-знаков включаются отдельно, по умолчанию выключены. Автоматизация относится к обычному клавиатурному вводу Markdown, а не вставке из буфера, программной замене или незавершённому IME. Сохранять точную вставку и одну отмену; не вводить новый порог размера ради этой функции.
- Высоту строки согласовывать с `FoldLayoutManager`, не вычислять её по случайному первому глифу документа. Проверять смешанные латинские и китайские шрифты, линейку номеров и позицию курсора.
- Линейка номеров строк во время рисования использует только уже готовую видимую раскладку TextKit; не вызывать `ensureLayout` из `drawHashMarksAndLabels`, поскольку изменение геометрии текста создаёт рекурсивный цикл layout/display.
- Генерация скрытых глифов для уже установленного блочного Markdown-изображения использует быстрый путь для пакетов, полностью находящихся внутри его исходного диапазона; не выполнять полный набор Markdown-проверок для каждого символа Base64 data URI.
- Сохранять обработку CRLF как одного переноса, а также CR, LF и Unicode-разделителей в индексе строк. Пустой документ и последняя пустая строка — отдельные случаи; проверять номер строки, выделение и попадание курсора. Не обобщать существующую обработку клика после конечного LF на все виды переносов без проверки.

## Большие документы и производительность

- Сохранять разделение ограничений в `DocumentPerformanceProfile`, `EditorLayoutPolicy`, `SyntaxParser` и `TextCodecService`: они измеряют разные величины и управляют разными операциями. Не заменять их одним общим признаком «большой файл».
- Статистика `DocumentStatistics` считает исходник или выделение: слова средствами Foundation, составные символы Swift Character, символы без пробелов, строки и оценку минут при 200 словах/мин. Это не статистика видимого Markdown. Снимок создаётся после паузы, пустое выделение не запускает полный пересчёт при движении курсора; сохранять проверки версии/поколения/области и недоступный результат для невалидного диапазона.
- Профиль большого файла включается при размере более 20 × 1024² байт или более 250 000 строк; усиленный профиль — более 50 × 1024² байт. По умолчанию большой профиль отключает перенос, предпросмотр, сворачивание и подсчёт символов, усиленный дополнительно отключает подсветку.
- Ручные исключения `DocumentFeatureOverrides` относятся к текущему документу и не переписывают глобальные настройки. Сохранять возможность отдельно вернуть функцию для конкретной вкладки.
- Для текста длиннее 500 000 единиц UTF-16 `EditorLayoutPolicy` отключает фоновую разметку; используется разметка видимой области. Не возвращать принудительную разметку всего документа при вводе, прокрутке или изменении ширины.
- Сохранять ограничения Tree-sitter по размеру и существующий облегчённый разбор там, где полный синтаксический разбор не используется. Не удалять запасной лексический анализ ради унификации.
- Кэши поиска и разбора должны учитывать документ, версию и параметры, предусмотренные их текущими ключами. Изменение кэша не должно возвращать результат другой вкладки или старой версии.
- Изменения горячего пути — ввода, прокрутки, разметки, подсветки, поиска — проверять на крупных смешанных текстах, включая глубокую прокрутку и изменение ширины окна. Использовать существующие проверки производительности; не вводить новые пороги и режимы без отдельной задачи.

## Файлы, сохранение и восстановление

- Операции чтения и записи проводить через существующие пути `FileService` и `AppState`. Для невалидного UTF-8 сохранять выбор пользователем кодировки; при записи использовать выбранную кодировку и запрещать преобразование с потерей символов. Существующая запись выполняется атомарно — через безопасную замену файла.
- Перед перезаписью исходного файла сохранять проверку внешних изменений и выбор пользователя: отмена, перезагрузка, другой файл или явное перезаписывание. `FileRevisionSnapshot` сравнивает идентичность, дату и размер; не описывать его как полную проверку содержимого по контрольной сумме.
- `WorkspaceSessionStore` хранит обычную сессию, `DocumentRecoveryStore` — восстановление после сбоя. Не объединять их жизненные циклы и не превращать сохранение сессии в автоматическую запись пользовательских файлов.
- По умолчанию выход сохраняет рабочее пространство; альтернативный режим спрашивает о несохранённых документах. В режиме сохранения сессии ошибка её записи отменяет выход. При успешном обычном выходе аварийные данные завершаются соответствующим существующим путём.
- Сохранять совместимость формата сессии: одна запись окна представляет группу системных вкладок в порядке AppKit. Восстанавливаются текст, путь, идентификатор, язык документа, кодировка, несохранённость, выделение, прокрутка, предпросмотр, выбранная вкладка, боковая панель и геометрия окна.
- Хранилища используют каталоги снимков и маркеры текущей сессии. Не менять порядок записи, переключения маркера, потребления и очистки без проверки сбоев и совместимости. При объединении восстановлений аварийный снимок того же идентификатора имеет приоритет.
- Изоляцию данных определяет `AppEnvironment`: официальная, development, experiment и acceptance сборки используют соответствующие пространства Application Support. Одной смены идентификатора приложения недостаточно для изоляции файлов; не прописывать общий путь вручную. Настройки проверять также в соответствующем `UserDefaults`.
- Рабочая папка (`FolderWorkspaceStore`) принадлежит состоянию окна отдельно от библиотеки. В режиме дерева чтение/сортировка в фоне охватывают раскрытые каталоги; явный полный список использует один общий рекурсивный снимок. Результат проверяет корень, поколение и конкретный запрос; символические ссылки не обходятся. Повторно проверять корень и компоненты пути перед чтением, не выдавая такую проверку за атомарную защиту от подмены пути. Открывать файлы существующим `AppState.openFile`, сохраняющим идентичность документа. Корень, раскрытие, сортировка и вид дерева/списка сохраняются отдельно для каждой системной вкладки в совместимом формате сессии. Поддерживаются сортировки по имени, естественному порядку, созданию и изменению. Один FSEvents-наблюдатель корня обновляет только загруженные раскрытые каталоги и текущий список; при смене корня/закрытии освобождать его и отклонять старые события. Недоступный корень показывать как ошибку, не заменять домашним каталогом. Реальное наблюдение и восстановление ещё требуют Mac-проверки. Подготовлены создание/дублирование с отменой последнего действия через существующий sidebar feedback; системная история отмены текста не меняется. Перед удалением копии сверять снимок содержимого и документы всех окон по пути и идентичности, включая ссылки; чтение/удаление больших деревьев выполняется в фоне. Пересекающиеся открытия/сохранения координировать до завершения файлового действия; проверки не устраняют внешнюю файловую гонку. Подготовлены перенос/переименование и Корзина с последовательным подтверждённым закрытием; списки обновляются и отменяются адресно без затирания новых действий. При ссылке учитывать точный исходный URL открытого документа отдельно от цели, включая перенос родительской папки; если будущая относительная цель меняет ресурс, отказать до дисковой операции. Обратный перенос того же ресурса сохраняет новые изменения содержимого и не требует сравнения их с исходными байтами, в отличие от удаления копии.
- Поиск папки использует только выбранный корень и неизменяемые снимки открытых документов с главного потока; несохранённый снимок имеет приоритет над диском. Не обходить символьные каталоги, не угадывать кодировку; пропуски видны отдельно. Диапазоны/контекст в UTF-16. Перед переходом сверять документ, версию или состояние диска и исходный фрагмент, также после асинхронного открытия. Подключены контроллер состояния окна, ленивые строки поиска и ожидание штатного открытия placeholder. Snapshot callback возвращает nil при нестабильности состава/путей документов, не выдаёт неполный набор за успех. `@Published` сообщает до завершения изменения: дождаться устойчивого состояния на следующем шаге главного потока, затем повторно проверить загрузку, владение и отмену. Mac/XCTest ещё не выполнялись.
- `SidebarLibraryStore` хранит пути, группы и состояние раскрытия, а не индекс содержимого документов. Сохранять совместимость существующего JSON и атомарную запись. Избранное и группы не должны менять содержимое файлов на диске.
- Отмена изменения списка недавних файлов, избранного или группы применяется только если затронутый список не изменился позже. Не затирать более новые действия пользователя при отмене.
- `ExperimentSampleLibrary` подключается только для экспериментальной сборки; уже существующие файлы примеров не перезаписываются. Не добавлять автоматические примеры в обычный запуск.

## Преобразования текста и предпросмотр

- Поиск по YAML-тегам — третий явный вариант существующего поиска папки. Обход и несохранённые снимки/идентичность общие с текстовым поиском; сейчас выбираются `.md` и `.markdown`. Только подтверждённые front matter разбираются локально через Yams с правилами YAML 1.2, без тела файла и запуска Pandoc. `MarkdownTagReader` возвращает по каждому ID строковые теги или ошибку; строковый скаляр и список строк сопоставляются целым тегом без разбиения по запятым. Числа, логические значения и вложенные структуры тегами не считаются. Незакрытая разметка остаётся Markdown, а ошибка содержимого закрытого YAML показывается отдельно. До открытия проверять прежний YAML-фрагмент и версию, курсор ставить к метаданным без угадывания диапазона слова. Не добавлять индекс или отдельный процесс для каждого файла.
- Настройки изображений по умолчанию не отправляют данные. Ручная загрузка использует выбранный PicGo endpoint или пользовательскую программу; проверять реальные байты/MIME, порядок результатов и отмену. Включаемые отдельно автоматическая локальная/сетевая загрузка и разрешения YAML не должны менять старое поведение при отсутствии ключей. Копирование ресурса сохраняет исходный файл и не перезаписывает занятый путь; после записи устаревший снимок оставляет файл с сообщением о его расположении. Отмена текста не удаляет файл. Извлечение адресов HTML/reference подтверждается cmark, общие определения не должны менять невыбранные изображения и обычные ссылки. Число полных контрольных разборов не растёт с количеством definitions.
- AI-подключения настраиваются в общем `AppPreferences.aiConfiguration`: отдельные выключенные по умолчанию профили текста, decisions и изображений с URL корня API, произвольным именем модели и явным протоколом. `aiFeatures` включает каждую функцию отдельно, `aiBackgroundEnabled` отдельно разрешает фон. Нативные орфография и грамматика управляются отдельными настройками NSTextView; автоматическое исправление слов выключено. Не отправлять грамматику в модель и не менять настройки во время marked text; после его окончания применить последние значения. Реальное поведение грамматики без орфографии проверять на Mac.
- Модель каждой AI-функции задаётся в `aiFeatureModelIDs`; `aiProfile(for:customCheck:)` наследует адрес, ключ и протокол профиля роли, затем подставляет модель функции и, для пользовательской проверки, непустую модель правила. Пустое значение наследует предыдущий уровень. Все запросы, фоновые операции и применение результата сверяют выбранную модель; локальное происхождение текста и системная грамматика моделей не используют.
- Перевод использует явный выбор языка (`AITranslationLanguage`) либо своё название. Смена языка синхронно отменяет текущий перевод и снимает его результат; исходный текст меняется только после принятия предложенной замены.
- `AIWritingController` хранит снимок редактора и версию, показывает оригинал/замену, применяет через `EditorRangeReplacementRequest` с `isAIGenerated`, проверяет профиль/ключ/актуальность перед применением и отменяет запросы при изменении текста, закрытии и выключении функций. Ручной выбор команды отделён от фонового результата; команды меню открывают существующую панель, без чата и новых окон. Отчёты терминов/противоречий ссылаются на два однозначных диапазона UTF-16; резюме вставляется отдельно. Вероятность Decisions не считать истинностью утверждения; извлечение решений — отдельная текстовая функция.
- Автодополнение отображается в LacTextView без изменения текста, принимается Tab и отклоняется Esc/вводом/сменой выделения. Снимок контекста и чтение Keychain выполняются после паузы; до показа и принятия проверяются документ, версия, курсор, профиль и ключ. На большом профиле фоновый анализ, автоматические метаданные и автодополнение не запускаются; ручные команды остаются отдельным явным действием. Не копировать строку на каждое нажатие клавиши.
- Для своих локальных серверов Info.plist объявляет NSAllowsLocalNetworking и описание NSLocalNetworkUsageDescription. Системное описание локализовано в трёх InfoPlist.strings (это текст macOS, не вызов L10n); глобальный NSAllowsArbitraryLoads не включён. HTTPS и локальные адреса проверять в установленном приложении на Mac.
- Поиск источников и чтение веб-страниц идут только через `JinaClient` с `AppPreferences.jinaConfiguration`: отдельные выключатели, полные URL API и ключи поиска/Reader. Не заменять Jina встроенным поиском модели. Без Reader показывать только непроверенные ссылки-кандидаты; с Reader проверять цитату документа, индекс страницы и цитату полученного содержимого. Недоступная страница не мешает остальным, отмена останавливает всю операцию. Это не доказывает смысловую достоверность. Ключи Jina также разделены по роли, адресу и окружению.
- Изображение создаётся явно, до вставки показывается; вставка добавляет data URI Markdown после выделения через тот же проверяемый путь отмены. MIME и расширение определяются по данным. Бинарное изображение генератора скачивается напрямую без его API-ключа; Jina Reader предназначен для веб-страниц. Описание выбранного файла передаёт реальные данные изображения модели с поддержкой картинок.
- Метаданные редактируются в панели и при включённом фоне могут обновляться после сохранения; `aiMetadata` хранится только в текущем объекте документа. `DocumentProvenance` локально учитывает события после включения, неизвестное/внешнюю замену/отмену не угадывает, не является детектором AI и не сохраняется после перезапуска. Не менять формат сессии или пользовательского документа ради сохранения этих данных без отдельной задачи.
- `AIClient` использует URLSession: Responses, Chat Completions, Decisions с именованным predicate-вопросом и Images. Проверять включение профиля до генерации; получение списка моделей доступно отдельной ручной командой и не доказывает доступность выбранной модели. Не добавлять автоматические повторы, смену сервера или передачу документов при просмотре настроек.
- `AIKeychainStore` хранит секреты в системной Связке ключей по окружению AppEnvironment, роли и нормализованному URL. Ключи не включаются в UserDefaults, документы или диагностику. Пустой ключ разрешён для сервера без авторизации. Перенаправления HTTP не выполняются; картинка по URL скачивается без API-ключа. При изменении профиля или скрытии раздела отменять запрос моделей и отбрасывать запоздавшие ответы.
- Выбранные ручные инструменты (контекст, сравнение, свои проверки, распознавание, голос, Mermaid и объяснение) используют `AIDocumentToolsController` внутри существующей панели. Меню открывает настройки входов через `prepare`; не запускать запрос до явной команды. Семантический поиск, индекс папок и скрытое чтение коллекции не добавлены.
- `AIContextService` читает только выбранные источники. Открытый файл в любом окне даёт `synchronizedSnapshot()`, включая несохранённый текст; `.opening`, `.failed` и заглушки восстановления недоступны, загруженный `.saving` допустим. Повторно сверять все версии и снимки файлов. При иной кодировке предложить открыть файл в редакторе, не угадывать её. Цитата контекста должна иметь единственное точное вхождение и диапазон UTF-16. Переход в ещё не созданный редактор проходит через `pendingAIContextSelection` и применяется после готовности с проверкой версии; это временное состояние, не формат сессии.
- `AITextComparison` выполняет обычное построчное сравнение с точным UTF-8 и сохранёнными переводами строк; модель объясняет результат отдельно. Не менять сравниваемые файлы. `aiCustomChecks` сохраняет имя, инструкцию и выключатель каждого правила; изменение/удаление/выключение правила снимает результат его запуска.
- Профили `.ocr` и `.audio` выключены по умолчанию; декодирование старых трёх профилей сохраняет их настройки. `AIMediaClient` вызывает настроенный сервер: OCR через Responses/Chat либо явный Gateway PDF, аудио через multipart audio/transcriptions. Gateway PDF возвращает docx_base64 при output=docx; Markdown получается существующим PandocImportService. Не угадывать URL артефактов и не передавать ключ другому получателю. Переносить EXIF-ориентацию, для vision отправлять PNG; PDF-размеры проверять перед Int. Проверять отмену между страницами и до/после синхронного Pandoc, не утверждать, что уже запущенный Process прерывается.
- Запись `AIVoiceRecorder` начинается только по кнопке и требует NSMicrophoneUsageDescription во всех трёх используемых plist и трёх InfoPlist.strings. Ожидание разрешения и сама запись привязаны к документу, прекращаются при скрытии панели, смене документа и выключении функции. Не отправлять аудио до «Выполнить», не удалять импортированные файлы. OCR/голос вставляются и в пустой документ по проверенному снимку курсора; Mermaid вставляется после выделения без замены исходного текста. Соседний LLMApiGateway и работающие сервисы не изменять в рамках редактора.

- Экспорт Markdown через встроенный Pandoc создаёт отдельный файл из актуального снимка; не менять путь, кодировку, несохранённость и историю отмены исходного документа. Команда PDF использует отдельный WebKit и системную печать в PDF без внешнего LaTeX; конкретная печать, пагинация и отмена ещё требуют запуска на Mac. До установки результата сохранять проверки конфликтов, не удалять временный файл во время активной печати и не менять снимок источника. Не добавлять автоматическую установку, произвольные команды или шаблоны без отдельной задачи.
- В текущей ветке к форматам экспорта добавлены MediaWiki (`.wiki`), RST, Textile и OPML через уже включённые преобразователи Pandoc. OPML описывает оглавление и не сохраняет произвольную вёрстку документа; фактический вывод поставляемой версии Pandoc и XCTest требуют проверки на Mac. Меню строится из `PandocExportFormat.allCases`; сохранять соответствие имени, расширения и преобразователя.
- Экспорт запускает Pandoc в фоне без командной оболочки, передаёт UTF-8 и читает диагностику без блокировки каналов. Итоговый файл заменять только после успешного преобразования; перед заменой проверять идентичность исходного и остальных открытых документов. Не выдавать экспорт GFM за точную копию оформления предпросмотра; Pandoc может читать указанные в документе внешние ресурсы.
- Pandoc 3.13 берётся только из приложения: Xcode кладёт его в `Contents/MacOS/pandoc`, Swift Package Manager — в `Bundle.module/Pandoc`. Официальный архив хранится в `Vendor/Pandoc`, перед прямой SPM-сборкой выполнить `sh Scripts/prepare-pandoc.sh`; Xcode делает это сам. Сохранять права запуска, лицензионные уведомления и проверки подписи в упаковке. Условия распространения исходников описаны в `Vendor/Pandoc/README.md`.
- Импорт DOCX, ODT, RTF, EPUB, FB2, HTML и LaTeX создаёт отдельный несохранённый `EditorDocument` с языком Markdown через существующий путь системных вкладок, не переписывая исходник. PDF не является входным форматом Pandoc. Доверенный фильтр `import-images.lua` встраивает доступные локальные и вложенные изображения в data URI; внешние ссылки оставляет ссылками. Не сохранять ссылки на удаляемый временный каталог и не применять результат к закрытому окну.

- `JSONFormatter` меняет структурные пробелы, сохраняя порядок и повторы ключей, запись чисел, строк и экранирования. Не заменять его преобразованием через словарь или числовые типы, которые меняют исходное представление. Сохранять проверку корректности, отмену и ограничение вложенности.
- `TextCodecService` различает обычное URL-декодирование и декодирование формы: знак `+` имеет разный смысл. Сохранять порядок автоматического распознавания, проверки Base64 как текста UTF-8 и корректности Unicode-пар.
- Автоматическое распознавание ограничено 16 384 единицами UTF-16; существующий путь преобразования предупреждает при размере входного текста более 8 × 1024² байт UTF-8 и отклоняет вход более 32 × 1024² байт UTF-8. Входом может быть выделение либо найденный текст под курсором. Не убирать эти границы и проверки отмены при смене алгоритма.
- Предпросмотр сохраняет один `WKWebView`; сравнение версии текста и темы выполняется отдельно. Не строить для определения изменений новую строку из темы и всего Markdown. Сохранять положение прокрутки и обновление темы без повторного разбора неизменившегося текста.
- При скрытии или удалении предпросмотра отменять его работу; устаревший результат не должен возвращать старую страницу. Обновление привязано к активности предпросмотра и поколению задачи.
- Сохранять локальную модель предпросмотра: JavaScript содержимого страницы выключен, политика источников ограничивает внешние ресурсы, HTML загружается без базового URL. Код приложения обновляет страницу в изолированной среде, передавая содержимое как данные. Не вставлять Markdown в исполняемый JavaScript.
- Mermaid 12.2.0 и собственный `Resources/Mermaid/render.js` выполняются только в изолированной среде приложения. Блок `mermaid` остаётся исходным code DOM, SVG создаётся рядом после успешного разбора; ошибка показывает исходник и локализованное сообщение. Сохранять strict/без HTML-меток, стандартные защищённые настройки библиотеки, запрет внешних ресурсов, последовательную очередь и проверку поколения/DOM после await. Скрытие предпросмотра инвалидирует также выполняющийся JS. Тема перерисовывает исходную диаграмму; экспорт использует подготовку локальных изображений диаграмм перед существующим Pandoc, без передачи исходного Mermaid как исполняемого содержимого. Лицензии и сведения о локальном комплекте хранятся вместе с ресурсами.
- Активированные ссылки HTTP(S) открываются внешним системным обработчиком, а не переходом внутри предпросмотра. Не добавлять сетевую загрузку документов, вход, телеметрию или внешние шрифты в несвязанной задаче.

## Интерфейс, перетаскивание и доступность

- Сохранять существующие мосты между SwiftUI и AppKit. `MainWindowView` использует `NSSplitViewController`, а системная панель инструментов следует за разделителем; видимость боковой панели согласована со SwiftUI в обе стороны. Не дублировать этот интерфейс независимыми состояниями.
- Переключение левой панели доступно в меню «Вид», кнопкой и `⌃⌘B`. Временный `isDistractionFree` относится к AppState окна: скрывает инструменты, предпросмотр, линейку, состояние и боковую панель без перезаписи настроек. Фактическая видимость панели — `isSidebarEffectivelyVisible`; обратная связь AppKit не должна сохранять программное скрытие в режиме. `⇧⌘J` возвращает прежнюю видимость инструментов, а `⌃⌘B` выходит из режима с показом панели. Системные вкладки и кнопки окна сохраняются, полноэкранный режим ОС не включается.
- Внешнее перетаскивание в боковую панель принимает обычные файлы поддерживаемых форматов и сохраняет порядок нескольких файлов. Различать перестановку групп, добавление в группу и избранное; список недавних файлов не является местом размещения.
- Наведение во время перетаскивания показывает цель; изменение порядка происходит при отпускании. При отмене, выходе из области, скрытии или закрытии окна останавливать отложенное раскрытие, автопрокрутку и обработчики событий.
- Сохранять ограничение локальных обработчиков мыши и прокрутки областью соответствующего элемента. При удалении представления или смене окна снимать наблюдателей и обработчики, отменять отложенные действия.
- `StableToolTip` показывает одну общую подсказку; её окно не получает фокус. Сохранять очистку при потере активности исходного окна, уходе указателя и удалении представления.
- Фокус клавиатуры отличается от выделения элемента. Декоративные рамки не должны перехватывать события. Сохранять доступные подписи, существующие идентификаторы автоматизации, системные настройки уменьшения движения и прозрачности.
- Ассоциации файлов изменяются только явным действием пользователя через `FileAssociationService`, для установленного официального приложения и выбранного типа. Не менять приложения по умолчанию при старте, установке или запуске тестов.

## Три языка интерфейса

- Обязательно поддерживать упрощённый китайский (`zh-Hans`), английский (`en`) и русский (`ru`). Новые и изменённые пользовательские тексты добавлять сразу на всех трёх языках.
- Использовать существующий механизм `L10n` в `LacEditor/App/L10n.swift` и каталоги:
  - `LacEditor/zh-Hans.lproj/Localizable.strings`;
  - `LacEditor/en.lproj/Localizable.strings`;
  - `LacEditor/ru.lproj/Localizable.strings`.
- Получать текст через `L10n.tr`. В текущем соглашении ключом служит исходный китайский текст. Не вводить параллельный механизм переводов.
- Переводить меню, диалоги, ошибки, подписи, подсказки, названия действий отмены и подписи для средств доступности, включая AppKit и HTML предпросмотра.
- Передавать переменные значения отдельно через параметры форматирования. Во всех переводах сохранять количество и типы подстановок; не строить ключи из имён файлов и других переменных данных.
- Сохранять одинаковый набор ключей без повторов в трёх каталогах. Проверять также ключи, передаваемые через переменные и значения перечислений: поиск только прямых вызовов `L10n.tr("…")` их не охватывает.
- Не переводить технические идентификаторы, сохраняемые значения перечислений, пути, расширения файлов, пользовательский текст и содержимое документов-примеров без отдельной задачи.
- Сохранять выбор «Как в системе / 中文 / English / Русский», применение после перезапуска и английский язык при отсутствии поддерживаемого языка системы. Изменять эту логику только в рамках явной задачи.
- Для изменения выбора использовать `L10n.saveLanguageSelection`: явный язык сохраняет также `AppleLanguages` для следующего запуска стандартных меню и диалогов; системный режим удаляет это переопределение. Сохранять ранний вызов `L10n.configure()` до создания редакторских состояний, а не переключать только отдельные представления во время работы.
- Для HTML предпросмотра использовать согласованный `L10n.languageCode`. Язык интерфейса не меняет язык кода документа, его текст и выбранную кодировку.
- Не добавлять зависимость поведения от переведённых фраз. Если затронут существующий код сравнения сообщений или их префиксов, проверить согласованность на всех трёх языках.

## Сборка, версии и выпуск

- Требования и процедуры сверять с `Package.swift`, `LacEditor.xcodeproj`, `Config`, `VERSIONING.md` и текущими скриптами. Официальный пакет предназначен для Apple Silicon; не менять платформу и архитектуру побочно.

- При изменениях ресурсов сохранять три языка в Xcode и Swift Package Manager, английский язык по умолчанию и работу `Bundle.module` / `Bundle.main` в соответствующих сборках. - В рамках выпуска согласовывать `VERSION`, `MARKETING_VERSION`, запись `CHANGELOG.md`, тег `v<версия>` и возрастающий `CURRENT_PROJECT_VERSION` по `VERSIONING.md`. Не повышать версии и не создавать тег для обычной правки без задачи выпуска.
- Пользовательские изменения описывать в разделе невыпущенных изменений `CHANGELOG.md`, как требует `VERSIONING.md`; техническую правку или изменение документации не выдавать за пользовательскую функцию. Не переводить весь журнал без отдельной задачи.
- `Scripts/prepare-release.sh` меняет версии и запускает проверки; это не команда только для чтения. Выполнять её в рамках согласованной подготовки выпуска. Официальную упаковку выполнять существующим `Scripts/package-release.sh`, без отдельного обходного сценария.
- Сборочный экземпляр приложения имеет `LSHandlerRank=None` — не предлагается как обработчик файлов; только архивная официальная копия получает `Alternate`. Приёмочная сборка не объявляет `CFBundleDocumentTypes`. Сохранять проверки и очистку регистраций сборочных копий в существующих скриптах.
- Для кандидата сохранять проверку стадии `RCn`, для официального пакета — пустой стадии, а также проверки подписи и целостности архива. Не устанавливать и не публиковать подготовленный пакет без соответствующего поручения.

| Языки | `LocalizationTests`, проверка трёх каталогов и ручная проверка системных меню и диалогов |
| Файловый ввод-вывод и большие документы | `Verification/FileServiceVerification.swift`, `LargeFileIOVerification.swift`, `PerformanceVerification.swift` |

- Классы тестов находятся в `LacEditorTests/`; выбирать конкретные случаи по изменению, например `swift test --filter LocalizationTests`. Не считать точечный запуск заменой полной проверки перед выпуском.
- `verify-release.sh` проверяет версии, сборки Debug/Release, XCTest, отдельные проверки ядра и Xcode Release. `run-acceptance.sh` включает этот сценарий и дополнительно выполняет анализ Xcode и проверки файлов размером 1/10/20/50/100 MB, платформы и приёмочного приложения. Учитывать уже выполненные проверки и не добавлять повторные ручные запуски без причины; обязательные шаги самих скриптов не отключать ради сокращения проверки.
- Отдельные GUI-сценарии — проверки запущенного интерфейса в `Verification` — не выполняются автоматически все вместе командой `run-acceptance.sh`. Они требуют macOS, подготовленного приложения и, где предусмотрено, системного разрешения на управление интерфейсом. Использовать предусмотренную сценарием тестовую идентичность, не запускать проверку над рабочим пользовательским приложением.
- Изолировать тестовые `UserDefaults` и временные каталоги; после теста восстанавливать изменённое общее состояние и снимать обработчики. Сценарии с фиксированными текстами кнопок должны явно задавать язык тестового приложения, не зависеть от языка машины.
- Длительные проверки, включаемые отдельной переменной окружения, не считать выполненными при пропуске. При изменениях сохранения и ввода проверять сценарии правки во время сохранения, позднего фонового результата, закрытия и отмены.
- Ручную приёмку выполнять по относящимся к изменению пунктам `ACCEPTANCE_TESTS.md`; для выпуска фиксировать результат в `AcceptanceReports/`. Не создавать выпуск при провале обязательных критических сценариев.

## Уточнения после исправлений аудита

- Первое открытие использует временный документ: до успешного чтения его нельзя сохранять поверх исходного файла или передавать в другое состояние окна, включая результат ошибочного чтения. Отмена удаляет временный документ и освобождает URL; поздний результат проверяет идентичность действующей операции. Отмена повторного чтения сохраняет прежний документ.
- Перед захватом рабочего пространства для выхода ожидать чтения и сохранения. После фоновой записи сравнивать снимок с актуальным состоянием; при новых правках или чтении повторять ожидание и запись. Очистка аварийных данных и подтверждение этого выхода выполняются без промежутка для нового события главного потока.
- `FileService.prepareRead` связывает содержимое с отметкой, проверенной до и после чтения и декодирования. Байты для отложенного выбора кодировки должны оставаться неизменными; не захватывать новую исходную отметку независимо от уже прочитанного текста.
- `WorkspaceSessionStore.load` не уничтожает данные: `consume` допускается только после успешной передачи несохранённых документов в активное аварийное хранилище. Ошибка чтения или запуска восстановления прекращает запуск с сообщением, без обычного сохранения пустой сессии и без очистки прежних данных.
- При незавершённом системном вводе откладывать метрики текста целиком и применять последнее требуемое значение после окончания композиции. Каждая порция обновления атрибутов повторно проверяет композицию.
- Сведения строки боковой панели обновляются при смене активности окна; команды контекстного меню не должны выбирать действия по сохранённому устаревшему признаку существования файла. Поведение меню при повторном открытии проверять на macOS.

## Доработки роадмапа

- Третий этап завершает выбор направления по внешнему исследованию: сохраняется TextKit 1, эксперимент TextKit 2 исключён, NSDocument не вводится. Общий слой для двух движков и разделение крупных классов отложены. Это не означает прохождения функциональной приёмки новой реализации.
- Подсветка хранит необработанные диапазоны после частичного применения. Изменение многострочной конструкции может затронуть хвост документа; не объявлять его обработанным после пересчёта одного видимого участка. Диапазоны Tree-sitter переводятся из байтов UTF-16 существующим преобразованием; превышение прежнего лимита использует существующий лексический путь.
- Сворачивание вычисляется отдельно от подсветки по снимку текста. Смена текста, языка, документа, выделения, активности и выключение функции отменяют поиск; перед применением проверяются версия, поколение и текущий объект. Мгновенное раскрытие сохраняется.
- Markdown и статистика используют отменяемые задачи. Привязка задачи к координатору проверяет поколение под существующей блокировкой и отменяет опоздавшую задачу. Синхронный cmark выполняется последовательно для всех предпросмотров; отменённая ожидающая задача не начинает разбор.
- Выбор файлов боковой панели отделён от открытого документа и фокуса, ограничен одним видимым списком. Cmd/Shift, стрелки, Cmd+A и Return действуют только при фокусе строки; пакетная организация списка имеет одну отмену с прежней проверкой последующих изменений. Формат библиотеки не меняется.
- Восстановление сначала читает метаданные и копирует файлы снимков без одновременного декодирования всех текстов. Все необходимые источники надёжно передаются до потребления рабочего пространства; затем тексты читаются по одному, выбранные вкладки имеют приоритет.
- Ожидающая восстановление вкладка использует существующее состояние opening и исходный EditorDocument. Отмена её загрузки проходит обычное подтверждение закрытия несохранённого текста; единственная аварийная копия удаляется только после явного отказа от сохранения. Она участвует в проверке идентичности файла, закрытии и ожидании чтения; её пустой текст нельзя редактировать, сохранять или отправлять в аварийный снимок. При переносе загружаемой вкладки сохраняются объект и признак ожидания; перенос вкладки с ошибкой чтения запрещён.
- Необязательное isDirty в существующей аварийной JSON-записи сохраняет чистые вкладки при файловой передаче. Старые записи без поля по-прежнему считаются несохранёнными. Формат рабочего пространства version 1 сохраняется; повторный аварийный запуск имеет прежнее ограничение по группировке окон.
- Для снижения пиков памяти не вводились новые численные бюджеты. Результат измерять на одном Mac до/после с несколькими вкладками по 50 МиБ; статическое ревью и подготовленные XCTest не означают пройденные сборку, GUI или производительность.

## Делегирование

- Если нужно целиком или почти целиком изучить файл длиннее 800 строк, передать его агенту `large-file-explorer`, указав путь, задачу и конкретный вопрос. Получить краткую выжимку и нужные диапазоны строк. Для небольшого участка использовать `rg` и точечное чтение.
- Повторяющийся код по существующему образцу передавать агенту `code-generator` только после самостоятельного выбора решения: указать пример, разрешённые файлы и критерии готовности.
- При делегировании явно распределять файлы, предупреждать о работе других участников и запрещать соседние улучшения. Не редактировать файл одновременно с агентом, который его изменяет.
- После работы агента проверять diff и нужные участки самостоятельно. Если задача требует независимого ревью, поручать его другому агенту.

## Статистика Markdown в текущей рабочей ветке

- `DocumentStatistics` считает составные символы и строки исходного текста, слова Markdown — по `MarkdownReadableText` из того же дерева cmark, что оформление. Один Han-знак — одно слово; остальные слова разделяет Foundation. Скорость чтения и краткий показатель задаются в существующих настройках, по умолчанию 200 слов/мин и число слов.
- `EditorDocument` принимает читаемую проекцию только после сверки с актуальным синхронизированным снимком; ввод, внешняя замена и смена языка снимают её актуальность. Выделение, версия, отмена и поколение расчёта проверяются до публикации. Не подставлять исходный подсчёт слов вместо отсутствующего результата Markdown. Неподдержанная HTML-разметка и неоднозначная часть преобразованного токена пока дают недоступную статистику.
- `MarkdownPresentationController` запускает общий разбор также для включённой статистики в исходном представлении при закрытом оглавлении; это не разрешает применять атрибуты оформления. Незавершённый системный ввод, включая редактор ячейки, откладывает публикацию. Переключение документа передаёт сохранённую скорость чтения, даже если сама настройка не менялась.

## Ширина Markdown в текущей рабочей ветке

- Необязательная `markdownMaximumWidth` ограничивает ширину обоих представлений Markdown при переносе строк. Существующий `applyLayout` центрирует контейнер горизонтальным inset; перенос отключён — сохраняется горизонтальная прокрутка без ограничения ширины. Вертикальный inset/typewriter остаётся независимым. Во время marked text изменение ждёт существующей отсрочки метрик родителя/ячейки. `MarkdownTypography.usesCustomFontMetrics` сохраняет прежний шрифт preview, когда пользователь изменил только ширину; печать ограничивает ширину доступной областью бумаги.

- `WindowManager.openFilesFromFinder` и ранняя очередь используют одинаковую маршрутизацию каталога/файла. Явно открытая папка меняет только `folderWorkspace` текущего состояния, не текст и не массив документов. Для нового файла родитель назначается только после фактического начала открытия, если root ещё отсутствует; отмена предупреждения и активация уже открытого файла папку не меняют.
- GFM email-координаты восстанавливаются из `MarkdownTextSourceCapture` до/после штатного postprocess того же cmark-разбора. Общий Source обслуживает переходы, статистику и копирование; не искать совпадающий адрес по всему документу. Сопоставлять полный literal, учитывать entities, UTF-16 и одну карту на ячейку.
- Оформленная копия по явной команде может загрузить выбранное подтверждённое удалённое изображение для RTF через существующий downloader/ImageIO; Copy HTML сохраняет адрес без загрузки. Перед записью буфера сохраняются проверки документа, версии, выделения, запроса и самого буфера.

## Оформление и копирование Markdown в текущей рабочей ветке

- `markdownLightColors` и `markdownDarkColors` хранят необязательные проверенные RGBA-значения текста, фона, ссылки, фона кода и цитаты. Пустое значение сохраняет системный цвет. Цвет текста применяется временными атрибутами, фон — свойством представления; исходник, атрибуты ввода и отмена не меняются. Снимок передаётся предпросмотру и PDF; изменения родителя и ячейки ждут окончания marked text.
- `markdownTOCMaxLevel` (1–6, по умолчанию 6) ограничивает видимые уровни бокового и встроенного оглавлений, предпросмотра и PDF. Полный список заголовков и адреса переходов сохраняются. Изменение уровня не включает пользовательские метрики шрифтов и не требует нового разбора Markdown.
- Подтверждённые emoji-shortcodes разрешаются общим локальным resolver. Оглавление получает отдельное отображаемое название, не меняя исходное название и якорь. Статистика и оформленное копирование используют ту же проекцию исходных диапазонов; выделение части преобразованного токена не угадывается.
- Оформленное копирование пишет проверенные простой текст и HTML. RTF добавляется только после существующих проверок точности; если он не подходит, два остальных формата сохраняются с явным сообщением. Отмена, неактуальный снимок или неподдержанный выбранный фрагмент не должны затирать буфер. Команды копирования исходного Markdown и HTML сохраняют отдельное назначение.
- Yams используется для вложенных Pandoc defaults и буквальных значений YAML; ссылки на входной и выходной файлы остаются под контролем существующего пути экспорта. Локальные ресурсы CodeMirror, Highlight.js и Prism используются только как дополнительные анализаторы языков кода через JavaScriptCore. Они не заменяют нативный редактор, не загружают темы и не выполняют пользовательский JavaScript.
- iPicUploader вызывает установленный iPic только по явной команде пользователя. Отмена ожидания не останавливает уже начатую внешнюю загрузку; неизвестный результат не выдаётся за подтверждённый URL. Ключи других загрузчиков сохраняются через существующий Keychain.

- Быстрое открытие ⌘⇧O использует поиск имён текущей папки и существующую боковую панель. Точное имя ранжируется перед непрерывным и последовательным совпадением букв относительного пути, затем применяется прежний естественный порядок. Во время быстрого открытия запрос запускается после короткой паузы ввода, Enter открывает первый подтверждённый результат. Отдельного индекса и чтения содержимого нет; после открытия, смены режима или root запрос быстрого вызова снимается. Существующие проверки поколения и отмены сохраняются.
- Настройка скобок и кавычек включает `{}` и одинарные кавычки; апостроф внутри слова не создаёт пару, соседний символ проверяется целиком, включая астральные буквы. Markdown auto-pairs обрамляет выделение символами `~` и `^`; при пустом курсоре они остаются одиночным вводом. Проверки кода, незавершённого системного ввода и история отмены остаются общими с остальными парами.

## Недавние и закреплённые папки в текущей рабочей ветке

- `RecentFilesStore.folderURLs` хранит отдельную историю папок в `recentFolderPaths`; прежние `urls/recentFilePaths` остаются списком файлов. Закреплённые папки — optional `pinnedFolderPaths` существующего JSON `SidebarLibraryStore`, отдельно от избранных файлов и групп. Меню/боковая панель открывают их через `AppState.openFolder(URL)`; недоступный путь даёт существующее сообщение, не удаляя запись и не меняя документы/root.
- Диалог и явное открытие папки через Finder записывают историю после проверки каталога. Восстановление сессии и автоматический родитель нового файла не считаются новым явным открытием. Явно выбранная символическая ссылка на папку переводится в её канонический путь.
- Перенос/переименование и удаление папки обновляют связанные recent/pinned пути по компонентам, не строковому префиксу. При отмене переноса переводятся обратно только сохранившиеся перемещённые записи; новые записи и удаление старых не отменяются. Возврат удалённого списка и обычная отмена действия над списком выполняются только при совпадении ожидаемой коллекции.
- Emoji разрешаются локальным каталогом `Resources/Gemoji` (gemoji v4.1.0, закреплённая ревизия и MIT LICENSE в ресурсе); отдельный процесс Pandoc для поиска имени не используется. Полное совпадение закрытого каталога Typora этим не утверждается.

- Быстрое открытие получает снимок закреплённых затем недавних папок из общих хранилищ и объединяет их с файлами одним worker. Пустой запрос показывает папки без обхода дерева; вызов доступен без root при наличии таких записей. Ранжирование имён общее, при равенстве порядок папок сохраняется. Перед публикацией и выбором проверяется неизменность списков. Типизированный результат папки вызывает `openFolder(URL)`, файла — прежний путь открытия; второй механизм окон не добавляется.

## Папка запуска и HTML/медиа в текущей рабочей ветке

- `startupFolderPath` — путь в общих настройках, пусто по умолчанию. Выбор пути не открывает папку немедленно. Первый register сначала применяет восстановление и затем выбирает default только при root=nil и пустой ранней очереди Finder. Одноразовый флаг ставится до восстановления вкладок, которое само может регистрировать окна. Dock reopen не применяет default повторно. Поздняя папка Finder меняет root обычным открытием, поздний файл следует прежним правилам выбранной папки/автоматического родителя.
- Подтверждённые cmark HTML-блоки разбираются SwiftSoup как HTML5. Audio/video используют src/source и AVPlayer с локальными и HTTP(S)-адресами; отображение ограничено видимой областью и существующими проверками версии/отмены/IME/сворачивания. Исходник и undo от показа не меняются. Реальное воспроизведение на Mac ещё не проверено; вложенные контейнеры и остальные незавершённые формы не объявляются поддержанными.
- Iframe получает отдельный непостоянный WKWebView только для подтверждённого блока, sandbox без same-origin и перехода верхнего окна; file/data/javascript адреса не загружаются. Жизненный цикл связан с документом/версией/видимостью, есть раскрытие исходника. Содержимое script/style/textarea между cmark-узлами учитывается общим HTMLContext. Поддержка конкретных внешних сервисов требует проверки на Mac.
- HTML без оформления сохраняет семантику текста/ссылок/поддержанных медиа и подтверждённые стили самого HTML span, но опускает настройки нативных шрифтов, цветов и лигатур приложения. Неподдержанные элементы дают явное предупреждение. Произвольные scripts и event attributes не исполняются в приложении.

## Системные замены, шрифты и формулы в текущей рабочей ветке

- Три отдельные выключенные настройки включают умные кавычки, тире и системные text replacements только в оформленном Markdown. Орфография/грамматика независимы. Делегат фильтрует только quote/dash/replacement результаты по полному подтверждённому диапазону, версии и токену проверки; обычное shouldChangeText не блокируется ради классификации автоматической замены. Parent/child имеют отдельные проверки, во время marked text свойства откладываются. Фактическая передача options и автоматическая выдача AppKit не проверены на Mac.
- Системное дополнение emoji работает через NSTextView.complete и локальный каталог. Подготовка контекста ленивая: обычный ввод в source без outline/statistics не запускает новый cmark-разбор. Принимаются подтверждённые текстовые диапазоны; child использует существующую карту rawBoundaries и parent revision, включая виртуальные ячейки. Esc/Tab не должны перехватывать более приоритетные операции редактора.
- `editorLigatures` nil/0/1/2 сохраняет прежний стиль либо выбирает системные лигатуры. Настройка влияет на формирование глифов через обычный атрибут, не временный цветовой атрибут. Оформляется видимая область и таблицы; сброс вне экрана применяется при появлении области, изменения при IME ждут завершения. Текст, dirty и undo не меняются. Печать/предпросмотр получают тот же снимок, HTML без оформления — без этих стилей. Реальная геометрия глифов ещё требует Mac.
- Меню Markdown вставляет встроенную и блочную формулы через общий MarkdownFormattingService и обычную одну undo-группу. Пробный текст подтверждает общий Math parser, исходник не меняется до принятого edit. Блочная формула поддерживает целиком выбранный paragraph в quote/list и подтверждённом top-level task: prefixes продолжений сохраняются, candidate math range/literal и остальная структура проверяются. CR/LF/CRLF нормализуются лишь для сравнения literal, исходное выделенное содержимое остаётся прежним. Пустой leaf EOF quote `> ` и top-level list/task с подтверждённым marker/одним пробелом создают пустое тело и сохраняют структуру. Partial/lazy/неподтверждённый пустой контейнер/table и неподтверждённые task пока отказываются. Встроенная формула в цитате доступна; полная контейнерная поддержка остаётся открытой.

- Полный list папки использует существующий `FolderSearchService.listing`, без отдельного индекса и второго алгоритма обхода. `ListedFile` хранит даты отдельно от прежнего `File` (его равенство URL/relativePath сохраняется для поиска). Группировка использует относительного родителя и естественный порядок групп; направление применяется к файлам. Дерево продолжает читать только раскрытые каталоги. FSEvents любого потомка обновляет полный list, а смена root/mode/sort отменяет старую работу; частичные ошибки видны пользователю. Старый currentPath читается совместимо, но не ограничивает новый полный список текущим подкаталогом.

- Обычные bullet/ordered list markers подтверждаются тем же cmark и хранят точный source range/физическую строку. Ordered отображает start+sibling, bullet — •; source не переписывается. Control glyph резервирует измеренную ширину номера, рисование ограничено видимой областью; выделение редактируемой строки возвращает исходный marker. Continuation не создаёт новый marker, task checkbox остаётся отдельным. Source switch, fold и marked input должны вернуть прежние glyphs; реальные caret/hit/VoiceOver/IME ещё требуют Mac.
- Выбранные уровни заголовков могут использовать small caps (малые прописные) только при подтверждённой CoreText-функции шрифта; иначе редактор сохраняет начертание и настройки показывают индикатор. CSS предпросмотра может синтезировать начертание. Источник, anchors и размеры выбранного уровня не заменяются текстовой конвертацией.

- GIF сохраняет многокадровые данные и воспроизводится системным NSImageView поверх пустого placeholder. SVG подтверждается полноценным XML-разбором без внешних сущностей и отображается через изолированный WebKit img с преобразованием в прозрачный PNG; исходные SVG bytes сохраняются для копирования/загрузки/экспорта. Анимация, прозрачность и реальная геометрия ещё требуют Mac.
- Направление RTL, выравнивание и интервалы абзацев входят в снимок оформления; нативные значения применяются к подтверждённым абзацам с восстановлением исходных атрибутов. Таблицы используют одинаковый порядок столбцов для рисования и попадания. Необязательное зачёркивание выполненного task item распространяется и на вложенные пункты; только подтверждённые cmark диапазоны получают временное оформление. HTML без оформления не получает эти декоративные правила. Вертикальная раскладка подключена к layout/линейке/блокам/дочерним представлениям, но фактическая геометрия, ввод и пиксели ещё не проверены на Mac.

- Копирование выбранного/всех изображений и скачивание всех сетевых используют существующий extractor и downloader, не перезаписывают файлы назначения и заменяют ссылки одной редакторской операцией с одной отменой. Повторы файла/URL используют одну копию; каждый SVG fragment сохраняется отдельно, а `%23` внутри имени остаётся частью имени. Undo текста оставляет созданные копии на диске. При отмене, ошибке или устаревшем снимке показываются уже созданные файлы; ссылки не применяются к другой версии документа.
- Remote изображения preview/PDF/PNG подготавливаются из того же cmark-прохода через временные маркеры и data URI; CSP остаётся img-src data:. Preview сначала показывает текст с placeholder и затем обновляет изображения в том же отменяемом задании; проверять актуальность также после WebKit navigation fallback. PDF/PNG ожидают подготовку ресурсов. Ошибка отдельной картинки не останавливает остальные, исходник не меняется. SVG data URI отделяет base64 от fragment; display/copy/renderer сохраняют fragment per occurrence.

- `markdownNumberHeadings` выключен по умолчанию. Общий счётчик назначает поддержанным H1–H6 номера с точкой/пробелом, включая нулевые пропущенные уровни; определения сносок исключены как прежде. Raw title, source ranges, slug и anchors неизменны. Fold получает source-sorted копию уже пронумерованных headings, резервирует место обратимыми отступами абзаца и рисует номер без изменения текста; изменения ждут IME. Preview/TOC используют безопасный пустой generated span и CSS, HTML plain удаляет этот marker. PDF/PNG получают тот же typography snapshot, включая custom image font override; фактическая геометрия и пиксели требуют запуска на Mac.

- Прямой запуск binary с позиционными путями передаёт их из `LacEditorApp.init` в общую раннюю очередь WindowManager до первого register. `-psn_…` пропускается, `--` разрешает имя с дефисом, неизвестная опция прекращает разбор путей; cwd фиксируется при запуске. Одинаковые ранние CLI/Finder пути объединяются, последующие явные открытия не подавляются. Существующий объект открывается обычным путём; отсутствующий CLI target создаётся только после NSAlert и повторной проверки состояния/диска. Отсутствующие родители не создаются; конкурентно появившийся объект не перезаписывается. Сессия/recovery/default-folder сохраняют прежний порядок, pending CLI также подавляет startup default.
- Move/rename/delete изображения связывает файловый шаг и редакторскую замену одной custom undo-записью; обычная регистрация текста отключена только на время этой замены. Перед каждой стороной undo/redo проверять точный UTF-16 текст, ресурсы и подтверждённые ссылки открытых документов. Файловый конфликт оставляет обе стороны без изменений и не регистрирует redo; ошибка редактора вызывает обратный файловый шаг, не гарантируемый при внешнем конфликте. Уже совершённая либо частичная дисковая операция сообщает фактические известные пути. Синхронный UndoManager при межтомном переносе требует отдельной проверки времени на Mac, новой системы async undo нет. Закрытые документы не сканируются. Копии remote после отмены остаются.

- Преобразование существующего списка использует один исходный cmark tree и проверочный разбор результата явной команды. Выбранные пункты одного уровня меняют marker и подтверждённые отступы продолжений; вложенные пункты двигаются вместе с родителем. Checkbox не входит в block indentation. Текст, код, ссылки, принадлежность пунктов родителям, плотность списков и отображаемые номера невыбранных пунктов должны совпасть; иначе команда оставляет исходник. Top-level marker в начале строки допускает tab-stop4 в padding и continuation; остаточные колонки частично потреблённого tab сохраняются пробелами, body tabs не меняются. Checkbox принимается только при подтверждении общим Source; tab в ancestor пока отклоняется. Применение остаётся одной editor replacement и undo-группой.

- Прописные заголовки включаются отдельно для H1–H6 и меняют только отображение. Source pieces сохраняют свои шрифты и стили, группы курсора объединяются по составным символам результата; доля TextKit между соседними позициями ввода не является числом UTF‑16 units. Для ß→SS, combining/emoji, вложенного оформления и вложений использовать ту же projection/геометрию; после раскрытия обычный NSTextView обрабатывает мышь и выделение. Исходник, anchors, undo, IME и raw title сохраняются.
- Общий масштаб принадлежит окну и не сохраняется в сессию; редактор использует NSScrollView magnification, preview — WKWebView magnification, не заменяя настройку размера шрифта. Системное pinch проходит прежний путь, marked text откладывает изменение. Экспорт не получает временный оконный масштаб. Стиль маркеров списка хранится в настройках по глубине; измерение и рисование используют один подготовленный формат, task checkbox не заменяется декоративным маркером. Фактическая геометрия этих функций ещё требует macOS.

- Upstream cmark не присваивает quoted task тип tasklist. Общий Source.quotedTaskCheckbox подтверждает item с quote ancestor и точные marker/state. Formatting дополнительно доказывает начальный TEXT prefix и bodyRange: снимается только этот prefix при сравнении AST, пустой исходный TEXT не создаёт лишний узел. Math callback проверяет исходные байты/offset, не меняя тип cmark node; checkbox остаётся в исходнике. Не применять getter checked к обычному item как доказательство состояния и не менять глобальные callbacks библиотеки.

- Preview/PDF выводят audio/video/iframe только после общего cmark source/DOM proof; поддержанные nested ranges выбирают внешнее media, fallback не получает отдельный overlay. Inline, whole-block и подтверждённые strong/em/strike/link containers используют прежние AV/WK жизненные циклы, source reveal/IME/версию. CSP расширен только media-src data/http/https и frame-src http/https, iframe сохраняет sandbox. Локальные audio/video целиком читаются в data URI в фоне в прежнем задании preview: сначала текст/placeholder, потом ресурсы; PDF/PNG ожидают их. Это требует памяти под bytes/base64, новый streaming handler не добавлен. Реальное playback, системные controls и статическое печатное состояние требуют Mac.

- Source.taskCheckbox проверяет именно cmark item, байтовые block coordinates переводит в UTF-16 и считает marker padding по абсолютным tab-stop4 колонкам. Допустимы 1–4 колонки; Tab после checkbox или внутри body не означает автоматический отказ. Для нового quoted-tab fallback дополнительно подтверждаются первый paragraph/TEXT и точный marker/trivia prefix. Общий Source.range и неоднозначные inline tab positions не расширяются этим правилом.
- При HTML-sensitive правке активной ячейки не переустанавливать старый полный snapshot: после завершения marked text используется временный снимок только текущей таблицы с raw cell text без runs. Старые HTML/link/image/media/SMART результаты и outline не считаются актуальными. Свежий background parse возвращает полное оформление после прежних generation/revision guards; обычный ввод не обходит документ.
- Пользовательский inline CSS проходит общий Source/HTMLContext/DOM proof и типизированный MarkdownInlineStyle. Текущий первый срез принимает документированные red/yellow и положительный rem, не произвольные CSS-темы; CSS number проверяется отдельно от Swift Double. Unsupported style даёт читаемый source fallback в доказанных диапазонах и блокирует ресурсные загрузки; Copy пересекающегося неподтверждённого форматирования сохраняет прежний буфер. Нулевой размер не подменять системным шрифтом. Остальные цвета/единицы/свойства этим срезом не объявлены готовыми.
- Экспорт .tex подготавливает body PNG в новый соседний каталог без перезаписи; metadata и прочие изображения имеют отдельный контракт. PNG I/O выполняется в фоне через принадлежащий каталогу fd, а финальные проверки и короткая атомарная установка .tex — вместе на основном потоке. После публикации sidecar при ошибке/отмене каталог оставляется, причина и известный путь сообщаются; не удалять файл по имени после отдельной проверки его identity. Нового общего механизма транзакций нет.

- Подтверждённый `details` использует первый `summary`, текст и поддержанные strong/em/span/ссылки через нативный TextKit. Системная кнопка меняет только временное раскрытие текущей версии редактора; исходный `open` задаёт начальное состояние и экспорт. При смене документа/версии временное состояние сбрасывается также после ввода и завершения IME. Вертикальное размещение использует существующие координаты медиа без второго поворота. Произвольные вложенные таблицы/медиа не объявлены поддержанными; реальные клавиатура, VoiceOver и геометрия требуют Mac.
- `MarkdownRubyRenderService` рисует подтверждённые подписи через Core Text. Общий разбор обслуживает Parser/редактор/Renderer/Copy; base поддерживает подтверждённые bold/italic/цвет с наследованием, annotation сохраняет исходный родительский шрифт и цвет. Неподдержанные фон/размер/украшения и сложные rt остаются исходником по общему правилу допуска. Сохранять NSFont descriptor и координаты составных символов; измерение, рисование и раскрытие используют согласованную геометрию. Фактическое отображение Core Text и озвучивание на Mac ещё не проверены.

- Типизированный `display:none` хранится как `MarkdownInlineStyle.hideOnExport`. Нативное редактирование показывает содержимое; выходной CSS скрывает его. При наследовании скрытие предка сохраняется. Для форматированного Copy использовать `editingCSS`, чтобы копировать видимый результат редактора; исходное Copy Markdown не меняется. Само CSS-скрытие не обещает отсутствия загрузки ресурсов. Другие значения display не добавлять без соответствующей задачи.

- Форматированное Copy Ruby использует общий collector и DOM proof того же cmark-дерева, принимает целое подтверждённое выделение и передаёт base+reading без rp-скобок в plain text. HTML сохраняет ruby/rt/rp; RTF с неподтверждённой точностью не записывается. Неподтверждённый/незакрытый Ruby ограничивается исходным диапазоном до закрытия либо конца подтверждённого родителя, при непригодном диапазоне — EOF; частичное выделение не должно обходить этот барьер. Схлопываемые пробелы, emoji и дополнительные украшения требуют своего proof, не проецировать base+reading на исходные HTML-теги. Доступность сохраняет штатный source value/UTF-16 selection NSTextView без дополнительного дублирующего элемента картинки; семантическое озвучивание Ruby требует VoiceOver на Mac.

- Первый raw SVG-срез принимает самостоятельный подтверждённый cmark paragraph/HTML block. Source/DOM proof и системный XMLParser сохраняют исходные SVG bytes; отсутствующий стандартный xmlns добавляется только в подготовленные данные. Редактор использует прежний изолированный SVG loader, HTML сохраняет vector data URI. Стандартные initial fill/stroke допустимы в контролируемом оформлении; не требовать служебные opacity/stroke-width ради гипотетического стороннего CSS. CurrentColor/внешние зависимости/неподтверждённый viewport и неподдержанные формы остаются отдельными частями полного SVG. Файловые действия заново проверяют исходные ссылки, raw SVG не становится Markdown-ссылкой из-за синтетической presentation image.

- Одиночные `<audio …/>`/`<video …/>` обрабатываются как документированное расширение Typora только после exact standalone HTML-block/source/container proof. Нормализация в явную пару временно меняет literal того же дерева для общего DOM proof и всегда восстанавливается; Markdown не переписывается. Slash внутри quoted src не является концом тега. Не подменять старые многотеговые media по одному suffix `/>`; Copy принимает только весь подтверждённый исходный диапазон, не запускает сетевую загрузку и не пишет неподтверждённый RTF.

- Обычные текстовые HTML div/p/table отображаются нативным AppKit/TextKit viewer после общего source/DOM proof. Не расширять исключение WebKit для формул/диаграмм/внешнего медиа на обычное HTML-содержимое без отдельного решения пользователя. Новый generic WK viewer признан спорным отклонением и заменяется; основной LacTextView остаётся единственным редактором и владельцем source/undo/session. Не добавлять новые режимы и отдельные механизмы жестов/доступности ради этого блока.

- В предпросмотре включение JavaScript-движка нужно только для изолированных внешних iframe. Основной Markdown сохраняет CSP `default-src 'none'` без script-src и прежний безопасный вывод: source scripts, event attributes и javascript URLs не исполняются. Не разрешать scripts основного документа ради медиа. Проверки child/parent и поздней навигации в XCTest используют только тестовый loopback listener; это не сервер приложения. Реальный WebKit и внешний сервис проверяются на Mac.
- Итоговый Pandoc HTML, в том числе пользовательский HTML writer, сохраняет исходные script/style и прочий документированный raw HTML. Это сериализация экспортного файла, не исполнение этих фрагментов в приложении. Preview/PDF сохраняют свой отдельный безопасный путь. При последующих изменениях не возвращать удалённую фильтрацию только в одной из ветвей root resources/embed-resources.
- Настройки встроенных формул и прежних правил их границ используют существующие `markdownInlineMath`/`markdownLegacyInlineMath` и единый syntax snapshot. Defaults true/false не меняются; выключение встроенных формул не сбрасывает выбранные совместимые правила и не отключает формулы в отдельных блоках.

- `markdownStrictMode` сохраняется в общих preferences и по умолчанию true, как прежний разбор cmark. Свободный режим изменяет только подтверждённые правила no-space heading и недостаточного отступа списка через публичный API того же дерева. Диапазоны новых/расширенных владельцев находятся в документ-локальной карте Source и учитываются `range`/`wholeLines`/`firstPosition`; tasklist не считать обычным item только по numeric type. Format, Copy, outline, anchor и export получают один syntax snapshot; перед применением фонового anchor сверять также текущий syntax. Export вправе точечно менять отдельную временную копию, но не документ/live text/dirty/undo. Whole-tree CommonMark roundtrip не применять: он меняет alerts/subscript. Неподтверждённые сложные случаи сохраняют строгий разбор.

- Обычные подтверждённые HTML div/p/table отображаются через `MarkdownHTMLBlockView` на AppKit/TextKit, без WebKit. Cmd-клик по подтверждённой ссылке открывает её; обычный клик раскрывает исходник (в summary details переключает раскрытие). Занятость ячеек таблицы хранится диапазонами IndexSet, без обхода каждой виртуальной ячейки colspan. Настройки абзаца и шрифта кода берутся из существующего редактора.

- Подтверждённый форматированный details проходит общий source/DOM-разбор также в предпросмотре и PDF/PNG, где исходное open определяет видимость body. Проверка не зависит от включения произвольных HTML-медиа: неподтверждённые теги не получают разрешение на исполнение.

- Форматированное Copy целого подтверждённого details использует снимок текущего раскрытия из Controller: он определяет plain и safe HTML и повторно проверяется перед записью буфера. Экспорт продолжает использовать исходное open. Целый подтверждённый raw SVG копируется существующим путём изображения; частичные/неподтверждённые диапазоны оставляют прежний буфер. Исходное Copy Markdown не меняется.
