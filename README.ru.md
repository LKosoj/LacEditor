# LacEditor

[中文](README.md) · [English](README.en.md) · Русский

Спокойный и быстрый редактор текста и кода, созданный для macOS.

LacEditor предназначен для повседневной работы с текстом, Markdown, JSON и кодом: откройте файл и пишите, переключайтесь между вкладками и включайте предпросмотр только при необходимости. Сложные функции доступны через системные меню и сочетания клавиш. Для локального редактирования не нужны учётная запись и облако. Необязательные функции ИИ и Jina передают нужное содержимое выбранным сервисам после включения и запуска.

## Почему LacEditor?

- **Открыл и пишешь**: не нужны учётная запись, мастер настройки рабочего пространства или лишняя конфигурация проекта — после запуска сразу доступен редактор.
- **Сосредоточенность без потери возможностей**: вкладки, поиск и замена, подсветка синтаксиса, предпросмотр Markdown и инструменты JSON под рукой, а интерфейс остаётся сдержанным.
- **Привычное приложение macOS**: системные окна, меню, выбор файлов, сочетания клавиш, тёмная тема и перетаскивание соответствуют привычкам системы.
- **Работа с большими файлами**: для длинных файлов кода и журналов используются разметка видимой области, фоновые задачи и несколько уровней защиты, чтобы набор и прокрутка оставались плавными.
- **Локальная работа с текстом**: редактирование, предпросмотр и восстановление не требуют входа или подключения к сети. При экспорте Pandoc может загружать ресурсы, указанные в документе.

## Основные возможности

### Помощник при работе с текстом

Команды доступны в меню «ИИ-помощник» и в его боковой панели. В «Настройки → Искусственный интеллект» каждая функция включается отдельно; по умолчанию всё выключено. Для орфографии и грамматики используется системная проверка macOS с отдельными настройками, без отправки текста AI-модели и без автоматической замены слов. Доступные языки и качество проверки определяет macOS.

Доступны ясность текста, «Переписать» (другими словами, короче, подробнее, изменить тон), перевод, «Согласованность» (термины и противоречия), «Взгляд читателя» (тон и непонятные места), структура, резюме, «Задачи и решения», таблицы и «Вопрос к документам» (ответ только по текущему документу или выделению, открытым документам текущего окна либо выбранным файлам, с проверяемыми и кликабельными цитатами; история разговора хранится только в памяти окна; при включённом Jina Search переключатель «Искать в интернете» позволяет модели искать до 3 раз на ответ через вызов функций (нужна поддержка на сервере), модели передаются первые 16 000 символов каждой страницы результата, с Reader цитаты проверяются по тому тексту, который получила модель, а источники из интернета показываются отдельно и открываются только по клику; следующие вопросы получают веб-источники прежних ответов (заголовок, адрес и проверенные цитаты), а ссылка в ответе кликабельна, только если она взята из этих источников; «Объяснить выделенное» — команда меню). У каждой функции есть описание «Нужно/Результат» в подсказках меню, панели ИИ и настройках; в контекстном меню изображения есть пункт «Описать изображение с помощью ИИ». Оригинал и правка показаны до принятия; принятая правка отменяется обычной командой. Правка текста не стирает результат в панели: подсказки принимаются по одной (место проверяется перед применением), результат убирается кнопкой «Сбросить результат». Пункты меню только открывают панель; сразу отправляет запрос лишь «Объяснить выделенное». Отчёт о согласованности делится на термины и противоречия и даёт переходы к обоим фрагментам; резюме вставляется отдельной кнопкой. Серое продолжение принимается Tab и отклоняется Esc или набором; для больших файлов оно не запускается. Метаданные предлагаются в панели, редактируются пользователем и могут обновляться после сохранения; хранятся только в текущем объекте документа.

Перевод выделенного текста доступен через выбор языка: 13 языков в списке и ввод своего варианта. Результат можно просмотреть и принять с обычной отменой. В настройках AI можно выбрать отдельную модель для каждой функции, в том числе перевода, и для каждого пользовательского правила. Пустое поле наследует модель по умолчанию; адрес, ключ и протокол берутся из подключения соответствующего типа.

Иллюстрация создаётся по явной команде, показывается до вставки и сохраняется в выбранный файл либо вставляется после выделения как встроенное изображение Markdown. Описание изображения получает реальные данные выбранного файла; нужна текстовая модель с поддержкой изображений.

Для текста, Decisions и изображений задаются свои адреса, модели и протоколы; ключи находятся в системной Связке ключей. Для OpenAI адрес — `https://api.openai.com/v1`; совместимый свой сервер настраивается вручную. Поиск источников и чтение найденных страниц выполняются через Jina, с отдельными выключателями, полными адресами API и ключами: по умолчанию `https://s.jina.ai/search` и `https://r.jina.ai/`. Если Reader выключен, показаны только ссылки-кандидаты; если включён, цитаты сверяются с полученным текстом. Это не гарантирует смысловую достоверность. Бинарные изображения от генератора загружаются обычным способом, Jina используется для веб-страниц.

Также есть пять ручных инструментов: проверка по выбранным документам (включая несохранённые вкладки других окон), точное сравнение двух версий с объяснением, сохранённые пользовательские проверки, распознавание изображения/PDF и генерация Mermaid. Они выбираются в той же панели помощника после включения соответствующего переключателя. Контекст даёт проверяемые цитаты и переход к источнику; эти инструменты читают только выбранные источники и каталог сами не обходят. Каждое пользовательское правило включается отдельно.

Для распознавания и аудио есть самостоятельные профили. В режиме Gateway PDF используется `/v1/pdf/convert` с `output=docx`, затем встроенный Pandoc; для совместимой модели с картинками можно выбрать Responses/Chat Completions. Аудио передаётся в `/v1/audio/transcriptions`. Укажите свой адрес и реально доступную модель; примеры из конфигурации соседнего шлюза — `llmgateway/pdf-converter` и `llmgateway/whisper-large-v3`.

Кнопка микрофона на панели инструментов включает диктовку: после включения «Диктовки» и указания модели расшифровки речи нажмите её, чтобы начать запись, и ещё раз, чтобы остановить; только тогда звук уходит на распознавание, затем текстовая модель убирает слова-паразиты и приводит текст в порядок, а результат вставляется у курсора (выделение не заменяется, одна отмена). Если текстовая модель выключена или очистка не удалась, вставляется необработанный текст; при сбое распознавания можно «Повторить» или «Удалить запись»; если документ закрыт или текст вставить нельзя, он копируется в буфер обмена. Распознанный текст и блок Mermaid вставляются только по нажатию, с отменой; сравнение исходники не меняет. OCR работает также с пустым документом.

Запрос к модели ждёт ответа до 10 минут. Сетевые ошибки различают таймаут, отсутствие сети, ненайденный сервер и сбой защищённого соединения и дают ручную кнопку «Повторить»; автоматических повторов нет. Ответ модели может быть в ограде ```json; пункты, которые не удалось проверить, пропускаются с указанием числа. Ручная отправка более 50 КБ (UTF-8 после удаления встроенных медиа) не уходит сразу: панель показывает источник и размер и отправляет только после «Всё равно отправить». После отправки панель показывает источник и размер. Изображения, OCR и аудио этим пределом не ограничены. Ответ модели, обрезанный по длине, показывается как ошибка, а не как полный; на AI-агента порог 50 КБ не действует: у него свои потолки и счётчики.

AI-агент — отдельная функция панели ИИ; по умолчанию она выключена и включается отдельно в «Настройки → Искусственный интеллект». Опишите задание и нажмите «Запустить»: модель сама ищет и читает открытые документы текущего окна (включая несохранённый текст) и файлы рабочей папки, ведёт план с заметками и отвечает; в том же разговоре можно задавать следующие вопросы, «Новый разговор» начинает заново. Агент работает только после «Запустить», в фоне не работает, «Остановить» действует в любой момент работы. Журнал действий перечисляет каждый поиск и каждый прочитанный файл с размером отправленного; панель показывает отправленные байты, размер контекста, число раундов и расход токенов, если его сообщает сервер. Доступ к файлам ограничен рабочей папкой: символьные ссылки, скрытые файлы и скрытые папки не читаются, кодировка файла не в UTF-8 не угадывается; без открытой папки доступны только открытые документы. Поиск в интернете по умолчанию выключен и требует Jina Search; перед каждым поиском показан запрос и нужно выбрать «Разрешить», «Разрешить в этом запуске» или «Отклонить». Модель читает только страницы из результатов поиска и сама адреса не выбирает; ссылка в ответе кликабельна, только если взята из реального источника. В длинных заданиях старые результаты чтения очищаются, при необходимости разговор сжимается в сводку, а план и заметки остаются; серверу нужна поддержка вызова функций (tools). Меню «Сценарий» только подставляет в поле готовый текст задания (проверка фактов, перевод длинного текста, согласованность между документами, правка файлов папки, черновик по заметкам); оно ничего не запускает и не включает интернет.

Агент ничего не меняет сам. Его правки — предложения, показанные как оригинал рядом с заменой: для открытых документов выберите «Принять» или «Отклонить» (либо «Принять все» / «Отклонить все»), принятая правка отменяется одним «Отменить»; новые внешние адреса в замене выделяются. Предложения для не открытых файлов (только в рабочей папке, не больше 10 файлов, чистый UTF-8 без BOM) записываются лишь после отдельной кнопки «Применить к файлам (N)» и подтверждения: перед записью файл читается заново и проверяется, а если на диске он изменился, пропускается; до и после записи сохраняется версия файла, её можно восстановить из истории версий; команда «Отменить» эту запись не отменяет. Сбой одного файла не мешает остальным, по окончании показан отчёт по каждому файлу. Непринятые предложения отбрасываются кнопкой «Новый разговор».

### Редактирование текста и кода

Поддерживаются распространённые форматы: TXT, Markdown, JSON, HTML, JavaScript, TypeScript, CSS, Python, Swift, Shell, YAML, C/C++, SQL и другие. Доступны номера строк, подсветка текущей строки, автоматические отступы и отступы клавишей Tab, отмена и повтор, базовое сворачивание и подсветка парных скобок.

Можно выбрать семейства шрифтов для обычного текста и кода; изменённые размер и интервал передаются в предпросмотр, PDF и PNG. Локальное аудио воспроизводится встроенным проигрывателем без автозапуска. Оформленный редактор копирует текст как plain, HTML и RTF и преобразует HTML/RTF при вставке; отдельно доступны копирование Markdown, HTML-кода и вставка исходного текста.

Поиск и замена — встроенная панель над редактором: счётчик совпадений, регулярные выражения, целые слова, `⌘E` ищет по выделению, `Esc` закрывает. `⌘L` и позиция курсора в строке состояния открывают переход к строке. Номера строк выровнены вправо, ширина линейки зависит от числа цифр. Горизонтальное поле редактора не меньше 16 pt, максимальная ширина Markdown по умолчанию 760 pt, в настройках её можно снять.

### Предпросмотр Markdown рядом с редактором

Редактор и предпросмотр расположены рядом. Заголовки, абзацы, списки, цитаты, разделители, ссылки, встроенный код, блоки кода, таблицы и расширения GFM отображаются в реальном времени. Предпросмотр можно закрыть в любой момент; длинные документы не требуют переходить к формату заметок.

Mermaid, flow и sequence отображаются в предпросмотре (`⌥⌘P`) и оформленном редакторе. Движки встроены в приложение; при ошибке остаются исходный код и сообщение. Контекстное меню диаграммы копирует PNG и сохраняет SVG, PNG или JPG; SVG содержит векторный результат того же отображения. Поддерживаемые профили экспорта подготавливают временные изображения для Pandoc, сохраняя Markdown документа.

```mermaid
flowchart LR
    A[Start] --> B[End]
```

Также поддерживаются математические формулы и их изображения в HTML, DOCX и EPUB, параметры страниц PDF и HTML-вставки. Цвета светлого и тёмного оформления настраиваются, для оглавления можно ограничить уровень заголовков, emoji берутся из локального каталога.

Предпросмотр следует за прокруткой редактора, показывает загрузку и ошибку с кнопкой «Повторить». Алерты раскрашены по типу, блоки кода подсвечены по языку (также в PDF и печати), полоса цитаты, флажки и выделение используют системный акцентный цвет. Печать и PDF всегда идут в светлой теме.

### Исходный и оформленный Markdown

Меню «Вид → Редактирование Markdown» переключает «Исходный Markdown» и «Оформленный текст». Оба представления редактируют один документ; переключение не преобразует его текст. В оформленном представлении поддерживаются заголовки, жирный и курсивный текст, зачёркивание, встроенный код, ссылки, цитаты и блоки кода. Подтверждённые встроенные служебные знаки раскрываются у выбранного элемента; соседнее оформление на той же строке сохраняется. Копирование создаёт обычный текст и HTML, а RTF добавляется при подтверждённой точности; отдельная команда копирует исходный Markdown. Подтверждённые маркеры обычных списков отображаются нативно и раскрывают исходник на редактируемой строке. Для GFM-таблиц, включая неполные строки и вложенность в списки и цитаты, доступны сетка, редактирование ячеек, переходы Tab, многострочный текст и перестановка строк и столбцов мышью. Локальные, сетевые и data URI изображения отображаются в редакторе, включая строчные, вложенные и табличные, а также анимированные GIF и SVG. Выбор представления относится к текущей вкладке; после восстановления сессии открывается исходное представление.

### Команды форматирования и оглавление

Меню «Формат Markdown» добавляет и снимает жирный текст (`⌘B`), курсив (`⌘I`), зачёркивание, встроенный код, заголовки 1–6 и цитаты в обоих представлениях; есть сочетания `⌘K` (ссылка), `⇧⌘K` (встроенный код), `⇧⌘X` (зачёркивание) и `⌥⌘1–6` (заголовки), а действия с изображениями собраны в подменю «Изображения». Без выделения вставляются парные знаки для ввода текста; заголовок и цитата действуют на выбранные строки. Каждая команда — отдельное действие отмены. Команды не снимают неподтверждённые или экранированные маркеры. Выделение нескольких абзацев для встроенного оформления и блочные команды внутри кода не меняют текст.

Также есть команды создания маркированного и нумерованного списков, списка задач, блока кода и горизонтального разделителя для обычных строк.

Раздел «Оглавление» в боковой панели показывает заголовки текущего Markdown-документа. Нажатие переводит курсор к заголовку и раскрывает свёрнутый участок. После правки список обновляется в фоне; устаревшие пункты недоступны для перехода. Оглавление работает и в исходном, и в оформленном виде; в последнем используется тот же разбор. Раздел по умолчанию свёрнут и не сохраняет раскрытие между запусками.

Task-флажки кликабельны, списки продолжаются и меняют отступ автоматически. Для обычных GFM-таблиц есть команды строк и столбцов, для встроенных ссылок — диалог, для сносок — подсказка и Cmd-переход. В настройках отдельно включаются автоматические пары скобок и кавычек и знаков Markdown; обе функции изначально выключены. Доступны приглушение соседних абзацев и режим печатной машинки. Для Markdown слова считаются по читаемому содержимому, символы и строки — по исходнику или выделению. В настройках выбираются показатель строки состояния и скорость чтения.

### Импорт и экспорт документов

«Файл → Экспорт» преобразует Markdown в HTML, Word (DOCX), ODT, RTF, EPUB, FB2, LaTeX, обычный текст, PDF, MediaWiki, RST, Textile и OPML. Pandoc 3.13 включён в приложение: отдельная установка и загрузка при запуске не нужны. PDF создаётся через WebKit и системную печать без внешнего LaTeX. Экспорт использует актуальный текст, включая несохранённые правки и новые документы без пути, и не меняет исходный документ. Новый документ должен иметь выбранный язык Markdown. Pandoc преобразует GFM; оформление может отличаться от предпросмотра. При экспорте могут загружаться сетевые ресурсы, указанные в документе. В HTML изображения встраиваются; в LaTeX относительные пути относятся к папке исходного файла.

«Файл → Импорт…» принимает DOCX, ODT, RTF, EPUB, FB2, HTML, LaTeX и PDF с текстовым слоем и создаёт новую несохранённую вкладку Markdown. Исходный файл не меняется. Распознанные встроенные и локальные изображения включаются в текст документа; сетевые ссылки на изображения сохраняются без загрузки фильтром импорта. Сложное оформление и размеры изображений могут не сохраниться; сложные команды LaTeX могут также потерять изображения. Встроенные страницы HTML не загружаются и не отображаются в предпросмотре; относительные ссылки на файлы остаются относительными. Сканированные PDF без текстового слоя не импортируются; TXT и Markdown открываются обычной командой «Открыть».

### Инструменты JSON сохраняют содержимое

Форматирование и сжатие изменяют только структурные пробелы, сохраняя порядок полей объектов, повторяющиеся ключи, запись чисел и экранирование строк. Для некорректного JSON по возможности указываются строка и столбец. Все изменения можно отменить одним действием.

### Файлы и окна

Поддерживаются несколько окон и вкладок, изменение порядка вкладок перетаскиванием, перенос вкладки в отдельное окно, недавние файлы, избранное и собственные группы. Один файл на диске имеет только один редактируемый экземпляр во всех окнах; внешние изменения по умолчанию не перезаписываются без предупреждения.

Быстрое открытие `⌘⇧O` показывается плавающей панелью над редактором, ищет по текущей папке, закреплённым и недавним папкам и выделяет совпавшие символы. Папка, переданная через Finder или перетащенная в окно, открывается в том же окне; для нового файла подключается его родительская папка, если рабочая папка ещё не выбрана. Пустой документ предлагает «Открыть папку…» и недавние файлы. В заголовке окна есть меню пути (⌘-клик).

Рабочая папка показывает дерево или список и открывает файлы во вкладках. Доступны создание, дублирование, перемещение, переименование и Корзина с отменой последнего действия, четыре сортировки и наблюдение за изменениями раскрытых каталогов; состояние папки сохраняется для каждой вкладки. Поиск по имени, содержимому и YAML-тегам работает в этой же панели, учитывает несохранённый текст открытых документов и проверяет результат перед переходом. Боковая панель управляется с клавиатуры, поддерживает выбор набором букв и VoiceOver; в контекстном меню избранного и групп есть «Вверх» и «Вниз».

Левую панель можно показать или скрыть через меню «Вид», кнопку на панели инструментов или `⌃⌘B`. Команда «Вид → Включить режим без отвлечений» (`⇧⌘J`) оставляет редактор на всю рабочую область окна: скрывает левую панель, предпросмотр, номера строк, строку состояния и панель инструментов. Повторная команда возвращает прежние значения; общие настройки не меняются. `⌃⌘B` также выходит из этого режима и показывает левую панель. Системные вкладки и кнопки окна остаются доступны; системный полноэкранный режим не включается. Режим относится к текущему окну и не сохраняется после перезапуска.

В настройках есть поле поиска, которое прокручивает к найденной строке и подсвечивает её. Панель инструментов настраивается средствами macOS, используется системный акцентный цвет.

В разделе «Настройки > Ассоциации файлов» можно посмотреть приложения по умолчанию для распространённых форматов и при необходимости назначить LacEditor. Установка и запуск не меняют ассоциации автоматически.

### Заметки и улучшения редактирования

- **Палитра команд** (`⇧⌘A`, «Вид → Палитра команд…»): плавающая панель над редактором со всеми доступными пунктами главного меню. Поиск по названию и пути меню, справа показаны горячие клавиши, `Return` выполняет, `Esc` закрывает. Недоступные, скрытые и системные пункты («Службы», «Окно») не показываются; палитра и быстрое открытие не открываются одновременно. `⇧⌘P` не используется: он занят пунктом «Параметры страницы…».
- **Операции со строками и комментарии**: «Правка → Строки» — дублировать строку (`⇧⌘D`), вверх/вниз (`⌃⌘↑`/`⌃⌘↓`), удалить строку (`⌃⇧K`), склеить строки (`⌃⌘J`), сортировка по возрастанию/убыванию (естественный порядок, устойчивая; при одной выделенной строке сортируется весь документ). «Переключить комментарий» (`⌘/`) работает для Swift, JS/TS, C, Python, Shell, YAML, SQL (строчные) и HTML, Markdown, CSS (блочные, построчно); JSON и обычный текст не поддерживаются. Каждая команда — одно действие отмены.
- **История версий и сравнение с диском**: после каждого успешного сохранения записывается версия файла macOS (ошибка не мешает сохранению). «Файл → Просмотр версий…» построчно сравнивает выбранную версию с текущим текстом; «Восстановить эту версию» — одна отменяемая замена, документ остаётся несохранённым. «Сравнить с файлом на диске…» сравнивает файл в кодировке документа. Недоступно для документа без пути; версии хранит система, удаления версий в интерфейсе нет.
- **Окончания строк и кодировка**: в строке состояния показаны LF, CRLF, CR или «Смешанные»; меню показывает счётчики и преобразует документ в LF/CRLF/CR (также «Правка → Окончания строк»). Преобразование — одна замена и одна отмена; U+2028/U+2029 переносами не считаются. «Файл → Сохранить в кодировке…» меняет только кодировку записи (документ становится несохранённым; если символы нельзя записать, сохранение отклоняется). «Открыть заново в кодировке…» заново читает файл с диска (при несохранённых правках сначала подтверждение; история отмены сбрасывается).
- **Wiki-ссылки**: Markdown поддерживает `[[имя]]`, `[[имя#Заголовок]]`, `[[имя|текст]]`. Файл ищется по имени в открытой папке (без папки — рядом с документом); если имён несколько, выбор не угадывается — укажите путь. В оформленном виде скобки скрыты, неразрешённая ссылка приглушена; Cmd-клик переходит (для отсутствующего файла предлагает создать); после `[[` появляются подсказки имён файлов; в предпросмотре и экспорте они заменяются обычными ссылками. Внутри таблиц и заголовков wiki-ссылки не распознаются, встраивание `![[…]]` не поддерживается.
- **Обратные ссылки**: при открытой папке раздел боковой панели «Обратные ссылки» показывает обычные и wiki-ссылки из других Markdown-файлов на текущий файл с фрагментом строки; клик переходит. Учитываются несохранённые правки открытых документов. Раздел не записывается в сессию.
- **Теги**: поиск тегов в папке находит и теги YAML front matter, и встроенные `#теги` в тексте (в том числе в заголовках, списках, цитатах и таблицах); сопоставление целым тегом без учёта регистра (`#a` находит `a` и `a/b`, но не `ab`). Не считаются тегами цифры, `C#`, заголовки, код, ссылки, wiki-ссылки, HTML, формулы и `\#`. Раздел «Теги» боковой панели показывает теги с числом файлов; загружается при раскрытии, смене папки и по «Обновить теги»; клик запускает поиск. В оформленном виде встроенные теги окрашиваются отдельным цветом. Список плоский (иерархия `a/b` не строится) и обновляется при раскрытии, смене папки и по команде; теги в таблицах не окрашиваются.
- **Шаблоны и заметка дня**: «Файл → Новая заметка из шаблона…» — выбор Markdown-шаблона из папки шаблонов и имени; файл создаётся в текущем каталоге (иначе в корне рабочей папки) без перезаписи и открывается; заменяются `{{title}}`, `{{date}}` (yyyy-MM-dd), `{{time}}` (HH:mm). «Файл → Заметка дня» открывает или создаёт сегодняшнюю заметку (из `daily.md` папки шаблонов, иначе пустую). «Настройки → Файлы и восстановление → Шаблоны и заметка дня»: папка шаблонов, папка заметок дня, формат даты. Отсутствующая папка заметок дня не создаётся; без рабочей папки команды предлагают её открыть.
- **Замена в папке**: поиск по содержимому папки имеет переключатели регистра, регулярного выражения и слова целиком, а также режим замены: предпросмотр «было → станет», флажки совпадений (по умолчанию выбраны все), «Заменить выбранное» и подтверждение с числом совпадений и файлов. Закрытые файлы записываются сразу в UTF-8 атомарно, «Отменить» их не возвращает; изменённые после поиска файлы, файлы не в чистом UTF-8 (например с BOM) и символические ссылки пропускаются с объяснением в итоге. Открытые документы меняются одной правкой в редакторе (одна отмена), без сохранения. Поиск по именам и тегам замены не имеет.
- **Режим чтения** (`⌥⌘R`, «Вид → Режим чтения»): запрещает правку, оставляя выделение, копирование, поиск и переход по ссылкам. Markdown показывается оформленным, при выходе возвращается прежний вид. Режим относится к текущей вкладке и между запусками не сохраняется; в строке состояния виден значок режима. Включается и кнопкой на панели инструментов; щелчок по значку в строке состояния выходит из режима, а кнопка режима Markdown выходит и показывает исходник.
- **Текущий элемент в строке состояния**: показывает путь Markdown-элементов под курсором, например «Заголовок 2 › Жирный» или «Цитата › Пункт списка › Ссылка». Скрыт для обычного текста, выделения, больших файлов, других языков и окон уже примерно 700 pt.
- **Понятный статус сохранения**: строка состояния различает «сохранено», «не сохранено» (с подтверждённой копией для восстановления или пока без неё), ошибку записи копии и новый документ без файла; в подсказке указано время последнего сохранения.
- **Цель письма**: настройка «Дневная цель по словам» (0 — выключено) показывает в строке состояния «написано / цель». Считается чистый прирост слов по документам за календарный день, вклад закрытых документов остаётся до конца дня; уведомлений нет.
- **Перенос разделов в оглавлении**: заголовок верхнего уровня можно перетащить или сдвинуть командами «Поднять раздел» и «Опустить раздел» из контекстного меню, также `⌥↑`/`⌥↓`. Раздел переносится с подразделами и одной отменой; уровень заголовка не меняется.
- **Закреплённые и недавние команды**: при пустом запросе палитра разбита на «Закреплённые», «Недавние» (до 5) и «Все команды»; кнопка-булавка в строке или `⌥↩` закрепляет и открепляет команду. Команда опознаётся по пути названий меню, поэтому после смены языка интерфейса прежние записи не показываются, но не удаляются.
- **Фокус на предложении**: «Вид → Приглушать соседние предложения» оставляет ярким только текущее предложение. В таблицах, у блочных изображений и при вертикальном письме действует область абзаца.
- **Сборка рукописи**: «Файл → Собрать рукопись…» при открытой папке объединяет выбранные `.md`/`.markdown` в новую несохранённую вкладку; порядок задаётся перетаскиванием или кнопками. Учитываются несохранённые правки открытых файлов, закрытые читаются как UTF-8 (остальные пропускаются с сообщением). Front matter остаётся у первого файла, относительные адреса изображений и ссылок заменяются абсолютными, поэтому результат не переносится на другой компьютер. Записи вида `[a][ref]`, HTML-ссылки и медиа не преобразуются и учитываются в сводке, совпадающие метки сносок показываются предупреждением, а исправлять их нужно вручную. Незакрытый блок кода в конце файла поглотит следующий файл. Исходные файлы не меняются.
- **Обновление ссылок при переименовании**: при переименовании или переносе Markdown-файла внутри открытой папки приложение находит wiki-ссылки и обычные ссылки на него и спрашивает подтверждение; по умолчанию ссылки не меняются. Открытые документы обновляются одной правкой с отменой, закрытые файлы (только UTF-8 без BOM) записываются на диск, и отмена переименования ссылки не возвращает. Папки, `file:`-адреса, ссылки-сноски, неоднозначные имена, имена с `# | [ ]` и собственные относительные ссылки перенесённого файла не обновляются.
- **Правки CriticMarkup**: подсветка `{++ ++}`, `{-- --}`, `{~~ ~> ~~}`, `{>> <<}`, `{== ==}` в исходном и оформленном видах; меню «Markdown → Правки» предлагает вставку, удаление и комментарий, принимает и отклоняет текущую или все правки, переходит к следующей и предыдущей. Правки в таблицах, коде и HTML не распознаются, предпросмотр и экспорт показывают разметку как обычный текст.

### Продолжение работы после выхода

По умолчанию при выходе сохраняется всё рабочее пространство, а при следующем запуске восстанавливаются окна, вкладки, текст, несохранённое состояние, выделения, положение прокрутки и состояние интерфейса. Снимки рабочего пространства и данные восстановления после сбоя хранятся отдельно; файлы на диске не перезаписываются автоматически. В настройках также можно выбрать обычное подтверждение сохранения перед выходом.

Это относится и к новым документам, которые ни разу не сохраняли в файл. После сбоя возвращается последний завершённый аварийный снимок: запись откладывается на 2 секунды, для крупных документов — на 5 секунд, поэтому самые последние правки могут не восстановиться. Явный отказ от сохранения при закрытии документа удаляет его данные восстановления.

Выход ожидает чтения и сохранения файлов и повторно записывает сессию, если за время записи появились изменения. Если безопасно восстановить сессию при запуске не удалось, приложение сообщает об ошибке и прекращает запуск, сохраняя данные восстановления на диске. Незавершённое открытие и его ошибочный результат нельзя сохранять поверх исходного файла или переносить в другое окно до успешного чтения.

### Язык интерфейса

В разделе «Настройки > Внешний вид > Язык» можно выбрать язык системы, китайский, английский или русский. Изменение вступает в силу после перезапуска приложения.

## Скачивание и установка

Скачайте последнюю версию arm64 в ZIP-архиве со страницы [Releases](https://github.com/LKosoj/LacEditor/releases), закройте старую версию, распакуйте архив и перетащите `LacEditor.app` в «Программы» с заменой. Требуются Apple Silicon и macOS 26 или новее. Настройки и рабочие пространства сохраняются. Содержимое каждого выпуска описано в [CHANGELOG.md](CHANGELOG.md); этот README описывает текущий код репозитория.

Если при первом запуске сборки с локальной ad-hoc-подписью macOS блокирует приложение, разрешите открытие в разделе «Системные настройки > Конфиденциальность и безопасность».

## Сборка из исходного кода

Схема `LacEditor` в режиме Debug использует отдельную идентификацию и данные разработки; установочный пакет выпуска создаётся командой `zsh Scripts/package-release.sh`.
Схема `LacEditor-UI-Experiment` сохраняет отдельную экспериментальную идентификацию.
Пакет выпуска использует данные основной версии; данные отдельного экспериментального пакета автоматически не переносятся.

Требования:

- macOS 26+
- Mac с Apple Silicon
- Xcode 26+

```bash
git clone https://github.com/LKosoj/LacEditor.git
cd LacEditor
sh Scripts/prepare-pandoc.sh
swift build
swift test
```

Подготовка распаковывает проверенный официальный архив из `Vendor/Pandoc`, без сетевой загрузки. Xcode выполняет этот шаг автоматически. Распакованный Pandoc увеличивает размер приложения примерно на 186 МиБ; архив в репозитории занимает около 41 МиБ. Сведения о версии, лицензии и распространении исходников: [Vendor/Pandoc/README.md](Vendor/Pandoc/README.md).

Для полной приёмки выпуска:

```bash
./Scripts/run-acceptance.sh
```

Также можно открыть `LacEditor.xcodeproj` в Xcode, выбрать схему `LacEditor` и нажать `Command+R`.

### Скрипты

Скрипты находятся в папке `Scripts` и работают на macOS. Они используют только файлы репозитория: исходный код, Pandoc и версии берутся локально, из Git ничего не скачивается и никуда не отправляется. Зависимости Swift загружает Swift Package Manager по адресам из `Package.swift`.

| Скрипт | Что делает |
| --- | --- |
| `prepare-pandoc.sh` | Сверяет контрольную сумму архива из `Vendor/Pandoc`, распаковывает Pandoc в `LacEditor/Resources/Pandoc` и разрешает его запуск. Нужен перед сборкой через Swift Package Manager; Xcode выполняет этот шаг сам. |
| `verify-release.sh` | Проверка перед выпуском: согласованность номеров версий, сборки Debug и Release, XCTest, отдельные проверки ядра и сборка Release в Xcode. |
| `run-acceptance.sh` | Полная приёмка: всё из `verify-release.sh`, анализ кода в Xcode, проверки файлов 1, 10, 20, 50 и 100 МБ, архитектуры и приёмочного приложения. После работы убирает регистрацию сборочных копий как обработчиков файлов. |
| `verify-bundled-pandoc.sh` | Проверяет Pandoc внутри готового `.app`: наличие, архитектуру arm64, версию 3.13, файлы лицензий, фильтр импорта и подпись. Путь к приложению передаётся аргументом. |
| `package-candidate.sh` | Собирает кандидата в выпуск, с `--release` — официальный пакет: сборка Release, подпись, ZIP-архив, проверка архива и распакованной копии. Ничего не устанавливает, не публикует и не пишет в Git. |
| `package-release.sh` | Вызывает `package-candidate.sh --release`. |
| `build-production.sh` | Собирает готовую к выпуску версию: запускает `verify-release.sh`, затем `package-release.sh` и кладёт в `dist` архив `LacEditor-<версия>-arm64.zip` и файл контрольной суммы `.sha256`. В конце печатает команду для загрузки обоих файлов в GitHub Release. Версию берёт из `VERSION` и сама её не меняет; новую версию сначала задаёт `prepare-release.sh`. |
| `package-experiment.sh` | Собирает отдельную экспериментальную версию «LacEditor 实验版.app», которая не заменяет официальную. |
| `prepare-release.sh` | Принимает новую версию вида `1.2.3`, требует запись в `CHANGELOG.md`, проверяет отсутствие такого тега, меняет `VERSION`, версию и номер сборки в проекте и запускает `verify-release.sh`. Коммит и тег не создаёт, а печатает команды для них. |
| `clean-build-artifacts.sh` | Показывает размер `.build`, `.swiftpm`, `build` и `DerivedData`. Удаляет их только с аргументами `--confirm` и точным путём к проекту. |
| `file-associations.sh` | Без аргументов показывает копии приложения, зарегистрированные как обработчики файлов. `--unregister-build <путь>` снимает регистрацию одной сборочной копии, `--clean` — всех копий, кроме установленной в «Программы». Приложения по умолчанию не меняются. |

## Техническое направление

Начиная с 0.14.0 используются системные вкладки окон macOS с поддержкой перетаскивания, отделения и объединения. Старые рабочие пространства восстанавливаются как группы системных вкладок в прежнем порядке с сохранением несохранённого содержимого, исходных путей файлов и открытия через Finder.

LacEditor использует SwiftUI для интерфейса, AppKit `NSTextView` для редактирования, TextKit для разметки видимой области и WebKit с `cmark-gfm` для локального предпросмотра Markdown. Чтение и запись файлов, анализ синтаксиса, поиск и замена, JSON, предпросмотр и восстановление остаются отдельными компонентами. Фоновые задачи проверяют версию документа, чтобы устаревшие результаты не перезаписывали более поздние изменения. В основе редактора остаётся TextKit 1.

Направления дальнейшей оптимизации перечислены в [NEXT_OPTIMIZATIONS.md](NEXT_OPTIMIZATIONS.md). Git, система плагинов и облачная синхронизация не входят в основные планы LacEditor.
