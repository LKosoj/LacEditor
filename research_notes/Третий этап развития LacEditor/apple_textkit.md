# Официальные материалы Apple о TextKit 2

## Что Apple подтверждает о пользе TextKit 2 и цене перехода

### Takeaway
TextKit 2 — основное направление развития Apple, но официальные материалы не обещают безусловного ускорения любого редактора. Для сильно изменённого NSTextView переход требует пересмотра работы с размещением текста, диапазонами и оформлением.

### Cited Findings
- В WWDC21 Apple описывает разметку видимой области: TextKit 2 всегда допускает обработку несмежных участков, TextKit 1 также имеет такой режим, включаемый отдельно. Запрос геометрии за пределами видимой области способен потребовать дорогой принудительной разметки. Источник не содержит сравнительных замеров LacEditor. — [Apple, Meet TextKit 2, WWDC21](https://developer.apple.com/videos/play/wwdc2021/10061/).
- В WWDC22 Apple рекомендует переходить на TextKit 2 и направляет туда будущие улучшения. Автоматический переход без кода относится прежде всего к приложениям без специальной модификации текстовых компонентов. Доступ к `layoutManager` способен переключить NSTextView обратно на TextKit 1; автоматического обратного перехода в том же компоненте нет. Глифы — отдельные визуальные части текста — не имеют прямого аналога API в TextKit 2. Вместо этого используются фрагменты разметки. TextKit 1 temporary attributes и TextKit 2 rendering attributes выполняют сходную роль временного оформления. — [Apple, What's new in TextKit and text views, WWDC22](https://developer.apple.com/videos/play/wwdc2022/10090/).
- В актуальной карточке `NSLayoutManager` отсутствует отметка deprecated в метаданных Apple DocC. Это проверено чтением JSON, а не только выдачи поиска. Нельзя из этого вывести обещание бессрочной поддержки. — [Документация NSLayoutManager](https://developer.apple.com/documentation/appkit/nslayoutmanager), [машиночитаемые метаданные](https://developer.apple.com/tutorials/data/documentation/appkit/nslayoutmanager.json).

### Inferences
- Для LacEditor, который уже использует разметку видимой области, чужое общее описание преимуществ не доказывает дополнительного ускорения после миграции.
- Общий слой временного оформления технически имеет смысл для двух движков, но Apple не требует вводить собственный `TextRenderingAttributes`. Если второй движок откладывается, необходимость этого слоя должна определяться текущим дублированием кода, а не подготовкой к неопределённой миграции.
- Исследование позволяет обосновать решение сохранить TextKit 1 сейчас. Оно не заменяет проверку корректности будущей реализации TextKit 2 в LacEditor.

### Gaps
- Официального сравнения задержек, памяти и китайского ввода для текущего LacEditor нет.
- Старые предупреждения WWDC22 о несовместимости конкретных функций нельзя автоматически считать перечнем неисправленных проблем macOS 26. Здесь они используются для объяснения архитектуры миграции.

## Какие новые возможности доступны именно на нужной версии macOS

### Takeaway
Найденный новый доклад действительно содержит номера строк и сворачивание разделов, но новые интерфейсы предназначены для macOS 27.0, а не для минимальной macOS 26 приложения.

### Cited Findings
- WWDC26/370 описывает `NSTextViewportRenderingSurface` и `NSTextViewportRenderingSurfaceKey`, новые возможности переопределения методов размещения видимой области в NSTextView/UITextView. Конкретные примеры редактора с номерами строк и сворачивания рецептов написаны на UIKit (`UITextView`), хотя доклад заявляет новые точки расширения и для AppKit (`NSTextView`). Apple отмечает цену полностью собственного текстового компонента: ввод, выделение, доступность и Undo/Redo приходится обеспечивать самостоятельно. — [Apple, Elevate your app’s text experience with TextKit, WWDC26](https://developer.apple.com/videos/play/wwdc2026/370/).
- В официальном JSON `NSTextViewportRenderingSurface` указан `platforms: [{introducedAt: "27.0", name: "macOS"}]`. Для `NSTextLayoutManager` аналогичные метаданные указывают macOS 12.0. — [Документация нового протокола](https://developer.apple.com/documentation/appkit/nstextviewportrenderingsurface), [JSON нового протокола](https://developer.apple.com/tutorials/data/documentation/appkit/nstextviewportrenderingsurface.json), [JSON NSTextLayoutManager](https://developer.apple.com/tutorials/data/documentation/appkit/nstextlayoutmanager.json).

### Inferences
- Нельзя ссылаться на простоту нового примера как доказательство простоты переноса всей линейки, фиксированной высоты строк, китайского ввода и сворачивания LacEditor на macOS 26.
- При сохранении требования macOS 26 новые интерфейсы macOS 27 потребовали бы отдельной ветки поведения для старой системы; это дополнительный объём, не повод добавлять его сейчас.

### Gaps
- На странице WWDC26/370 текст несколько раз говорит «2027 releases», несмотря на название WWDC26. Это несогласованность самого источника. Для определения доступности здесь использована явная версия 27.0 из Apple DocC, а не попытка исправить календарные формулировки Apple.
- Не найден официальный отдельный доклад WWDC25, который бы подтверждал перенос этих новых интерфейсов на macOS 26. Отсутствие найденного доклада не является доказательством отсутствия всех изменений TextKit в macOS 26.
