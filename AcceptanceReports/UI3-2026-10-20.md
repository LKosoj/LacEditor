# 界面实验 UI3 验收记录

日期：2026-10-20。版本：**0.15.0 · UI3（构建 66）**。
分支：`codex/flclash-ui-experiment`；UI2 基线 `ea7ea8a`，正式基线仍为 `7024a03` / 0.14.4（63）。

## 本轮交付

- Markdown 阅读样式：15 px / 1.7 系统字体、最大 760 px 阅读宽度，统一标题、列表、引用、表格、代码和深浅色画布；长代码和宽表格局部滚动。
- 保留同一个 WebKit 页面，正文更新 article，主题只更新样式；保留阅读比例、代码/表格横向位置，重载恢复最新内容。
- 保留原生 preview pane、WKWebView 与编辑器，隐藏时暂停渲染，重开恢复分栏比例。即时几何切换避免逐帧文本重排。
- 侧栏标题支持键盘聚焦显示隐藏操作，补充展开/收起辅助描述，并遵循减少动态效果。
- 不修改正文排版、字体、IME、TextKit 引擎、原生标签与 NT2 标题栏路径。

## 原生窗口性能记录

同机优化 Release 工作负载：792,000 字节 Markdown，预热 2 秒，30 轮窗口 1000/1180 pt 缩放、跨区域滚动、预览开关与侧栏切换。以下计时为同步操作加 AppKit layout，**不是显示帧时间或输入延迟**。

| 操作 | UI2 中位 / P95 ms | UI3 中位 / P95 ms |
| --- | --- | --- |
| 预览开关 | 9.308 / 12.123 | 9.036 / 12.470 |
| 窗口缩放 | 7.951 / 14.178 | 7.874 / 13.274 |
| 跨区域滚动 | 9.306 / 15.388 | 10.242 / 16.373 |

差异较小且存在运行波动，不能据此声称整体提速。确定的行为改善是预览编辑/换主题不重新导航，开关不重建编辑器与 WebKit。

另一次 Debug 原生标签测试 100 次切换：中位 4.565 ms，P95 8.719 ms，最大 13.985 ms；同样仅测同步切换与 layout，不能当作真实指针到显示的延迟。

### 内存与大文件

- 普通文档 UI2 宿主 RSS 约 176 → 200 MiB；UI3 约 235 → 181 MiB，中间约 232 MiB。缓存/系统回收会影响结果，短循环不能证明无泄漏，也不能据此声称降低整体内存。
- 独立串行执行 52,428,816 字节 Markdown 负载，沿用大文件模式、预览关闭；30 次缩放/跳转，16.7 秒完成，无崩溃，正文/选区/编辑器实例保持。
- 50 MB 缩放中位 8.899 ms / P95 12.536 ms；滚动中位 1.223 ms，但深处首次布局 P95 585.821 ms、最大 661.953 ms。**首次深区跳转仍有明显布局停顿，应作为下一轮性能项。**
- 50 MB 宿主采样 RSS 约 132 → 峰值 392 → 326 MiB；峰值是离散采样最大值，并非完整进程树的连续峰值。
- RSS 仅含 XCTest 宿主，不含 WebKit WebContent/GPU 子进程；预览保留实例换取连续性，关闭预览并不立即释放全部预览内存。
- CMark 单次解析内部不能逐字符取消；队列串行、开始前/结束后检查取消与 generation，过期结果不应用。没有据此宣称大预览完全可中断或长时间无任务积压。

### Instruments

- UI2/UI3 同一优化工作负载分别执行 Time Profiler；目标 `xctest`，不是用户正在运行的正式 App。两份 `potential-hangs` 表在 250 ms 阈值下均为 0 行。
- Animation Hitches 模板分别记录并导出。显示服务表涉及整个桌面，且 UI3 采集期间另有测试窗口负载，不满足隔离的逐帧 A/B 条件；不使用原始 hitch 数量声称本 App 帧率或提速。
- 保存 compact 导出与日志；大型原始 Animation Hitches 临时 trace 在完成导出后移入废纸篓，项目减少约 1.1 GB 占用，实际磁盘空间需清空废纸篓后才释放。Time Profiler 小型 trace 暂存 `.build`。
- 尚未验证：真实前台手动拖拽时的隔离帧率、完整 WebKit 子进程内存、10 分钟连续编辑、Leaks/Allocations 长时间增长。
