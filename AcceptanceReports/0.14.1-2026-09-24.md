# 0.14.1（60）关闭标签确认回归

## 问题与修复

原生标签关闭提示框选择“不保存”后未关闭。旧流程在 sheet 完成回调里再次调用 performClose，重新进入 AppKit 的原生标签关闭判断，同时依赖会被焦点事件重置的批准标记。

改为一条等待保存/确认的流水线。确认通过后在下一次主队列调度中调用 close，执行已经批准的关闭，避免重入 performClose；取消解除等待状态，关闭时重置等待状态。仍在关闭前清理文档恢复记录，保留保存失败/取消的原有保护逻辑。

## 证据

- 新增真实 NSWindowTabGroup + NSAlert sheet 的 XCTest，点击实际 NSButton，覆盖保存、不保存和取消，并验证磁盘文件。
- 修改前：同一测试中“不保存”的窗口可见性和标签组移除断言均失败，复现用户问题。
- 修改后：同一测试全部通过；不保存不修改磁盘，保存写入 edited 后关闭，取消保留未保存文档和标签；不会再次弹出提示框。
- 全部 60 项 XCTest 通过。
- Debug / Release 构建成功，run-acceptance.sh 七阶段通过，包括文件格式、性能、1–100 MB 文件门禁及隔离 UI App 构建。
- Analyze 完成，Vendor 既有警告仍存在；既有 SwiftUI 更新期间发布状态警告仍存在。
- 本轮没有额外进行人工全屏、多屏与全外观回归；关闭行为证据来自真实窗口的自动化测试。
