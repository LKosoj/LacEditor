## Порядок реализации

1. После решения по ресурсам положить только перечисленные файлы и оригинальные notices в каталог ресурсов; обновить оба списка сборки и прямые проверки. Без CDN и без исполнения Markdown как HTML или JavaScript.
2. Отдельный узкий WKWebView host с локальным `loadFileURL` и CSP без сети принимает source как данные, выбирает `flow` либо `sequence` и утверждённую тему; отображает в локальном контейнере. Дождаться реальной загрузки шрифта и завершения отрисовки, проверить SVG и размеры; ошибка возвращает исходник. SVG/bitmap снять полностью с учётом отрицательных границ и масштаба; отмена и закрытие очищают задачу. Не ослаблять CSP обычного предпросмотра.
3. Общий cmark-результат подтверждает fenced blocks с именами `flow`/`sequence`, возвращает точные UTF-16 диапазоны и source. Через существующий controller/layout показывать только видимые блоки, раскрывать исходник при выделении, соблюдать версию, IME и отмену. Не смешивать grammar этих движков с Mermaid. Значения тем/параметров и экспорт проверять по полной матрице 25.1.
4. HTML/PDF/EPUB/DOCX используют созданное локально изображение и согласованные размеры; сохранить альтернативный текст и исходник. Переиспользовать существующие пути этих экспортов, не создавать новый общий framework.
5. XCTest: оба языка, две sequence темы, сложные/ошибочные случаи и Unicode; источник как данные, отказ от сети, полный bitmap, актуальность, отмена, выбор/IME и экспорты. Реальное WebKit, VoiceOver, разные масштабы и полную матрицу проверить на Mac. До этого 25.1 остаётся незавершённой.

Первый сквозной срез реализован для закрытых верхнеуровневых блоков: общий cmark подтверждает тип и диапазон, editor показывает локальное изображение с раскрытием source, preview и PDF/PNG вызывают тот же изолированный renderer. Добавлены Swift-тесты parser/editor/preview/PDF и независимое статическое review. Некорректный блок остаётся исходным текстом. Маркеры стрелок в SVG, точность bounds, системный ввод, печать и WebKit/XCTest на Mac ещё не проверены. Вложенные блоки, способы выбора `hand`, доступность и HTML/EPUB/DOCX остаются обязательными; этот срез не закрывает 25.1.

## Общая подготовка рисунков для HTML, EPUB и DOCX

Владелец AppState/Pandoc и тестов этих путей — files; отдельный подготовитель и его тесты — blocks. Для экспортируемого неизменного snapshot один фоновый общий `MarkdownPresentationParser.parse` возвращает cmark-подтверждённые `diagrams`, `formulas` и `inlineFormulas`; источники и позиции не извлекаются отдельным поиском по сырому тексту. Если их нет, сохранить нынешний путь экспорта. HTML без стилей уже использует WebKit renderer и не проходит эту замену повторно.

На main actor перед запуском Pandoc подготовитель обрабатывает все формулы одним MathJaxRenderService в порядке исходных UTF-16 диапазонов, сохраняя общее состояние макросов, нумерации и меток конкретного snapshot; Mermaid и flow/sequence строятся соответствующими существующими локальными сервисами последовательно. Параметры размера, оформления и опций берутся снимком до старта. Каждый результат должен быть PNG с данными; ошибка/отмена явно прерывает экспорт и не меняет destination. На протяжении ожиданий проверяются номер задачи, документ, версия и отмена; остановка останавливает активный WK service. Перед передачей результата снова сверить исходные диапазоны и их непересечение.

Только временная копия Markdown получает замены с конца к началу: блоковые и inline-диапазоны превращаются в Markdown image с корректно экранированным alt и data URI. Исходный документ, выделение и undo не меняются. Для quote/list сохраняется исходный префикс до подтверждённого диапазона; table pipe и UTF-16/CRLF проверяются примерами. Подготовленная копия передаётся существующему Pandoc export с прежними destination/conflict/atomic install; source path и окружение остаются прежними. Применять только к HTML/DOCX/EPUB, включая соответствующие разрешённые профили: LaTeX и текстовые форматы сохраняют исходные формулы и диаграммы. RawType-режимы с TOC не смешиваются с этим шагом; не пересчитывать исходные ranges по изменённому документу. Для пользовательских shell/PDF-engine профилей автоматическое преобразование не добавлять.

Проверка: реальные входы с макросом в одной формуле и использованием в другой, все три движка, inline и block, таблица/Unicode/CRLF/quote, source unchanged, отмена во время каждого сервиса, смена версии и destination, недействительная формула/диаграмма. Проверить bundled Pandoc 3.13: HTML содержит data URI, DOCX/EPUB ZIP действительно содержат PNG bytes и нужные подписи; не считать созданный ZIP доказательством без чтения содержимого. Внутренние `\\ref` внутри изображений этих трёх форматов и сложные вложенные диаграммы остаются обязательными последующими частями, поскольку один PNG сам по себе не содержит кликабельной области. WebKit/Pandoc/XCTest на Mac ещё не проверены.

Общий подготовитель подключён к стандартным и профильным HTML/DOCX/EPUB; использует один упорядоченный MathJax batch и существующие локальные сервисы диаграмм. При правке отменяются подготовка и запущенный Pandoc, перед установкой проверяются снимок и destination. Добавлены тесты исходника, stale/cancel, HTML data URI и PNG bytes внутри DOCX/EPUB; независимое статическое review завершено. Системный Linux Pandoc 3.1.3 отдельно создал PNG внутри обоих ZIP, но это не проверка bundled 3.13/XCTest/WebKit на Mac. Вложенные диаграммы, прямые ссылки в изображениях и остальные требования 25.1/12 остаются.
