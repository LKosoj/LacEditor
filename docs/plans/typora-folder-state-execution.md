# 19: состояние папки, внешние изменения, сортировка и вид — план до кода

Статус: state/session, сортировки, list/tree и FSEvents реализованы и подготовлены к независимому ревью; ранее реализованные файловые действия 19 и интеграция поиска 20 проверяются отдельно. Проверки macOS/XCTest в Linux не запускались; полная приёмка 19 остаётся открытой.

## Текущее устройство и границы

- `FolderWorkspaceStore` принадлежит одному `AppState` и содержит один root, раскрытые URL, результаты непосредственного чтения и поколения фоновых задач. Сегодня он сортирует папки первыми в естественном порядке, вручную обновляет раскрытые ветви и не хранит корень в сессии; автоматического наблюдения нет.
- `WindowManager.captureWorkspaceSnapshot` сохраняет одну запись на **группу** системных вкладок, объединяя документы разных `AppState`. При восстановлении `apply` снова создаёт системную вкладку для каждого документа. Поэтому одно поле root в `WorkspaceWindowSnapshot` потеряло бы различие папок вкладок. У каждого восстановленного документа должна быть сохранена информация исходного состояния окна.
- Новая системная вкладка, включая вкладку при открытии файла, **не наследует** root родительского окна; она получает собственный пустой root, пока пользователь не выберет папку. Перенос документа между окнами не переносит root источника и не меняет root приёмника. При очередном сохранении сессии для документа записывается root того `AppState`, который реально владеет им в момент снимка.
- `WorkspaceSessionStore` пишет `Manifest(version: 1)` и два независимых механизма сессии/аварийного восстановления; данные лежат под `AppEnvironment.dataDirectoryName`. Не вводить другой файл настроек, общую для окружений папку, базу или индекс. Не изменять механизм снимков содержимого и маркеров сессии.

## Сохранение и восстановление

1. В `WorkspaceDocumentSnapshot`, `WorkspaceDocumentReference` и `DocumentMetadata` добавить необязательное состояние папки (`folderWorkspace`): стандартизованный путь root, массив **относительных компонентов** раскрытых каталогов, enum сортировки и enum вида, относительный путь текущего каталога для списка. Один и тот же объект состояния копируется всем документам одного `AppState` при снимке; сам `EditorDocument` им не владеет. У снимков аварийного восстановления без соответствующей обычной сессии folder state отсутствует.
2. Оставить `version: 1` и старые поля. Новые поля декодируются через `decodeIfPresent` с пустым root и текущими значениями по умолчанию при отсутствии; неизвестное значение сортировки/вида отдельно обрабатывать безопасным default, не отбрасывать всю сессию. Старые manifest без дополнительных полей, recovery с приоритетом текста, порядок вкладок и список снимков должны открываться как раньше; чтение старого manifest не записывает его обратно. Старый бинарный читатель обязан игнорировать неизвестные JSON-поля; проверить тестом на старую модель, а не предполагать.
3. В `captureWorkspaceSnapshot` получать данные папки из каждого `groupState` до `flatMap` документов, не брать root только выбранной вкладки. При `restoreInitialSession` передать поле рядом с соответствующим ID документа в `RestoredWindow`; `apply` назначает его новому `AppState` именно этой вкладки, включая первую. Recovery подменяет только содержимое того же ID, но не теряет папку из workspace; дополнительные аварийные документы получают пустую папку.
4. Хранить обычный стандартизованный путь без нового bookmark (постоянной ссылки) на первом этапе: проект не использует sandbox, существующий workspace уже хранит пути. После перезапуска проверять root свежими значениями: существует, каталог, сам не симлинк. Недоступный/удалённый root остаётся видимым как недоступный с понятной ошибкой и действием выбора другой папки, не заменяется домашним каталогом и не блокирует восстановление текста. Переезд root при выключенном приложении автоматически не определяется; требование автоматического переноса после перезапуска этим вариантом не закрывается и потребует отдельного согласования bookmark. Никаких security-scoped разрешений без sandbox-контракта.
5. Для `expanded` сохранять компоненты относительно root, не `hasPrefix` строк; запрещать абсолютные пути, пустые/`.`/`..`, симлинки и выход из root. Восстанавливать сверху вниз: прочитать root, подтвердить непосредственного ребёнка, раскрыть его и лишь после его успешного чтения переходить к сохранённым потомкам. Не перечислять свёрнутые каталоги, не восстанавливать отсутствующий узел на основании одного сохранённого текста пути. Смена root/отмена/закрытие прекращает цепочку через существующие поколения; некорректная ветвь пропускается с локальной ошибкой и не мешает документам.

## Автоматическое наблюдение

Выбор: один системный FSEvents stream для выбранного root с `FileEvents` и `WatchRoot`. [Apple указывает](https://developer.apple.com/documentation/coreservices/kfseventstreamcreateflagfileevents), что события могут приходить для отдельных файлов и их будет больше; поток отслеживает всю иерархию root на уровне ОС, но приложение не обходит и не индексирует свёрнутые ветви. `NSFilePresenter` недостаточен как единственный источник: [Apple ограничивает его уведомления координированными операциями](https://developer.apple.com/documentation/foundation/nsfilepresenter?changes=_2). CoreServices — штатная часть macOS, не внешний пакет.

- Создать один поток после проверки root и зарегистрировать на выделенной последовательной очереди; использовать `FileEvents`, `WatchRoot`, `UseCFTypes` и `SinceNow`, не сохранять глобальный журнал. Колбэк копирует пути и флаги до выхода, передаёт на главный поток с номером поколения и текущим root; старая доставка после смены/закрытия игнорируется. Владелец отменяет, снимает с очереди, инвалидирует и освобождает поток ровно один раз при смене root/закрытии, включая неудачный старт.
- События объединяются по родительскому каталогу: перечитываются только реально раскрытые ветви дерева или текущий открытый каталог списка, чьи непосредственные дети затронуты. Флаги изменения файла позволяют обновить дату/сортировку родителя. События свёрнутых ветвей игнорируются, их данные будут считаны при раскрытии. Не разрешать симлинки для обхода и сверять компоненты пути, поколение и принадлежность root перед применением.
- `MustScanSubDirs`, `UserDropped`, `KernelDropped` или неизвестное объединённое событие означает утрату подробностей: Apple требует пересканировать отслеживаемую иерархию. Здесь отображается только лениво загруженный срез, поэтому перечитать все **уже раскрытые/текущий** каталоги сверху вниз, перепроверяя родителей и дочерние идентичности; не утверждать, что скрытая иерархия пересканирована. При её будущем раскрытии прочитать фактическое содержимое. При `RootChanged` перепроверить первоначальный root и показать недоступность, если он исчез/подменён; не угадывать новое место и не менять пути открытых документов. См. [обработку FSEvents Apple](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html).
- При активации окна сохраняется существующий `refresh()` как дополнительная проверка после приостановки/ошибок ОС. Создание/запуск потока может не удаться: показывать понятную ошибку и сохранять ручное обновление, не выдавать watch за активный. Нет гарантии доставки каждого отдельного события и атомарной защиты от внешней подмены между проверкой и чтением; это отдельно проверяется на Mac.

## Вид и сортировка

- Добавить в `FolderWorkspaceStore` enum вида `.tree`/`.list` и сортировки `.name`, `.natural`, `.created`, `.modified`. По умолчанию `.tree` и текущий `.natural`. Название — локализованное сравнение строк; естественная сортировка — существующий `localizedStandardCompare`; для дат — сначала более новые (`creationDate` или `contentModificationDate` соответственно), неизвестная дата последней. Папки по-прежнему первыми; при совпадении устойчиво разрешать имя и полный путь. Даты считывать вместе с непосредственными детьми на фоновой очереди, затем сортировать там же; смена сортировки повышает поколение запроса, поздняя сортировка не перезаписывает новую.
- Tree сохраняет нынешние раскрываемые строки. List показывает только непосредственных детей текущего каталога; выбор папки входит в неё, управление «назад»/хлебные крошки возвращает к корню, файл открывается существующим путём. Текущий каталог обязан быть подтверждённой реальной папкой под root, без обхода ссылок. При его удалении вернуться к ближайшему подтверждённому родителю с сообщением; не рекурсивно перечислять остальные папки. Отдельный `ScrollView` не добавлять: строки обоих видов остаются отдельными элементами общей `LazyVStack`.
- При переключении вида сохранять раскрытые ветви дерева как состояние вкладки; список не инициирует чтение всех сохранённых ветвей. Наблюдатели держать только для root и текущих реально раскрытых ветвей текущего вида; при возврате в дерево восстановить их через подтверждение ветвей. Поиск 20 и фильтр библиотеки не менять; переключение сортировки/вида не меняет документ и текстовую отмену.
