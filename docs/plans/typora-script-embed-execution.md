# 15: распознанный код встраивания Twitter/X

Это оставшаяся документированная часть HTML Typora, не разрешение выполнять произвольный script документа. [Typora](https://support.typora.io/HTML/) показывает blockquote.twitter-tweet со стандартным widgets.js и изолирует такой код в sandbox iframe. [Документация X](https://docs.x.com/x-for-websites/embedded-posts/overview) подтверждает две части встраивания: исходную разметку и официальный JavaScript, который превращает её в пост. Получение кода через [меню X](https://help.x.com/en/using-x/how-to-embed-a-post) не требует создания интеграционного аккаунта приложения. Наличие статического кода не доказывает доступность конкретного поста или работу сервиса в WebKit.

Первоначальные варианты ниже сохранены как история обсуждения; принятое решение и текущий результат приведены после списка.

1. Подтвердить исходный диапазон в том же дереве cmark, порядок HTMLContext и структуру SwiftSoup через прежние временные комментарии. Принять документированную пару полного blockquote.twitter-tweet и следующего script с точным официальным адресом widgets.js; атрибуты и содержимое сверить с официально выдаваемым кодом. Произвольный inline script или event attributes не переносить в страницу редактора. Начать с отдельного целого HTML-блока, затем покрыть фактическое разделение blockquote/script между cmark-узлами без второго Markdown-разбора.
2. Сохранить исходный текст и резервный текст поста/ссылки. Внутри изолированного iframe строить подтверждённую разметку и фиксированный официальный loader, а не исполнять непроверенную строку из документа. Использовать имеющийся MarkdownIframeBlock и жизненный цикл WebKit; новое поле допускается только если существующая модель не различает обычный iframe и распознанный widget. Не создавать отдельное окно, сервер или механизм расширений.
3. Проверить наследование Content Security Policy — правил разрешённых загрузок — для srcdoc. Сейчас контейнер разрешает только обычные frame HTTP(S) и не разрешает scripts. Правила нужно расширять лишь для распознанного widget в его отдельном непостоянном WebKit, сохраняя sandbox без same-origin, доступа к локальным файлам и тексту документа. Не включать scripts в основной Markdown preview. Не угадывать работоспособность загрузчика по одному факту разрешения URL.
4. Подключить обычные проверки document/revision/generation, видимости, отмены, marked text, исходного выделения и изменения размеров. Уход за экран и смена документа освобождают view существующим путём. Нажатие неинтерактивной области/Command-click раскрывает источник. Изменение размеров не меняет source, dirty или undo.
5. Заранее определить вывод: HTML сохраняет работающий изолированный widget; PDF/печать/PNG получают проверяемое статическое содержимое, а при недоступном сервисе — уже имеющийся резервный текст/ссылку. Не выдавать текстовый fallback за успешную загрузку внешнего поста. Форматированное Copy передаёт подтверждённые текст/HTML без потери исходных данных и без неподтверждённого RTF.
6. Swift fixtures: официальный код и Unicode/пути, неверный/лишний script и атрибуты, crossing/inert DOM, совпадение source, отсутствие выполнения scripts снаружи iframe, невозможность прочитать родительский документ/локальный файл, lifecycle/IME/resize/reveal/undo. Для сети использовать существующие подменяемые загрузчики; фактический стандартный widgets.js и пост отдельно проверить на Mac. Повторное независимое review и проверка корневым агентом обязательны.

Реализация ещё не начата. Не добавлять новые пользовательские режимы, собственный whitelist UI или фоновые сетевые запросы из-за этого пункта. CSS-темы исключены. Проверенные адреса/атрибуты официального loader зафиксировать до кода, не копировать случайный пример из стороннего сайта.


## Уточнённый план GPT-6.1-Terra

`files_execution` детализировал, `native_execution` независимо рассмотрел. Основной агент подтвердил политику вывода. Первый конечный пример — один целый HTML_BLOCK документированной формы; pinned cmark подтверждает, что blockquote и script без пустой строки между ними входят в него, следующий абзац отдельный. Сверяются Source/literal/HTMLContext/DOM и точные атрибуты, затем из единственной HTTPS status-ссылки извлекается цифровой идентификатор. Неоднозначные идентификаторы и неподтверждённые формы остаются исходником до своего среза.

Для показа исследуется официальный удалённый адрес `https://platform.twitter.com/embed/Tweet.html?id=…&dnt=true`. Он возвращает страницу с официальными embed runtime/Tweet scripts; JavaScript страницы разбирает обязательный параметр id. Это внутренний проверенный по исходникам адрес, а не обещанный публичный API. Его использование позволяет сохранить прежнюю CSP основной страницы без разрешения scripts и не переносить script документа в приложение. Политика srcdoc вместо этого не выбрана: по [CSP](https://www.w3.org/TR/CSP/#csp-inheriting-to-avoid-bypasses) он наследует ограничения родителя.

Native/preview/HTML используют существующий iframe с прежней фиксированной высотой. Автоматическое изменение высоты требует отдельной фактической проверки. Для PDF/PNG/печати существующий PDFService передаёт внутренний `staticWidgetFallback` до первого renderPage и загрузки WebKit: только этот widget выводится как подтверждённый статический текст и ссылка, без iframe/img/script. Остальные ресурсы документа сохраняют прежний путь. HTML без оформления остаётся интерактивным. Новых пользовательских настроек, проверки здоровья внешнего сервиса или определения успеха по одному load-event не добавлять.

Linux-проба: прямой официальный адрес с идентификатором примера Typora вернул 200 и фактически отобразил пост в отдельном headless Chromium (DOM содержит article и исходный текст). Отдельная проба iframe с прежним sandbox пока не подтвердила пост; пустая печать не доказывает причину. Реальное выполнение в sandbox и WK остаётся обязательной проверкой архитектуры до объявления работоспособности. Исследовательские пробы не меняют правила приложения, исходный текст или настройки пользователя.

Реализован первый целый подтверждённый блок: редактор и предпросмотр используют прежний iframe, а PDF, печать и PNG получают статический текст и ссылку. Форматированное копирование целого блока передаёт тот же iframe и пустой обычный текст, как для существующего iframe; частичное выделение не меняет буфер. Исходный widgets.js не исполняется и не переносится при форматированном копировании. Для дочернего iframe разрешён JavaScript в движке WebKit, при этом строгая политика основной страницы остаётся прежней и не разрешает скрипты документа. Тестовый loopback-сервер проверяет изоляцию и не входит в приложение.

Проверки исходного диапазона, DOM, статического вывода и буфера добавлены и рассмотрены независимо; выполнение XCTest, WebKit и PDFKit на Mac ещё требуется. Загрузка реального поста во внешнем iframe не подтверждена, автоматическая высота пока не реализована. Исходный документ и обычное копирование Markdown сохраняют исходную разметку.
