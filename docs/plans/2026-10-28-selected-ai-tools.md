# Выбранные функции AI: пункты 1, 2, 3, 5, 6, 7, 8

Пользователь выбрал контекст документов, сравнение версий, свои проверки,
распознавание скриншотов/сканов, голосовой черновик, Mermaid и объяснение фрагмента.
Поиск по всей коллекции (пункт 4) не входит в работу. Каждый сценарий включается
отдельно и по умолчанию выключен; пользовательские правила имеют свои выключатели.
Прежние настройки, документы и незакоммиченные изменения сохраняются.

## Решение и зависимости

Использовать существующую панель помощника, проверку версии и отмену.
Для семи ручных инструментов добавляется контроллер состояния выбранных входов;
система плагинов, индекс файлов и новые окна не нужны. Сравнены встроенные
модели, копирование серверного кода и вызов уже существующих HTTP-интерфейсов.
Выбран последний вариант: серверная часть LLMApiGateway остаётся на сервере.
Сам шлюз, конфигурация провайдеров и работающие службы не меняются.

## Подробные задачи и критерии

1. **Контекст.** Явно выбрать открытые вкладки или файлы, показать список,
   получить актуальные тексты, включая несохранённые, и передать их как данные.
   Проверять смену/закрытие любого источника и незавершённое открытие. Проверки:
   другие окна, кодировки, несохранённый текст, изменение источника во время ответа.
2. **Сравнение.** Два явных входа «до/после», обычное точное построчное сравнение,
   отдельно объяснение модели. Проверки: CRLF/LF, конечный перенос, пустые файлы,
   emoji, составные символы и изменение файла во время ответа. Исходники не менять.
3. **Свои проверки.** Имя, инструкция и отдельный выключатель; добавление,
   изменение, удаление, сохранение в настройках. Изменение/отключение выбранного
   правила отменяет старый результат. Никакой скрытой автоматической перезаписи.
5. **Скриншоты и сканы.** Выбор изображения/PDF, отдельный OCR-профиль, просмотр
   Markdown и явная вставка после выделения или в пустой документ. Поддержку
   входных изображений согласовать с реальным форматом отправки модели.
6. **Голос.** Импорт аудио либо запись с разрешением микрофона, отдельная команда
   расшифровки, просмотр и вставка. Удалять только собственные временные записи.
   Проверить отказ разрешения, отмену ожидания, выключение функции, смену документа
   и скрытие панели. Импортированный файл не удалять.
7. **Mermaid.** Выделение → исходный код диаграммы → просмотр/копирование/явная
   вставка блока mermaid после выделения. Рендер использует существующий локальный
   Mermaid. Генератор изображений и внешний сервис рендера не добавляются.
8. **Объяснение.** Непустое выделение текста/кода → объяснение в панели без
   замены исходника. Проверить требование выделения и устаревание результата.

Перед запросом показывать выбранные входы. Перед показом и вставкой сверять
документ, версию редактора, источники, настройки и ключ. Вставка проходит через
EditorRangeReplacementRequest с isAIGenerated и сохраняет обычную отмену.
Фоновый анализ и поиск по папкам к этим ручным командам не добавляются.

## Подтверждённые контракты соседних проектов

- LLMApiGateway `llm_gateway_core/api/v1/audio.py`: multipart POST
  `/v1/audio/transcriptions`, поля file/model/response_format=text. Ответ текст
  либо JSON с text. Пример настроенного алиаса: `llmgateway/whisper-large-v3`.
- Gateway `llm_gateway_core/api/v1/pdf.py` передаёт поля и JSON конвертера без
  изменения. Контракт MCPDoc `pdf_docx_mcp/service.py`, функции
  `_read_convert_request` и `_format_convert_response`: multipart file/model,
  output=docx; ответ docx_base64. Алиас: `llmgateway/pdf-converter`.
- Поле markdown конвертера очищается до обычного текста (`server.py:1397`),
  поэтому для сохранения структуры берётся DOCX и уже существующий PandocImportService.
  URL артефактов не угадываются, API-ключ чужому получателю не передаётся.
- Responses шлюза принимает текст и изображения, но не произвольные input_file.
  Контекст выбранных текстовых файлов сериализуется в текст запроса.
- Указанный в старых заметках алиас llmgateway/ocr в текущих operation rules
  отсутствует; приложение не прописывает его как работающую модель.

## Исполнение и проверка

GPT-6.1-Terra сначала подробно планирует работу, затем владеет одним из наборов:
медиа-профили/клиент; снимки/сравнение/правила; ручные инструменты/запись/панель.
Основной агент связывает меню, настройки, разрешения, переводы и сборочные списки.
После реализации — независимые ревью, исправления до чистого результата и
собственная проверка итоговых изменений.

HTTP-тесты используют подставной URLSession; ключи из соседнего проекта не
копируются. Реальная серверная обработка не запускалась. Linux не предоставляет
Swift/macOS SDK, поэтому сборка, XCTest, PDFKit, микрофон, ввод и интерфейс требуют
проверки на Mac; статические проверки не выдаются за их прохождение.

## Фактический результат и границы проверки

Семь инструментов подключены к существующим меню и панели; добавлены девять
исходников, отдельные профили OCR/аудио, совместимое чтение старых настроек,
разрешение микрофона во всех конфигурациях и переводах. Выбор файлов явный,
исходные документы не переписываются. Для цитат предусмотрен отложенный переход
после создания редактора, с повторной проверкой версии. Пустые источники
допускают честный ответ без цитат.

В трёх независимых направлениях GPT-6.1-Terra исправлены: выбор пустого источника
при незавершённом открытии; продолжение записи/ожидания разрешения после смены
контекста; устаревшая разница после изменения файла; диапазоны PDF перед Int;
передача отмены фоновым задачам; TIFF/HEIC в vision; ориентация EXIF; потеря
перехода при ещё не созданном редакторе; подготовка активного редактора в тестах.
Повторные проверки этих изменений завершились без новых подтверждённых замечаний.

Основной агент проверил git diff --check, 574 одинаковых ключа переводов с
совпадающими параметрами, 257 уникальных объектов Xcode, подключение девяти
исходников, описания микрофона в трёх plist и трёх InfoPlist.strings. Шесть новых
наборов содержат 29 подготовленных тестов; расширены также тесты старых профилей
и ключей. Они не запускались в этой среде.

Отдельно выполнено преобразование синтетического DOCX в GFM системным Pandoc
на Linux: сохранены заголовок, таблица, русский/китайский текст, emoji и числа.
Это проверка принципа DOCX → Markdown, а не Swift-клиента, встроенного macOS
Pandoc или работающего Gateway OCR. Ключи соседнего проекта не читались и не
копировались, шлюз и сервисы не изменялись и не перезапускались.

Стандартное difference(from:) и уже запущенный синхронный Pandoc не прерываются
посередине вызова; отмена передаётся задаче, проверяется до/после, результат
отбрасывается, собственные временные файлы очищаются. Сборки, XCTest, микрофон,
PDFKit, кодировки через интерфейс и живые модели нужно проверить на Mac.
