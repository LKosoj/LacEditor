# 25.2: загрузка изображений

Статус: ручная загрузка выбранного или всех локальных inline-изображений, автоматическая загрузка локальных и явно переданных online-вставок и разрешение документного YAML подключены к редактору и прошли статическое независимое ревью; автоматические способы по умолчанию выключены. Программы и службы не устанавливались и не запускались, изображения не отправлялись. Требование включает другие способы загрузки и политики; эти шаги не закрывают 25.2. Новая библиотека и CSS-темы не добавляются. Swift/XCTest и системный ввод на Mac не проверены.

Источники: [Typora — загрузка изображений](https://support.typora.io/Upload-Image/), [Typora — изображения и YAML](https://support.typora.io/Images/), [PicGo — локальный HTTP API](https://docs.picgo.app/gui/guide/advance), [PicGo Core — API сервера](https://docs.picgo.app/core/guide/commands). Typora документирует iPic, uPic, Picsee, PicGo/PicList, PicGo-Core и пользовательскую команду; для команды ей передаются пути изображений, а последние N строк stdout содержат N адресов. Она допускает `http:`, `https:` и `file:`. Перед реализацией каждого специализированного варианта проверить его текущий фактический публичный интерфейс и лицензию; названия приложений сами по себе не определяют протокол. Мы не устанавливаем, не запускаем и не настраиваем внешние инструменты при разработке этого плана.

## Текущие границы

`MarkdownImageEditingService` подтверждает inline-изображение через cmark и строит редактирование адреса; полноценный пакетный extractor всех форм и точных диапазонов пока не существует. `MarkdownPresentationController.imageData` загружает локальный файл/data URI для отображения и не является uploader. `AppState.presentMarkdownImage` и `EditorRangeReplacementRequest` используют актуальный снимок, проверку и AppKit undo. `FileService` предоставляет идентичность и снимок файла (ресурс, время, размер; не хеш). `AIKeychainStore` обслуживает ключи AI по собственным профилям; ключи и адреса AI не использовать для загрузки. Нельзя читать `document.text` как гарантированно актуальный текст.

## Поведение и источники

1. В существующих настройках изображения добавить явный выбор настроенного uploader и глобальное действие при вставке; по умолчанию загрузка выключена. Отдельные существующие по плану переключатели применения к локальным и online изображениям определяют область автозагрузки. Перезапуск приложения не должен включать её сам. Выбор файла, вставка, paste и drop проходят один общий путь политики, сохраняя штатный приоритет текста. Ручные команды: выбранное изображение и все локальные изображения документа. Команды работают для source/formatted, не затрагивают посторонние документы.
2. Настройка «разрешить документный YAML» по умолчанию выключена. Только при её включении `typora-copy-images-to: upload` разрешает автозагрузку в этом документе; значение `ipic` учитывать как документированную старую форму с соответствующим проверенным адаптером, не заменять незаметно другой службой. Меню документа может записать/изменить это поле через существующий цикл AppKit и один undo, сохраняя остальные исходные поля/комментарии; при невозможности точно изменить сложный YAML не переписывать его догадкой. Определить приоритет документного значения и глобального действия по документации/матрице 01 и проверить: отсутствие/другое значение, глобальная настройка запрещает документный override, пустой и несохранённый документ.
3. Общий extractor использует cmark и исходный `NSString` для точных UTF-16 диапазонов адреса, исходного фрагмента и связи с узлом: inline, reference и HTML-изображения из полного 10/15 должны постепенно покрываться с отдельными тестами. Не обрабатывать примеры в code и произвольные совпадения строк. Если замена общего reference-определения влияет на другие ссылки или позиция не доказана, показать конкретный отказ до записи; не переписывать исходник целиком. Сохранить alt, title, формат, окружающий текст и исходный файл.
4. Для локального пути использовать базу документа и URL-правила существующего loader: корректно декодировать пробелы/Unicode/`%`, относительный путь без базы не угадывать. Для data URI декодировать реальные байты и MIME и, когда выбранный инструмент принимает только пути, записать приватную временную копию с подходящим расширением и очистить её после завершения/отмены. Оригиналы не перемещать и не удалять. Online изображения повторно загружать только при явно включённой политике online; передавать фактические данные, не текст URL вместо изображения, и сообщать ошибки скачивания. Точный порядок и совместимость MIME/data URI проверить с выбранным адаптером.

## Способы, транспорт и результат

- **Пользовательская команда / PicGo-Core и совместимые инструменты:** пользователь явно задаёт программу и аргументы; значения `${filename}`/`${filepath}` для несохранённого файла — пустые строки, после разбора аргументов пути изображений добавляются отдельными аргументами. Не интерполировать пути через shell и не загружать/устанавливать программу автоматически. Захват stdout/stderr через временные файлы, ожидание и отмена процесса по уже существующему ограниченному пути; последние N строк считаются адресами только при совпадении числа и порядка. Не выводить диагностику как адрес; непригодный результат — ошибка без изменения соответствующей ссылки. Shell-синтаксис пользовательской команды и специальные адаптеры, где нужны другие правила, требуют явного отдельного контракта, а не молчаливого исполнения.
- **PicGo/PicList server:** пользователь указывает уже работающий endpoint; не запускать сервер. Подтверждённый PicGo JSON API: POST `/upload` с `{"list":["/absolute/path"]}`, ответ `success` и массив `result` в порядке запроса. Для бинарных данных использовать проверенный server multipart `files` либо временные локальные файлы; не посылать пустой list, потому что сервер может взять системный clipboard. Адрес, доступность и возможная авторизация задаются пользователем; секрет сервиса при необходимости хранить отдельно от AI-ключей в системном Keychain, не в YAML/логе. Точное соответствие PicList API подтвердить до подключения его отдельного пункта; не утверждать совместимость по названию.
- **iPic, uPic, Picsee и прочие документированные инструменты:** изучить их актуальные официальные способы вызова, аргументы, ответ и права; реализовать отдельные минимальные адаптеры на тех же входах/результатах. Если нет документированного стабильного интерфейса, зафиксировать конкретное ограничение и доступный пользователю custom command, но не вычёркивать оставшуюся совместимость из плана. Никакого выбора нового внешнего сервиса вместо пользователя.
- Для каждого ответа проверять валидность абсолютного `http:`, `https:` или `file:` по описанию Typora и кодировать адрес в контексте конкретного Markdown/HTML-синтаксиса; сохранять порядок и не интерпретировать произвольный stdout как код. Результаты и диагностика относятся к каждой картинке; успешные загрузки уже существуют у стороннего сервиса и отмена/undo документа их не удаляет.

## Актуальность и применение

Снять `synchronizedSnapshot()` и идентификатор документа/редактора, текущую версию, URL документа, выделение и точные исходные адреса на главном потоке; снимок настроек и выбранного uploader фиксировать вместе с заданием. Чтение данных и сеть/процесс выполняются асинхронно, при отмене, закрытии документа, смене окна/источника или отказе сервиса останавливать применяемую задачу и очищать временные файлы. Проверить текущность после каждого callback и непосредственно перед заменой: тот же документ/редактор, версия, URL, доступность редактирования, отсутствие marked text (незавершённого системного ввода), совпадение всех заменяемых исходных фрагментов. Устаревший результат не меняет текст и показывает итог пользователю; он не доказывает удаление уже отправленных данных на сервере.

Частичный результат показывать с адресами/ошибками каждого изображения; успешные допустимо применить только после проверки всего выбранного набора, одной составной заменой диапазона через `shouldChangeText → replace → didChangeText`, отдельной группой undo и корректным выделением. Не применять частичный или старый результат незаметно. Ошибка одного изображения не превращает другие в ложный успех; повторная отправка выполняется явным действием. Проверить, что один undo восстанавливает исходные адреса без удаления пользовательских локальных или загруженных файлов.

## Порядок и проверка

Сначала отдельный миниэтап extractor/transport без UI, затем существующие настройки/команды и ручная загрузка, затем YAML и автоматическая политика после проверки вставки 10; далее остальные документированные адаптеры и совместимость 15/22–25. Файлы по последовательной передаче: `MarkdownImageEditingService`, необходимые новые `Services` для uploader, `AppPreferences`/`SettingsView`, `AppState`, `LacEditorCommands`, узкие editor handlers и XCTest; общие списки сборки и локализации обновляет основной агент. Пока общие файлы заняты 09 и 24, их не менять.

XCTest: точные диапазоны и замена только адресов inline/reference/HTML и исключение code, Unicode/CRLF/дубликаты и выбранное/all, относительный путь/data URI/MIME/несохранённый документ; mock URLProtocol для JSON/multipart с реальными байтами, порядком и ошибками, локальный тестовый процесс для argv/stdout/переменных/отмены, частичный ответ и неверные URL. Детерминированно задержать результат и проверить edit/selection/document/URL/настройку/закрытие, readonly/marked text, отсутствие изменения текста при отказе, один undo/redo и cleanup. Проверить старую политику вставки при выключенном uploader. На Mac отдельно проверить пользовательские инструменты, сервер, системные панели, paste/drop, настоящую сеть и IME. Ни один тестовый сервер/инструмент или отправка сейчас не запускались.

### Следующее подключение после передачи общих файлов

Ручное действие для выбранного изображения и действие для всех локальных изображений добавить в существующее меню Markdown; настройки в `AppPreferences`/`SettingsView`: выключено по умолчанию, выбор уже настроенного PicGo endpoint или явных программы и массива аргументов. `AppState` до начала получает `synchronizedSnapshot` и `EditorTextExtractionRequest` с требованием редактируемости, запоминает документ, версию, выделение, адрес файла и параметры загрузчика. Транспорт работает вне main; при завершении повторно проверить владельца окна, документ, обе версии, выделение, доступность редактирования и отсутствие незавершённого ввода. Закрытие, смена документа или отмена отменяют задачу; уже отправленные данные невозможно отозвать. Только после всех проверок построить одну замену исходного диапазона, сохраняя остальной текст, и выполнить её через существующий `EditorRangeReplacementRequest` с одной группой undo. Адрес ответа должен быть безопасно записан в конкретной исходной форме и повторно подтверждён cmark; неоднозначная запись даёт видимую ошибку без изменения документа. Для несохранённого документа относительные локальные пути не угадывать. В тестах использовать URLProtocol/локальный процесс только под XCTest, задержанный ответ и фактический редактор; настоящие сервисы и программы не запускать в текущем окружении.

Ручной ввод online Markdown-адреса, копирование в папку по политике YAML, оставшиеся сложные формы reference/HTML и отдельные API прочих документированных загрузчиков остаются обязательными последующими частями полной 25.2. Backend явно отказывает запросу, если в его области есть неподтверждённый reference или HTML; это не означает поддержку частичного результата.

### Следующий подэтап: автоматическая загрузка локальной вставки

Независимый глобальный переключатель по умолчанию выключен. При включении и настроенном uploader существующий `presentMarkdownImage` использует тот же путь для выбора файла, paste и drop: подтверждает реальный формат через ImageIO, получает подпись и title, отправляет file/data выбранным транспортом до вставки, затем повторно сверяет окно, документ, исходный снимок, выделение, настройки и возможность редактирования. Успешный URL вставляется существующей командой редактора одной группой undo; ошибка/отмена не меняет документ. Clipboard data направляется uploader без обязательного Save Panel; для команды создаётся приватный временный файл. Закрытие и перенос документа отменяют задачу через тот же `imageUploads`. При выключенном переключателе прежний локальный путь и Save Panel сохраняются. XCTest с реальными редактором и тестовой программой проверяет file/data, старый выключенный путь, изменение документа и выделения до ответа, IME, отказ и undo; реальный пользовательский uploader во время разработки не запускается. Online и документный YAML остаются отдельными обязательными шагами.

### Документная политика YAML: первый срез

Согласно [Typora Upload Images](https://support.typora.io/Upload-Image/), для документной загрузки сначала включается отдельное разрешение YAML; `typora-copy-images-to: upload` активирует загрузку при вставке. [Typora Images](https://support.typora.io/Images/) отдельно описывает значение с путём как копирование в папку: нельзя трактовать его как upload. Флажок разрешения по умолчанию выключен. При включении обрабатывать один front matter текущего синхронизированного снимка за вставку, а не каждый файл изображения. Предусмотренный `Pandoc` 3.13 и короткий фиксированный Lua Reader разбирают поле через `pandoc.read` и возвращают структурированный результат: отсутствующее поле, скаляр, неподдерживаемый тип или ошибка. Используется только пакетный ресурс приложения, без пользовательского кода; обычные текстовые узлы объединяются без снятия Markdown-оформления, чтобы `**upload**` не превратился в `upload`. Фактические YAML plain, quoted и block scalar нужно проверить на встроенной версии. Отсутствующий ключ наследует глобальную политику; `upload` включает загрузку; путь/copy и исторический `ipic` требуют отдельной реализации и не подменяются отправкой. Ошибка YAML или недоступный Pandoc видимо останавливает вставку без потери исходного текста, если разрешение включено и документ содержит front matter. Ввод и выход временные, отмена прекращает собственный процесс и очищает файлы; после результата снова проверяются документ/окно/версия/выделение/настройка. XCTest проверяет формы скаляра, Unicode, другие значения/типы, ошибки, отмену и приоритет global/document. Фактический Pandoc/XCTest на Mac не запускался.

### Online-вставка: первый срез

Отдельная отключённая по умолчанию настройка разрешает повторную загрузку online-изображений. Определять только явно переданный объект URL `http`/`https` при переносе или вставке, не распознавать произвольный текст как картинку и не нарушать штатный приоритет обычного текста, зарегистрированные типы, readonly и marked text. Скачать реальные байты через URLSession, подтвердить формат ImageIO, отправить выбранным uploader; после завершения сверить снимок/выделение и вставить одной обычной операцией с undo. Отмена прерывает HTTP-запрос и uploader, не обещая отозвать уже отправленное. Проверить URLProtocol и фактический paste/drop в editor XCTest; ручной ввод Markdown-адреса и другие способы вставки остаются отдельными пунктами полного объёма. До кода согласовать передачу LacTextView/Coordinator и повторное независимое ревью.

### Reference-изображения: первый срез и оставшаяся работа

Определение `[label]: destination`, включая подтверждённые определения внутри цитаты и списка, обычное экранирование и переносы строки в метке/адресе, проверяется пробной подстановкой уникального адреса и повторным cmark-разбором. Если определение используется обычной ссылкой или выбрана лишь одна из нескольких картинок, только затронутые image nodes превращаются в inline-ссылки с исходным raw alt/title; определение и обычные ссылки сохраняются. При загрузке всех несколько картинок с общим определением загружаются один раз. Title на следующей строке, включая пустой, и простой title с переносом внутри поддерживаются после проверки cmark; неоднозначные контейнерные формы явно отклоняются и остаются обязательными. Кандидаты нескольких определений подставляются в один проверочный снимок: число полных cmark-разборов не растёт с числом ссылок. Между разборами проверяется отмена; сам отдельный вызов cmark не прерывается. Добавлен XCTest на 100 различных ссылок, но времени или памяти на Mac пока не измеряли; до полной приёмки проверка крупных файлов обязательна.

### HTML img и сторонние программы

Подтверждённые cmark HTML-теги `img` в inline/block, включая несколько вложенных тегов, дают точные диапазоны `src`; остальная разметка сохраняется. Текст внутри `script`, `style` и других raw-text элементов не является тегом изображения, даже если cmark разбил HTML на несколько узлов. 106 legacy-имён без `;` сверены с [WHATWG entities.json](https://html.spec.whatwg.org/entities.json), а числовые ссылки — с правилами HTML; таблица используется как данные стандарта, согласно [IPR policy WHATWG](https://whatwg.org/ipr-policy) её включение в исходники лицензируется BSD 3-Clause. Общий notice добавляет основной агент. Недоказанные исходные координаты явно отклоняются. `template` соответствует [HTML Standard](https://html.spec.whatwg.org/dev/syntax.html): содержимое шаблона состоит из элементов, а не raw-text. Тесты с комментариями, quote атрибутов, template, Unicode и несколькими img написаны, но Mac/XCTest не запускались.

[Typora Upload Images](https://support.typora.io/Upload-Image/) документирует PicGo-Core через `picgo upload` как пользовательскую команду и автоматический запуск PicGo.app. В LacEditor пользовательская программа с аргументом `upload` уже доступна, но отдельный автоматический запуск приложения не заявлен. Официальная страница [uPic](https://github.com/gee1k/uPic) подтверждает CLI без достаточного описания argv и ответа; [iPic](https://github.com/toolinbox/iPic) описывает Finder Services и clipboard, но не гарантирует здесь программный ответ. Адаптеры iPic/uPic/Picsee и автоматический запуск PicGo не считать готовыми и не придумывать их протокол; нужны проверяемые официальные контракты и отдельные реальные проверки на Mac.

В настройках добавлена явная проверка uploader: после нажатия отправляется встроенная тестовая PNG и показывается адрес или ошибка; изменение настроек, отмена и уход из раздела прекращают работу. UI XCTest проверяет явный запуск и отмену команды при смене конфигурации, но системный поиск SwiftUI-кнопки/текста и фактические XCTest на Mac пока не проверены. Сетевые сервисы и пользовательские программы при разработке не вызывались.

### Копирование при вставке: backend подготовлен, UI ещё подключается

`MarkdownImageCopyService` разрешает абсолютную папку или относительный путь от сохранённого документа и создаёт отсутствующие каталоги; `${filename}` поддержан согласно [Typora](https://support.typora.io/What%27s-New-0.9.58/). Сейчас подставляется имя документа с расширением, как в существующей команде загрузчика; точное совпадение Typora требует Mac-проверки. Проверенные данные записываются с `.withoutOverwriting`, существующий файл/символическая ссылка не заменяются; тот же ресурс не копируется повторно. Отдельные настройки разрешения YAML и глобальной папки по умолчанию выключены. Приоритет документа, системный выбор другого имени при конфликте, сверка снимка после копирования, сообщение с путём оставленной копии, редактор/undo и тесты взаимодействия подключены и прошли статическое независимое ревью. Существующая вставка при ошибке или stale не удаляет созданный пользователем файл. Foundation/XCTest и системные панели на Mac не проверялись; обработка конфликта в самой системной панели требует реального Mac-сценария.

## Первый backend-этап: точный контракт до реализации

Этап подготовительный: не меняет настройки, редактор, исходник, сеть и пользовательские файлы в приложении. Новый `Services/MarkdownImageUploadService.swift` содержит только модели, чистое извлечение и два фактических транспорта; отдельный файл extractor допустим только если разделение действительно сокращает код. Новый `LacEditorTests/MarkdownImageUploadTests.swift`. Основной агент добавляет исходник в Xcode и применимые прямые вызовы `swiftc`. Согласовать передачу если общий `MarkdownImageEditingService` занят; не менять общие editor/Preferences файлы для этого этапа.

**Извлечение.** Вход — неизменяемый Markdown `String`, `NSRange` UTF-16 выбранного изображения либо явный запрос всех локальных изображений, URL документа отдельно; выход — упорядоченные записи с полным диапазоном исходного узла, доказанным диапазоном только адреса, оригинальным raw-срезом адреса, декодированным cmark URL и видом. Извлекать confirmed cmark `image` из всех поддержанных документных контейнеров, исключая code и непроверяемые диапазоны. Первая реализуемая форма — inline `![alt](destination "title")`: допустимы angle destination/скобки/экранирование лишь когда точный raw-диапазон доказан и повторный разбор подтверждает тот же URL/alt/title; неоднозначный случай возвращает отдельную причину отказа и не заменяется. Первая стадия обязана обнаруживать reference и raw HTML `<img>` как неподдержанные записи/причины, не терять их молча и не притворяться что all complete; для reference описать совместные ссылки и определения, для HTML — атрибуты/кавычки и безопасность. Полная 25.2 требует корректной поддержки обеих форм в последующих этапах, а не их постоянного исключения. Несколько изображений с общим адресом остаются отдельными позициями; выбрано — однозначное пересечение курсора/выделения по существующим правилам 10, не соседняя картинка.

**Вход для транспорта.** После извлечения и пользовательского выбора отдельный подготовитель получает реальные данные каждого разрешённого файла/data URI и имя/MIME, либо документированный локальный абсолютный путь, когда конкретный инструмент его принимает. Относительный файл разрешается от каталога сохранённого Markdown, `file:` преобразуется в файловый URL; отсутствующая база или файл, неверный data URI и неподдержанный MIME — ошибка конкретной позиции. Срезы, ID документа и версия принадлежат будущему UI-клиенту; backend не читает `AppState`, NSTextView или Keychain. Чтение и отправка вне главного потока.

**Custom command.** Модель — явно заданный пользователем URL исполняемого файла и отдельные шаблонные аргументы с `${filename}`/`${filepath}` как значениями внутри аргумента; имени/пути несохранённого файла соответствует пустая строка. В ходе работы приложения добавить реальные локальные image paths в том же порядке; data URI материализовать в приватный временный каталог и удалить только после завершения процесса. Не использовать shell, не запускать никакую программу во время написания или проверки этого плана. Процесс запустить только по соответствующему действию пользователя/разрешённой политике, с stdout/stderr во временных файлах, отменой и ожиданием завершения. Пока главный процесс команды работает, отмена останавливает его группу вместе с обычными дочерними процессами; намеренно отделившиеся процессы и процессы после выхода главного остановить этим способом нельзя. Ненулевой код, неверное количество или формат последних N строк — явный отказ без замены; диагностика и секреты не смешиваются с адресами. Совместимость произвольного shell-синтаксиса Typora и особые API приложений остаются следующими обязательными вопросами; процесс сам может выполнять действия, зависящие от его кода.

**PicGo server.** Модель хранит явно настроенный полный endpoint и отдельно при наличии поддержки конкретного сервера — credentials, полученные клиентом из его действующего хранилища; generic Keychain abstraction не добавлять. Базовый протокол [официального PicGo GUI 2.4+](https://docs.picgo.app/gui/guide/advance): multipart POST, каждый бинарный объект в поле `files`, ответ JSON `success: true`, `result: [url, ...]`. Это отправляет реальные байты и работает с удалённым endpoint; локальные пути в JSON `list` применять только для доказанного локального сервера и передавать абсолютные пути, не путать путь с бинарной передачей на удалённый хост. Никогда не отправлять пустой список: сервер может использовать системный буфер обмена. Проверять HTTP status, JSON и точное количество URL, по порядку без угадывания; URL поддерживает `http`, `https`, `file` по Typora. У современных серверов необязательный Bearer определяется их документацией, но не вводить его как обязательный для всех вариантов. Ошибки/частичность серверов без однозначного сопоставления дают отказ набора, не приписывают адрес другой картинке. Сеть через URLSession; отмена отменяет запрос и не обещает отозвать уже загруженное изображение.

**Проверки.** Чистые XCTest: точные UTF-16 с Unicode/CRLF/скобками/title/escape, выбранное и all, два одинаковых адреса, code и неподтверждённые reference/HTML; однозначность, отсутствие изменения входа. Файлы в временной папке: исходные байты и MIME локального PNG/JPEG и data URI, относительный URL, отсутствие базы, ошибка и cleanup. Локальный тестовый процесс только в XCTest с записью argv и искусственным stdout: пробелы/Unicode, `${filename}`/`${filepath}`, порядок N, ошибка/частичный вывод и отмена; тест не вызывает пользовательские uploaders. URLProtocol в XCTest проверяет бинарное multipart тело, не локальный путь, endpoint/JSON порядок, неполный ответ и отмену. Продолжение после подключения UI проверит stale revision, partial-result и один undo; без этого backend не считается сквозной загрузкой. Реальные инструменты, сервисы и весь XCTest на Mac пока не запускались.
