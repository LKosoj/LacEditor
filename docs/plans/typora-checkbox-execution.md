# 05: кликабельные флажки задач — план до кода

Эта часть добавляет флажок в оформленном Markdown для уже существующих `[ ]`, `[x]`, `[X]`. Источник остаётся обычной строкой; режим, новая библиотека, дополнительное окно и автоматическое изменение файла не нужны. Клавиатурная часть и полная 05 принимаются отдельно. Данный план не утверждает, что TextKit-геометрия или реальный ввод уже проверены на Mac.

1. **Подтверждение разбором.** В `MarkdownPresentationParser.swift` выяснить по фактически поставляемому cmark-gfm и его заголовкам, как определяется tasklist-узел и состояние; использовать уже включённое расширение `tasklist`. В `MarkdownPresentation.swift` добавить только необходимые данные подтверждённого флажка: диапазон `[ ]` в UTF-16, диапазон одного символа состояния, исходное состояние и принадлежность пункту. Привязать диапазон к исходной строке с существующим преобразованием UTF-8 → UTF-16; не искать произвольное `[x]` во всём документе. Для табов, отсутствующей точной позиции, незакрытой/экранированной и неоднозначной конструкции — не публиковать флажок. Проверить вложенные списки/цитаты, `[X]`, код и соседние похожие строки. Проверить реальный экспортируемый API конкретной версии cmark до выбора вызова; не предполагать его имя.
2. **Нативное отображение.** В `MarkdownPresentationController.swift` передать подтверждённые диапазоны той же версии в `FoldLayoutManager.swift` вместе с имеющимся результатом разбора; применять только видимую область, отменять/сбрасывать при правке, смене документа, отключении оформления и закрытии. Не менять исходный текст, высоту строки, историю отмены или атрибуты во время marked text. Использовать существующую позицию символов и рисование AppKit поверх области `[ ]`, не вставлять attachment (объект, меняющий строку). Сначала проверить, что исходные знаки не проступают, а выделение, цвет, ширина строки, номера строк, скрытие и сворачивание остаются корректны. Если текущая геометрия не позволяет это сделать без изменения строки или высоты, зафиксировать конкретное препятствие, а не выдавать обычный текст за флажок.
3. **Клик.** В `LacTextView.mouseDown` добавить проверку только подтверждённого видимого флажка, не меняя существующее попадание по изображению; проверить приоритеты отдельно и не перехватывать клики вне области флажка. Для обработки использовать существующий согласованный путь редактора/координатора: перед изменением сверить активный Markdown-документ, редактируемость, отсутствие marked text, текущую версию, наличие состояния в актуальном результате разбора и фактические три исходных символа по диапазону. При устаревшей позиции отказать. Заменить только один символ: пробел → `x`, `x`/`X` → пробел; выполнить `shouldChangeText` → замена → `didChangeText`, одна отдельная группа undo/redo (отмена/повтор), сохранить исходное выделение и не передвигать курсор. Название действия — существующая локализация только если подходящее значение уже есть; иначе три строки локализации потребуются отдельно, сообщить основному агенту. Обычный клик по изображению и тексту остаётся прежним.
4. **Проверки XCTest.** В `MarkdownPresentationParserTests.swift`: все состояния, Unicode/emoji перед маркером, UTF-16 и CRLF, вложенность/цитата, несколько пунктов, код/экранирование/неполные и недостоверные позиции. В `MarkdownLayoutTests.swift`: область попадания и её отсутствие в исходном виде, при сворачивании и marked text, неизменность строки и высоты; соседство изображения не меняет его область. В `TaskListEditingTests.swift` (и существующем interaction-тесте по необходимости): настоящий маршрут клика через редактор для каждого состояния, один undo/redo и сохранение выделения; недоступный редактор, смена документа/версии, изменённый маркер и IME не меняют текст; клик вне флажка и по изображению проходит своему обработчику. Не считать синтетический marked text реальной проверкой китайского ввода.
5. **Подключение и приёмка.** Предполагаемые файлы: модель, parser, controller, `FoldLayoutManager.swift`, `LacTextView.swift`, необходимые точечные места `EditorCoordinator.swift` и указанные существующие тесты. Один владелец этих общих файлов, изменения изображений не отменять; локализации, общие сборочные списки и `AGENTS.md` обновляет основной агент. Новых исходных файлов не требуется; прямые вызовы сборки проверить на фактические зависимости после реализации. Проверить diff и независимое ревью, на Mac выполнить XCTest и вручную: оба представления, мышь и выделение, IME, VoiceOver, прокрутку, соседство изображений, сворачивание и большой документ. Без Mac эти проверки остаются незавершёнными; успешный парсер или невидимый флажок не доказывают пользовательский результат.

Состояние: подготовлена реализация и XCTest, требуется независимое ревью и запуск на Mac. Разбор исходника cmark точного тега swift-cmark 0.8.0 показал, что `> - [x] quoted` выдаётся обычным `item`, а не `tasklist`; для них согласовано узкое расширение: подтверждённый cmark пункт внутри цитаты и точный маркер в исходном префиксе пункта, без общей эвристики по строке. Диапазоны с табами и неоднозначные случаи остаются исходником. Полная задача 05 остаётся незавершённой. Синтетический тест marked text не заменяет реальный ввод IME.
