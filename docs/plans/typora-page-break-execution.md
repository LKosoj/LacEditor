# 15: видимый разрыв страницы

Предварительный план GPT-6.1-Terra `blocks_execution`, независимо рассмотрен `files_execution` и `native_execution`. Экспортный путь уже использует подтверждённый `pageBreakStyle`/`provenPageBreaks`; редактор остаётся непрерывным текстом. Новую систему разбиения редактора на страницы не создавать.

1. В существующем дереве cmark собрать точные HTML-блоки документированного пустого div с page-break-after:always (и поддержанной парой break-after:page). Проверить Source, последовательный HTMLContext и прежний DOM proof; не распознавать код, script/template/select, лишние атрибуты, невалидные/непустые элементы. Проверка: положительные варианты, отрицательные и отмена.
2. Модель хранит исходный диапазон. Fold показывает одну видимую метку с локализованным названием, резервируя место до рисования, без изменения строки/undo. Для многострочного исходника не сохранять пустые исходные фрагменты; не потерять соседние list/quote markers. Пересечение с fold/selection и marked text раскрывает исходник существующим путём.
3. Обработчик попадания использует фактическое преобразование координат при zoom/vertical. Проверить document/revision/selection, родительский и табличный IME, прокрутку и возврат к исходнику. Не добавлять второй путь изменения текста.
4. Swift fixtures: parse/layout, реальный reveal, видимые размеры/соседи, многострочная форма, Unicode/CRLF, масштаб/направление, выделение, undo/redo и источник без изменений. Независимое review реализации; фактическая геометрия и PDF/печать на Mac отдельно.

Ключ `markdown.pageBreak` добавлен в три существующих словаря. Native marker подключён к Parser/Model/Fold/Controller и существующему click/reveal. Подготовлены parent/child marked, NSEvent при масштабе, выделение, source reset, undo и геометрические fixtures; два независимых повторных review конкретных новых дефектов не нашли после исправления исчезавшей метки при marked text. Export fixtures подготовлены ранее; Swift/XCTest/PDFKit на Linux не запускались.
