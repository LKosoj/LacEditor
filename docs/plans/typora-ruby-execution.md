# 15: нативные подписи Ruby

Предварительный план подготовлен GPT-6.1-Terra `native_execution`, независимо проверен GPT-6.1-Terra `files_execution` и `blocks_execution`. Используется имеющийся Core Text; дополнительная библиотека этому срезу не нужна.

1. Компонент рисования получает исходный атрибутированный base и annotation, сохраняет NSFont и его настройки. Горизонтальное расположение использует CTLine, вертикальное — CTFrame с verticalForms/rightToLeft. Измеряются реальные границы подписи и основного текста, резервируются оба расстояния от базовой линии; размеры ограничиваются доступной областью. Преобразование координат для рисования и попадания должно быть общим и обратимым. Проверка: Swift fixtures 1×/2×, края/обрезание, длинная подпись, CJK/RTL/emoji и составные символы, недостаточная область.
2. Разбор в существующем дереве cmark подтверждает точную последовательность ruby, простой base TEXT, необязательные rp, один rt с простым TEXT, закрытие ruby в одном родителе. Сверяются диапазоны UTF-16, весь текст и HTMLContext; временные комментарии подтверждают структуру того же HTML через SwiftSoup. Неподтверждённые атрибуты, пересечения, несколько rt или вложенная разметка остаются исходником до своего среза. Проверка: entities, rp, Unicode/CRLF, повторения, code/script и несовпадающие DOM/source.
3. Модель хранит исходный диапазон, base/rt и подтверждённые диапазоны. Переносы координат снимка обрабатываются вместе с остальными встроенными элементами. Controller готовит только видимую область и проверяет документ/версию/поколение, IME и выделение. Не пересекать Ruby с image/math/uppercase/table без подтверждённого владельца диапазона.
4. Fold резервирует реальные размеры над/под базовой линией до рисования и использует те же значения для hit/reveal. Вертикальный результат CTFrame нельзя повторно поворачивать как обычную картинку. Клик раскрывает исходник обычным путём редактора; отдельный механизм курсора не создаётся. Проверка: геометрия, zoom, вертикальное направление, reveal, resize/scroll, ввод и одна отмена.
5. Сохранить штатное доступное представление исходного NSTextView: оно содержит base/reading и существующие координаты UTF-16. Не добавлять дублирующий элемент изображения и не подменять текст/координаты всей строки ради Ruby. Это минимальное решение отдельно рассмотрено `native_execution` и `blocks_execution`. Проверить value/selection/descendants, смену документа/версии, прокрутку и раскрытие. Семантическое озвучивание Ruby и чтение тегов остаются проверкой VoiceOver на Mac; обычный AX fixture их не доказывает.
6. Preview/PDF/Copy передают подтверждённую семантику Ruby; источник остаётся неизменным. Для каждого потребителя отдельные fixtures и независимое повторное review. Непокрытые формы Ruby не объявлять готовыми.

Компонент горизонтального/вертикального рисования и его тесты подготовлены, независимо статически проверены. Интеграция находится в реализации. Linux не содержит Swift/macOS frameworks: компиляция, реальные пиксели Core Text, AppKit, PDF, клавиатура и VoiceOver не запускались.

Первичные источники: [Core Text и мосты типов шрифтов](https://developer.apple.com/library/archive/documentation/StringsTextFonts/Conceptual/CoreText_Programming/Overview/Overview.html), [Ruby API](https://developer.apple.com/documentation/coretext/ctrubyannotationcreatewithattributes(_:_:_:_:_:)), [направление CTFrame](https://developer.apple.com/documentation/coretext/ctframeprogression), [документированный пример Typora](https://support.typora.io/HTML/).


Проверка отдельным Linux Chromium: для `漢<rp>(</rp><rt>kan</rt><rp>)</rp>` Selection/innerText дают `漢kan`, textContent содержит скобки. Для документированного примера с пробелами внутри base/rt Selection отличается от простого соединения исходных строк. Copy не должен угадывать это нормализованное выделение; соответствующая граница требует отдельного подтверждения WebKit. `MarkdownRubyOutputTests` добавлен основным агентом, независимо статически проверен `files_execution`; ожидаемый consumer ещё в реализации, тесты не запускались.


Copy подключён основным агентом к общему same-tree Ruby collector и DOM proof. Полное выделение передаёт base+reading, HTML сохраняет rp для браузерного fallback; неподтверждённое RTF не пишется. Для частичных, незакрытых, неподтверждённых Ruby действует барьер исходного диапазона, соседний обычный текст остаётся доступен. Пробелы с неподтверждённым схлопыванием и emoji/дополнительные украшения пока дают явный отказ. Независимое review выявило и исправило затенение имени списка, неполный EOF-барьер и повторный линейный поиск emoji; общий guard украшений перенесён в collector без второго Markdown-разбора. Проверка Swift/WebKit по-прежнему не выполнялась.


## Текущее состояние после финального ревью

Интеграция общего разбора с редактором, Renderer и Copy подготовлена. Подтверждённый base поддерживает жирное/курсивное начертание и цвет, включая наследование внешнего оформления; rt сохраняет шрифт и цвет родителя. Общая проверка допуска отклоняет неподдержанные фон, размер и украшения, а также пересекающиеся HTML-владения. Дескриптор шрифта сохраняется при изменении размера подписи. Добавлены Swift-проверки наследования, source ranges, Copy/Renderer и Core Text; независимый повторный статический просмотр не нашёл новых замечаний. Это обновляет исторические промежуточные статусы выше. Swift/XCTest и реальные пиксели, вертикальное размещение и VoiceOver требуют Mac.
