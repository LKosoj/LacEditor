# 06: автоматические пары Markdown — миниплан

Дополнено: при включённых Markdown-парах клавиши `~` и `^` обрамляют выделенный текст; при пустом выделении вводится один знак. Настройка скобок и кавычек также включает `{}` и одинарные кавычки, с проверкой целого символа для апострофа в слове. Добавлены проверки Unicode, кода, настройки и фактического нажатия с undo; независимое статическое ревью замечаний не выявило, XCTest на Mac ещё не запускались. `=` и `$` остаются отдельной работой.

Для 25.5 подготовлены три независимых выключенных настройки: системные умные кавычки, тире и текстовые замены macOS. Само применение ещё не подключено: ему нужен подтверждённый контекст обычного текста и отложенное изменение во время системного ввода. Typora рекомендует системные текстовые замены и системную настройку сочетаний, отдельного редактора заготовок для macOS не требуется ([заготовки](https://support.typora.io/Text-Snippet/), [сочетания](https://support.typora.io/Shortcut-Keys/)); кавычки и тире не применяются в исходном режиме, YAML, коде и формулах ([пунктуация](https://support.typora.io/SmartyPants/)).

Статус: первая часть подготовлена, ожидает независимого ревью и проверки на macOS; Swift/XCTest здесь не запускались. Настройки пар скобок/кавычек и Markdown-маркеров независимы и по умолчанию выключены. Проверка контекста использует существующий проход по NSString; стоимость для больших документов на Mac не измерена. Первая часть 06 охватывает обычный ввод только в Markdown: `[]`, `()`, `""`, `**`, `__` и парные обратные кавычки. Это не закрывает всю 06/25.5. [Typora описывает отдельные настройки пар скобок/кавычек и Markdown-маркеров](https://support.typora.io/Auto-Pair/), а также обрамление выделения знаком `~` без автоматической завершающей пары. Дополнительные `=`, `$`, остальные документированные пары и сочетания, сниппеты и умная пунктуация остаются обязательной последующей частью по матрице 01 и своим зависимостям. Граница первой части не объявляется полным поведением Typora.

## Управление и минимальные точки

- Сначала сверить два имеющихся пользовательских предпочтения с `AppPreferences` и существующей страницей настроек. Если их нет, для полного согласованного поведения потребуются два **конкретных** независимых предпочтения: «парные скобки и кавычки» и «парные символы Markdown», без общего «умного режима». Предлагаемое безопасное начальное значение обоих — выключено, чтобы не менять набор до выбора пользователя; значение по умолчанию и окончательные подписи уточнить перед кодом, поскольку Typora-документация не подтверждает их для этой сборки. Не менять `isAutomaticQuoteSubstitutionEnabled`, `isAutomaticDashSubstitutionEnabled`, системную орфографию или остальные настройки NSTextView.
- В `EditorTextView` передавать актуальные значения из существующих предпочтений в уже созданное/повторно присоединённое представление. Проверять язык через актуальный `EditorCoordinator.currentLanguage`, активный документ и `ioState`, а не навсегда захваченную копию документа; не применять этот этап к JSON и другим языкам. Приоритет передачи и владельцев общих файлов согласовать после завершения работы 13.
- Обрабатывать только одно ASCII-нажатие пользователя в существующем пути `LacTextView.keyDown`/`insertText`: не трактовать произвольную многосимвольную вставку, paste, drag-and-drop, программную замену или завершение IME как отдельные клавиши. `keyDown` уже первым отдаёт системному вводу marked text, обрабатывает Esc и отдаёт Tab сначала AI-автодополнению, затем спискам; новая обработка не изменяет этот порядок и не перехватывает Tab. Проверить `event.characters` и модификаторы; не обходить AppKit для мёртвых клавиш, Option/Command и системного способа ввода. Выбрать минимальное подключение по текущему коду, не добавляя второй путь набора текста.
- Любая замена использует актуальный `NSTextView`/`NSString`, одну замену в координатах UTF-16 и существующий цикл AppKit; если введённый текст или состояние не подходят, штатный ввод остаётся штатным. Проверять один диапазон выделения, редактируемость, активность и отсутствие marked text; не копировать весь документ при каждом нажатии. Автоматическая пара вместе с одним вводом должна отменяться одной операцией; обычные слова сохраняют существующее объединение undo. Обрамление выделения — одна отдельная отмена с выделением первоначального содержимого. Skip закрывающего знака перемещает курсор без изменения строки и без нового undo.

## Контракт первого набора

1. **Вставка:** при пустом выделении в подтверждённом допустимом контексте ввод `[` даёт `[]`, `(` → `()`, `"` → `""`, `*` → `**`, `_` → `__`, обратная кавычка → две обратные кавычки; курсор остаётся между знаками. Перед существующей буквой/цифрой или при неоднозначной разметке разрешать только явно проверенные случаи, иначе передать обычный ввод AppKit. Внутри слова `_` и апостроф не превращать в оформление; `'` не является частью этого первого набора.
2. **Выделение:** одиночная открывающая клавиша вокруг допустимого однострочного выделения ставит пару вокруг точного исходного текста и сохраняет его выделенным. Не терять китайский, emoji, составные символы и пробелы. Не обрамлять через несколько абзацев, границу кода либо незавершённое/неоднозначное выделение до подтверждения правил; обычный ввод может заменить выделение как до функции. В контексте ссылок и существующей разметки проверить границы и экранирование, не разрушать соседние маркеры.
3. **Закрытие:** если курсор непосредственно перед подтверждённым ожидаемым закрывающим знаком, та же закрывающая клавиша переводит курсор за него без дублирования и без изменения undo; для симметричных `"`, `*`, `_` и обратной кавычки сначала распознать доказанный контекст открытой пары. Не считать случайный символ справа автоматически закрывающей парой, особенно при незавершённом Markdown и вложенности. Точное подтверждение парного контекста определить по существующей локальной логике и тестам, без нового постоянного глобального состояния по умолчанию.
4. **Удаление:** Backspace между подтверждёнными пустыми парными знаками удаляет оба за одну отменяемую операцию; в остальных случаях выполняется существующий `deleteBackward` AppKit. Проверить границу составного символа и попытки удалить вручную набранные несвязанные знаки, отмену/повтор и непустую пару. Delete вперёд менять только если это подтверждено матрицей 01; не добавлять поведение наугад.
5. **Экранирование и код:** нечётное число обратных слешей перед знаком отключает автоматическую пару/skip; чётное обрабатывается по правилам контекста. Внутри inline-кода и fenced-/indented-кода, включая код внутри цитаты/списка, не превращать `*`/`_` или backticks в Markdown-пару; обычные знаки должны вводиться так, как позволяют настройки и ожидаемое поведение кода. Последовательность обратных кавычек для создания/закрытия fence не должна ломаться автоматическим skip: зафиксировать на примерах ``, ``` и более длинного ограждения. Допустимость обычных скобок/кавычек внутри кода уточнить отдельно по Typora и не применять автоматическую пару там без доказанного правила.

## Контекст и горячий путь

`MarkdownPresentationController` хранит результат разбора и версию, но в исходном представлении при закрытом оглавлении разбор может быть выключен, а после каждой правки прежний результат устаревает. Нельзя считать такой снимок безусловно актуальным или включать фоновый разбор целого документа на каждую клавишу. `MarkdownFormattingService.intersectsCodeBlock` и `ListContinuationService.isInCode` сейчас частные и рассчитаны на другие операции: их повторное использование не доказано для inline-кода, вложенных контейнеров и больших файлов.

До реализации выбрать минимальный способ достоверно определить текущий контекст, проверить обычный и оформленный виды и нагрузку: использовать уже имеющийся актуальный результат там, где он действительно есть, а неподтверждённые ситуации безопасно пропускать через обычный ввод. Если для поддержанного сценария нужен дополнительный проход, измерить его на крупных документах и описать стоимость; не вводить новый кэш, порог, отдельный механизм разбора или библиотеку без согласования. Отказ в неопределённом контексте — защита исходника, но не основание объявить полный Markdown auto-pair выполненным. Не подключать затрагиваемые `LacTextView`/parser/controller, пока другой агент работает над 13.

### 25.5: системные замены по подтверждённому контексту

Три уже подготовленные настройки передаются существующему NSTextView, но включаются только непосредственно перед пользовательским вводом в оформленном Markdown, когда текущий снимок cmark подтверждает весь затрагиваемый диапазон как обычный текст. Отдельно проверять предыдущее слово/знаки для системной замены, а не только позицию курсора; URL, YAML, code, math, raw HTML и source mode исключены. При отсутствии актуального доказательства остаётся обычный ввод. Во время marked text свойства и строку не менять, после завершения применить последние значения.

Общий parser возвращает уже подтверждённые точные TEXT-диапазоны и существующие UTF-16 проекции ячейки, без второго разбора на клавишу. Controller предоставляет проверку документа, editor revision и полного диапазона; после снимка переносит только однострочные изменения внутри подтверждённого обычного текста, которые не вводят синтаксис Markdown. Переход через границу узла, синтаксическая правка или неоднозначная позиция сбрасывают подтверждение до следующего отложенного разбора. Пустые строки и начало нового абзаца требуют отдельного доказательства; нельзя считать неопределённый контекст обычным текстом. Активная table child переводит границы через `rawBoundaries` и сверяет parent source/revision. Этот контракт не должен превращать набор в полный cmark-разбор на основном потоке или запускать новый разбор для каждой клавиши.

Coordinator/LacTextView и child принадлежат native; Parser/Model/Controller сейчас заняты media 15 и будут переданы последовательно. XCTest должен проверять системный NSTextView path, переключатели, реальные диапазоны замены, обратный переход в исходник, URL/code/math/YAML, emoji и CRLF, смену документа/версии, parent/child marked, выделение и undo; только фактическая macOS проверит системные правила пунктуации и пользовательские Text Replacements.

Первый срез подключён: три системных свойства включаются по настройкам только в оформленном Markdown; delegate фильтрует quote/dash/replacement по полному подтверждённому source range, не изменяя spelling/grammar. Отдельные токены parent и child и revision исключают проверенные устаревшие результаты; child использует rawBoundaries. Настройки откладываются при marked input. Подготовлены XCTest на диапазоны code/URL, текущую и устаревшую проверку, child и marked; независимое статическое чтение выполнено. Фактическая передача options и результаты системного AppKit, системные пользовательские замены и XCTest на Mac не проверялись. Начальная кавычка пустой строки и остальные случаи на границах TEXT проверяются отдельным продолжением; это не завершение 25.5.

Начальная одинарная/двойная кавычка в пустом документе или обычной пустой строке теперь получает подтверждение из того же снимка: диапазоны raw HTML собираются по source-порядку без второго cmark parse, code/math/YAML/контейнеры и неподтверждённые отступы исключаются. Добавлены LF/CRLF и управляемый NSTextView `handleTextCheckingResults` с одним undo; эти тесты независимо прочитаны, но на Mac не запускались. Остальные позиции границ TEXT и фактическая интеграция системного проверяющего сервиса остаются открытыми.

### `$`: снимок обычного текста и локальная пара

Когда включена существующая настройка Markdown auto-pair, source mode прогревает cmark snapshot в фоне даже при закрытом outline и выключенной статистике. Подтверждённый TEXT переносится через безопасные однострочные правки без повторного разбора; синтаксические изменения, потеря диапазона и переход в другую область требуют обычного debounce. Пустая top-level строка подтверждается fence/raw контекстом. Непарный `$` в подтверждённом TEXT блокирует последующий участок строки, но `$` внутри уже подтверждённой формулы, inline code, URL или escape не блокирует соседний текст. Свежий ввод пары, её локальные skip/delete и child table используют проверки документа/revision/IME и UTF-16 проекцию. Неподтверждённый контекст передаёт обычный ввод; произвольный inline HTML и виртуальные table cells пока остаются консервативными границами. Подготовлены source-only и parent/child XCTest, их статически просмотрели; реальный AppKit, системный IME и XCTest на Mac не запускались.
