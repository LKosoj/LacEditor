# 16: копирование и вставка форматированного текста — миниплан

При копировании подтверждённые emoji подставляются из того же разбора; частичное выделение знака отклоняется без изменения буфера. Покрытие выделения проверяется по конечным блокам и подтверждённым маркерам, поэтому неиспользованное определение сноски не теряется молча. Если cmark возвращает несопоставимые позиции после определения ссылки, операция консервативно отклоняется, в том числе для части соседнего абзаца или таблицы. Независимое статическое ревью замечаний не выявило; Pandoc и XCTest на Mac ещё не запускались.

Исходник — один Markdown-документ; отдельный веб-редактор, новые зависимости, настройки и постоянный индекс не нужны. Полная 16 включает HTML/RTF/plain, явные команды и ресурсы изображений; первые ограниченные подэтапы не закрывают задачу. Файлы общего редактора сейчас у других авторов, до передачи их не изменять.

Первый backend HTML/RTF → GFM подготовлен в `ClipboardMarkdownConversionService.swift` вместе с XCTest; независимое ревью после исправления отмены конкретных ошибок не выявило. Он подключён к оформленной вставке без ресурсов. Отдельный backend вложений RTF и data URI подготовлен и проверен статически, но ещё не подключён к интерфейсу; встроенный Pandoc, XCTest и AppKit на Mac не запускались. Запись вложений и остальные части 16 остаются обязательными.

## Проверенные возможности

- Системный Linux Pandoc **3.1.3** реально преобразовал `HTML → GFM` и `RTF → GFM` через stdin/stdout, включая `--sandbox` в простых примерах с жирным текстом и ссылкой. В отдельном пробном HTML iframe с `file:///etc/hostname` sandbox вернул предупреждение о недоступности ресурса, не включив содержимое. Это не выполнение поставляемого macOS Pandoc 3.13. В архиве `Vendor/Pandoc/pandoc-3.13-arm64-macOS.zip` официальный man-файл явно перечисляет `html` и `rtf` как reader, `gfm`, `html`, `rtf` как writer; двоичный файл здесь не запускался.
- `PandocExportService.prepare` использует временные файлы, Process и выходной файл, рассчитан на экспорт в пользовательский путь, не на буфер; прямо применять его к paste без нового промежуточного пользовательского документа нельзя. `findPandoc()` можно переиспользовать. Для бинарных/крупных входа и выхода требуется исключить взаимную блокировку stdin/stdout/stderr; либо независимое одновременное чтение каналов, либо приватный временный каталог с гарантированной очисткой. Проверка ограничения файлов/сети обязательна: включённый man Pandoc 3.13 предупреждает, что HTML reader может загрузить iframe; `--sandbox` ограничивает I/O и не является общей изоляцией всех фильтров/внешних PDF. Не добавлять filters, PDF или сеть к конвертации буфера.
- В `LacTextView.paste` уже есть маршрут обычной картинки: при одновременно имеющемся plain text он предпочитает текст. При добавлении rich paste согласовать новый приоритет с 10, не нарушить вставку чистого изображения. Две задачи не должны одновременно редактировать LacTextView/координатор.

## Приоритет и граница 16а

1. Только formatted Markdown: при обычной вставке предпочесть HTML, иначе RTF, иначе plain text; считывать данные pasteboard ровно один раз в момент вызова и передавать immutable snapshot. В source-режиме штатный plain-text путь остаётся штатным. Команда «Вставить как исходник» вставляет plain text без скрытой конвертации. Чистая картинка идёт существующим явным путём 10; HTML/RTF с вложенной картинкой не обрабатывать как одиночную картинку.
2. Первый проверяемый этап после согласования — HTML или RTF **без встроенных ресурсов** → GFM, с простым текстом, жирным, ссылками, списками/таблицами; отсутствие HTML в RTF-only — не повод брать plain text. При наличии HTML и RTF используется HTML. Не выдавать одну строку plain как сохранённое форматирование, не угадывать кодировки RTF. Если первый поддерживаемый тип повреждён/конвертер не запустился, показать ошибку и не вставлять другой формат молча; исходный текст/выделение остаются прежними. Формат с картинками и сложные вложения остаются обязательной следующей частью.
3. Изменить только необходимое в `PandocExportService` либо добавить небольшой `ClipboardMarkdownConversionService` с явным stdin/выходом и источником HTML/RTF; во втором случае основной агент включает source в обе сборки и direct `swiftc`. Использовать существующий встроенный Pandoc; запускать `-f html|rtf -t gfm --sandbox` без filters и пользовательских файлов, обработать ненулевой exit и диагностику. Не читать содержимое ссылок из буфера и не загружать iframe в сеть; проверить на реальном 3.13. Данные входа/выхода и временные каталоги чистить при успехе, ошибке и отмене. Не ставить новые пороги размера. Process-вызовы блокирующие, поэтому фон; механизм отмены завершает дочерний процесс и возвращает один результат, без сохранённого постоянного состояния.
4. `EditorCoordinator`/`LacTextView`: получить на главном потоке актуальный выбранный `EditorDocument`, `synchronizedSnapshot()`, документный URL/ID, revision редактора, `NSRange` и выделенный текст. Фоновая задача получает только неизменяемые данные; новый paste, переключение вкладки/документа, изменение текста/выделения, read-only, marked text, закрытие и отмена инвалидируют результат. После возвращения повторно сверить всё, затем применить через `EditorRangeReplacementRequest` / `shouldChangeText → replace → didChangeText` одной группой undo. Ни один завершившийся старый Process не может вставить текст в другой документ или новое выделение.

## Копирование и отдельные команды

1. В formatted режиме захватить точный выделенный UTF-16 исходник и создать три вида одного pasteboard item: plain читаемый текст, HTML-фрагмент и RTF. HTML формировать через существующий безопасный Markdown renderer без исполнения пользовательского кода; RTF — проверить имеющийся Pandoc writer или нативный `NSAttributedString` на сохранность ссылок/списков. Источник для копирования Markdown — ровно исходный выделенный диапазон, отдельная команда; «Копировать HTML-код» кладёт HTML как обычный текст. Копирование не меняет текст, выделение, dirty и историю undo.
2. Частичное выделение внутри исходных маркеров нельзя автоматически считать полным Markdown-фрагментом: сверить диапазоны с общим cmark presentation, проверить полное/частичное выделение, иначе сохранить буквальный текст в первом ограниченном этапе и явно не объявлять полную 16. Расширить до правильной сериализации отображаемых подфрагментов до полной приёмки.
3. `LacEditorCommands.swift` — точечные команды существующего меню, без новых окон; переводы и сборочные файлы ведёт основной агент. Формирование больших результатов и запись pasteboard после фоновой задачи проверяют актуальность выбранного документа/выделения; ошибки не затирают существующий буфер.

## Встроенные ресурсы

В HTML и RTF могут быть data URI, локальные/удалённые ссылки или встроенные бинарные изображения. Определить точный результат Pandoc 3.13 и способ выдачи ресурсов с `--sandbox`, не исполнять HTML и не забирать внешние ресурсы. Для бинарных данных использовать согласованный путь 10: пользователь явно выбирает место, данные проверяются по содержимому, имена не перезаписывают чужие файлы, stale после записи сообщает о сохранённом файле, undo текста не удаляет изображение. Множественные изображения и формат потерь требуют явной проверки. Неподдержанный случай не объявлять успешной конвертацией с невидимой потерей картинки; полный сценарий остаётся частью 16.

## Проверки

- XCTest настоящего встроенного Pandoc на Mac: HTML-only, RTF-only, оба с разным содержимым (доказать приоритет), plain-only, Unicode/CRLF, ссылки, списки и таблицы; malformed и недоступный бинарник, ненулевой exit, длительная задача/отмена, большой input/output без зависания, очистка временных файлов. Проверить sandbox без внешнего доступа с локальным fixture iframe; отдельно resource samples.
- Настоящий NSTextView/NSPasteboard: source/formatted, отдельная вставка исходника, полный и частичный Markdown selection, каждая репрезентация copy, один undo/redo, marked text/read-only, пересечение пути 10. Детерминированно задержать завершение преобразования и сменить document/revision/selection, затем убедиться, что старая вставка не происходит. Проверить несколько окон и отказ без порчи старого буфера.
- Mac: Safari, Pages и обычный текстовый редактор, RTF-only и комбинированный буфер, ссылки/таблицы/изображения, языки и emoji, фактический вывод и ввод, доступность и длинные документы. Сохранить окружение, версии, входы/выходы и результаты; Swift/XCTest и macOS здесь не запускались.

## Интеграция с редактором и ячейками: порядок работ

1. Обычная вставка: в `LacTextView` и `MarkdownTableCellEditor` перехватывать только явно доступный formatted Markdown и неизменяемую копию первого доступного HTML, затем RTF. Source, plain-only и чистая картинка остаются на существующих путях. Coordinator фиксирует ID документа, версию, режим, целевое выделение и идентификатор активной ячейки, затем запускает существующий `ClipboardMarkdownConversionService` вне главного потока. Новая вставка и отключение координатора отменяют предыдущий процесс; возврат сверяет документ, editable, marked text, текст и выделение, а также идентификатор ячейки. Ошибка первого выбранного формата сообщает существующим способом и ничего не вставляет; нельзя незаметно брать другой формат. HTML/RTF с неподтверждёнными вложенными ресурсами не считать успешно конвертированным; изображения остаются обязательными в отдельном шаге с явным сохранением по 10.
2. Применение: основной текст меняется существующим `shouldChangeText` → replace → `didChangeText` с одним undo. Для активной обычной или виртуальной ячейки применять подтверждённую конверсию к самому child через существующую обратимую проекцию и цикл основной замены: преобразовывать `|` и переводы строк по правилам ячейки; виртуальные разделители появляются только в принятой замене. Не завершать child до получения результата и не использовать одинаковую нулевую позицию для определения столбца. Отмена, изменение выделения или переход B→C не меняет source и не создаёт разделителей.
3. Copy: необходима проекция выделения **по дереву полного документа**, а не повторный разбор выбранной подстроки. Существующая модель span содержит диапазоны маркеров, но не хранит все назначения ссылок, преобразования escape/entity и соответствие отображённого текста исходным UTF-16 границам; её одной недостаточно для правильного `**bold**` с выбором `ol`, code, reference links и таблиц. Небольшой отдельный cmark-проход по фиксированному снимку строит только пересекающийся выбранный диапазон: для текстовых узлов сопоставить исходные byte positions через существующую Source-карту с UTF-16, сохранить подтверждённые вложенные inline-узлы и ссылки из полного дерева, обрезать текст по выбору, а структурные узлы оставить в согласованном фрагменте. Для escapes, entity, typographic substitutions и табличного `\\|` нужна явная карта границ; если отображаемую часть нельзя однозначно сопоставить, не выдавать буквальные маркеры за оформленный результат и сообщать отказ. При копировании ячейки начало берётся из её собственной проекции/выделения и полного документа, включая виртуальную пустую ячейку. Преобразование не выполняется на каждую клавишу или draw.
4. Из одного подтверждённого фрагмента сформировать plain, безопасный HTML и RTF (проверить доступные AppKit/Pandoc API без загрузки внешних ресурсов); единый pasteboard item записать только после подготовки всех данных и повторной проверки документа, выделения и состояния самой pasteboard. Явное Copy Markdown копирует точный source, Copy HTML кладёт HTML текстом, Paste as Source вставляет исходный plain; меню/локализации и AppState требуют последовательной передачи от владельца. Ошибка не очищает предыдущий буфер. Parser/model/controller/Fold принадлежат автору 11/12; при необходимости доступа к `Source` сначала согласовать минимальный API и передачу, не менять их одновременно.
5. XCTest настоящего NSTextView/NSPasteboard и coordinator: HTML-only/RTF-only/оба/plain/image, source/formatted, одиночная отмена/повтор, stale при переключении документа/режима/выделения и повторной вставке, IME/readonly; обычная и виртуальная B/C с одинаковой позицией, задержанное завершение и отказ без материализации. Copy: полный и частичный strong/emphasis/code/link, reference определения за пределами выделения, escapes/entity, emoji/CRLF, таблицы, plain/HTML/RTF и сохранность буфера при ошибке; явные команды отдельно. Системные приложения и IME, bundled Pandoc 3.13 и производительность проверяются на Mac, здесь их выполнение не заявляется.

Отдельно 09: документированные Typora Cmd+Enter (строка после текущей) и Shift+Cmd+Backspace (удаление строки) проводить через существующие таблицы 08 и undo; не перехватывать незавершённый системный ввод. Текущий child должен корректно сохранить/перевести положение после команды; проверить обычную и виртуальную ячейку, границы, вложенные таблицы, отказ последней строки и обычный ввод вне таблицы. Эти команды не закрывают остальные требования 09.

Следующий узкий шаг copy: только подтверждённый cmark закрытый fenced-блок верхнего уровня. Сопоставить тело исходника с literal cmark после нормализации CR/LF, сохранить частичное выделение UTF-16, выводить экранированный `<pre><code>` и соответствующий code-run; неоднозначные отступы, незакрытые и вложенные блоки пока отклонять. Проверить целый и частичный блок, Unicode, CRLF, пустое тело и незакрытый блок; остальные блоки остаются в полном объёме 16. XCTest на Mac отложен.

Очередной узкий шаг copy: для целиком выделенной верхнеуровневой одноабзацной однострочной цитаты сохранить `<blockquote>` и префикс `> ` в обычном тексте, а встроенные выделения и ссылки сохранить через текущий разбор. Более сложные целиком выбранные цитаты пока явно отклонять; частичный текст остаётся текущим inline-путём. Проверить Unicode, CRLF, вложенное выделение и отказ многострочной цитаты; полная поддержка вложенных и многострочных цитат остаётся обязательной.

Для этой подтверждённой простой цитаты подключить тот же импорт безопасного HTML в RTF, после сохранения и повторного чтения проверить отступ абзаца. Если система не сохранила отступ, не заменять буфер плоским RTF. Interaction XCTest получает RTF через настоящий `NSTextView` и проверяет отступ и исходник. Остальные формы цитат и проверки реальных приложений остаются открытыми.

Одна полная цитата с вложенными цитатами и абзацами допускается в RTF только после проверки полного текста и увеличения отступа на каждом уровне для каждого непустого участка. Смешанные вложенные списки/таблицы и неоднозначные структуры остаются открытыми; реальный round-trip AppKit ещё не запускался.

Первый consumer изображений подключён к копированию в редакторе: проверенные data URI и локальные изображения передаются в HTML, а RTF принимается только после проверки вложений и связей. Для RTF с `pict` и HTML с data URI вставка использует подготовленный backend и сверяет подтверждённые изображения, затем выбирает место каждого файла и записывает без перезаписи; при отмене или устаревании после записи пути сообщаются исходному документу либо текущему документу живого окна. Абсолютные HTTP(S) и локальные file URL остаются ссылками без чтения при конверсии; адрес с HTML entities проверяется существующим извлечением src, порядок и адреса сверяются после разбора. Проверка HTML работает в фоне, смешанный HTML проходит оба пути. Исходный текст заменяется одной операцией только после подготовки всех ресурсов. Тесты ожидают завершения фактической задачи и проверяют успешное сохранение, отмену второй панели, правку и закрытие документа после записи. Относительные HTML-ресурсы без известной базы и проверки AppKit/Pandoc на Mac остаются обязательными.

RTF-путь сверяет количество `pict` с подтверждёнными изображениями, чтобы не вставить результат с потерянной картинкой. Линейный проход по группам учитывает простую соседнюю пару `shppict`/`nonshppict` как одно изображение; неоднозначные и другие формы могут отклоняться. Отдельный тест вставляет удалённую HTML-картинку в виртуальную ячейку C и отменяет её через undo. Полную совместимость RTF и фактический системный ввод ещё предстоит проверить.

Явное Copy HTML может сохранить подтверждённое удалённое HTTP(S) изображение ссылкой, включая alt и title, без сетевого чтения. Обычное форматированное копирование пока отказывает для такого изображения: RTF не считается готовым, пока вложение не получено и не проверено без скрытой загрузки.

Подтверждённая cmark и существующим parser форма `<u>текст</u>` при полном или частичном выделении переносится в plain, HTML и RTF с подчёркиванием. Вложенные и неподтверждённые HTML-теги остаются отдельной работой; сохранение всех стилей в составном структурном RTF ещё требует проверки.

Подтверждённые parser `==highlight==`, `^sup^` и `~sub~` переносятся в plain/HTML и RTF, включая частичное выделение; RTF принимается только если после обратного чтения цвет либо уменьшенный шрифт и положение сохранены по всему диапазону. Составной структурный RTF с такими стилями пока отклоняется, реальная поддержка системного RTF проверяется на Mac.

Для smart punctuation копируется literal cmark: частичное выделение сопоставляет подтверждённые типографские кавычки, тире и многоточие с исходником. Часть многосимвольного исходного знака не угадывается; другие неподтверждённые преобразования остаются явным отказом.

Следующий подэтап цитат: целиком выделенная верхнеуровневая цитата из абзацев допускает несколько строк/абзацев; plain получает `> ` на каждой строке, HTML содержит единый blockquote с переносами, диапазоны runs смещаются по UTF-16. Заголовки, списки и вложенные цитаты внутри пока отклоняются. XCTest сравнивает LF/CRLF, emoji, bold на второй строке и часть исходника; сложная вложенность остаётся обязательной.

Следующий copy-срез: целиком выбранный подтверждённый заголовок верхнего уровня выводится в HTML как соответствующий `h1`–`h6`, plain остаётся текстом заголовка. Сохранить существующие inline runs и частичный выбор, не менять исходник; случаи неподтверждённых границ отклонять. Проверить ATX и Setext, UTF-16, вложенное оформление, CRLF и частичный выбор. Сохранение типографики заголовка в RTF и составные фрагменты остаются обязательными.

Следующий узкий подэтап: вложенные цитаты, состоящие только из абзацев и цитат, копировать с соответствующей глубиной `> ` в plain и вложенными blockquote в HTML; сохранять смещения runs при Unicode/CRLF. Списки и иные блоки внутри по-прежнему явно отклонять до их отдельного сопоставления. RTF вложенной цитаты пока должен отказывать до подтверждения каждого уровня отступа, чтобы не потерять структуру.

Следующий подэтап после передачи Coordinator: полностью выделенный cmark thematic break передавать как `<hr>` в HTML и `---` в plain. Частично выделенный разделитель отклонять. RTF не считать сохранившим линию до подтверждения системного представления; rich copy должен оставлять буфер прежним. Проверить разновидности маркера, Unicode и CRLF вокруг, частичный диапазон и исходник.

До передачи Coordinator можно расширить чистую проекцию: списки внутри целиком выделенной цитаты проходят существующий рекурсивный обработчик списка и сохраняют оба уровня в HTML/plain. Доказать LF/CRLF, вложенный list и Unicode с точными runs; RTF смешанной структуры по-прежнему отказывается до подтверждения всех уровней.

Минимальный RTF для цитаты со списком: если это один самостоятельный blockquote и первая строка — непустой обычный текст до списка, определить его в восстановленном attributed text и проверить отступ именно этого абзаца, отдельно проверить глубину списка. Если якорный текст не найден или форма неоднозначна, отказ; цитата только из списка, несколько цитат и вложенные цитаты остаются обязательными случаями дальше. Проверить обычный/вложенный list, Unicode и сохранение отступа после RTF round-trip, Mac ещё не запускался.

Подготовка ресурсов paste без пользовательской записи: в CopyService принять уже полученный GFM, извлечь подтверждённые cmark inline `data:image/...;base64` через существующий сервис изображений 25.2 и проверить декодированные байты/ImageIO. Вернуть точные диапазоны и байты; отдельно подготовить одну замену адресов только после получения адресов файлов из существующего пути 10. Сохранять alt/title, UTF-16, порядок и surrounding Markdown; изображения иных форм и неподтверждённые данные явно отклонять в этом срезе. XCTest использует настоящий PNG, два изображения, emoji/CRLF, invalid MIME/base64 и проверку неотредактированного входа. Панель назначения, запись без перезаписи, stale/undo и HTML/RTF ресурсы остаются обязательной последующей интеграцией, а не считаются реализованными этим backend.

RTF backend до интеграции: отдельный фиксированный вызов существующего Pandoc с `--sandbox --extract-media=media` внутри приватного временного каталога; до его очистки cmark подтверждает каждый адрес, он должен указывать на обычный извлечённый файл строго внутри `media` без символических ссылок. Прочитать/декодировать фактические байты через ImageIO, преобразовать их в data URI и заменить лишь подтверждённые адреса через существующий проверяющий путь. Повторяющиеся ссылки, порядок, отказ отсутствующего/внешнего ресурса, отмену и удаление временного каталога проверить XCTest; сохранить прежние вызовы clipboard/emoji/yaml tags. Linux Pandoc 3.1.3 уже извлёк настоящий PNG из `\\pict`; встроенный 3.13 и Mac пока не запускались. Отдельный пользовательский выбор и запись останутся следующими шагами.

Отдельная чистая проекция copy: полностью выделенное подтверждённое cmark изображение с `data:` и проверенными ImageIO байтами даёт читаемый alt в plain и экранированный `<img>` в HTML; неполное выделение или неподтверждённые данные отклоняются. Связь с буфером и RTF/локальные пути требуют передачи Coordinator и отдельного доказательства: до этого эта часть не является доступным пользователю копированием и не закрывает 16. XCTest: PNG, Unicode alt, частичное выделение и неверные байты.

Для такого HTML отдельно проверить нативное преобразование в RTF: результат после обратного чтения обязан содержать вложение с изображением; без него возвращать отказ. XCTest проверяет реальные байты изображения после обратного чтения, а не только наличие `<img>`. Сочетания с другими элементами и фактический системный буфер включать только после теста с настоящим AppKit на Mac; доступность для пользователя пока не объявлять.

Если картинка находится внутри ссылки, проверять после RTF round-trip также атрибут ссылки именно у вложения, а не наличие ссылки в другом месте. Тест использует полный исходник cmark с изображением внутри ссылки и проверяет адрес/изображение; отсутствие подтверждения означает отказ, локальный системный результат пока неизвестен.

Следующий чистый подэтап copy: по явно переданному URL документа разрешать локальную Markdown-картинку через уже существующее чтение/ImageIO 25.2 и формировать безопасный data URI для буфера. Несохранённый документ с относительной картинкой, отсутствующий файл и remote URL отклонять; исходный файл только читать. Проверить PNG с Unicode/пробелом в имени и отдельные случаи отсутствующей базы и неверного содержимого. UI и полнота 16 остаются открытыми.

Следующая интеграция после передачи Coordinator: HTML с подтверждёнными data URI и RTF с embedded media конвертировать в фоне, затем для каждого изображения показывать системный `NSSavePanel` и только подтверждённый файл записывать без перезаписи. Каждому ресурсу сопоставлять точный диапазон, не повторять имена по умолчанию без выбора; отмена до записи не меняет документ, после уже записанных файлов сообщать их сохранение и не удалять. После каждой панели и перед/после записи сверять документ, окно, revision, выделение, child/virtual и marked text; при stale не вставлять старый результат, показать путь сохранённого файла имеющимся сообщением. После подготовки всех адресов провести одну замену через текущий editor/child и одну группу undo; undo не удаляет файлы. Проверить несколько картинок, отмену второй панели, конфликт существующего файла, stale во время записи, закрытие/перенос, formatted/source, virtual cell, IME и undo через настоящий путь; локальные и удалённые HTML-ресурсы остаются отдельными случаями. Никаких файловых действий до выбора пользователя.

Inline code с переносами: только при совпадении нормализованного тела с literal cmark преобразовывать CRLF/CR/LF в пробелы и сохранять точные границы UTF-16 для частичного выделения; половину CRLF отклонять. Проверить полный и частичный выбор, Unicode и исходный текст; более сложные неподтверждённые формы остаются отказом.

Цитата с заголовком: целиком подтверждённые cmark заголовки внутри уже поддержанных цитат сохраняются как h1–h6 в HTML и как текст с префиксом цитаты в plain; UTF-16 runs остаются привязаны к отображаемому тексту. Смешанный RTF с заголовком и цитатой пока явно отклоняется прежней проверкой. Проверить Unicode, CRLF и вложенное оформление; другие структуры остаются отдельными случаями.

При копировании fenced code сохранять подтверждённое cmark имя языка в HTML class `language-*` с экранированием, не меняя plain и исходник. Для частичного и полного выбора использовать тот же исходный блок; проверить Unicode/CRLF, имя языка и отсутствие произвольного HTML из info. Синтаксическая подсветка RTF остаётся отдельной частью.

Rich copy выбранных HTTP(S) изображений: только явная команда копирования подтверждает изображение в уже существующем cmark tree и записывает точный диапазон src в сформированном безопасном HTML. Для каждого выбранного remote URL выполнить существующий URLSession/ImageIO download в задаче, заменить только записанный диапазон на data URI, затем проверять RTF-вложения и их связи прежним путём. До записи буфера повторно проверять snapshot/выделение/составной ввод/generation/changeCount; отмена, ошибка сети или устаревание оставляют буфер прежним. Explicit Copy HTML по-прежнему сохраняет remote URL без загрузки. Тест с URLProtocol должен доказать selected-only, bytes, повторяющиеся картинки и отмену; реальная сеть на Mac остаётся проверкой.

Расширение fenced copy: брать подтверждённый block и точные bodySegments из уже открытого общего cmark-разбора, включая закрытые/незакрытые и проверенные quote/list. Частичное выделение пересекает только исходные segments, разделённые CRLF не режет; literal и info берутся из того же узла, не создаётся второй разбор. HTML/plain сохраняют контейнер и язык; структурный RTF цитаты/списка с code до доказательства его сохранности отказывается. Проверить CRLF/Unicode, вложенную цитату, пустой/незакрытый, частичное выделение и неизменность текста; tab в неподтверждённых префиксах остаётся отказом.

Частично потреблённый tab в теле fence: синтетические пробелы cmark включаются в copy только когда выбран породивший их tab; для quote с tab использовать подтверждённую позицию начального `>` и проверенный конец строки, не ослабляя общий Source.range. Проверить полный и частичный выбор, quote и точные пробелы.

Составной RTF: при существующем обходе cmark добавлять в `Fragment` упорядоченные ожидаемые части содержимого и их контекст (цитаты, списки, заголовки, ячейки и вложения). Последовательно сопоставлять всё содержимое с результатами системного HTML-импорта и обратного чтения RTF, проверяя структуру именно у соответствующих частей; не искать повторяющиеся слова по отдельности и не считать общего наличия таблицы или списка доказательством. Для пустых частей и системных разделителей нужны отдельные подтверждённые правила; при неоднозначности оставлять прежний отказ. Переиспользовать существующие проверки стилей и изображений без второго разбора документа. Проверить составные структуры, повторяющийся текст, Unicode, CRLF и утрату/перестановку частей; фактический AppKit требует проверки на Mac.

Обычное Copy публикует подтверждённые plain и HTML независимо от доступности RTF. RTF добавляется только после существующих проверок сохранения структуры и атрибутов; если он не подтверждён, сообщение перечисляет действительно скопированные форматы. Ошибка проекции, изображений или устаревший снимок не меняет буфер. Проверить сложную структуру без RTF, подтверждённый RTF, ошибки ресурсов и устаревшее выделение на настоящем NSPasteboard.

Полностью выделенная цитата с подтверждённой cmark таблицей использует уже существующую проекцию таблицы внутри цитаты; plain сохраняет префиксы цитаты, HTML — оба контейнера. Проверить Unicode и CRLF. RTF этого сочетания пока не подтверждён и не добавляется.

При копировании таблицы HTML сохраняет подтверждённое cmark выравнивание каждого выбранного исходного столбца, включая частичный выбор нескольких ячеек. RTF с таким выравниванием до проверки каждой ячейки не добавляется; plain и HTML остаются доступны.

Подтверждённый thematic break внутри цитаты копируется как `---` и `<hr>` с сохранением окружающих переносов. Поскольку cmark может включить префикс следующей строки в его конечную позицию, для этого случая границу ограничивает физическая строка разделителя; проверить LF/CRLF и Unicode.

До реализации проекции сносок выбранные cmark footnote reference и definition отклоняются явно, чтобы ссылка не исчезала из копируемого текста. Определение проверяется также с начала физической строки, поскольку позиция cmark начинается у его тела; обычное выделение вне сноски продолжает работать, а буфер при отказе не меняется.
