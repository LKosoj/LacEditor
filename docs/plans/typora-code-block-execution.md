# 06а. Код внутри Markdown

Общий план требует язык блока, его выбор/копирование и цветную подсветку с сохранением исходника. `SyntaxHighlighter.tokens` возвращает UTF-16 диапазоны и умеет принимать `documentID: nil`: backend Tree-sitter тогда создаёт отдельный parser, не используя кэш документа и языка, поэтому два блока одного языка не разделяют дерево. Это целесообразно для первого рабочего среза; для длинных блоков и повторных правок измерять стоимость на Mac, не придумывать порог или постоянный индекс. Существующие языки/alias из EditorLanguage использовать без новых grammar; неизвестное имя остаётся обычным кодом. Общую подсветку файлов не менять.

Первый последовательный этап до кода: общий cmark parser подтверждает fenced code node, точные opening/closing и info/body в UTF-16; в исходнике информация языка не удаляется. Для top-level блока исходное тело должно побайтно/посимвольно соответствовать literal cmark с точной обработкой CRLF; для quote/list строить проверенную карту каждой строки после подтверждённого контейнерного префикса и отказать в неоднозначной табуляции. Нельзя применять смещение literal к тексту документа без этой карты. Отдельный вызов SyntaxHighlighter получает неизменный локальный код и nil documentID; возвращённые ranges переводятся только через подтверждённую карту и применяются temporary foreground в видимой части блока, не затрагивая остальной Markdown. Controller отменяет работы при правке/документе/теме, проверяет generation/revision/IME и восстанавливает прежние цвета; не разбирать весь документ на каждый scroll и не считать другие блоки идентичными.

Следующие обязательные части: создание/закрытие fence, выбор языка с одним undo, копирование содержимого, скрытие и раскрытие маркеров с сохранением info, вложенные/незакрытые блоки и полная матрица языков 25.8. Без отдельного согласования не добавлять grammar или окно. XCTest: два соседних блока одного и разных языков с независимыми состояниями, Unicode/emoji и CRLF, quote/list префиксы, неизвестное имя, смена/удаление/передвижение, source и выделение, stale/cancel/IME, проверка отсутствия перекраски за пределами. На Mac — реальные цвета, ввод и время длинных файлов.

Первый независимый backend реализован и прошёл статическое review: известное имя сопоставляется с существующим EditorLanguage, для подтверждённого тела CR/LF нормализуются с точной картой UTF-16, SyntaxHighlighter вызывается без общего documentID, результат ограничивается запрошенной видимой областью. В editor он ещё не подключён; текущий слой пока принимает только тело без удалённых префиксов контейнера.

Сопряжение цвета: основной EditorCoordinator отдельно назначает временный foreground для Markdown и может позднее перезаписать подсветку кода. До подключения нужно согласовать порядок повторного применения с этим путём и восстановление исходного foreground при возврате к source/отключении; нельзя просто вызвать SyntaxHighlighter.apply на весь документ. Точный source mapping вложенных строк, длинный один блок, отмена и IME остаются обязательными.

Первый верхнеуровневый сквозной срез подключён: cmark подтверждает закрытые fences и диапазон тела, controller разбирает видимые тела независимо и накладывает временный foreground после обычной Markdown-подсветки; при возврате source обычный цвет восстанавливается существующим координатором. Исправлен отказ callback при marked text: снятие собственного token и повторное планирование после композиции проверяется управляемым XCTest. Два независимых статических review завершены. Сложные/вложенные и незакрытые блоки, границы cmark с табами/отступом, команды языка и копирования, все грамматики и измерение большой нагрузки остаются обязательными; фактические цвета, IME и XCTest на Mac не запускались.

Команды текущего fence: существующее меню Markdown направляет в координатор две явные команды — копирование содержимого и изменение имени языка; отдельное окно редактора не создаётся. Координатор берёт синхронизированный снимок и фактическое единственное выделение, на явный запрос разбирает его существующим cmark parser в фоне и находит ровно один подтверждённый code block по курсору/выделению. Нельзя менять текст при marked input или недоступном редактировании; версии документа, исходный диапазон info и выделение проверяются после фоновой работы, диалога и shouldChangeText. Выбор языка использует существующий NSAlert с текстовым полем, чтобы сохранить произвольные имена; подтверждение заменяет только infoRange одной группой undo. Копирование использует literal cmark и пишет в системный буфер лишь после проверок; отмена/устаревший снимок оставляет исходник и буфер прежними. Текущий model API закрытых верхнеуровневых блоков применяется первым срезом, вложенные/незакрытые подключаются после их подтверждения без второго пути. Проверить обычный и source вид, произвольный/пустой язык, CRLF/Unicode, отмену, соседние блоки, stale и undo; настоящий AppKit/IME — на Mac.

Следующий срез добавляет незакрытые fence и исходный диапазон info, включая неизвестный и пустой язык. Для цитат и списков формируются отдельные диапазоны тела: каждая строка сверяется с соответствующей строкой literal cmark и подтверждённым префиксом, а перекраска затрагивает только эти диапазоны. Поддержаны варианты пробелов префикса, полностью и частично потреблённые табы; создаваемые cmark пробелы отдельно отмечены как не имеющие исходной длины. Копирование с частичным выделением такого tab проверяется отдельным срезом. Отсутствующий конечный перевод строки допускается только когда cmark добавил один LF. Индекс результатов позволяет выбирать видимые строки и tokens без полного прохода при каждой прокрутке; неудачный разбор не перезапускается для неизменного снимка. Статическое review завершено; остальная матрица блоков и реальные XCTest/IME на Mac ещё требуют проверки.

### Исследование полноты языков до выбора зависимости

Сверка 28 октября 2026 года: официальная страница Typora перечисляет 128 основных названий, а не только 12 нынешних разборов LacEditor. Автоматическое сравнение точных имён с метаданными пакетов (без ручного сопоставления aliases и без доказательства подсветки) нашло 106 совпадений для CodeMirror 5.65.21 и 79 для highlight.js 11.12.0; несовпадающие имена нельзя автоматически считать отсутствующими языками. Нужна отдельная таблица каждого официального имени и alias с проверкой реального примера.

CodeMirror 5.65.21 — MIT, copyright Marijn Haverbeke and others; официальный проект описывает более 100 языковых режимов. В архиве npm 759 412 байт, файлы JavaScript режимов около 1 193 283 байт, `runmode.node.js` 11 544 байта, `mode/meta.js` 15 926 байт. Его runMode выдаёт исходные участки и стили в callback; для JavaScriptCore нужен узкий локальный загрузчик фиксированных режимов и их зависимостей, адаптация Node-шима без DOM и маппинг стилей в существующие цвета TextKit. Сам редактор CodeMirror не нужен. На локальном Node фиксированный пример Go сохранил все 46 UTF-16 единиц и дал 6 окрашенных участков; 1 012 000 байт повторённого примера обработаны за 70 мс в этой среде. Это не оценка JavaScriptCore или Mac, память, отмена синхронного JavaScript и сложные mode-зависимости требуют отдельной проверки.

highlight.js 11.12.0 — BSD-3-Clause, copyright Ivan Sagalaev и contributors; официальный проект указывает 193 языка, часть расширений из отдельной таблицы не входит в основной пакет. Архив npm 853 791 байт, `lib` около 1 669 090 байт, ядро `lib/core.js` 76 324 байта; каталог языков включает также alias-файлы. Публичный результат highlight.js — HTML, поэтому для точных диапазонов потребуется безопасно разбирать результат или отдельно подтвердить используемую структуру токенов, а также проверить вложенные стили и смещения UTF-16. Некоторые названия Typora отличаются и не могут просто перенаправляться на похожий язык без подтверждения.

Сто отдельных Tree-sitter grammar дают нативные деревья, но требуют множество отдельных исходников, лицензий, сборочных подключений и соответствующих примеров; их точные размеры и покрытие здесь не измерены. CodeMirror ближе к официально описанному поведению Typora и его runMode удобнее для диапазонов, но это пока кандидат, не выбранная зависимость. До подключения нужны точный список файлов и notices, сопоставление каждой официальной записи, реальный JavaScriptCore probe без документа/сети, проверка UTF-16/CRLF/вложенных режимов и отмены, измерения длинных блоков и глубокого scroll на Mac. Исследовательские npm-архивы находятся только в `/tmp/laceditor-code-language-audit`; на этапе исследования ресурсы проекта не менялись.

Источники: [Typora: список языков](https://support.typora.io/Code-Fences-Language-Support/), [CodeMirror 5](https://github.com/codemirror/codemirror5), [highlight.js и лицензия](https://github.com/highlightjs/highlight.js), [таблица языков highlight.js](https://github.com/highlightjs/highlight.js/blob/main/SUPPORTED_LANGUAGES.md).

Ввод fence, первый бесспорный случай: если formatted Markdown состоит из одной только первой строки opening fence и курсор в её конце, Return создаёт пустую строку и подходящее закрывающее ограждение одним штатным insertText/undo; обычный Enter и marked input остаются существующему обработчику. Эта строка не может быть закрытием предыдущего блока, поэтому для неё не нужен полный разбор на горячем пути. Остальные позиции, вложенность, CRLF и существующее содержимое требуют отдельного подтверждённого контекста и остаются обязательными, а не объявляются готовыми. XCTest: обычное создание, язык, undo, незавершённый ввод, отсутствие перехвата внутри кода/в source mode; результат проверки на Mac отдельно.

Enter top-level расширен: последний подтверждённый cmark снимок хранит интервалы code/HTML/math/YAML/контейнеров; Coordinator передаёт только однострочные правки и проверяет текущий revision. Новая строка с opening fence получает закрытие одной отменой, если контекст подтверждён; при отсутствии подтверждения используется обычный Enter. Существующий закрытый или непустой незакрытый блок не закрывается повторно. Добавлены тесты быстрого ввода после snapshot, CRLF, обычного Enter внутри кода и reentry; статическое review проведено. Quote/list, вся матрица и реальный Mac остаются открытыми.

Enter внутри quote/list: общий cmark snapshot должен отдельно подтверждать непрозрачные блоки и контейнеры, а для текущей физической строки — её предков и точный исходный префикс продолжения. После snapshot допускаются только однострочные правки вне неизменного префикса; при любом сомнении остаётся обычный Enter. Координатор на проверенной строке вставляет body и closing с подтверждённым префиксом одной заменой и undo, сохраняя CRLF/UTF-16 и соседа; не выполняет новый разбор или обход документа на Enter. Нужны actual NSTextView tests цитаты, списка и их вложенности, быстрой правки после snapshot, изменённого префикса, уже закрытого/незакрытого блока, marked text и undo. Model/Controller подтверждение передаются владельцем 06а до подключения; фактический AppKit/IME — на Mac.

Пользователь разрешил необходимые библиотеки. Подключён локальный CodeMirror 5.65.21: только runner, необходимые режимы и зависимости, без редактора/тем; отдельный JavaScriptCore преобразует исходник как данные в UTF-16 диапазоны. Для восьми недостающих записей подключены ядро и точные grammar highlight.js 11.12.0 / ABAP / YARA с отдельными лицензиями; публичный HTML-результат не исполняется, а разбирается как фиксированные span и сверяется с исходным текстом. Все 153 имени в 115 CodeMirror-строках матрицы и восемь примеров второго движка прошли локальный Node probe; Swift/JavaScriptCore/XCTest на Mac не запускались. Проверка отмены выполняется между токенами; отдельный долгий синхронный RegExp остановить этим способом нельзя. Статическое независимое review обоих bridges завершено.

Таблица всех 128 основных имён — [typora-code-languages-matrix.md](typora-code-languages-matrix.md). Для `solidity` и `v` подключены оригинальное ядро и соответствующие grammar PrismJS 1.30.0 (MIT); отдельный локальный runner проверяет исходный текст по структуре токенов. Примеры обоих языков прошли Node probe, JavaScriptCore/XCTest на Mac ещё не запускались. Для `svelte` подключена отдельная MIT grammar highlightjs-svelte 1.0.6 с исходным LICENSE и необходимыми xml/javascript/css sublanguages; её пример прошёл Node probe. Для `pseudocode` подготовлены собственные лексические правила и XCTest на пример с `do` и `<--` из [issue Typora](https://github.com/typora/typora-issues/issues/5427); точная семантика закрытой grammar Typora остаётся непроверенной. Не определено имя `bhdl`: без подтверждения не подставлять VHDL. Обычный текст не выдаётся за подсветку. У пакета Solidity metadata и файл лицензии противоречат друг другу, а у одного из проверенных пакетов Svelte metadata MIT без вложенного LICENSE; эти спорные файлы в приложение не включены; Solidity обеспечивается отдельной grammar PrismJS.

Первый подготовительный API Enter для контейнеров получает opening/continuation prefix из уже подтверждённого cmark пустого незакрытого fence; он разрешает только неизменённый snapshot той же revision; handler подключён, есть interaction XCTest для quote/list, CRLF, tab и undo, статическое review завершено. Тот же механизм сохраняет подтверждённый prefix при однострочных правках после него и поддерживает замену доказанной строки абзаца в quote/list на fence без ожидания нового разбора; последующие строки цитаты требуют все маркеры `>`, а продолжение list проверяет отступ по первой подтверждённой строке каждого item; в quote+list позиции сравниваются только при совпадающем quote prefix. Добавлены controller и interaction XCTest. Остальные формы строк, контейнеров и реальная проверка Mac остаются обязательной частью 06а.

При изменившемся quote prefix и неподтверждённых позициях с табами paragraph continuation пока использует обычный Enter; полная поддержка этих форм остаётся обязательной.

Пустая подтверждённая cmark цитата или item сохраняет prefix при наборе fence: после `> ` допустимы ещё до трёх пробелов, после marker списка — один–четыре пробела. Пять пробелов намеренно не принимаются: pinned cmark трактует следующий fence как indented code. Tab padding проверяется по абсолютным остановкам в четыре колонки; примеры `-\t`, `>\t`, `> -\t` подтверждены pinned cmark и статическим review. Неоднозначные формы пустых контейнеров остаются для дальнейшей проверки.
