## 12. Математика: MathJax 4.1.3

**Предложение:** закреплённый выпуск [MathJax 4.1.3](https://github.com/mathjax/MathJax/releases/tag/4.1.3), лицензия [Apache-2.0](https://github.com/mathjax/MathJax/blob/4.1.3/package.json); предоставить локальный комплект для TeX → SVG, а не подключать сеть. `tex-svg` — объединённый компонент для разбора TeX и вывода SVG; дополнительно потребуются локальные компоненты `mhchem`, `physics` и все фактически загружаемые ими ресурсы. Конкретный окончательный список файлов, поддерживаемых пакетов и размер измерить после согласования на отобранном комплекте; проверить все транзитивные лицензии и уведомления. Не считать `tex-svg` плюс два файла доказанно полным автономным комплектом до проверки фактической загрузки в изоляции.

- Typora документирует `\def`, `\newcommand`, химический `mhchem`, отдельное включение `physics`, метки `\label`, `\tag` и ссылки `\ref`: [Math and Academic Functions](https://support.typora.io/Math/). MathJax [поддерживает mhchem](https://docs.mathjax.org/en/stable/input/tex/extensions/mhchem.html) и [physics](https://docs.mathjax.org/en/stable/input/tex/extensions/physics.html); второй пакет требуется подключать явно, он переопределяет стандартные команды. Сохранить описанное отдельное включение physics, определить значения и переключение при реализации по матрице 01. Перечень остальных требуемых пакетов определить по всем примерам Typora, не объявлять два пакета исчерпывающим набором.
- Нумерация MathJax настраивается, по умолчанию выключена; `\label`, `\ref`, `\eqref` и ссылки вперёд требуют согласованной обработки документа: [нумерация MathJax](https://docs.mathjax.org/en/stable/input/tex/eqnumbers.html). Для видимой области потребуется состояние меток и макросов той же версии всего документа; отдельный независимый вызов на каждый блок не доказывает правильности ссылок или нумерации. Проверить повторные метки, ссылки вперёд, изменение и удаление определения, изоляцию документов.
- SVG удобен как кандидат для вывода и печати, но исходный TeX сохраняется для редактирования и копирования: [MathJax SVG](https://docs.mathjax.org/en/stable/output/svg.html) указывает на ограничение копирования знаков и фиксированную ширину некоторых таблиц. Проверить автономность SVG, локальный кэш глифов, перенос/повторную раскладку при смене ширины, масштаб, выделение и доступность. CommonHTML — альтернатива для копирования текста, но требует проверить ресурсы шрифтов и геометрию в нативном представлении. Не подключать оба варианта заранее.
- KaTeX — альтернативный движок, а не гарантированная замена: [список команд](https://katex.org/docs/supported) подтверждает многие формулы и макросы, но также содержит неподдерживаемые конструкции в [таблице поддержки](https://katex.org/docs/support_table.html). Сравнение должно включать chemistry, physics, нумерацию и межформульные ссылки на конкретных примерах; нельзя заключать, что KaTeX не поддерживает всю химию или все макросы. Выбор MathJax обусловлен документированной связью с набором команд Typora и наличием названных расширений, а не доказанной полной совместимостью.

На Mac до решения о включении проверить локальную загрузку без сети, контрольный набор 01 (включая матрицы, дроби, chemistry и physics, макросы, прямые и обратные ссылки, ошибки и валюту), исходный текст/undo/IME, смену документа и версии, текстовые интервалы UTF-16, доступность и реальную печать/PDF. Сопоставить редактор, предпросмотр и экспорт; измерить размер именно проверенного набора файлов, время и память. Вывод в TextKit и ссылки между выражениями остаются техническими рисками до фактической проверки.

## 25.1. Flow и sequence: отдельные движки

[Документация Typora](https://support.typora.io/Draw-Diagrams-With-Markdown/) прямо называет `flowchart.js` для блока `flow` и `js-sequence` для блока `sequence`, отдельно от Mermaid. Существующий Mermaid не заменяет эти грамматики; нельзя незаметно переводить один синтаксис в другой. Страница также описывает темы sequence `simple` и `hand` и экспорт рисунков в HTML/PDF/EPUB/DOCX.

| Конструкция | Кандидат и минимальный состав для проверки | Лицензия и ограничения |
|---|---|---|
| `flow` | [flowchart.js 1.18.1](https://github.com/adrai/flowchart.js/blob/master/package.json), вместе с указанным там Raphaël 2.3.0. Зафиксировать точный выпуск и происхождение готового файла до использования. | [MIT](https://github.com/adrai/flowchart.js/blob/master/license); [Raphaël MIT](https://github.com/DmitryBaranovskiy/raphael/blob/master/license.txt). Проверить, включён ли Raphaël в выбранную сборку, чтобы не поставлять его дважды. |
| `sequence` | [js-sequence-diagrams 2.0.1](https://github.com/bramp/js-sequence-diagrams/blob/master/bower.json), [Snap.svg](https://github.com/adobe-webplatform/Snap.svg) и один из underscore/lodash. README называет `simple` и `hand`, опциональный jQuery и Web Font Loader для пользовательских шрифтов. Проверить фактический минимальный комплект для обеих тем: для `hand` README указывает CSS и файлы Daniel; наличие этих файлов и работу автономно подтвердить отдельно. | [BSD-2-Clause](https://github.com/bramp/js-sequence-diagrams/blob/master/LICENCE); Snap.svg — [Apache-2.0](https://github.com/adobe-webplatform/Snap.svg/blob/master/LICENSE), underscore — [MIT](https://github.com/jashkenas/underscore/blob/master/LICENSE), Web Font Loader при необходимости — [Apache-2.0](https://github.com/typekit/webfontloader). Условия и происхождение шрифта Daniel проверить по фактическому комплекту: одной фразы README недостаточно для полного лицензионного учёта. |

Вместо Snap.svg `js-sequence` версии 2 допускает Raphaël, уже нужный для flow; это потенциально уменьшит число библиотек, но заявленный диапазон sequence — Raphaël 2.2.x, тогда как flow требует 2.3.0. Совместимость обеих тем с одним Raphaël 2.3.0 не доказана. Предпочитать один общий движок только после сравнения работающих образцов; иначе использовать документированный Snap.svg. Не загружать одновременно оба варианта только ради предположения о совместимости. Точные версии зависимостей sequence выбрать и зафиксировать по результатам проверки, включая исходники, контрольные суммы и лицензии.

Проверка до принятия: по одному обычному, сложному и ошибочному примеру каждого синтаксиса; темы и выравнивание, все параметры матрицы, Unicode, изменение размера, актуальность версии, ошибка и исходник, копирование/сохранение, отсутствие сети и внешних обращений. На Mac проверить расположение в TextKit, курсор, VoiceOver, отмену, IME, обновление без разметки всего документа; отдельно открыть HTML/PDF/DOCX/EPUB с изображениями. Проверить отсутствие обращения к CDN, шрифтам и сервисам сети; установить фактические файлы и размер только после согласования. До успешных проверок любые утверждения о полном соответствии остаются неподтверждёнными.
