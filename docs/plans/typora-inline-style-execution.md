# 15: документированные стили HTML span

Предварительный план подготовлен GPT-6.1-Terra (`files_execution`), независимо проверен GPT-6.1-Terra (`native_execution`). CSS-темы не входят в работу.

1. Первый срез распознаёт документированные `color:red`, `background:yellow` и `font-size:2rem` через общий тип `MarkdownInlineStyle`. Первый срез содержит цвет текста, фон и размер rem, сериализует фиксированные CSS-свойства и наследует лишь отсутствующие поля. CSS number проверяется отдельно от Swift Double: шестнадцатеричные числа недопустимы. Последняя валидная декларация побеждает. Неподдержанное валидное значение остаётся исходником; нулевой размер не подменяется системным шрифтом. Другие цвета, единицы и свойства не объявляются готовыми этим срезом.
2. Подтверждать только точную пару `<span style="...">…</span>` с одним атрибутом после Source/HTMLContext/DOM proof на существующем дереве. Значение атрибута декодируется существующим SwiftSoup. Не применять CSS из неподтверждённого диапазона, script/template или несовпадающего источника.
3. Передать типизированный стиль в существующие Parser/Controller/Fold/Renderer/Copy. Вложенный span меняет только свои свойства; шрифт сохраняет подтверждённые bold/italic. Размер rem сопоставляется с корнем WebKit 16 CSS px. Исходник, диапазоны UTF-16, выделение, undo и marked text сохраняются. Для таблицы использовать её собственный source mapping и общий HTMLContext; не доверять локальному wrapper после изменения контекста.
4. Swift-проверки: точные красный/жёлтый и 32 pt, порядок деклараций и наследование, число с точкой/экспонентой, hex/невалидные/нулевые/неподдержанные значения, исходные entities, вложенность/heading/table, source mismatch, reveal/marked/stale/undo и Copy/RTF/HTML/PDF. AppKit/WebKit и реальный результат на Mac проверяются отдельно.

Основной агент подготовил модель и чистые Swift fixtures, зарегистрировал её в Xcode и четырёх прямых вызовах swiftc. Независимое review выявило несовместимость Swift hex float с CSS number; добавлены строгая грамматика и regression. Повторный независимый review модели новых конкретных дефектов не нашёл. Первый срез Parser/UI/Copy/Renderer интеграции подготовлен и прошёл независимые статические проверки; фактическое исполнение на Mac ещё не проверено.

Владение: основной агент — модель, списки сборки и общая документация; `files_execution` — Renderer; Parser/Controller/Fold по согласованной передаче от `blocks_execution`; Copy — `native_execution`. Изменения файлов коллег не отменяются. Сборка Swift и XCTest в Linux не запускались.


## Документированное `display:none`

Предварительный план `files_execution` независимо проверен `native_execution`; основной агент сверил [первичный источник](https://support.typora.io/HTML/). В редакторе содержимое видно, экспорт скрывает его. Это отдельное свойство HTML, не CSS-тема.

1. Добавить `hideOnExport` в существующий тип, принять только `display:none`, а остальные значения оставить неподдержанными. Между предками скрытие объединяется через OR: потомок не отменяет скрытого предка. Сохранить прежнюю обработку цветов/размеров. Проверить pure Swift fixtures деклараций и наследования.
2. Нативное представление сохраняет видимость. `css` включает скрытие для выходного HTML, preview/PDF/PNG; `editingCSS` опускает только скрытие. Форматированное Copy использует видимый результат редактора — контракт проекта, а не подтверждённое обещание Typora. Исходное Copy Markdown сохраняет исходник. Проверить соседний текст, вложенность, таблицы, фактическую CSS visibility в WK и сохранение исходника/undo.
3. Ранее отрицательные fixtures с `display:none` заменить на неподдержанное `position:fixed`, сохранив проверку ресурсного барьера. Скрытый CSS сам по себе не подавляет загрузку ресурсов; существующий ресурсный путь не менять.
4. Независимое review каждого потребителя и общей модели, затем `git diff --check` и сверка сборочных списков. Запуск Swift/XCTest и геометрия AppKit/WebKit требуют Mac.

Модель и fixtures подготовлены основным агентом, независимый статический review `files_execution` конкретных дефектов не нашёл. Потребители и их проверки находятся в реализации.


Срез `display:none` подключён к Copy и существующим inline/block/table путям Renderer. Добавлены Swift fixtures WK/PDFKit и фактического буфера/RTF; повторное независимое статическое review конкретных дефектов не нашло. Root отдельно проверил политику HTML без оформления: он сохраняет подтверждённые стили самого HTML span, включая скрытие, но не добавляет нативные настройки приложения. Это существующее поведение, не новое включение декоративных стилей. Реальное выполнение fixtures по-прежнему требует Mac.
