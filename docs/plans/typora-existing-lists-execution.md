# 04/05: преобразование существующих списков

Предварительный план подготовлен GPT-6.1-Terra. Основной агент реализует сервис/Swift-tests, Terra независимо проверяет код. Используются существующие меню и editor shouldChange/didChange/undo; нового режима нет.

1. Перед новым newBlockEdit распознать existing list в одном cmark tree с текущим Source: один parent list, последовательные siblings, точные source marker/padding и task checkbox state. Курсор действует на пункт, selection — на выбранные физические строки. Same-type остаётся дословно неизменным, новый ordered subset начинается с1. Переписываются только подтверждённые prefixes, выделение переводится по UTF-16 delta, одна замена и одна отмена.
2. Первый кодовый срез принимает лишь item из одной физической строки. Поддержаны checkbox/обычные/ordered, quote и однострочные nested leaf при доказанных границах; неоднозначный partial marker, tab, смешанные parents и multi-line parent не меняются. Swift-тесты: Unicode/CRLF, checked, старт7), пустойitem, subset, no-op, отказы и actual command+undo в обоих представлениях. Независимое статическое review новых конкретных дефектов не нашло, Mac/XCTest не запускались.
3. Полный многострочный/вложенный срез остаётся обязательным. Нельзя просто заменить prefix: `- parent\n  - child` после `1. parent\n  - child` теряет вложенность (подтверждено cmark/Pandoc3.13). Нужна коррекция именно block marker+padding indentation продолжений, без учёта checkbox как block indent. Сохранять вложенные/обычные/fenced содержимое, quote prefixes, LF/CRLF и blank/lazy формы. Пробный cmark разбор результата команды должен подтвердить сохранность child subtree и literals; это явная команда, не дополнительный parse на keyDown. Конкретный минимальный helper и границы proof уточняются до следующего кода.

Пока нет полноценного преобразования всех многострочных/nested случаев; первый срез не объявляет04/05 завершёнными.

4. Реализация многострочного среза: выбрать пункт по первой выбранной строке или продолжению под курсором, преобразовать его последовательных siblings, потомков оставить внутри родителя. Изменить marker+padding и подтверждённые continuation spaces после общего containerPrefixes; checkbox не входит в block indent. Пустые строки и lazy продолжения сохраняются дословно. Один пробный разбор результата сравнивает все литералы/URL/title/code info, порядок узлов и parent item, включая невыбранный текст. Неподтверждённые tab cases остаются отказом. Swift fixtures покрывают вложенные, quote CRLF/Unicode, fenced code, task, lazy и caret/selection. Требуется независимое review и Mac XCTest.

5. Следующий предварительный план Terra для tab: сначала top-level non-task marker в начале строки, tab-stop4 и cmark padding1…4 columns, continuation до structural boundary; остаток пересекающего границу tab заменить эквивалентными ASCII spaces, body tabs сохранить. Blank/lazy неизменны, обязательна та же AST proof и UTF‑16 mapping. Quote/nested/task tabs требуют следующего общего container/checkbox proof; этот первый срез не закрывает все tab cases. Реализация и Swift fixtures подготовлены основным агентом, независимое review ожидается.

6. При review уточнена граница task tabs: подтверждённый прежним Source.taskCheckbox checkbox на первой строке и tab только в continuation поддерживаются тем же block proof (checkbox не входит в indent). Добавлен отдельный fixture. Табы в первой строке task/ancestor пока требуют общего source proof и не объявляются готовыми.

7. Собственная проверка основного агента выявила raw-marker/ordinal расхождение: cmark сливает соседние ordered lists даже при вставленном `1.`. Предварительный Terra review подтвердил минимальный fix: для всех выбранных вновь ordered item проверяется фактический ordinal1+index; task→plain в уже ordered сохраняет marker/padding и исходный ordinal. Merge с предыдущим списком, меняющий выбранные номера, отказывается без separators и правок соседей. Regression source start7)/subset и actual editor undo добавлены, независимое review новых конкретных дефектов не нашло. Mac/XCTest не запускались.

8. Quoted task: общий Source helper и Math callback реализовал Terra после независимого плана/review; основной агент подключил Formatting. Начальный TEXT и его точный ASCII checkbox prefix доказываются отдельно, подпись нормализует только подтверждённый prefix и сохраняет невыбранный checked state. Создание новых quoted task, снятие checkbox, ordered marker7) и mixed task/ordinary, bold body и реальный command undo получили Swift fixtures; reference-link вместо начального TEXT и partial marker пока отказываются. Независимое repeat review реализации Formatting ожидается; Mac не запускался.

9. Общий block-prefix proof теперь считает абсолютную ширину tab-stop4 и собственный padding1…4, включая ancestor tabs; Copy consumer поправлен владельцем отдельно, Renderer использует лишь точный source prefix. Основной агент подключил это к Formatting: собственная ширина считается от реального marker column, continuation — от visual ancestor width, частичный tab сохраняет остаточные колонки. Pinned cmark подтвердил структуру пяти новых пар, independent Terra review конкретных дефектов не нашёл. Source checkbox также поддерживает подтверждённые tabs в marker/после checkbox/body и quoted/nested позициях; реальные click/undo и сквозное продолжение unchecked получили Swift fixtures. Старые reference-first-line, пустые ancestors и переменные quote-prefix формы пока требуют отдельного proof, Mac не запускался.
