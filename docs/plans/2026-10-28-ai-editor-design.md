# AI в LacEditor: подключения, функции и исследование

## Запрос и границы

Исходник: `.attachments/20261028_004929_ai-editor-features-backlog.md`.
Нужно подключение OpenAI и собственных серверов, отдельный выбор текстовой,
decisions-модели и модели изображений. Каждая пользовательская функция должна
иметь собственный переключатель. Дополнительно исследовать полезные функции,
которых нет в исходном списке.

Поддержка подключения не равна реализации всех функций бэклога. Первый
независимый этап — настройки и HTTP-клиент для трёх ролей. Пользователь позднее подтвердил реализацию функций, уточнил системную проверку
грамматики и Jina для поиска и чтения страниц. Текущий результат описан в конце
документа; первый этап ниже сохранён как история выполнения. Чат, автоматическая перезапись документов,
индексирование библиотеки и внешние интеграции не добавляются.

Существующие незакоммиченные изменения, включая Pandoc, оформленный Markdown,
оглавление и Mermaid, сохраняются. Коммиты, выпуск и реальные платные запросы
не выполняются в рамках проверки без предоставленного подключения.

## Проверенный контекст проекта

- macOS 26+, SwiftUI/AppKit, TextKit 1; текущая среда Linux без Swift.
- `AppPreferences` — общий объект настроек окон с внедряемым UserDefaults.
- `SettingsView` — существующие разделы настроек; AI добавляется туда.
- Для диапазонов текста используются UTF-16 и `NSRange`.
- `EditorTextExtractionRequest` извлекает актуальное выделение из NSTextView.
  `EditorRangeReplacementRequest` проверяет версию редактора и оригинал, затем
  выполняет замену с отменой. Этот путь следует использовать для AI-правок.
- `synchronizedSnapshot()` нужен для анализа документа целиком; `document.text`
  может отставать от ввода. Версия редактора и версия модели различаются.
- Сетевого AI-клиента и хранения API-ключей в проекте пока не было.

## Сравнение подходов

| Подход | Польза | Ограничение | Решение |
|---|---|---|---|
| Только OpenAI Responses | Меньше кода | Не покрывает многие свои серверы | Недостаточно для запроса |
| Явно выбранные HTTP-протоколы, URLSession | OpenAI и совместимые серверы, без зависимости SDK | Каждый формат ответа проверяется отдельно | Выбран для первого этапа |
| Универсальная система плагинов, маршрутизация и автоматические переходы между серверами | Больше гибкости | Новая инфраструктура, сложнее понять передачу данных | Не добавлять |

Собственный сервер должен поддерживать выбранный HTTP-контракт. Одного похожего
имени модели недостаточно. Нельзя автоматически угадывать протокол по имени
модели или отправлять документ другому серверу после ошибки.

## Этап 1: подключения и модели

### Настройки

Три независимых профиля: текст, decisions, изображения. В каждом:

- отдельный переключатель, изначально выключен;
- URL корня API, например `https://api.openai.com/v1` или URL своего шлюза;
- идентификатор модели, который всегда можно ввести вручную;
- явный выбор протокола: Responses/Chat Completions для текста;
  Decisions/Responses/Chat Completions для классификации; Images для картинок;
- API-ключ в системной Связке ключей, отдельно от обычных настроек;
- кнопка получения списка моделей, без отправки документа и без генерации.

Профили сохраняются в общем AppPreferences. Ключи разделяются по окружению
AppEnvironment, роли и URL сервера: смена URL не переносит ключ другому серверу.
Пустой ключ допустим для сервера без авторизации. Результаты получения моделей
относятся к снимку настроек; после его изменения устаревший ответ не применяется.
Успех `/models` подтверждает доступ к списку, но не возможность генерации
конкретной моделью. Отсутствие `/models` не запрещает ручной ввод модели.

### HTTP-контракты

| Роль | Запрос | Проверка ответа |
|---|---|---|
| Текст Responses | POST `responses`, model/input/instructions, store=false | Собрать текстовые элементы output, отличать отказ/незавершённый ответ |
| Текст Chat Completions | POST `chat/completions`, model/messages | Текст assistant, отказ и причина остановки |
| Decisions | POST `decisions`, input/questions с predicate | Вероятность ответа на именованный вопрос, отказ, корректный диапазон 0…1 |
| Decisions через текстовый API | Явно выбранный Responses или Chat | Обычный текст; схема классификации определяется конкретной функцией |
| Изображение | POST `images/generations`, model/prompt | base64 либо загрузка URL без пересылки API-ключа |
| Список моделей | GET `models` | data[].id; ручной ввод остаётся доступен |

Decisions API возвращает оценку вопроса, а не исправленный текст. Превращать
вероятность в решение следует только с критерием конкретной функции, проверенным
на примерах. Нельзя представлять оценку модели как доказанную истинность.
OpenAI документирует отдельный Decisions API; свой сервер может его не иметь.
Идентификаторы моделей не ограничиваются жёстко заданным каталогом приложения.

Запросы выполняются URLSession без командной оболочки и стороннего SDK.
Не добавляются автоматические повторы генерации, запасные серверы или параметры,
которые могут не поддерживаться выбранной моделью. HTTP(S)-URL проверяется;
перенаправление запроса не должно переносить секрет к другому получателю.
Ошибки не включают ключи или отправленный документ.

### Файлы и порядок

1. `Models/AIConfiguration.swift`: роли, протоколы, профили, Codable-настройки.
2. `Services/AIKeychainStore.swift`: чтение/запись/удаление секретов.
3. `Services/AIClient.swift`: точные запросы и разбор ответов, отмена.
4. `App/AppPreferences.swift`: сохранение конфигурации без секретов.
5. `Views/AISettingsView.swift`, `Views/SettingsView.swift`: отдельный раздел,
   три независимо включаемые роли, ключи, URL, модель, список моделей.
6. Списки Xcode и SPM, переводы на китайском/английском/русском,
   AGENTS, README и CHANGELOG.
7. Независимое ревью и исправления до отсутствия подтверждённых замечаний.

Модель/клиент и UI можно разрабатывать параллельно после согласования имён
типов; общие настройки, списки сборки и переводы меняет один исполнитель.

### Критерии проверки

- URLProtocol в XCTest проверяет реальные сформированные URL, заголовки и JSON
  всех протоколов, Unicode, ответы, HTTP-ошибки, пустые результаты и отмену.
- Секрет не попадает в Codable-конфигурацию; отдельный UserDefaults сохраняет
  профили и независимость переключателей.
- Keychain-тесты на Mac проверяют замену, удаление и разделение окружений/URL.
- Изменение URL/модели во время запроса не показывает старый результат.
- Не включённые роли не запускают генерацию; просмотр настроек не делает
  сетевых запросов. Кнопка списка моделей — явное действие.
- На Mac: `swift build`, `swift test`, Xcode-сборка и ручная проверка настроек.
  Статическое чтение на Linux эти проверки не заменяет.

## План пользовательских функций: первоначальная разбивка работ

### Общая основа предложений

Каждое предложение хранит документ, исходный диапазон UTF-16, исходный текст,
версию, результат и объяснение. Предпросмотр показывает оригинал и правку;
«Принять» использует существующий EditorRangeReplacementRequest, «Отклонить»
убирает предложение. Одна принятая правка — одно действие отмены. Изменение
текста, закрытие документа, выключение функции или смена профиля отменяет запрос
и делает результат неприменимым. Запоздавший HTTP-ответ проверяется повторно.

Общий выключатель фоновой обработки не заменяет переключатели функций.
Выключение фона сохраняет ручные команды включённых функций. Выключение одной
функции останавливает только её работу и убирает её предложения. Выключение
подключения останавливает все использующие его операции. Возврат переключателя
не должен автоматически применять прежний результат. Кэш, телеметрия и сбор
пользовательских текстов не нужны для этого этапа.

### P0

| Функция / отдельный переключатель | Реализация | Приёмка |
|---|---|---|
| Грамматика и пунктуация | По уточнению пользователя: системная проверка NSTextView, отдельные настройки орфографии и грамматики, без AI и автоматической замены | Реальная проверка поддерживаемых языков, подчёркивания и IME на Mac обязательна; качество определяет macOS |
| Ясность текста | Отдельные советы с причиной: повтор, тяжёлая конструкция, избыточность | Выключение ясности не отключает грамматику; совет не применяется сам; смысл не меняется |
| Переформулировать / сократить / расширить | Три независимые ручные команды и переключателя, только выделение; несколько вариантов до применения | Отмена одной правки; актуальная версия; emoji/CJK; нет выделения — нет запроса; отказ модели не выдаётся за результат |
| Термины и имена | Сопоставлять упоминания, показывать оба места; не нормализовать автоматически | Реально одинаковый объект, переходы к обоим диапазонам; исправление одного места делает старые карточки неактуальными |

Сначала ручное переписывание и проверка диапазонов, затем фоновые подсказки.
Это уменьшает риск одновременного изменения ввода и применения ответа.
Decisions-профиль при необходимости классифицирует тип проблемы; не вставлять
обязательный дополнительный вызов модели перед каждой простой командой.

### P1

| Функция / отдельный переключатель | План | Основная проверка |
|---|---|---|
| Продолжение текста | Отдельное отображение подсказки без изменения документа; принять/отклонить; отменить при вводе и IME | Задержка, навигация, Tab, отсутствие устаревшего продолжения; не мешать обычному вводу |
| Оценка тона | Индикатор и объяснение оценки | Субъективность явно обозначена, отключается отдельно от изменения тона |
| Изменить тон | Выбор целевого тона, оригинал/вариант до применения | Сохранение смысла и отдельная отмена |
| Структура | Предложения заголовков, абзацев и перестановок; без автоматической перестановки текста | Ссылки на исходные блоки, проверка актуальности всей перестановки |
| Резюме | Отдельное представление с версией и временем; ручная вставка | Никаких новых фактов, актуальность; выключение фона не мешает ручному запуску |

### P2 и смежные функции

| Функция / отдельный переключатель | План и зависимость | Проверка |
|---|---|---|
| Противоречия | Ручной анализ, пара конфликтующих мест и объяснение | Отрицания, даты, условия; ложные срабатывания на размеченном корпусе |
| Источники | Сначала отдельный выбор поискового сервиса и правил передачи текста; затем подтверждение конкретного утверждения | Содержание источника действительно подтверждает утверждение; модель не придумывает ссылки |
| Метаданные | Сначала определить место хранения; теги и описание как предложения | Пользователь может изменить; сохранение документа не меняется скрытно |
| Происхождение текста | Локальный учёт реальных событий ввода/вставки/AI, неизвестное не угадывать | Диапазоны после редактирования и отмены, совместимость восстановления; это не детектор AI |
| Личный словарь стиля | Только после отдельного решения о хранении принятых правок | Удаление словаря, приватность, отсутствие неявной отправки истории |

В исходном бэклоге численные пороги качества не заданы. Их нельзя придумать
и объявить выполненными. Нужен набор примеров на трёх языках, базовая оценка,
затем согласование допустимой доли смысловых ошибок и ложных подсказок.

## Исследование дополнительных функций

Документация конкурентов подтверждает наличие сценариев, но не доказывает их
качество и востребованность у пользователей LacEditor. Приоритеты ниже —
продуктовые рекомендации, а не результаты пользовательского эксперимента.

| Дополнение / свой переключатель | Польза | Риск и минимальная реализация | Приоритет |
|---|---|---|---|
| Перевод выделения | Работа с многоязычными текстами | Оригинал и перевод, сохранение Markdown, имён/чисел, явное применение | Следующий кандидат после P0 |
| Поручения из заметок | Быстро получить список действий | Ссылка на исходник; срок и исполнитель только если указаны; не создавать задачи во внешних сервисах | P1 |
| Решения и открытые вопросы | Подготовка итогов обсуждения | Разделять принятое решение, предложение и неизвестное; привязка к тексту | P1 |
| Заметки в таблицу/список Markdown | Привести разрозненные записи к читаемому виду | Не терять факты; модель распределяет смысл, синтаксис формирует обычный код | P1 |
| Что непонятно адресату | Найти пропущенные определения и условия | Вопросы к конкретным местам вместо выдуманных дополнений | P1/P2 |
| Иллюстрация к выделению | Практическое применение модели изображений | Показать описание, явная генерация, предпросмотр; вставка только после выбора пользователя | Отдельный этап изображений |
| Описание изображения для доступности | Помочь читателю с программой чтения экрана | Требует модели с приёмом изображений, которого текстовый API не гарантирует; человек проверяет результат | P2 |

Перевод и сценарии изображений описаны у [Notion](https://www.notion.com/help/notion-ai-faqs).
Извлечение поручений — в [Notion AI Autofill](https://www.notion.com/en-gb/help/autofill).
Преобразование выделения в таблицу — в [Copilot для Word](https://support.microsoft.com/en-us/word/copilot/draft-and-add-content-with-copilot-in-word).
Сценарии вопросов к документу — в [обзоре Copilot для Word](https://support.microsoft.com/en-us/word/welcome-to-copilot-in-word).
Локальный учёт происхождения, уже присутствующий в исходном бэклоге, имеет
аналог в [iA Writer Authorship](https://ia.net/writer/support/editor/authorship).

Изображения требуют отдельного решения: сохранить в выбранный файл и вставить
ссылку либо встроить в Markdown. Для несохранённого документа относительный
путь не определён. Нельзя добавлять постоянную папку ресурсов и скрыто менять
сохранение документа без этого решения. Картинки не следует представлять как
точные технические схемы; для схем уже есть Mermaid.

Не требуют модели: подсчёт слов, оглавление, проверка синтаксиса Markdown,
поиск пустых описаний изображений, точная замена известного термина,
формирование таблицы из готовых ячеек. Эти операции остаются обычным кодом.

## Подтверждённая реализация функций и уточнение Jina

После первого этапа пользователь потребовал реализовать функции и использовать
системную грамматику, затем уточнил Jina для поиска и скачивания страниц с
возможностью своего endpoint — адреса API. Эти уточнения заменяют прежнее
предложение использовать встроенный веб-поиск модели. Следующий код подготовлен,
но сборка и приёмка на macOS не подтверждены.

### Что подключено

- `AIFeature` и `AIFeatureSettingsView`: 22 отдельных сценария, по умолчанию
  выключены; общий выключатель фона не заменяет отдельные. Нативные орфография
  и грамматика имеют два дополнительных переключателя и не требуют модели.
- `EditorTextView` и `EditorCoordinator`: параметры NSTextView без автоматической
  замены слов; изменения параметров откладываются до завершения системного ввода.
  Реальные языки, подчёркивание и работа grammar-only определяются macOS.
- `AIWritingService`: ясность, переписывание, сокращение, расширение, перевод,
  термины, тон, структура, резюме, противоречия, метаданные, поручения, извлечение
  решений, таблицы и аудитория. Вопрос к профилю Decisions — отдельный сценарий:
  вероятность не подменяет извлечение решений или доказательство истинности.
- `AIWritingController` и `AIWritingView`: панель вместо чата, оригинал и правка,
  принятие/отклонение, существующая отмена, дата и версия результата. Снимок берётся
  из актуального редактора; изменение текста и настроек отменяет старую работу.
  Термины/противоречия содержат два однозначных перехода UTF-16. Ручное резюме
  вставляется отдельно; отмена фоновой работы не делает её отчёт ручным.
- `AICompletionController` и `LacTextView`: серое продолжение, Tab/Esc, отмена при
  вводе, выделении и композиции. Контекст и ключ читаются после паузы, а не при
  каждом нажатии. Перед показом и принятием сверяются профиль и ключ. Уже
  существующий большой профиль отключает фоновые AI-операции; новые пороги не
  вводились. Ручные операции остаются явными командами.
- Иллюстрации показываются до сохранения/вставки; фактический MIME определяет
  расширение и data URI. Вставка после выделения не удаляет его текст. Описание
  изображения получает реальные данные выбранного файла, нужен совместимый
  протокол и модель с поддержкой изображений.
- Метаданные хранятся в текущем `EditorDocument.aiMetadata`, редактируются в
  панели и могут генерироваться отдельной задачей после сохранения при включённом
  фоне. Сессия и пользовательские файлы ради их хранения не менялись.
- `DocumentProvenance`: локальные диапазоны набранного, вставленного и созданного
  встроенной моделью текста. Неизвестное, отмена и внешняя замена не угадываются.
  Учитываются только события после включения; после перезапуска запись не
  сохраняется. Это не детектор AI и не доказательство авторства.

### Поиск и чтение Jina

- `JinaConfiguration`, `JinaSettingsView`, `JinaClient`: отдельные выключатели
  поиска и Reader, полные адреса API, ключи Связки ключей по адресу/виду сервиса.
  Пользователь может задать свои серверы. Переключение раздела очищает черновики.
- Search: POST `https://s.jina.ai/search`, JSON `{"q":"..."}`. Reader:
  POST `https://r.jina.ai/`, JSON `{"url":"..."}`. Оба запрашивают JSON, ключ
  необязателен в клиенте для совместимого своего сервера; hosted Search может
  потребовать его. Протокол проверен по [официальной документации](https://docs.jina.ai/).
- С выключенным Reader возвращаются только ссылки-кандидаты, текстовая модель
  не требуется. С включённым Reader страницы читаются через Jina и передаются
  настроенной модели как данные. Проверяются исходная цитата документа, индекс
  страницы и наличие цитаты в полученном тексте. Само по себе совпадение цитаты
  не подтверждает смысловое следование вывода модели.
- Ошибка одной страницы не мешает чтению остальных. Если ни одна не прочитана,
  остаются явно неподтверждённые кандидаты; отмена останавливает операцию.
- Бинарные изображения генератора загружаются напрямую, без пересылки API-ключа;
  Jina Reader применяется к веб-страницам, а не к байтам изображений.

### Ревью и собственная проверка

Три независимых направления GPT-6.1-Terra: панель/жизненный цикл, сервисы/Jina,
автодополнение/системная проверка/происхождение. Исправлены смешение старого
результата с новой командой, замена ручного выбора фоновым, потеря ручного отчёта,
зависание индикатора при сохранении, сохранение устаревшей картинки, принятие
старого профиля/ключа, копирование строки при каждом вводе, отказ всей проверки
при недоступности одной страницы, черновик ключа на скрытой странице настроек,
неоднозначные ссылки на цитаты и смешение происхождения фонового резюме после
отмены. Повторные адресные ревью новых изменений завершились без подтверждённых
ошибок и предупреждений.

Основной агент прочитал итоговые пути и проверил `git diff --check`, 537
одинаковых уникальных ключей переводов и форматные параметры, подключение десяти
новых исходников в Xcode, уникальность 239 объектов проекта, зависимости прямых
`swiftc`-проверок от DocumentProvenance. Наборы AI/Jina/системной проверки содержат
38 тестов; ни один из них здесь не запускался.

Выполнен реальный анонимный POST Jina Reader для `https://example.com`: HTTP 200,
присутствуют `data.url` и непустой `data.content`. Проверка касается транспорта и
формата Reader, а не запуска Swift-клиента. Реальные Jina Search, модели, качество
на русском/китайском/английском, системная грамматика, ввод, undo и отрисовка на
Mac не проверены. Linux не предоставляет Swift/AppKit/XCTest. Перед использованием
нужны сборки SPM/Xcode, тесты и функциональная приёмка на Mac; численные критерии
качества моделей из первоначального бэклога не измерены и не объявлены выполненными.

Личный словарь стиля после P2 остаётся будущим расширением, как и в исходном
бэклоге. Учёт происхождения и метаданные не являются долговременной историей;
её сохранение потребовало бы отдельного изменения формата хранения.

Для указанных пользователем локальных серверов Info.plist объявляет
NSAllowsLocalNetworking и трёхъязычное NSLocalNetworkUsageDescription через
InfoPlist.strings. Общие ограничения сетевых соединений не отключались:
NSAllowsArbitraryLoads включён для указанных пользователем HTTP AI/Jina-серверов;
локальный доступ и системный запрос необходимо проверить в приложении на Mac.
Основание: [ATS локальной сети](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking)
и [описание разрешения сети](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy).
