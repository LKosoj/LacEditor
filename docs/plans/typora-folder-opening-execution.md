# 19/25.6: открытие папки из Finder и родительская папка файла

Предварительный план files_execution (GPT-6.1-Terra): использовать один существующий путь WindowManager.openFilesFromFinder и ту же очередь ранних Finder URL. Реальный каталог передать в folderWorkspace.setRoot активного состояния после регистрации окна; файл — в прежний identity/openFile путь. Новая модель окон или обработчик запуска не нужны. Официальное описание открытия папки и автоматического родителя: https://support.typora.io/File-Management/.

Точные правила этого шага:

1. Очередь до регистрации окна и обычное событие используют одну функцию маршрутизации; отфильтрованные ранее внешние URL не возвращаются. Каталог не читается как текстовый документ и не создаёт ложный opening/failed документ.
2. Явное открытие папки заменяет рабочую папку активного состояния, как существующий пункт «Открыть папку». Документы и несохранённый текст не заменяются. Последовательность URL обрабатывается в прежнем порядке; при нескольких явных папках последняя становится активной рабочей папкой.
3. Для нового открываемого файла после выбора целевого AppState задаётся его родитель, только если root ещё отсутствует. Явный или восстановленный root не перезаписывается. Уже открытый файл, в том числе через alias/hardlink, активируется прежним identity-путём без изменения папки.
4. Политика каталогов/символических ссылок, загрузки и ошибок остаётся у FolderWorkspaceStore. Ни сохранение файла, ни создание каталога не выполняются. Finder/open -a используют существующие события AppDelegate.

XCTest: раннее событие до окна, каталог не становится документом, очередь каталог→файл, сохранение несохранённого текста и существующей папки, активация уже открытого файла. Существующие Swift-тесты, Finder, open -a, системные вкладки, ошибки доступа и реальные символические ссылки на Mac требуют выполнения после доступа к машине. CLI-параметры, закреплённые/недавние папки и настройки запуска остаются следующими обязательными частями 25.6.
