[Типора: HTML](https://support.typora.io/HTML/) описывает встроенное оформление, отдельные HTML-блоки, audio/video и iframe; [медиа](https://support.typora.io/Media/) также описывает пути относительно документа и перетаскивание видео. Скрипты и обработчики событий у обычного HTML отключены; iframe в Typora изолирован. Всё это остаётся обязательным объёмом 15, включая источник, печать/экспорт и доступность. Никаких CSS-тем, замены TextKit на веб-редактор или нового движка.

## Первый сквозной образец: локальный audio

Выбор: `AVPlayerView` (системный элемент macOS с кнопками воспроизведения) поверх существующего TextKit, а не WKWebView для целого документа. Он даёт настоящее управление звуком и использует системный AVKit; новая внешняя библиотека и собственный проигрыватель не нужны. Позиция и видимость относятся к одному подтверждённому блоку. Для HTML, которому нужны вложенные элементы, и iframe впоследствии потребуется отдельное сравнение безопасной обработки и изолированного WKWebView; этот выбор не исключает их.

1. Подготовительная независимая часть в новом `Services/MarkdownHTMLMediaService.swift` и `LacEditorTests/MarkdownHTMLMediaServiceTests.swift`: чистый разбор **одного** переданного cmark-подтверждённого `html_block`, без второго общего разбора документа и без поиска HTML регулярным выражением по всему файлу. На первом шаге принимать только отдельную строку `<audio src="relative-or-file-url" />` с одной заключённой в кавычки `src` и XML-совместимым экранированием, без других атрибутов/вложенных узлов; поддержать одинарные и двойные кавычки и пробелы. Foundation XMLParser может проверять именно эту ограниченную форму, с запретом внешних сущностей; не считать его полноценным HTML-парсером. Пути и `src` возвращать данными, не исполнять HTML. Обычные HTML-варианты, атрибуты `controls`, `preload`, `source`, entity HTML и multi-line остаются следующим обязательным этапом, не молча нормализуются в исходнике.
2. После передачи `Preview/MarkdownPresentationParser.swift`/`Models/MarkdownPresentation.swift` общий cmark один раз возвращает `MarkdownAudioBlock` только для `html_block` на верхнем уровне, чья точная raw UTF-16 вырезка подтверждена Source и чистым разбором; cmark `code`, fenced/indented code и escaped `<` исключены. На точной версии swift-cmark 0.8.0 локальный C-пробник подтвердил, что `<audio src="song.mp3" />` — `html_block`, а в backticks — `code`; в quote это вложенный `html_block`, пока остаётся исходником. Таблицы, quote/list и неоднозначные табы — следующие обязательные случаи; не угадывать положение или использовать байтовую колонку как UTF-16.
3. `MarkdownPresentationController` создаёт `AVPlayer`/`AVPlayerView` только для видимого подтверждённого блока и только если исходник скрыт выбранным представлением; разрешает обычные относительные и `file:` URL относительно текущего документа, не читает произвольный HTTP в этом первом срезе. Синхронизировать с изменением URL документа и приложенным снимком: объект/ID документа, версия редактора, поколение, точный диапазон и `src`, текущая область и отмена. Неподтверждённый или недоступный URL оставляет исходник видимым; уведомления об ошибке и удалённые источники — отдельные обязательные шаги, а не вечный отказ.
4. `FoldLayoutManager` резервирует фиксируемую по реальному frame системного элемента высоту одной видимой строки блока и скрывает только его глифы; остальные строки блока сводятся без удаления исходника. Использовать существующую проверку сворачивания и выделения, без полного layout документа. Добавить player как subview текущего `LacTextView`, перемещать при прокрутке/resize и удалять/останавливать при потере актуальности, закрытии, деактивации, source mode и уходе из viewport. Изменение показа не меняет строку, dirty, выделение или undo. Выделение внутри исходного диапазона и доступное действие «редактировать исходник» скрывают player и возвращают обычный текст; клик по кнопкам player не перехватывать редактором. При marked text в parent или активной дочерней ячейке отложить установку/снятие разметки до завершения композиции. Файлы parser/model/controller/layout сейчас принадлежат 11/12: подключение последовательно после handoff, а не параллельная правка.
5. `LacTextView`/`EditorCoordinator`: только при необходимости узкий callback существующего reveal, без нового окна и новой навигационной системы; перед редактированием проверить текущие документ, диапазон и версию. Новых пользовательских настроек и локализаций не вводить на чистом шаге; название действия доступности передать основному агенту для трёх локализаций. Основной агент обновляет Xcode/SPM и прямые `swiftc`, включая системный AVKit, если он требуется в конкретном пути.

XCTest: чистый разбор одиночных/двойных кавычек и Unicode-URL, entity, неверного/дополнительного атрибута, скрипта и незакрытого тега; cmark/source tests для emoji/CRLF, настоящего html_block, fenced/inline code, quote/list и соседнего Markdown; контролируемые URL/revision/document/viewport/selection/marked/очистка, source/undo и прекращение player. В интеграционном XCTest использовать короткий локальный звуковой fixture и настоящий player с управлением без обязательного воспроизведения звука; на Mac отдельно проверить аудиовыход, остановку, сворачивание, VoiceOver, вставку и большие документы. Не объявлять звук работающим по одному появлению subview. Данные пользователя не менять.

## Выполненный первый аудиообразец

`MarkdownHTMLMediaService` разбирает ограниченную самостоятельную форму, общий parser добавляет точные диапазоны в `MarkdownPresentation.audioBlocks`. Контроллер проверяет воспроизводимость локального файла через AVFoundation, показывает системный `AVPlayerView` только в видимой области, без автоматического старта; недоступная форма остаётся исходником. Путь проверяется как `file:` относительно документа. Генерация, версия, URL, видимость и незавершённый ввод проверяются после фонового ожидания; отменённый результат не устанавливается. Выделение раскрывает исходник, действие доступности переводит к нему. Удаление, деактивация и смена документа останавливают player и освобождают его.

Независимое ревью выявило нормализацию tab в XML-атрибуте, смещение player после изменения высоты блоков выше и видимый player поверх свёрнутого текста. Исправлены отказ буквальному tab в значении (числовая XML-ссылка сохраняется), обновление frame после изменения геометрии и уведомление общего пути сворачивания. Адресное повторное чтение без новых конкретных ошибок. `MarkdownHTMLMediaServiceTests` и `MarkdownAudioInteractionTests` подготовлены: Unicode/CRLF и код, отрицательные формы, настоящий локальный WAV без воспроизведения, source reveal, фактический frame после смены метрик, fold/unfold и деактивация установленного player. Эти Swift-тесты здесь не запускались; они не доказывают звук или VoiceOver.

### Подтверждённый iframe в редакторе — до кода

`MarkdownHTMLMediaService.iframe(in:)` разбирает только целый cmark `html_block` и возвращает URL http/https, размеры и проверенные атрибуты; сомнительная форма остаётся исходником. Общий parser сохраняет отдельную модель с исходным UTF-16 диапазоном. Внешние документы и редактор в WebKit не переносятся.

Для видимого верхнеуровневого блока Controller создаёт отдельный `WKWebView` с непостоянным хранилищем и локальной оболочкой: внешний документ разрешает только iframe по http/https, сам iframe использует sandbox существующего `iframeHTML` без same-origin и top-navigation. Новые окна и верхняя навигация запрещены; локальные файлы не загружаются. Значения width/height в пикселях применяются напрямую, проценты — к доступной ширине и высоте viewport, по умолчанию 560×315; высота процента не зависит от высоты самого iframe. Оформление разрешается только текущему документу/версии вне marked text; при изменении viewport, сворачивании, выделении, source view и закрытии view переставляется или уничтожается. Доступное действие раскрывает исходник. Тесты проверяют cmark source/UTF-16, размеры, изоляцию, callback/reveal/fold/смену документа и исходник; сеть, провайдеры, настоящий WebKit/VoiceOver и AppKit/XCTest на Mac ещё предстоит проверить.

Этот ограниченный путь реализован и независимо прочитан. Общий HTML-контекст исключает iframe и audio внутри script; повторное размещение добавляет view, если при первой разметке у него ещё не было прямоугольника. Подготовлен interaction-тест с loopback-адресом, изменением ширины, раскрытием исходника, сворачиванием и деактивацией. Он и реальная изоляция WebKit на Mac не запускались. Вложенные блоки и остальные формы HTML и media остаются частью 15.

Для подтверждённого cmark `html_inline` использовать существующий SwiftSoup-разбор атрибутов ссылки и общий контекст HTML. Разрешать только согласованную пару `<a ...>...</a>` внутри одного родителя; сохранять проверенный `href` и `title` с экранированием, оформление удалять. Остальные атрибуты и неподтверждённые пары остаются пропуском с предупреждением. Маркеры исходника и обычный preview не изменять. XCTest: адрес с entity, Unicode и вложенным оформлением, закрытие/неверная вложенность и скриптовый адрес; WebKit/XCTest на Mac остаются отдельной проверкой.

### Общий audio/video путь — до кода

Один подтверждённый cmark `html_block` разбирается SwiftSoup как HTML5, сохраняя точный диапазон cmark; возвращаются вид audio/video, `src` либо последовательные дочерние `source src`, наличие controls и размеры video. `src` самого элемента имеет приоритет над дочерними источниками. Включая многострочные теги, HTML entities, кавычки и регистр, не выполнять события или autoplay; при неподтверждённых структуре и атрибутах исходник остаётся видимым. Воспроизводимость источников проверяется последовательно AVFoundation, без автоматического старта. Относительные/file разрешаются относительно документа; HTTP(S) через существующий AVPlayer, без других схем. Контроллер использует тот же видимый AVPlayerView, актуальность документа/revision, отмену, fold/reveal и marked text; video резервирует высоту и следует допустимым размерам, кнопки соответствуют controls. Добавить XCTest разбора и реального editor lifecycle, выбора источника, remote URL без реального сетевого обращения, Unicode/CRLF, code/script, изменения/закрытия и source/undo. Многоуровневые quote/list, drag и другие произвольные HTML структуры остаются дальнейшими этапами 15; физическое воспроизведение и сетевые сервисы проверять на Mac отдельно.

Использовать точку drop, текущий документ и обычный цикл `shouldChangeText`/`didChangeText` с одной undo-группой, без чтения или копирования видео. Для read-only/marked text и недоступного типа сохранить системную обработку drag; для активной таблицы не угадывать структуру. XCTest: Unicode, пробелы/#/кавычки, адрес относительно файла и без него, начало/середина/конец текста, UTF-16, фактический цикл drop и один undo, read-only/marked; настоящие Finder drag и воспроизведение остаются проверкой Mac. ### Единый `typora-root-url` — план до реализации

[Typora Images](https://support.typora.io/Images/) определяет YAML `typora-root-url` как локальный корень для `src`, начинающегося с `/`; документированный `/blog/img/test.png` при корне `/User/Abner/Website/typora.io/` указывает внутрь этого корня. [Typora Media](https://support.typora.io/Media/) распространяет правило на video; выпуск [0.9.58](https://support.typora.io/What%27s-New-0.9.58/) упоминает `${filename}`. URL без схемы и без начального `/` остаётся относительно папки Markdown; `file:` остаётся явным абсолютным файлом; `http:`/`https:` и `data:` сохраняют прежние пути. При отсутствии свойства абсолютный `/...` остаётся системным абсолютным путём, как сейчас. Для значения YAML использовать существующий Yams YAML 1.2 и scalar literal, отсутствие отличается от ошибочного типа/значения; относительное значение корня разрешать от папки сохранённого документа, `${filename}` — существующим правилом полного имени файла. Без документа относительный корень не угадывать. Пустое значение и неподдерживаемая схема требуют явного результата ошибки для пользовательской операции и неизменного исходника; точная обратная совместимость сохраняется при отсутствии metadata.

1. Один небольшой `MarkdownResourcePaths` (значение снимка: document URL + разрешённый root) с двумя операциями: разрешить ресурс и получить существующий адрес при вставке; использовать общий YAML helper, не новый parser или Process. Только `src` изображений и audio/video: обычные ссылки, iframe и назначения записи не переопределять. Root-relative ресурс разбирать как URL, чтобы `%23` отличался от `#fragment`, `?query` не входил в имя файла; `file:` не переинтерпретировать. Никаких записей файлов при разрешении путей. При вставке существующее относительное правило сохраняется: оно корректно указывает файл независимо от корня; отдельная опция выбора root-relative синтаксиса не вводится без согласования.
2. Снимок брать из актуального синхронизированного текста вместе с revision. В нативном parser вычислять один root на общую фоновую операцию и передать с `MarkdownPresentation`; controller использует его для всех `imageData` и AVPlayer источников, проверяя revision/document/url и отмену. Изменение YAML снимает устаревшие изображения/player как обычная правка. Не читать и разбирать YAML при каждой картинке или скролле. Вставка и video drag берут тот же текущий snapshot перед одной undo-заменой; copy-images-to по-прежнему задаёт папку записи, а результат превращается в адрес единым helper.
3. Upload `payload` и rich clipboard projection получают тот же root вместе с документным снимком, сохраняя порядок, отмену и прежние stale checks. Проверить data URI, HTTP и настоящий локальный файл; исходный `src` заменяется только после успешной пользовательской операции. Plain Copy HTML оставляет исходный URL. Явные ошибочные metadata не превращать в незаметный выбор системного `/`.
4. Preview и native PDF/PNG создают временное представление ресурсов из подтверждённых cmark src и общего helper до WebKit; доступ к локальным данным применять существующим механизмом snapshot/проверки, не переписывать исходник. HTML без оформления должен сохранять исходные адреса (как текущий контракт), а не сохранять временные data URI локальных файлов; экспорт PDF/PNG проверять настоящим изображением/пикселями. Pandoc writers, которым нужны bytes (DOCX/EPUB и др.), получают только во временном AST/snapshot подтверждённые локальные адреса, без изменения оригинала и без переназначения пользовательского `--resource-path`; ссылки и HTML output остаются исходными там, где ресурс не встраивается. Нужны отдельные проверки встроенного Pandoc 3.13 и WebKit на Mac: нынешний WebKit стартует с baseURL=nil, а простой `<base>` для root не соответствует относительным src.
5. Tests: quoted/block YAML, aliases, `${filename}`, отсутствие/невалидный тип/несохранённый документ; документ и root в разных каталогах, `/`, обычный relative, `../`, file/http/data, UTF-16 и имя с `%23`, `#` и `?`; один файл отличим от другого с похожим именем. Проверять отдельно native image/video, upload и rich copy, вставку/копирование, смену root во время работы, HTML, PDF/PNG пиксели и DOCX/EPUB bytes. Результаты настоящего Mac/WebKit/AVFoundation/Pandoc/XCTest отдельно, без сетевых сервисов на host. Конкретный UI `Use Image Root Path` и запись YAML должны использовать существующий YAML путь с одной undo, сохранять остальные поля/комментарии и рассматриваться отдельным следующем шагом без угадывания перезаписи.

### Запись `typora-root-url` через существующий YAML CST — до кода

Для команды выбора папки использовать уже поставляемые SwiftTreeSitter/TreeSitterYAML: парсить только подтверждённый front matter, находить верхнеуровневую пару по key/value и переводить byteRange UTF-16 в NSRange. Для обычных quoted/plain, alias и block scalar менять только значение; у `&anchor` сохранить anchor и заменить непосредственно scalar, поэтому связанные aliases естественно получают новое значение, как при ручной правке. Если значение само alias — заменить только его, оставив anchor/другие поля. Отсутствующий ключ добавить в block/flow mapping; при отсутствии front matter добавить новый в начало, не изменяя существующий текст. До применения повторно проверить Yams-разбор, ожидаемый root и точный исходный диапазон; комментарии и прочие участки остаются побайтно вне замены. Неподтверждённая или ошибочная грамматика даёт явный отказ. Команда использует существующий NSOpenPanel и editor replacement/одну undo, snapshot/selection/revision и marked guards; тестировать quoted, flow, block scalar/chomping, anchors/aliases, comments, CRLF, Unicode и undo. Проверка Tree-sitter/Yams/AppKit на Mac обязательна.

### Содержимое textarea при встраивании HTML — до кода

Pandoc 3.13 обрабатывает атрибуты src при создании самостоятельного HTML, включая текст внутри textarea. Для стандартного и профильного HTML с встраиванием общий cmark/HTML context подтверждает границы textarea; только содержимое заменяется временным уникальным маркером. После Pandoc каждый маркер должен встретиться ровно один раз и заменяется исходным текстом до установки файла; неоднозначный диапазон или потерянный маркер дают ошибку. Проверить доступный временный PNG внутри textarea, отсутствие root-url, несколько блоков, Unicode, сущности и разбиение между узлами; исходный документ не менять. Реальный bundled Pandoc и XCTest на Mac ещё не запускались.

### Root URL для media в Pandoc — до кода

Для audio/video и дочерних source общий cmark/HTML context подтверждает диапазоны атрибутов в исходном снимке. В смешанном HTML block временные уникальные атрибуты сопоставляют эти диапазоны с узлами SwiftSoup; не использовать неактивные template и source, когда у родительского элемента уже есть src. Менять только адреса с ведущим `/` и только во временном снимке, перепроверить результаты тем же путём, исходник не менять. Использовать снимок в стандартном и профильном HTML с встраиванием и в PDF-engine; относительные, сетевые и явные file адреса не зависят от YAML root. Проверки: standalone и вложенные media, порядок источников, HTML entities, script/textarea/template, ошибочный YAML и пути с кодированием, query и fragment; сквозная проверка embedded bytes на встроенном Pandoc. Inline-разметка, разделённая между отдельными cmark nodes, остаётся отдельной обязательной границей.

### Медиа внутри цитаты и списка

Native parser подтверждает каждую строку cmark HTML block по исходному literal и существующей проверке prefix предков; для HTMLContext prefix заменяются пробелами только во временной копии с теми же UTF-8/UTF-16 координатами. Audio/video/iframe разбираются из cmark literal, отступ списка учитывается в общей геометрии; split script/template исключаются. Неподтверждённые позиции с tab остаются исходником. Подготовлены tests Unicode/CRLF, многострочных атрибутов, script/template и локального WAV с reveal. AVFoundation, WebKit, marked text и фактическая геометрия на Mac ещё не проверены; произвольная вложенная HTML-разметка остаётся отдельным объёмом 15.

При активном script многострочный промежуток через quote/list подтверждается тем же traversal: literal TEXT ranges должны идти по порядку и покрывать каждую непробельную единицу, а ASCII prefix каждой строки — соответствовать предкам. Только эти prefix маскируются в снимке HTMLContext; неподтверждённый остаток, включая неразобранное reference definition, консервативно запрещает дальнейшее подтверждение HTML без изменения source. Обычные inline пары strong/b/em/i/u/s/del/mark/sub/sup используют общий cmark helper с точным source proof и проверкой вложенности для native presentation, rich copy и Renderer, включая пары в Markdown heading/link/strong/emph. Теги с атрибутами и неоднозначная вложенность остаются исходником; tests добавлены, AppKit/IME/XCTest на Mac не запускались.

### Вложенное media — исследование перед следующим этапом

Одиночные audio/video/iframe и блоки в quote/list уже проходят существующие `MarkdownAudioBlock`/`MarkdownIframeBlock`, но элемент между текстом либо внутри общего `<div>` пока не создаёт native player. Локальная проверка pinned cmark показывает, что в `before <video controls><source src="a.mp4">fallback **bold**</video> after` открывающий тег, source и закрывающий тег — отдельные HTML inline nodes, а fallback и Markdown strong — отдельные siblings. Существующий export `mediaSources` проверяет отдельные src, но не возвращает весь диапазон парного элемента. Текущий `markdownMediaRect` позиционирует системный элемент от начала строки и не подходит для соседнего inline текста.

Согласованный путь: из того же cmark traversal и HTMLContext подтвердить начало/конец элемента и все src/source, включая порядок и приоритет родительского src; двумя уникальными markers доказать фактический элемент и его границы в безопасном DOM. У iframe fallback — raw text: marker закрытия должен находиться после тега, а не внутри текста. Исходный диапазон оставлять точным UTF-16 и не менять документ; при неопределённости оставлять исходник. Для native inline использовать существующую геометрию control glyph, а не block-rect начала строки, и прежние AVPlayerView/изолированный WKWebView с проверками revision, URL, viewport, fold/reveal и marked text обеих областей. Preview/PDF нуждаются в отдельном включении уже существующего безопасного HTML media path без ослабления CSP. Проверить смешанный текст до/после, nested/split, несколько source, приоритет src, iframe fallback, отмену и фактическую геометрию на Mac.

Первый согласованный срез реализован для одного cmark parent и доказанного nested HTML block: общий inert DOM proof использует два comments, source сравнивается по UTF-8, iframe fallback и допустимые атрибуты сверяются; при подтверждённом media пересекающиеся image/math/emoji glyph не устанавливаются. Inline системный player использует существующий control glyph и его rect, а block путь сохраняется. Подготовлены tests соседнего текста, локального WAV/play/reveal/resize, iframe/reveal/vertical/zoom/child marked, missing file и управляемой поздней отмены; AppKit, AVFoundation, WebKit и XCTest на Mac ещё не запускались. Across-parent, остальные формы nested media и общий safe media preview/PDF остаются открытыми.

Для preview/PDF согласован следующий срез: использовать подтверждённые media того же cmark дерева и общий DOM proof, сохранить окружающий текст и не показывать fallback image отдельно от активного video. HTTP(S) audio/video загружает WebKit, локальные пути разрешаются через существующий `MarkdownResourcePaths`, а bytes передаются как data URI с системным MIME; порядок `source` и fragment сохраняются. В CSP добавляются только `media-src data: http: https:` и `frame-src http: https:`; iframe остаётся в прежнем sandbox, удалённые script и style не включаются. PDF/PNG получают штатное неподвижное состояние WebKit без обещания воспроизведения. Полное чтение локального видео и base64 увеличивают расход памяти; лимиты не вводятся. Нужны проверки отмены и актуальности, локального media, fallback и статического вывода, а также воспроизведения и sandbox на Mac.

Этот срез подготовлен и независимо статически просмотрен: подтверждённые standalone и paired audio/video/iframe выводятся с окружающим текстом, nested blocks объединяют media, image и named-anchor markers; неподтверждённые источники в этих путях не активируются. Preview сначала показывает страницу, затем готовит локальные файлы в прежней задаче; PDF/PNG ожидают данные. Подготовлены XCTest локального WAV и смены revision, статического PDF с контрольным документом, iframe, fallback и скрытого media. Тесты не запускались на Mac: фактическое воспроизведение, autoplay policy, вид системных controls в PDF и изоляция iframe остаются проверкой. Paired HTML с границами в разных cmark parent и другие неподтверждённые nested случаи остаются открытыми.

Вложенные audio/video с одним cmark parent собираются последовательным стеком и проходят прежнюю проверку DOM: отображается только внешняя подтверждённая пара, вложенный fallback отдельно не показывается. Для целого HTML block признак block определяется по подтверждённому literal без quote/list prefixes; старый standalone path и новый результат не дублируются. Подготовлены fixtures block/inline/quote/list, исходника, некорректного вложения и script/template. Pinned cmark и Chrome подтвердили отдельный случай пересечения с Markdown strong: браузер меняет границы media, поэтому он остаётся исходником. Остальные формы с разными parent ещё требуют отдельной проверки; XCTest и геометрия на Mac не запускались.

Подтверждённые пары внутри Markdown strong/emphasis/strikethrough и link используют тот же DOM proof и прежнюю inline-геометрию. Подготовлены проверки сохранения оформления и одного anchor в preview, маршрута обычного и Cmd-click к AVPlayerView и соседним ссылкам, linked iframe при marked text/reveal/vertical/zoom и отказа позднего audio после смены revision. Само нажатие конкретной системной кнопки и реальное воспроизведение при этих действиях ещё требуют проверки на Mac; попадание события в overlay само по себе этого не доказывает.

Документированные пустые `<div style="page-break-after:always"></div>` и `<div style="page-break-after: always; break-after: page;"></div>` проходят проверку source, HTMLContext и итогового DOM и выводятся с фиксированным безопасным правилом разрыва. Подготовлены XCTest обеих форм, отказа неподтверждённых тегов, PDF с контрольным документом и PNG без разрыва; Linux Chrome подтвердил две страницы. Фактические Swift/WebKit/PDFKit/XCTest на Mac и отдельная нативная метка остаются проверкой.

Для многострочных HTML comments подготовлены проверки видимой исходной строки в редакторе и невидимости в DOM, PDF и печати; literal comment внутри code fence должен оставаться текстом. Отдельные fixtures проверяют script/template и незакрытый comment, соседние Unicode и неизменность source. Linux cmark и Chrome подтвердили отсутствие текста comment в PDF; AppKit/WebKit/PDFKit/XCTest на Mac пока не запускались. Изменение production code в этом проверочном срезе не потребовалось по статическому чтению.

По [документации Typora](https://support.typora.io/HTML/) исходные `id`, `class`, `data-*`, script/style/meta могут сохраняться при экспорте, хотя не применяются при редактировании. Текущий встроенный HTML plain использует безопасный exporter и отбрасывает script/style/template и большинство этих атрибутов; styled preview/PDF также используют ограниченный безопасный вывод. Это различие остаётся открытым требованием совместимости, а не разрешением выполнять script в предпросмотре. Документированный `display:none` должен показывать содержимое при редактировании и скрывать его после экспорта; текущий source fallback этого ещё не реализует.
