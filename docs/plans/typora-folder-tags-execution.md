# 20: поиск по YAML-тегам

Предварительный план подготовлен агентом файловых задач GPT-6.1-Terra до реализации. Полный поиск по имени/содержимому уже существует; этот шаг добавляет третий предусмотренный вид поиска, без постоянного индекса и нового YAML-парсера.

1. `Resources/Pandoc/tags-reader.lua` получает один JSON-пакет снимков с уникальными ID. Встроенный `pandoc.read(..., 'gfm+yaml_metadata_block')` читает только подтверждённый front matter. Пользовательские значения не становятся кодом. Отдельный некорректный документ возвращает ошибку своего ID; остальные не теряются. Результат — Pandoc AST с метаданными, выводимый штатным JSON writer.
2. `MarkdownTagReader.swift` принимает снимки с ID, вызывает один существующий фиксированный путь Process через `ClipboardMarkdownConversionService`, сверяет уникальность/полноту ID и типы ответа. Только скаляр и список текстовых тегов; сравнение целого тега, без разбиения по запятым. Ошибка YAML и неподдерживаемое значение не выдаются за отсутствие тегов. Сначала проверить контракт Lua на доступном Pandoc 3.1.3; это не заменяет встроенный 3.13 на Mac.
3. `FolderSearchService` переиспользует обход, идентичность и актуальные снимки открытых документов. Отбирает Markdown с подтверждёнными границами front matter, собирает один пакет, сохраняет версии и исходники для проверки результатов. Не запускать Pandoc для каждого файла. `FolderSearchController` и существующая панель получают режим тегов; запрос явный, актуальность/отмена и открытие проходят существующие пути. Не угадывать диапазон YAML по случайному совпадению слова.
4. Swift/XCTest: scalar/list/block, кавычки и Unicode, пустые/ошибочные/вложенные значения, один процесс на пакет, отмена/очистка, dirty-снимки, aliases и изменение файла перед открытием. Нужны отдельные проверки встроенным Pandoc, настоящего интерфейса и большой папки на Mac.

Доступные системные средства: [пользовательский Reader Pandoc](https://pandoc.org/custom-readers.html), [Lua API](https://pandoc.org/lua-filters.html#module-pandoc.json). Это конкретное преобразование тегов, а не общий запуск произвольных пользовательских фильтров.

## Подготовленная реализация

Подключены `MarkdownTagReader`, фиксированный JSON-проход существующего Process helper, `SearchKind.tags`, третий вариант панели и проверяемый переход к началу front matter. `Input.frontMatter` явно отделён от полного текста, общий обход передаёт только этот диапазон. Подготовлены XCTest для одного процесса, строгих ID, per-document ошибок, отмены/очистки, точного тега, dirty/hardlink, изменения файла и текущего снимка контроллера. Независимое статическое чтение без новых конкретных замечаний. Проба app-owned Lua на системном Pandoc 3.1.3 успешна для scalar/list/ошибок; встроенный macOS Pandoc 3.13 и XCTest не запускались. Данные block scalar преобразуются в текст метаданных Pandoc (переносы могут стать пробелами); это не обещание дословного YAML-значения.
