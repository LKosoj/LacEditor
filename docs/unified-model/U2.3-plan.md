# U2.3 — ядро разбора: Preview/MarkdownDocumentParser.swift

Статус: план (код не менялся). Номера строк — по рабочей копии на 05.11.2026
(парсер 3588 строк, рендер 2497, `MarkdownHTMLMediaService` 2405,
`MarkdownImageUploadService` 1903). Строки, помеченные «~», получены обзором
и перед правкой перепроверяются через `rg`.

Имя типа позиций везде новое: `MarkdownSourcePositions` (U2.1; раньше
`MarkdownPresentationParser.Source`).

## 0. Что делаем простыми словами

Сейчас Markdown разбирается дважды разными кодами: парсер редактора
(`MarkdownPresentationParser.parse`) и рендер предпросмотра
(`MarkdownRenderer.renderBody`). Они местами по-разному решают, что считать
медиа, SVG, ruby и т. д. U2.3 строит одно ядро: один проход cmark (библиотека
разбора Markdown) по тексту с замаскированными участками → дерево узлов
`MarkdownDocumentModel`. При расхождении берём правило рендера (решение 1 общего
плана): то, что видит читатель, важнее подсветки в редакторе.

Не входит: блоки кода (U2.4), доп. данные редактора — elementIndex, editorContext,
readableText, fence-контекст (U2.5), инвариант U2.6. Здесь только точки
подключения (пустые вызовы с понятной сигнатурой).

## 5. Отмена и производительность

- `isCancelled` проверяется в начале каждого `visit`, в циклах по строкам и в тяжёлых
  местах (SwiftSoup-подтверждение). Отмена возвращает `nil`, а не частичную модель.
- При выключенном `Includes.*` соответствующая работа не выполняется вовсе
  (wikiLinks, noteEmbeds, criticMarkup, emoji — не ищутся; uppercaseRuns,
  readableText, elementIndex, blockIndex, editorContext — не вызываются), поля
  модели остаются `nil`/пустыми. Включение флага не меняет остальные узлы.
- Подтверждение HTML выполняется только если в тексте есть `<` (быстрая проверка
  до SwiftSoup). Позиции в UTF-16 считаются один раз на узел.

- `Package.swift`/прямые `swiftc` в `Scripts/*.sh`: каталог Preview берётся целиком,
  проверить списки в `Scripts/run-acceptance.sh`, `Scripts/verify-release.sh`.
- Правила в `docs/agents/markdown-editor.md` — обновить после реального переноса.
- Проверки: `swiftc -frontend -parse` на новых файлах; `swiftc -typecheck -swift-version 5`
  там, где есть `#if compiler(>=6.2)`; стенды.

Риски:
1. Литералы cmark (title, alt, тела комментариев) после маскировки содержат
   заменитель `P` — брать текст из исходного по диапазону.
2. Маска сохраняет длину UTF-16, а cmark считает байты UTF-8: нужен перевод через
   `MarkdownSourcePositions`; старая байтовая `maskedFrontMatter` не годится.
3. Рендер и парсер подтверждают HTML разными путями — риск тихого изменения
   редактора; закрываем сравнительным тестом и корпусом U0.
4. Модель на диске не совпадает с U1.1 — нужна сверка перед подзадачей a.
5. `recoverLooseLists` (строка 13) остаётся в старом парсере до U7.3.
6. Большой объём переносимого (≈1500 строк): переносить функциями, прогонять
   корпус после каждого шага.

1. При расхождениях берём правило рендера (решение 1), включая callout и ID заголовков.
2. Таблицы: показ (`Projection`) остаётся в старом файле как адаптер.
3. `elementIndex`/`editorContext` — только в U2.5; в U2.3 лишь точки подключения.

- `Table.Cell.colspan`/`rowspan` заполняются из `cmark_gfm_extensions_get_table_cell_colspan/rowspan` (0 — ячейка-заполнитель).
