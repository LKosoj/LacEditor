# Функции редактора и заметок

Читать при изменении палитры команд, операций над строками, истории версий, окончаний строк, wiki-ссылок, обратных ссылок, тегов, шаблонов, сниппетов, замены в папке, цели письма, сборки рукописи и обновления ссылок.

- Поиск по тегам (YAML и встроенные `#теги`, см. ниже) — третий явный вариант существующего поиска папки. Обход и несохранённые снимки/идентичность общие с текстовым поиском; сейчас выбираются `.md` и `.markdown`. Только подтверждённые front matter разбираются локально через Yams с правилами YAML 1.2, без тела файла и запуска Pandoc. `MarkdownTagReader` возвращает по каждому ID строковые теги или ошибку; строковый скаляр и список строк сопоставляются целым тегом без разбиения по запятым. Числа, логические значения и вложенные структуры тегами не считаются. Незакрытая разметка остаётся Markdown, а ошибка содержимого закрытого YAML показывается отдельно. До открытия проверять прежний YAML-фрагмент и версию, курсор ставить к метаданным без угадывания диапазона слова. Не добавлять индекс или отдельный процесс для каждого файла (полнотекстовый индекс существует только у режима «По словам»).
- Палитра команд `⇧⌘A` (не `⇧⌘P`: он занят «Параметры страницы…») — `CommandPaletteOverlay` (`Views/CommandPalettePanel.swift`), состояние `AppState.commandPalette` (`CommandPaletteController`), логика `CommandPaletteService`. Снимок пунктов `NSApp.mainMenu` берётся при открытии (`menu.update()` на каждом уровне), ранжирование — `FolderSearchService.NameQuery.rank`. `run` закрывает панель, фокус возвращается, и следующим проходом главного потока `performPending` заново находит пункт по пути индексов и проверяет видимость, доступность и название, иначе ничего не делает. Недоступные, скрытые и системные («Службы», «Окно») пункты не показываются; открытие отказывается при marked text и закрывает быстрое открытие (`showQuickOpen()` / `showCommandPalette()` взаимно исключают друг друга). Закреплённые и недавние команды (`AppPreferences.commandPalettePinned`/`commandPaletteRecent`, пути названий меню в `UserDefaults`) общие для окон; запись — путь стабильных ключей `PaletteCommand.key`, а не показанных названий: каждый уровень меню переводится через `L10n.stableKey(forDisplayed:)` (обратный поиск по трём каталогам, ключи с одинаковой тройкой переводов объединяются в канонический — наименьший), поэтому закреплённое переживает смену языка; незнакомый лист без цели или с целью `NSApp.delegate` (системные пункты цепочки ответчиков) получает ключ `sel:<селектор>`, остальное хранится по показанному названию. Старые записи переводятся `CommandPaletteService.migrated` при загрузке настроек, запись, равная показанному пути живой команды, заменяется её ключом в `present` (`upgrading`). Ограничения: названия с переменной частью (имена папок, профилей), неоднозначные переводы и пункты SwiftUI без совпадения в каталогах остаются привязанными к языку; «Показать/Скрыть боковую панель» — разные команды; названия dev/experiment/acceptance-сборок — ключи каталога, поэтому корректны. Недавние — до 5, запись только после фактического запуска в `performPending`; закреплённая в недавние не пишется. При пустом запросе секции «закреплённые → недавние → остальные» без повторов (`CommandPaletteService.entries`), при непустом — обычное ранжирование; `⌥↩` закрепляет выбранную. Индекс не добавлять.
- `LineEditingService` — чистый сервис: границы строк только CR, LF, CRLF (U+2028/U+2029 — содержимое), UTF-16, терминаторы сохраняются (при сортировке остаются на своих позициях), сортировка естественная и устойчивая. Применение: `AppState.editLines` → `EditorCommandNotification.editLines` → `EditorCoordinator.applyLineEditing` — один цикл `shouldChangeText` → замена → `didChangeText`, одна группа отмены; отказ при marked text, недоступном редактировании, нескольких выделениях, активной ячейке таблицы и смене версии/выделения. В оформленном Markdown правки идут в координатах textStorage, строки с суррогатом большого data URI отклоняет `shouldChangeText`. Комментарии: `EditorLanguage.commentSyntax` (`CommentSyntax` в том же файле, чтобы не менять списки swiftc); блочный синтаксис применяется построчно, пустые строки пропускаются, снятие — только если закомментированы все непустые строки. `⌃⇧K` отличается от системного `⌃K`.
- Версия `NSFileVersion` добавляется на `fileWriteQueue` после успешной записи и снимка `FileRevisionSnapshot`; ошибка идёт только в журнал (`fileVersionLog`) и не влияет на результат сохранения, `ioState` и отметку файла. Для `DocumentRecoveryStore` версии не создаются. `VersionHistoryController` + `VersionHistoryView` — лист окна (`versionHistorySheet`, один на `AppState`); результат применяется только при совпадении поколения, URL и `synchronizedSnapshot()`, правка делает его устаревшим (`isStale`), восстановление блокируется до «Обновить». Сравнение переиспользует `AITextComparison.changes(before:after:)`. Восстановление — одна `EditorRangeReplacementRequest` на весь текст (`groupsUndo`), без прямого присваивания модели и записи файла. Сравнение с диском читает файл кодировкой документа с проверкой `FileRevisionSnapshot` до и после; кодировку не угадывать.
- Сравнение текущего текста с другим документом или файлом («Файл → 比较文本…»): `TextCompareController` + `TextCompareView` + `TextCompareSource` (имя, `isUnsaved`, асинхронная загрузка), лист `textCompareSheet`, один на `AppState`, не открывается поверх листа версий или рукописи. Справа всегда живой снимок текущего документа, слева — снимок другого открытого документа (в том числе несохранённого) или файл через `NSOpenPanel`: UTF-8, иначе кодировка документа, без угадывания. Документ с `isLargeFileMode` и файл больше `largeFileByteThreshold` (проверка до чтения) или больше `largeFileLineThreshold` строк отклоняются: `difference(from:)` нельзя прервать. Результат применяется только при совпадении поколения и `synchronizedSnapshot()`, правка делает его устаревшим; закрытие листа, вкладки и `closeAuxiliaryWindows` отменяют работу. Только просмотр, текст не меняется. Строки с разными концами (CRLF и LF) считаются разными. Строки диффа общие с историей версий (`TextDiffRow`, `textDiffSummary`). Левую сторону «диск» можно подать готовым источником через `presentTextCompare(initial:)`: тогда список документов и выбор файла не показываются.
- Окончания строк определяет `LineEndingService` только по CR/LF/CRLF в фоне (`DocumentTaskCoordinator.Kind.lineEndings`) по снимку с проверкой поколения и `textRevision`, пауза 0,5 с; в большом профиле при несинхронизированных правках живой текст не копируется (показывается «…»). `EditorDocument.lineEndings` временное, в сессию не пишется. `AppState.convertLineEndings` — одна замена всего документа через `EditorRangeReplacementRequest` (`groupsUndo`) с проверкой документа, версии, выделения и задачи `.lineEndingConversion`; для оформленного Markdown с суррогатами отказывает сообщением. Смена кодировки (`applySaveEncoding`) только помечает документ несохранённым через `savedEncoding`, запись идёт существующим `write` с запретом потери символов, в UndoManager не регистрируется. «Открыть заново в кодировке» (`reopen`) читает `FileService.readRawData` и применяет результат через `finishReload`; для несохранённого документа сначала NSAlert, ошибка оставляет документ доступным. Формат сессии и аварийного восстановления не менялся.
- Wiki-ссылки распознаются только внутри TEXT-узлов общего cmark-разбора (`MarkdownWikiLinkExtractor`, `onSmartRange` в `MarkdownPresentationParser`); не добавлять второй разбор `[[`. Код, экранирование, HTML, `![[…]]`, таблицы и заголовки остаются текстом (в v1 не поддержаны). `MarkdownWikiLinkResolver` чистый: не читает диск и не выбирает файл при нескольких совпадениях (`ambiguous` → сообщение через `setStatusError`); имя без `/` сравнивается с именем файла, с `/` или `./` — с путём от базы (открытая папка, иначе каталог документа); регистр и расширение `.md/.markdown` не важны, Unicode — в форме NFC. Список файлов — только `WikiLinkCatalog` (по одному на окно, `AppState.wikiCatalog`; `FolderSearchService.markdownFiles`, символические каталоги не обходятся, обновление по `filesDidChange` с паузой 0,5 с) либо чтение с диска в фоне для экспорта и ленивого Cmd-клика. Cmd-клик идёт через `navigateMarkdownLink`; отсутствующий файл — прежний диалог создания. Подстановка в предпросмотре и экспорте не меняет число строк и документ, неразрешённая ссылка выводится текстом. Подсказки после `[[` — системное `NSTextView.complete`: проверяют документ, версию, выделение, IME и разбор до показа и вставки, вставка в одной группе отмены, `]]` не дублируются; имена с `#`, `|`, `[`, `]` в подсказки не попадают.
- «Обратные ссылки» — раскрываемый раздел боковой панели под оглавлением (`isBacklinksExpanded`, в сессию не пишется); `MarkdownBacklinksController` отдельно от `FolderSearchController`. Обход — `FolderSearchService.backlinks` через общий `scan` поиска папки (параметры `skip`/`prepare`), цель и не-Markdown файлы пропускаются, снимки открытых документов имеют приоритет. `MarkdownBacklinkScanner`: предфильтр по имени цели (как есть, в NFC и percent-кодированное; другие кодировки, например `+`, не находятся), затем один общий cmark-разбор на файл; ссылка = разрешённая wiki-ссылка (`ambiguous`/`missing` не считаются) либо обычная ссылка на файл с проверкой `DocumentFileIdentity`. Пауза 500 мс; перед публикацией проверяются поколение, цель и повторный `snapshots()`; переход проверяет фрагмент как поиск папки. Скрытие раздела и смена языка вызывают `close()`.
- Теги: поиск (третий вариант поиска папки) находит теги YAML и встроенные `#теги`. Встроенные берутся из TEXT-узлов общего cmark (`emojiCompletionRanges`), без индекса; исключаются ссылки и wiki-ссылки; предфильтр `MarkdownTagReader.hasCandidate` отсекает файлы без `#`, за которым идёт буква, цифра, `_` или не-ASCII символ, а перед ним — не буква/цифра и не `_ - / & \ #`. Правила: слева — начало текста, пробел, знак/символ Unicode (кроме `# / - _ & \`) или Han/кана/хангыль; тело — буквы, цифры, метки и `_ - /`, первый символ буква/цифра/`_`, хвостовые `-` и `/` отрезаются, нужна буква или `_`; если дальше в исходнике `\`, `&`, `#` или продолжение слова за границей куска — тег не угадывается. Сопоставление целым сегментом без учёта регистра (`#a` — `a` и `a/b`, не `ab`), флаг регистра для тегов не используется. Раздел «Теги»: `FolderTagsController` (`AppState.folderTags`; поколение, корень, отмена, повторная сверка снимков, `invalidate()` при сворачивании, смене корня и закрытии) + `FolderTagsSection`; в сессию не пишется; клик → `FolderSearchController.searchTag`. Окраска — `MarkdownPresentationController.applyInlineTagColors` (временный `.foregroundColor` `NSColor.lacTagText`, контраст не менее 4,5:1, возврат к исходнику снимает существующим путём); поиск и список тегов находят теги и в таблицах, но в ячейках таблиц они не красятся; пользовательский inline CSS перекрывает цвет. Ограничения: теги плоские, список не обновляется сам, свободный режим `markdownStrictMode == false` не учитывается.
- Шаблоны и заметка дня (`NoteTemplateService`, `AppState.swift`): шаблоны только UTF-8 без лимита размера, `{{title}}`, `{{date}}` (yyyy-MM-dd), `{{time}}` (HH:mm) подставляются за один проход по `unicodeScalars` (значения не разбираются повторно), даты — `DateFormatter` с `en_US_POSIX` и текущим часовым поясом. Запись — `FileService.createWorkspaceTextFile` с `.withoutOverwriting`; цель — `folderWorkspace.currentDirectory ?? rootURL`; отсутствующая папка заметок дня не создаётся, заметка дня открывает только обычный файл (каталог и ссылка — ошибка). Ключи `templatesFolderPath`, `dailyNotesFolder`, `dailyNoteDateFormat` (пустой/неподходящий формат — yyyy-MM-dd). Чтение и запись — в фоне в `AppState.templateTask` (новый запуск отменяет прежний, `closeAuxiliaryWindows` отменяет; перед применением проверяются корень и `ownsVisibleState`). Отмены создания нет: `undoFolderWorkspaceItem` удаляет только пустые файлы.
- Сниппеты (`SnippetStore`, `SnippetService`, `SnippetPickerPanel`, `SnippetSettingsView`): сниппет — `id`, `name`, `text` (пустое имя после обрезки и пустой текст запрещены, лимита размера нет). Подстановки `{{selection}}`, `{{date}}` (yyyy-MM-dd), `{{time}}` (HH:mm), `{{cursor}}` делает общий `NoteTemplateService.substitute` за один проход по `unicodeScalars`: каждое `{{selection}}` получает весь текст выделения, значения заново не разбираются; первый `{{cursor}}` задаёт курсор (смещение UTF-16), остальные удаляются, без метки курсор в конце вставки. Панель выбора — отдельный `SnippetPickerOverlay`, а не палитра команд; пункты «Правка → Вставить сниппет…» и «Сохранить выделение как сниппет…» видны в палитре, горячих клавиш нет. Хранилище одно на приложение (`SnippetStore.shared`, создаётся при первом обращении, `WindowManager` и `AppState.init` его не читают; для тестов есть `init(storageURL:)`). Вставка (`AppState.insertSnippet`) берёт свежее извлечение выделения (`allowsInsertionPoint`, `requiresEditable`) прямо перед правкой, пространство `.source`, одна запись отмены (`groupsUndo`), курсор задаётся `resultingSelection`; отказ в режиме чтения, при marked text, при `ioState != .idle`, при смене ревизии редактора и в пустой ячейке таблицы (`virtualTableTarget`) не меняет текст. Если результат равен выделению, координатор отклоняет правку сообщением. Окончания строк документа (CRLF) сниппет не подгоняет. Табуляции по полям, триггеров, папок, импорта и экспорта нет.
- Замена в папке — только режим текста (`.files`/`.tags` её не получают). Поиск и замена в папке пропускают адреса `data:`, как и поиск в документе (`TextSearchService.searchableRanges`). `FolderSearchService.search(options:)` принимает `TextSearchService.Options` (регистр/regex/слово; по умолчанию прежнее поведение); неверный шаблон → `Message.invalidPattern`. `FolderReplaceService` строит правки через `TextSearchService`, без дублирования логики панели поиска; `interpretsEscapes` берётся из `findReplace.interpretsEscapes` окна. Открытые документы: `WindowManager.applyFolderReplace` — одна замена объемлющего диапазона (`EditorRangeReplacementRequest`, `groupsUndo`) после проверки `ioState == .idle`, версии снимка, фрагментов и marked text; диск не пишется. Закрытые файлы — последовательно в фоне `FolderReplaceService.replaceOnDisk`: `FolderSearchService.readForReplace` (отметка до/после чтения, путь без ссылок, префикс BOM и не-UTF-8 пропускаются), точные фрагменты, повторная сверка `FileRevisionSnapshot` перед `FileService.writeUTF8`; перед каждым файлом проверяется, что он не открыт. Подтверждение — NSAlert с «Отмена» по умолчанию; отмена оставляет частичный отчёт, запущенная запись не прерывается, окно подмены между последней проверкой и записью остаётся. Выбор хранится как множество снятых флажков (`excluded`); режим замены включается отдельным переключателем. Маска файлов (`FolderFileFilter`) ограничивает поиск, а значит и замену: заменяются только найденные совпадения, отдельно маска при замене не проверяется. Откат замены закрытых файлов — `FolderReplaceBackupStore` (`Services/FolderReplaceBackupStore.swift`): хранится только последняя операция (`Application Support/<AppEnvironment.dataDirectoryName>/FolderReplaceBackup/<operationID>/`: `manifest.json` с корнем и датой, на файл `NNNNN.orig` — точные старые байты, `NNNNN.json` — путь, SHA-256 старого и будущего текста). Порядок: `FolderSearchController.apply` создаёт `Recorder`, `replaceOnDisk(backup:)` записывает копию и `.json` (точка фиксации) ДО проверки снимка и записи файла; ошибка копии → `writeFailed`, файл не пишется. Прежняя операция удаляется только после первой успешной записи новой; открытые документы не копируются (у них обычная отмена). `revert` по каждой записи: открыт в редакторе → `openInEditor`; файл читается через `readForReplace` (символические ссылки и не-UTF-8 → `conflict`); хэш равен будущему → возвращается точная копия (`reverted`), равен старому → `notApplied`, иной → `conflict` (файл не трогается); испорченная копия → `failed`. Возвращённые и `notApplied` записи удаляются, остальные остаются для повторной попытки. Откат запускает `revertLastReplace` (меню «Правка → 撤销上次文件夹替换…» и кнопка в отчёте) только при совпадении корня окна с корнем копии и подтверждении; замена и откат взаимно исключаются во всех окнах (`busyController`).
- Цель письма: `WritingGoalStore` (`@MainActor`, один на `AppPreferences`, ключи `writingGoalDay`, `writingGoalEntries`) хранит по `EditorDocument.id` базовое и последнее число слов за локальный день; прогресс — сумма `max(0, последнее − базовое)`. Обновляется только из `AppState.recordWritingGoal` по готовой статистике всего документа; выделение, большой профиль, `.opening`/заглушки и недоступная статистика не обновляют. Смена языка документа вызывает `rebase`, закрытие — `markClosed`: вклад остаётся до конца дня и не переносится. Новый день берёт базой последнее значение. `progress()` ничего не пишет и не публикует; таймера нет. `EditorDocument` и `DocumentStatistics` на хранилище не ссылаются (списки `swiftc`).
- Сборка рукописи: лист окна `ManuscriptView` + `ManuscriptController` + `AppState.swift`, только при открытой папке; выбор и порядок живут в контроллере окна, смена корня сбрасывает, скрытые файлы по умолчанию не отмечены. Чтение — `FolderSearchService.manuscriptSources` поверх общего `scan`: открытые документы приоритетнее диска, символические ссылки, невалидный UTF-8, изменившиеся и исчезнувшие файлы попадают в `problems`, невыбранные не читаются. Склейка — чистый `ManuscriptService` в фоне с проверкой поколения, корня и владения окном; результат — несохранённая вкладка через `openNativeTab`, как импорт. Front matter остаётся у первой части, у остальных удаляется только подтверждённый. Адреса изображений и вложенных ссылок становятся абсолютными `/…` с двойной проверкой разрешения; не-ASCII не кодируется. Ссылочная запись, HTML без кавычек, `<a>`/audio/video/source и адреса с `\`/`&` только считаются (регулярное выражение считает также теги в блоках кода). `typora-root-url` первой части блокирует преобразование. Метки сносок сравниваются, текст не переписывается. Незакрытый блок кода на конце части закрывается добавленным ограждением (`closingOpenFence`), файл попадает в `Report.closedCodeBlocks`, следующая часть не поглощается. Исходные файлы и документы не меняются.
- Обновление ссылок при переименовании: `FolderSearchService.renameReferences` строит план до переноса (нужно старое состояние для идентичности и однозначности имени), `MarkdownRenameLinkService` чисто строит правки только цели wiki-ссылки и сырого пути вложенной ссылки с проверкой точного адреса и обратного разрешения. Закрытые файлы пишутся как при замене в папке (`readForReplace`, `FileRevisionSnapshot`, `writeUTF8`), открытые — `WindowManager.swift` (одна замена, одна отмена, режим чтения — пропуск). Подтверждение идёт после переноса, по умолчанию «Не обновлять»; отмена переноса ссылки не возвращает. Папки, `file:`-адреса, ссылки-сноски, HTML и собственные относительные ссылки перенесённого файла не обновляются.
- «Заменить всё» в области «Все открытые документы»: сначала `OpenDocumentsSearchController.replaceAll` считает совпадения и спрашивает подтверждение (`NSAlert`, по умолчанию «Отмена», числа документов и замен), затем по одному документу вызывает `WindowManager.applyOpenDocumentsReplace(documentID:revision:request:)`: одна правка редактора и одна запись отмены на документ, диск не пишется, несохранённые вкладки участвуют (адрес файла не нужен). Нижняя часть пути общая с `applyFolderReplace` (`applyEnclosingReplacement`). Документ изменился, занят, в режиме чтения, открывается или в профиле большого файла — пропускается и попадает в итог «имя (причина)». Отмена останавливает следующие документы, выполненные остаются. После замены выбирается вкладка, с которой она запущена. Извлечение с этой областью (`OpenDocumentsSearchService.extract`) пишет записи с префиксом «имя:строка:», пропущенные вкладки — блоком «已跳过：…» в конце.
- Проект рукописи (`.laceditor/project.json`): модель `ManuscriptProject`/`ManuscriptNode` (неизвестные поля хранятся в `extra` и пишутся обратно; статус читается строкой или объектом; версия новее `supportedVersion` — только просмотр, файл не перезаписывается; повреждённый файл переносится в `project.json.corrupt`, `-2`… только при «Создать заново»). Запись — `ManuscriptProjectStore.update`: проверка модели, `FileRevisionSnapshot` (внешнее изменение — перечитать и сообщить), атомарная запись. Пути только относительные, без `..` и `.laceditor`, повтор пути запрещён. Исходные файлы проект не меняет. Дерево «书稿» в боковой панели: перенос мышью (`ManuscriptTreeRows.destination`, тип `com.laceditor.manuscript-node` объявлен в трёх plist) и клавиатурой (⌥⌘↑/↓, меню «书稿项目»). Сборка в проектном режиме идёт по порядку дерева с режимами «正文/仅梗概/梗概加正文» и заголовками групп; отметка «记住选择» пишет `include` в манифест. Слова — `ManuscriptWordCounter` (фон, кеш по дате и размеру, файлы до 5 МБ, открытые документы из памяти; для китайского считается каждый иероглиф).
- Полнотекстовый индекс (SQLite FTS5) есть только у режима поиска «По словам»; теги, палитра команд, замена в папке и остальные режимы работают без него. Подробности — в `folders-and-library.md`.
- Версии файла: лист «历史版本» (`VersionHistoryController`) имеет три режима — `history` (системные версии), `disk` (сравнение с диском) и `snapshots` («快照», именованные копии из `DocumentSnapshotStore`). Режим «快照» умеет переименовать и удалить выбранный снимок и сделать новый; восстановление помечается как «恢复快照». `FileVersionInfo.title` — название снимка. Кнопки «Показать» в уведомлении о снимке нет (`InlineFeedbackState` умеет только «Отменить»).
- Доска карточек (`WriterBoardController`, `WriterBoardView`, `WriterBoardModel`) и сводный просмотр (`WriterCombinedViewController`, `WriterCombinedView`, `WriterCombinedPage`) открываются из меню «书稿项目» отдельными окнами (`WriterAuxiliaryWindowController`), без сочетаний клавиш. Доска показывает прямых потомков открытой группы; фильтр только скрывает карточки (группы не скрываются), порядок меняется через `moveNode`, пустое описание/метка хранятся как nil. Описание без AI — `SceneSynopsisDrafter` (в манифест описание попадает только после «接受»; TextRank: два самых «центральных» предложения; мало пригодных предложений — первые; лимит 300 знаков, для китайского 120).
- Сводный просмотр: берутся только узлы с `include == true` (выключенная группа скрывает ветку), открытые документы приоритетнее диска (`WriterNodeTextLoader`), плашка «文本已变化» включается по отпечатку состава и текстов (сравнивается в пределах запуска, на диск не пишется); страница сама не обновляется, только по кнопке «刷新».
- Карточки мира (этап 9): обычный `.md` с шапкой YAML `type` (character/place/organization/item/rule), необязательными `id`, `aliases`, `relations` (`{to, kind}`) и `ai: exclude`. Тип определяется шапкой, не папкой; файлы рукописи (узлы манифеста) карточками не считаются. Новые карточки создаются в существующей папке «Мир»/«World»/«设定» или в новой на языке интерфейса, без перезаписи (конфликт имён — суффикс « 2»). `StoryCard` неизвестных полей не хранит; шапка правится только `StoryCardHeaderEditor` построчными заплатками (неизвестные поля, комментарии, пустые строки и CRLF остаются, результат перечитывается Yams, потоковая шапка отклоняется). `id` добавляется первой правкой шапки. `relations.to` — id или название; разрешение `StoryCardCatalog.resolve(reference:)`.
- Упоминания (`StoryCardMatcher`): без AI, шапка и блоки кода пропускаются; не-CJK имена сравниваются по нормализованным словам (`SearchTextNormalizer`), имя с заглавной буквы совпадает только со словом с заглавной, стоп-слова и однобуквенные имена игнорируются, при перекрытии побеждает длинное; китайские имена ищутся буквально. Индекс слов только сужает круг сцен в `StoryCardMentionService.scenes`, каждый кандидат перепроверяется матчером.
- Индекс упоминаний и список сцен карточки несут признак полноты (`StoryCardMentionIndex.isComplete`, `scenesResult`): если часть сцен не прочиталась (`problems`/`snapshotsUnavailable`), интерфейс пишет «提及结果不完整», а не «нигде не упомянут». Кандидаты без AI группируются по нормализованной основе имени; китайский текст локально не разбирается (имена ищет AI). `mentionedStoryCardURLs` берёт живой текст открытых документов и не добавляет текущую карточку саму в себя.

- Ментальная карта не хранится на диске: это вид текста, рукописи или карточек мира. Формат файлов и `project.json` не менялись; в `UserDefaults` — только настройки с префиксом `LacEditor.mindMap.`.
