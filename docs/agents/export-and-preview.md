# Импорт, экспорт, печать и предпросмотр

Читать при изменении Pandoc, импорта, экспорта, PDF, PNG, печати, `WKWebView` предпросмотра и Mermaid.

- Печать Markdown не запускает печатную операцию непосредственно внутри callback WebKit JavaScript: вход в вывод откладывается до следующего прохода главного потока, чтобы не вызвать повторную отрисовку `WKWebView` из незавершённого IPC callback. Сохранение PDF из системной панели использует официальный `WKWebView.createPDF`, поскольку `WKPrintingView` на macOS 26 может бесконечно записывать один документ; полученный векторный PDF разбивается на листы выбранного размера с полями и переносом ссылок, по умолчанию используется портретный A4. Физическая печать остаётся на `NSPrintOperation`. Печатный `WKWebView` сохраняет ограниченную высоту viewport. Перед выводом высокие изображения и Mermaid SVG ограничиваются фактической высотой печатной области с сохранением пропорций. До полной высоты HTML растягивается только представление для единого PNG-снимка.
- Панель выбора файла для импорта использует рабочий системный `runModal()` и показывает локализованный список расширений из фактического `PandocImportService.extensions`. После выбора и после фонового преобразования повторно проверять владение состоянием и исходный документ.
- Экспорт Markdown через встроенный Pandoc создаёт отдельный файл из актуального снимка; не менять путь, кодировку, несохранённость и историю отмены исходного документа. Команда PDF использует отдельный WebKit и системную печать в PDF без внешнего LaTeX. До установки результата сохранять проверки конфликтов, не удалять временный файл во время активной печати и не менять снимок источника. Не добавлять автоматическую установку, произвольные команды или шаблоны без отдельной задачи.
- В текущей ветке к форматам экспорта добавлены MediaWiki (`.wiki`), RST, Textile и OPML через уже включённые преобразователи Pandoc. OPML описывает оглавление и не сохраняет произвольную вёрстку документа. Меню строится из `PandocExportFormat.allCases`; сохранять соответствие имени, расширения и преобразователя.
- Экспорт запускает Pandoc в фоне без командной оболочки, передаёт UTF-8 и читает диагностику без блокировки каналов. Итоговый файл заменять только после успешного преобразования; перед заменой проверять идентичность исходного и остальных открытых документов. Не выдавать экспорт GFM за точную копию оформления предпросмотра; Pandoc может читать указанные в документе внешние ресурсы.
- Pandoc 3.13 берётся только из приложения: Xcode кладёт его в `Contents/MacOS/pandoc`, Swift Package Manager — в `Bundle.module/Pandoc`. Официальный архив хранится в `Vendor/Pandoc`, перед прямой SPM-сборкой выполнить `sh Scripts/prepare-pandoc.sh`; Xcode делает это сам. Сохранять права запуска, лицензионные уведомления и проверки подписи в упаковке. Условия распространения исходников описаны в `Vendor/Pandoc/README.md`.
- Импорт DOCX, ODT, RTF, EPUB, FB2, HTML и LaTeX создаёт отдельный несохранённый `EditorDocument` с языком Markdown через существующий путь системных вкладок, не переписывая исходник. PDF не является входным форматом Pandoc. Pandoc запускается с `--sandbox` и cwd исходника; output и stderr остаются во временном каталоге вне исходной папки, а RST/LaTeX include не раскрываются, включая внутренние. Доверенный фильтр `import-images.lua` встраивает вложенные изображения и локальные файлы только с каноническим путём внутри каталога источника; percent-escapes декодируются один раз, `/bin/realpath` вызывается через `pandoc.pipe` без shell. Абсолютные пути, `file:`, выход за корень и symlink наружу запрещены; внешние URI остаются ссылками и не загружаются. Не сохранять ссылки на удаляемый временный каталог и не применять результат к закрытому окну.
- Предпросмотр сохраняет один `WKWebView`; сравнение версии текста и темы выполняется отдельно. Не строить для определения изменений новую строку из темы и всего Markdown. Сохранять положение прокрутки и обновление темы без повторного разбора неизменившегося текста.
- При скрытии или удалении предпросмотра отменять его работу; устаревший результат не должен возвращать старую страницу. Обновление привязано к активности предпросмотра и поколению задачи.
- Сохранять локальную модель предпросмотра: JavaScript содержимого страницы выключен, политика источников ограничивает внешние ресурсы, HTML загружается без базового URL. Код приложения обновляет страницу в изолированной среде, передавая содержимое как данные. Не вставлять Markdown в исполняемый JavaScript.
- Mermaid 12.2.0 и собственный `Resources/Mermaid/render.js` выполняются только в изолированной среде приложения. Блок `mermaid` остаётся исходным code DOM, SVG создаётся рядом после успешного разбора; ошибка показывает исходник и локализованное сообщение. Сохранять strict/без HTML-меток, стандартные защищённые настройки библиотеки, запрет внешних ресурсов, последовательную очередь и проверку поколения/DOM после await. Скрытие предпросмотра инвалидирует также выполняющийся JS. Тема перерисовывает исходную диаграмму; экспорт использует подготовку локальных изображений диаграмм перед существующим Pandoc, без передачи исходного Mermaid как исполняемого содержимого. Лицензии и сведения о локальном комплекте хранятся вместе с ресурсами.
- Активированные ссылки HTTP(S) открываются внешним системным обработчиком, а не переходом внутри предпросмотра. Не добавлять сетевую загрузку документов, вход, телеметрию или внешние шрифты в несвязанной задаче.
- Предпросмотр следует за прокруткой редактора: `MarkdownRenderer.renderPage(includeSourcePositions:)` добавляет `data-sourcepos` только для предпросмотра (не для экспорта, копирования и PDF), `MarkdownPreviewScrollRelay` в `EditorDocument` передаёт позицию с объединением 50 мс. Обработчик снимает только поставивший его предпросмотр; при вертикальном письме позиция не передаётся. Номер строки берётся из индекса редактора, а cmark считает только CR/LF/CRLF: при U+2028/U+2029 выше видимой области допустим сдвиг на число таких разделителей. Не исполнять JavaScript документа ради синхронизации.
- Предпросмотр показывает индикатор загрузки через 0,3 с и сообщение об ошибке навигации с кнопкой «Повторить» подвидом того же `MarkdownWebView`; оба привязаны к последней навигации и активности предпросмотра. Печать и PDF всегда используют светлую тему (`markdownOutputUsesDarkMode`), HTML и PNG — тему окна. Печатный CSS задаёт светлые переменные и правила разрыва страниц; ссылки всегда подчёркнуты. Алерты получают класс вида только из белого списка (`lac-alert-note/tip/important/warning/caution`). Блоки кода известных языков подсвечиваются в предпросмотре и PDF/PNG/печати нативным `SyntaxHighlighter` (плоские span, кэш по тексту; без JavaScript и без новых порогов); «HTML без стилей» и копирование подсветку не получают. Системный акцент (`--lac-accent`) — только у полосы цитаты, флажка задачи и выделения в предпросмотре, обновляется по `NSColor.systemColorsDidChangeNotification`; ссылки и фокус сохраняют контрастный цвет. Подсказка пустого документа — только в предпросмотре (`renderPage(isPreview:)`).
- Yams используется для вложенных Pandoc defaults и буквальных значений YAML; ссылки на входной и выходной файлы остаются под контролем существующего пути экспорта. Локальные ресурсы CodeMirror, Highlight.js и Prism используются только как дополнительные анализаторы языков кода через JavaScriptCore. Они не заменяют нативный редактор, не загружают темы и не выполняют пользовательский JavaScript.
- Экспорт .tex подготавливает body PNG в новый соседний каталог без перезаписи; metadata и прочие изображения имеют отдельный контракт. PNG I/O выполняется в фоне через принадлежащий каталогу fd, а финальные проверки и короткая атомарная установка .tex — вместе на основном потоке. После публикации sidecar при ошибке/отмене каталог оставляется, причина и известный путь сообщаются; не удалять файл по имени после отдельной проверки его identity. Нового общего механизма транзакций нет.
- Итоговый Pandoc HTML, в том числе пользовательский HTML writer, сохраняет исходные script/style и прочий документированный raw HTML. Это сериализация экспортного файла, не исполнение этих фрагментов в приложении. Preview/PDF сохраняют свой отдельный безопасный путь. При последующих изменениях не возвращать удалённую фильтрацию только в одной из ветвей root resources/embed-resources.
