# HTML, изображения, медиа и оформленное копирование

Читать при изменении HTML-блоков, audio/video/iframe, SVG, GIF, Ruby, details, inline CSS, загрузки и управления изображениями, оформленного копирования.

- Подтверждённые общим cmark HTML-блоки разбираются SwiftSoup; исходные позиции остаются у cmark и последовательного HTMLContext. Локальные audio/video воспроизводятся системным AVPlayerView без автозапуска; HTTP(S) audio/video в редакторе не загружаются. Iframe остаётся отдельным непостоянным WebKit и показывает только запасную ссылку, без удалённого адреса. После ожидания проверяются документ, версия, поколение, URL, видимость и IME; раскрытие исходника, сворачивание, деактивация и уход с экрана останавливают и удаляют media view. Изменение высоты блоков обновляет frame видимых дочерних представлений. Скрипты и обработчики событий из документа не исполняются.
- Настройки изображений по умолчанию не отправляют данные. Ручная загрузка использует выбранный PicGo endpoint или пользовательскую программу; проверять реальные байты/MIME, порядок результатов и отмену. Включаемые отдельно автоматическая локальная/сетевая загрузка и разрешения YAML не должны менять старое поведение при отсутствии ключей. Копирование ресурса сохраняет исходный файл и не перезаписывает занятый путь; после записи устаревший снимок оставляет файл с сообщением о его расположении. Отмена текста не удаляет файл. Извлечение адресов HTML/reference подтверждается cmark, общие определения не должны менять невыбранные изображения и обычные ссылки. Число полных контрольных разборов не растёт с количеством definitions.
- Оформленная копия загружает выбранное удалённое изображение только если у этого документа включено `allowsRemoteImages`, через `MarkdownRemoteImageDownloader`. Без разрешения адрес остаётся в HTML буфера, а в RTF подставляется пустой `data:`. Copy HTML сохраняет адрес без загрузки. Перед записью буфера сохраняются проверки документа, версии, выделения, запроса и самого буфера.
- Оформленное копирование пишет проверенные простой текст и HTML. RTF добавляется только после существующих проверок точности; если он не подходит, два остальных формата сохраняются с явным сообщением. Отмена, неактуальный снимок или неподдержанный выбранный фрагмент не должны затирать буфер. Команды копирования исходного Markdown и HTML сохраняют отдельное назначение.
- iPicUploader вызывает установленный iPic только по явной команде пользователя. Отмена ожидания не останавливает уже начатую внешнюю загрузку; неизвестный результат не выдаётся за подтверждённый URL. Ключи других загрузчиков сохраняются через существующий Keychain.
- Подтверждение HTML, медиа, SVG и ruby делает ядро (`Preview/MarkdownHTMLProof.swift`, `MarkdownHTMLConfirmation.swift`) по дереву cmark; результат одинаков для панели и редактора, адаптеры его только выводят.
- Подтверждённые cmark HTML-блоки разбираются SwiftSoup как HTML5. Audio/video используют src/source и AVPlayer только с локальными адресами; HTTP(S) в редакторе пропускаются, а отображение ограничено видимой областью и существующими проверками версии/отмены/IME/сворачивания. Исходник и undo от показа не меняются. Вложенные контейнеры и остальные незавершённые формы не объявляются поддержанными.
- Iframe получает отдельный непостоянный WKWebView только для подтверждённого блока, но страница оболочки содержит запасную ссылку, а не удалённый `src`. Переходы внутри кадра отменяются. file/data/javascript адреса не загружаются. Жизненный цикл связан с документом/версией/видимостью, есть раскрытие исходника. Содержимое script/style/textarea между cmark-узлами учитывается общим HTMLContext.
- HTML без оформления сохраняет семантику текста/ссылок/поддержанных медиа и подтверждённые стили самого HTML span, но опускает настройки нативных шрифтов, цветов и лигатур приложения. Неподдержанные элементы дают явное предупреждение. Произвольные scripts и event attributes не исполняются в приложении.
- GIF сохраняет многокадровые данные и воспроизводится системным NSImageView поверх пустого placeholder. SVG подтверждается полноценным XML-разбором без внешних сущностей и отображается через изолированный WebKit img с преобразованием в прозрачный PNG; исходные SVG bytes сохраняются для копирования/загрузки/экспорта.
- Копирование выбранного/всех изображений и скачивание всех сетевых используют существующий extractor и downloader, не перезаписывают файлы назначения и заменяют ссылки одной редакторской операцией с одной отменой. Повторы файла/URL используют одну копию; каждый SVG fragment сохраняется отдельно, а `%23` внутри имени остаётся частью имени. Undo текста оставляет созданные копии на диске. При отмене, ошибке или устаревшем снимке показываются уже созданные файлы; ссылки не применяются к другой версии документа.
- Remote изображения preview/PDF/PNG подготавливаются из того же cmark-прохода через временные маркеры и data URI, но запрос уходит только при `allowsRemoteImages` и только через `MarkdownRemoteImageDownloader`. Без разрешения маркер заменяется на `data:,`. CSP остаётся img-src data:. Preview сначала показывает текст с placeholder и затем обновляет изображения в том же отменяемом задании; проверять актуальность также после WebKit navigation fallback. PDF/PNG ожидают подготовку ресурсов. Ошибка отдельной картинки не останавливает остальные, исходник не меняется. SVG data URI отделяет base64 от fragment; display/copy/renderer сохраняют fragment per occurrence.
- Move/rename/delete изображения связывает файловый шаг и редакторскую замену одной custom undo-записью; обычная регистрация текста отключена только на время этой замены. Перед каждой стороной undo/redo проверять точный UTF-16 текст, ресурсы и подтверждённые ссылки открытых документов. Файловый конфликт оставляет обе стороны без изменений и не регистрирует redo; ошибка редактора вызывает обратный файловый шаг, не гарантируемый при внешнем конфликте. Уже совершённая либо частичная дисковая операция сообщает фактические известные пути. Новой системы async undo нет. Закрытые документы не сканируются. Копии remote после отмены остаются.
- Preview/PDF выводят audio/video/iframe только после общего cmark source/DOM proof; поддержанные nested ranges выбирают внешнее media, fallback не получает отдельный overlay. Inline, whole-block и подтверждённые strong/em/strike/link containers используют прежние AV/WK жизненные циклы, source reveal/IME/версию. CSP исполняемого HTML: `default-src 'none'; img-src data:; media-src data:; frame-src 'none'; style-src 'unsafe-inline'`. Удалённые audio/video в предпросмотре и PDF становятся `data:,`, удалённый iframe заменяется ссылкой. Обычный HTML-экспорт может оставить удалённые адреса и настоящий iframe в файле; скрытый WebKit их не открывает. Локальные audio/video целиком читаются в data URI в фоне в прежнем задании preview: сначала текст/placeholder, потом ресурсы; PDF/PNG ожидают их. Это требует памяти под bytes/base64, новый streaming handler для локальных файлов не добавлен.
- Пользовательский inline CSS проходит общий Source/HTMLContext/DOM proof и типизированный MarkdownInlineStyle. Текущий первый срез принимает документированные red/yellow и положительный rem, не произвольные CSS-темы; CSS number проверяется отдельно от Swift Double. Unsupported style даёт читаемый source fallback в доказанных диапазонах и блокирует ресурсные загрузки; Copy пересекающегося неподтверждённого форматирования сохраняет прежний буфер. Нулевой размер не подменять системным шрифтом. Остальные цвета/единицы/свойства этим срезом не объявлены готовыми.
- Подтверждённый `details` использует первый `summary`, текст и поддержанные strong/em/span/ссылки через нативный TextKit. Системная кнопка меняет только временное раскрытие текущей версии редактора; исходный `open` задаёт начальное состояние и экспорт. При смене документа/версии временное состояние сбрасывается также после ввода и завершения IME. Вертикальное размещение использует существующие координаты медиа без второго поворота. Произвольные вложенные таблицы/медиа не объявлены поддержанными.
- `MarkdownRubyRenderService` рисует подтверждённые подписи через Core Text. Общий разбор обслуживает Parser/редактор/Renderer/Copy; base поддерживает подтверждённые bold/italic/цвет с наследованием, annotation сохраняет исходный родительский шрифт и цвет. Неподдержанные фон/размер/украшения и сложные rt остаются исходником по общему правилу допуска. Сохранять NSFont descriptor и координаты составных символов; измерение, рисование и раскрытие используют согласованную геометрию.
- Типизированный `display:none` хранится как `MarkdownInlineStyle.hideOnExport`. Нативное редактирование показывает содержимое; выходной CSS скрывает его. При наследовании скрытие предка сохраняется. Для форматированного Copy использовать `editingCSS`, чтобы копировать видимый результат редактора; исходное Copy Markdown не меняется. Само CSS-скрытие не обещает отсутствия загрузки ресурсов. Другие значения display не добавлять без соответствующей задачи.
- Форматированное Copy Ruby берёт ruby из узла модели документа (`MarkdownInlineNode.Ruby`, cmark при копировании не вызывается; U4.5), принимает целое подтверждённое выделение и передаёт base+reading без rp-скобок в plain text. HTML сохраняет ruby/rt/rp; RTF с неподтверждённой точностью не записывается. Неподтверждённый/незакрытый Ruby ограничивается исходным диапазоном до закрытия либо конца подтверждённого родителя, при непригодном диапазоне — EOF; частичное выделение не должно обходить этот барьер. Схлопываемые пробелы, emoji и дополнительные украшения требуют своего proof, не проецировать base+reading на исходные HTML-теги. Доступность сохраняет штатный source value/UTF-16 selection NSTextView без дополнительного дублирующего элемента картинки.
- Первый raw SVG-срез принимает самостоятельный подтверждённый cmark paragraph/HTML block. Source/DOM proof и системный XMLParser сохраняют исходные SVG bytes; отсутствующий стандартный xmlns добавляется только в подготовленные данные. Редактор использует прежний изолированный SVG loader, HTML сохраняет vector data URI. Стандартные initial fill/stroke допустимы в контролируемом оформлении; не требовать служебные opacity/stroke-width ради гипотетического стороннего CSS. CurrentColor/внешние зависимости/неподтверждённый viewport и неподдержанные формы остаются отдельными частями полного SVG. Файловые действия заново проверяют исходные ссылки, raw SVG не становится Markdown-ссылкой из-за синтетической presentation image.
- Одиночные `<audio …/>`/`<video …/>` обрабатываются как документированное расширение Typora только после exact standalone HTML-block/source/container proof. Нормализация в явную пару временно меняет literal того же дерева для общего DOM proof и всегда восстанавливается; Markdown не переписывается. Slash внутри quoted src не является концом тега. Не подменять старые многотеговые media по одному suffix `/>`; Copy принимает только весь подтверждённый исходный диапазон, не запускает сетевую загрузку и не пишет неподтверждённый RTF.
- Обычные текстовые HTML div/p/table отображаются нативным AppKit/TextKit viewer после общего source/DOM proof. Не расширять исключение WebKit для формул/диаграмм/внешнего медиа на обычное HTML-содержимое без отдельного решения пользователя. Новый generic WK viewer признан спорным отклонением и заменяется; основной LacTextView остаётся единственным редактором и владельцем source/undo/session. Не добавлять новые режимы и отдельные механизмы жестов/доступности ради этого блока.
- Удалённые iframe в предпросмотре больше не создаются. JavaScript остаётся для Mermaid в его изолированной среде. Основной Markdown сохраняет CSP `default-src 'none'` без script-src и прежний безопасный вывод: source scripts, event attributes и javascript URLs не исполняются. Не разрешать scripts основного документа ради медиа. Проверки child/parent и поздней навигации в XCTest используют только тестовый loopback listener; это не сервер приложения. Реальный WebKit и внешний сервис проверяются на Mac.
- Обычные подтверждённые HTML div/p/table отображаются через `MarkdownHTMLBlockView` на AppKit/TextKit, без WebKit. Cmd-клик по подтверждённой ссылке открывает её; обычный клик раскрывает исходник (в summary details переключает раскрытие). Занятость ячеек таблицы хранится диапазонами IndexSet, без обхода каждой виртуальной ячейки colspan. Настройки абзаца и шрифта кода берутся из существующего редактора.
- Подтверждённый форматированный details проходит общий source/DOM-разбор также в предпросмотре и PDF/PNG, где исходное open определяет видимость body. Проверка не зависит от включения произвольных HTML-медиа: неподтверждённые теги не получают разрешение на исполнение.
- Форматированное Copy целого подтверждённого details использует снимок текущего раскрытия из Controller: он определяет plain и safe HTML и повторно проверяется перед записью буфера. Экспорт продолжает использовать исходное open. Целый подтверждённый raw SVG копируется существующим путём изображения; частичные/неподтверждённые диапазоны оставляют прежний буфер. Исходное Copy Markdown не меняется.
- Живые вью вставок (плеер аудио/видео, iframe, HTML-блок, details) при правке вне них остаются теми же объектами: быстрый путь переносит ключи (`shiftMedia`), а замыкания вью (раскрытие исходника, ссылки, доступность, `canInteract`, проверка навигации iframe) ищут запись по самому вью и сверяют `currentRevision`, не храня `block`, `generation` и `revision` создания. Правка внутри или вплотную к вставке снимает только эту вставку (`removeTouched`). Подробности — в `performance.md`.
- Подменяется любой `data:тип/подтип` (порога длины нет, включая SVG без Base64); ручной набор `data:` не подменяется, вставка и ответы ИИ подменяются (`MarkdownMediaTable.incoming`). Аудио, видео и PDF из `data:` показываются в оформленном режиме через временные файлы `<tmp>/LacEditor-media/<pid>/<id документа>/` (`MarkdownDataMedia`, один адрес — один файл, удаляются при закрытии документа). Белый список типов и расширений один: `MarkdownDataMedia.extensions` (mp3, m4a, wav, ogg, aac, flac, mp4, mov, webm, pdf); другие типы остаются обычными данными. PDF из `data:` принимают отдельным блоком `<embed>` и `<iframe>` (`src`), `<object>` (`data`) без вложенного содержимого, внутри строки — `<embed>` (`PairedMediaCollector`, тег сам себе пара; проверка через `provenMediaIndices`; `<iframe>` и `<object>` внутри строки остаются исходником). Правая панель PDF не показывает. Вид PDF за экраном освобождается, страница и точка запоминаются в `pdfPositions` (ключ сдвигается в `shiftMedia`) и восстанавливаются при возврате, при смене документа в контроллере позиции сбрасываются; пока блок только потерял прямоугольник, вид остаётся в словаре с плеером или документом; ссылка `[отчёт](data:application/pdf…)` открывается через временный файл. Оформленное копирование PDF идёт обычным путём.
- Буфер обмена (`LacTextView.writeSelection`): в обычном тексте токенов и Base64 нет (`MarkdownMediaTable.clipboardText`: `![…](…)` и HTML-тег убираются целиком, у `[текст](…)` остаётся текст); внутренний тип `com.laceditor.markdown-source` несёт настоящий исходник, и вставка в LacEditor возвращает media. «Копировать Markdown» и копирование блока кода отдают настоящие данные сознательно. Ячейка таблицы (`MarkdownTableCellEditor`) работает так же при копировании, вырезании, перетаскивании и Services: `EditorCoordinator.tableCellMediaPayload` даёт исходник в виде текста ячейки, без экранирования таблицы; вставка и бросок в ячейку идут через `pasteTableCellMediaSource`. Бросок из открытой ячейки в текст окна сначала закрывает ячейку (`pasteMediaSource`).
- Вырезание (`cut`) в `LacTextView` и `MarkdownTableCellEditor` не идёт через асинхронное оформленное копирование: `copy` при `isCutting` сразу вызывает системный путь, иначе последующее удаление отменило бы запись в буфер. `pasteRichText` вызывает `synchronizeLiveText()` до снятия версий: иначе отложенная синхронизация недавней правки молча отбрасывает результат конвертации.
- Новое изображение из буфера (`.data`), Continuity Camera и ИИ без явной автозагрузки, `copyFolder` и `typora-copy-images-to` идёт по правилу `MarkdownImagePlacement.decision`. Несохранённый документ и заметка хранилища (`AppState.isVaultFile`) встраивают data URI сразу: окно «图片» (alt/заголовок) остаётся, блока выбора места нет. Сохранённый документ показывает в этом окне блок `MarkdownImagePlacementPrompt` (повторно используется окном ИИ): «保存在文档旁边» (по умолчанию) или «嵌入文档» и галочка «记住此文档的选择». «Рядом» пишет файл `<имя документа без расширения>.assets/image-ГГГГММДД-ЧЧММСС.<ext>` (`jpeg` как `jpg`; при совпадении `-2`, `-3`…, запись `.withoutOverwriting`) и вставляет относительную ссылку через `MarkdownImageEditingService.address`. «Встроить» вставляет `data:` обычным путём `apply`: при включённой карте media адрес заменяется токеном `MarkdownMediaTable`. Ошибка записи показывается в `statusMessage` («无法保存图片：%@»), в текст ничего не вставляется. Отмена undo текст откатывает, а файл не удаляет. Выбор хранится в `AppPreferences` (`markdownImagePlacement(for:)`, ключ `markdownImagePlacementChoices`, путь `standardizedFileURL.path`) и записывается сразу после «应用»: галочка снята забывает выбор, отмена окна ничего не меняет; при переименовании или переносе файла выбор теряется. При запомненном выборе в окне он уже отмечен. Ссылка на существующий файл (`.file`) и сетевой адрес работают как раньше; окно «Сохранить как…» для новых данных больше не показывается.
- Continuity Camera («Импорт с iPhone или iPad»): `LacTextView.validRequestor(forSendType:returnType:)` принимает `png`/`tiff`/`public.jpeg` только если вид редактируемый, нет marked text и задан `imageTransferHandler`; `readSelection(from:)` уменьшает снимок через `MarkdownImageReducer` (длинная сторона не больше 2048 px без увеличения маленьких, JPEG 0,8, PNG при реальной прозрачности) и отдаёт `.data` тому же обработчику, что и вставка. Типы `png`/`tiff`/`public.jpeg` регистрируются один раз через `NSApplication.registerServicesMenuSendTypes([], returnTypes:)` в `LacTextView.viewDidMoveToWindow`: без регистрации система не спрашивает `validRequestor`. Обычная вставка `.data(png/tiff)` не уменьшается. В режиме чтения и в ячейке таблицы (`MarkdownTableCellEditor`) Continuity не принимается. Сканы документов (PDF) не поддерживаются: только изображения.

## Копирование с оформлением

- `MarkdownClipboardCopyService.project` проецирует выделение на `MarkdownDocumentModel` (`MarkdownClipboardProjector*.swift`); cmark и `MarkdownSourcePositions` в нём не используются, кроме разбора запасного текста `<video>`/`<audio>` (`MarkdownHTMLMediaService.renderedInlineMediaHTML`: один разбор документа на проекцию, только когда выделение задевает такое медиа). SwiftSoup проектор использует для проверки и вывода HTML-блоков и тегов (`MarkdownClipboardProjector+HTML.swift`). Принцип «nil при любом сомнении» сохранён. Параметра `model` у `project` нет: модель редактора всегда содержит `.noteEmbeds` и `.criticMarkup`, проектор такую модель отвергает, а в режимах CriticMarkup текст другой, поэтому `project` разбирает текст сам.

## CriticMarkup при оформленном копировании

- Режимы предпросмотра «только результат» и «только оригинал» действуют и на оформленное копирование: перед проекцией текст разрешается через `CriticMarkupRender.resolved`, а выделение пересчитывается (начало внутри замены уходит в начало замены, конец — в её конец). В режиме «показывать» и при «Копировать как Markdown» текст копируется как есть. Ключи состояния `<details>` при разрешённом тексте не пересчитываются.
- Оформленное копирование текста внутри `<script>`/`<template>`/`<textarea>` в абзаце и эмодзи в абзаце между блоками `<template>` идёт как в панели: текст копируется обычным текстом, сами теги и выделение, задевающее тег, дают отказ. Выделение, режущее маркер или заголовок выноски (`[!warning] Заголовок`), копируется обычным текстом исходника без `> `.
- `![[x.png]]` адаптер `MarkdownHTMLRenderer` выводит как обычную картинку `![x](путь)` (файл ищется рядом с документом, затем от корня папки) и дальше идёт по существующему пути локальных картинок; нет файла — курсивная подпись «Вложение недоступно». Встроенные заметки картинки не загружают (политика `img-src data:`): вместо них подпись `alt`.
- Отдельная HTML-картинка (`displayImage`) с атрибутом-обработчиком `on*` (`onerror`, `onload`) остаётся исходником, как audio/iframe с лишними атрибутами.
- Открывающий `<audio`/`<video`, разорванный на строки (в том числе в цитате или пункте с доказанным префиксом контейнера), в абзаце из одного этого тега вместе со следующим `html_block` с закрывающим тегом считается одним блоком медиа (`multilineMediaOpening`, `PairedMediaCollector.merges`; на время DOM-проверки literal тега переносится в блок и затем возвращается). Текст документа не меняется. Другие многострочные встроенные теги по-прежнему отключают HTML-разметку документа; предпросмотр, PDF и экспорт HTML (`MarkdownHTMLRenderer`) собирают такой тег так же: подтверждённое объединение убирает абзац с тегом и выводит тег в начале блока, иначе вывод прежний. Якоря внутри объединённого блока не размечаются, `data-sourcepos` указывает на строку блока; оформленное копирование такой тег не собирает.

## Режимы блоков в оформленном редакторе (T8b)

Режим 1 — правится прямо в тексте; режим 2 — вид заменяет исходник, но курсор или клик раскрывает его строку, и он правится как текст; режим 3 — «только просмотр»: сам исходник не раскрывается (или раскрывается неочевидно), поэтому есть явная команда «编辑源代码» в контекстном меню.

| Вид блока | Режим | Как пользователь меняет исходник |
| --- | --- | --- |
| Блок кода (```` ``` ````), встраивание `![[…]]` (в редакторе остаётся текстом) | 1 | Прямо на месте |
| Формула (строчная и блочная), Mermaid/flow/sequence, Ruby, строчный raw SVG | 2 | Клик или выделение раскрывает строку |
| Изображение (`![](…)`, HTML-картинка, GIF, блочный raw SVG) | 3 | Команда «编辑源代码» переключает документ в исходный вид, каретка в начале блока; клик исходник не раскрывает |
| HTML-блок, `details` | 3 | Команда выделяет весь блок и раскрывает исходник (клик по блоку делает то же) |
| audio / video / PDF, iframe | 3 | Команда выделяет весь блок и раскрывает исходник (клик попадает в плеер/PDF/WebKit); есть и действие VoiceOver с тем же названием |

- Пункт строит `Coordinator.diagramMenu(at:)` через `diagramMenuHandler` текстового вида; `MarkdownPresentationController.blockSource(at:)` находит блок под мышью (вью-вставки по рамке, изображение по `imageResource(at:)`), `isCurrentBlockSource` проверяет документ, версию, поколение и наличие блока перед действием.
- Пункт есть только в оформленном Markdown, когда вид редактируемый, не режим чтения, нет marked text и `ioState == .idle`. У режимов 1 и 2 его нет (проверяет `testEditableBlocksDoNotOfferEditSource`).
- `WKWebView`, `PDFView` и `AVPlayerView` показывают своё меню и не передают клик текстовому виду, поэтому созданы подклассы `MarkdownIframeWebView` (`willOpenMenu`), `MarkdownPDFView` и `MarkdownPlayerView` (`menu(for:)`): они дописывают пункты из того же `diagramMenuHandler`. Приведения `as? WKWebView/PDFView/AVPlayerView` остаются верными.
- Для нового вида вставки сначала определить режим; режим 3 обязан получить эту команду.
