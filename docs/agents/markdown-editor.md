# Оформленный Markdown

Читать при изменении разбора cmark, оформленного представления, команд форматирования, списков, задач, таблиц, оглавления, ссылок, сносок, статистики, формул и настроек оформления.

Подробная карта жизненного цикла правки в оформленном представлении: [`markdown-editing-flow.md`](markdown-editing-flow.md). При расследовании сначала сверять фактический путь с этой картой, а найденные изменения поведения заносить в её журнал.

- Для Markdown доступно переключение исходного и оформленного представлений одного редактора. `isMarkdownFormatted` относится к объекту документа и не записывается в сессию; после восстановления используется исходное представление. Переключение не должно менять строку, несохранённость, выделение или историю отмены.
- Выделение внутри формулы (строчной и блочной) раскрывает её исходник: формулы не входят в `selectionTouchesOpaqueMedia`, в отличие от изображений, аудио, видео и iframe.
- В оформленном представлении клик и выделение на изображении не раскрывают его Markdown-исходник; редактирование синтаксиса изображения выполняется в исходном представлении. Явный путь — команда «编辑源代码» в контекстном меню изображения: она переключает документ в исходное представление с кареткой в начале блока. При каждом переключении представления отменять прежние задачи изображений и сбрасывать их установленные диапазоны, чтобы повторное включение оформления загружало видимые изображения заново.
- Блочное изображение задаёт свою высоту только line fragment, содержащему канонический глиф начала изображения; не определять его по одному пересечению character range, которое после ленивой переразметки может повторяться у соседнего фрагмента. Остальные фрагменты скрытого исходника, включая перенос перед следующим пустым абзацем, имеют минимальную высоту и не должны повторять высоту изображения.
- Путь текущего элемента строится из `MarkdownPresentation.elements` (`MarkdownElementIndex`) того же cmark-разбора только в оформленном Markdown: блоки по целым строкам, строчные элементы по подтверждённым span, поиск двоичный с подъёмом по родителям. `EditorDocument.markdownElementPath` временный, снимается при правке, смене языка, проекции и настроек синтаксиса, при marked text и большом профиле. Вычисляется на главном потоке в координатах отображения при пустом единственном выделении, для активной ячейки — только блоки. Отдельный разбор ради пути включает `setElementPathEnabled` с паузой 0,4 с; порог ширины 700 pt — только решение представления, подписи зависят от `MarkdownElement.Kind`. В исходном Markdown этот разбор не запускается на вводе.
- `CriticMarkupService` чистый: вложенность запрещена, пустая строка прерывает правку, `\{` — литерал, границы CR/LF/CRLF, координаты UTF-16. Запрещённые зоны (код, HTML-блоки, формулы, таблицы, front matter) ядро не оформляет; в сносках правки оформляются; строчный HTML не исключается. В редакторе правка — span `.critic(kind)` (строит `MarkdownPresentationBuilder+Obsidian`, ядро включено флагом `.criticMarkup`), диапазон — весь `{…}`, знаки `{++`, `++}` и т. п. — маркеры (скрываются вне курсора, как у других строчных видов). Цвет — временный `.foregroundColor` в `MarkdownPresentationController.reapplyDecorationColors` (его вызывает `EditorCoordinator.reapplyDecorationColors` после цвета ссылок и до `reapplyVaultPageDim`), только при готовом актуальном разборе (`parsedRevision == revision`, длина текста совпадает, без marked text, без `hasPendingLiveEdits`), независимо от режима оформления (в режиме исходника цвет остаётся); после правки до нового разбора цвет кратковременно отсутствует, устаревший снимает следующий проход подсветки. Индекс элементов для команд — `currentElementIndex` (бывший `criticElementIndex`; уйдёт при переходе команды на `model.elements`). Команды: `CriticMarkupCommand` → `EditorCommandNotification.criticMarkup` → `applyCriticMarkup`, одна группа отмены, замены от конца к началу; отказ при marked text, режиме чтения, активной ячейке, большом профиле и суррогате data URI. Горячих клавиш нет; предпросмотр, экспорт и оформленное копирование разметку обрабатывают (см. `export-and-preview.md`, раздел CriticMarkup), «Копировать как Markdown» копирует текст как есть.
- `FoldLayoutManager.drawGlyphs` вырезает glyph-диапазоны установленного и скрытого исходника блочного изображения из системной отрисовки, в том числе из смешанного пакета с соседним текстом; само изображение рисуется отдельным фоновым проходом, а части соседнего текста — обычным способом.
- Ядро (`MarkdownDocumentParser`) получает структуру cmark и переводит позиции UTF-8 в UTF-16; оформление редактора строит из модели `MarkdownPresentationBuilder`. Встроенные маркеры раскрывать по точному выделению и подтверждённому владельцу элемента: соседний элемент на той же строке остаётся оформленным. Заголовки, списки и сложные блоки сохраняют раскрытие по строке. Неоднозначная разметка остаётся исходником. Подтверждённые обычные маркеры списков оформляются отдельно; таблицы используют нативную сетку, описанную ниже. Локальные, data URI и HTTP(S) изображения поддерживают отдельные абзацы, inline, контейнеры и ячейки; загрузка в фоне сверяет документ, версию, путь и видимую область. Уже установленные изображения удерживать до смены документа, правки или выключения оформления, чтобы прокрутка не меняла высоту текста и не запускала цикл выгрузки и повторной загрузки. Системную проверку орфографии и грамматики отключать для документа с `data:image`, чтобы Base64-содержимое не попадало в spell server. Выделение раскрывает исходник, строка документа не меняется. Скрытие маркеров независимо от сворачивания строк; высоту заголовков считать по пересечению фрагмента строки с заголовком, включая отступы и цитаты.
- При вводе и удалении букв, цифр, пробела и знаков препинания (`typingPunctuation`, эмодзи) внутри одной строки обычного Markdown (изображения, формулы и эмодзи, в том числе в ячейках таблиц, блоки кода, диаграммы, аудио/видео, iframe, details, блоки HTML и ruby и сноски не мешают; без оглавления, якорей, разрывов страницы, заглавных и нумерованных заголовков) оформление не снимается: `beforeEdit` получает вставляемый текст, контроллер проверяет правку только чтением (`MarkdownPresentation.canShift`) и затем сдвигает диапазоны на месте (`MarkdownPresentation.shift` и `FoldLayoutManager.shiftMarkdownPresentation`), а `edited` даёт вставке оформление соседнего символа (`matchInsertedStyle`): слева, а после перевода строки и в начале текста справа. Enter (чистый `"\n"` без отступа, `range.length == 0`) в конце обычного абзаца тоже не снимает оформление, если после строки идёт пустая строка или конец текста, абзац начинается с начала строки и не лежит в заголовке, цитате или пункте: контроллер берёт правку из `MarkdownPresentation.paragraphBreakEdit` (она сама вызывает `canShift`), позиция правки там стоит после уже имеющегося перевода строки (`point`, а не позиция каретки), и по этой правке контроллер сдвигает оформление, тогда как `keptEdit` и `matchInsertedStyle` берут настоящую вставку из аргументов `beforeEdit`. Абзац включает свой завершающий перевод строки, поэтому новая пустая строка уходит в `separatorAfter`: `MarkdownTextEdit.lineBreak` не растит блок на его конце и растит разделитель (`after`), `atOpenLine` с `paragraph(_:)` растит абзац только при Enter в конце текста без перевода строки. Таблицы и блоки кода ниже абзаца только сдвигаются; абзац вплотную над таблицей (без пустой строки), вторая пустая строка подряд, буква на пустой строке, CRLF, пробел перед переводом и `hasActiveTable` идут прежним путём. Правка в отступе строки, внутри маркера, подмены, чекбокса, на границе встроенного элемента, в строке, начало которой похоже на разметку блока (`#`, `>`, `-`, `1.` и т. п.), рядом с разметочными знаками (`* _ ~ = ^ ` + "`" + ` [ ] < > | $ \ &`), с другими символами или с переводом строки (кроме Enter выше) идёт прежним путём (правка в первом слове строки, которая остаётся прозой, быстрый путь допускает): `shiftAroundEdit` снимает только задетые элементы и их стили (`removeTouched`, `dropTouched`), остальное сдвигает, а разбор при расхождении `spans` один раз восстанавливает стили всего документа. Презентация сбрасывается целиком (`clear`) лишь при правке без текста, открытой таблице и заглавных или нумерованных заголовках. Новый разбор применяется по тем же проверкам поколения и версии; при его установке видимая область переоформляется заново. `parsedResult`, `parsedSource` и оглавление после правки по-прежнему недействительны. Сдвиг на месте: разбор после установки проходит `prepareForEditing` (сортировка `spans`, префиксные максимумы концов `spanEnds` и `completedEnds`, проверка порядка списков; любая установка `presentation` идёт через `adopt`), правила сдвига лежат в `MarkdownTextEdit`, умный текст, читаемый текст, `elements` и контекст ограждений после сдвига сбрасываются, как раньше. Модель умеет сдвигать все поля (изображения, формулы, эмодзи, якоря, разрывы страницы, оглавление, сноски, ruby, диаграммы, аудио, iframe, details, HTML, заголовки), а `hasOnlyTextStructure` закрывает только оглавление, якоря, разрывы страницы и заголовки с номером или заглавными буквами; сноски, изображения, формулы, эмодзи (в том числе в ячейках таблиц), блоки кода, диаграммы, аудио/видео, iframe, details, блоки HTML и ruby пропускает (`canShift` = `hasOnlyTextStructure` и `canShiftElements`; стенд зовёт `canShiftElements` напрямую). Готовые объекты изображений, формул и эмодзи переезжают вместе с элементами: слой сдвигает свои словари в `shiftMarkdownMedia`, контроллер ключи установленного в `shiftInstalledMedia` (ключ блочной картинки — абзац, правило `block`, остальные `away`); готовое не очищается и не загружается заново, незавершённые загрузки картинок и SVG не отменяются: их ключи тоже переезжают, а завершение сверяет текущую ревизию контроллера (`currentRevision?() == self.revision`), поколение и адрес картинки на её нынешнем месте. Незавершённые ruby и аудио отменяются в `cancelPending` и после разбора запускаются заново. Занятое задание формул на быстром пути отменяется, `emojiValues` сбрасывается; `install` сравнивает kept и свежий результат по изображениям, формулам и эмодзи и при отличии вызывает `clearReady()` и `cancelImageJobs()` (незавершённые загрузки отменяются, `applyVisible` в конце `install` запускает их заново по ключам свежего разбора). GIF после сдвига получают `notifyGeometryChanged`. Правила: все диапазоны элементов `away` (касание правки отклоняет сдвиг), у изображения `paragraphRange` — `block`, но Enter в конце текста без перевода строки (`lineBreak` и `atOpenLine`) при `NSMaxRange(paragraphRange) == range.location` `canShiftElements` отклоняет: `block` растил бы абзац картинки на вставленный перевод, а полный разбор его не включает, `baseRuns` у ruby относительны строки и не двигаются, блоки HTML/диаграмм/аудио/iframe/details тоже только `away` (их `html`, `body`, `source` берутся из текста, правка внутри устарила бы их), а у аудио, iframe, details и HTML между правкой и блоком должен остаться зазор (`MarkdownTextEdit.spaced` в окне `reaching(1)`): иначе соседняя строка может изменить разбор, заголовок, задетый правкой, убирается из `headings` при сдвиге, у остальных `range` и `plainTextRange` сдвигаются (`number`, `uppercaseRuns` не сдвигаются: они остаются причиной отказа). Сноски: ссылки и определения идут не по порядку, поэтому `canShiftElements` проходит по всем; правка в теле определения (в том числе в ленивой строке продолжения, `allowsTypingEdit` её пропускает) отклоняется тем, что тело не покрывает ни один блок текста (`covered`), а не проверкой сносок: не ослаблять это условие (тест `testShiftRejectsFootnoteBodyAndMarkerEdits`). `lastFootnote` сбрасывается при сдвиге (`shiftPresentation`), подсказки сносок при быстром пути не меняются (их рамки лежат в координатах вида и обновляются после разбора, при прокрутке и смене геометрии); `applyVisible` обновляет их по всей видимой области, а не только по неоформленной части. Новый список элементов обязан быть упорядочен в `prepareForEditing` (для изображений — по `range` с общим `paragraphRange` у одного абзаца), иначе `isReadyForShift` ложен. Блоки кода вне правки сдвигаются вместе с готовой подсветкой: `MarkdownCodeBlock` двигается в `shift` правилом `away`, ключи `codeResults`, `codeFailed` и `codeColoredRanges` — в `shiftCodeHighlighting`, токены хранятся от начала тела блока (`bodyRange.location`) и сдвига не замечают; незавершённые задания отменяются в `cancelPending` и после разбора запускаются заново только для блоков без результата, а `pruneCodeHighlighting` после разбора снимает результаты, ключ которых не совпал ни с одним блоком. Правка внутри блока, в строке ограждения или вплотную к блоку снимает результат только этого блока; `dropKeptPresentation` при неподтверждённом сдвиге тоже чистит её полностью. Таблицы вне правки только сдвигаются (`MarkdownTable.shift`, `TableLines.shift` через `MarkdownTableRows.shifted(by:)`, вложенные позиции строк относительные); правка внутри таблицы или вплотную к ней снимает только эту таблицу, а открытая таблица (`FoldLayoutManager.hasActiveTable`) — всё оформление (`clear`). Быстрый путь ячейки (`restoreActiveTable`) не менялся; пока оформление сдвинуто и разбор не пришёл, `currentTablePresentation` отдаёт nil, ячейка берёт свежий разбор. Отклонённая правка не меняет ничего: сначала `canShift`, потом `shift`. Владелец разделителя абзацев, кончающийся на месте вставки, и строка пункта, кончающаяся на ней, слоем не растягиваются. `restoreStyles(in:)` вырезает восстановленный диапазон из `styledRanges`, иначе следующий `applyVisible` счёл бы его оформленным.
- `MarkdownPresentationController` разбирает снимок в фоне с отменой и проверкой поколения, версии редактора, документа и активности. Оформлять только ещё не оформленную часть видимой области, не переустанавливать атрибуты уже оформленного текста и не раскладывать весь документ при вводе или прокрутке. Видимый диапазон получать из уже готовой TextKit-разметки без её принудительного достраивания. Во время незавершённого системного ввода отложить оформление до его окончания. При возврате к исходнику восстановить шрифты, параметры нового ввода и ранее скрытые глифы, включая область за экраном. Не применять к оформлению пороги других подсистем и не добавлять новые ограничения без отдельной задачи. Адреса `data:` в Markdown (в любом режиме) редактор показывает короткими токенами `data:тип,AA==#lac-media-<хэш>`; live provider и сохранение восстанавливают точный исходник из таблицы, а выделения переводятся между файловыми и экранными координатами (подробности — в `editing.md` и `text-state-and-background.md`). Перестройка проекции внутри `updateNSView` сбрасывает только внутренний результат оформления и не публикует изменения `EditorDocument` синхронно во время обновления SwiftUI.
- Меню «Формат Markdown» использует актуальный NSTextView в обоих представлениях. `MarkdownFormattingService` возвращает одну замену и итоговое выделение в UTF-16; применение проходит обычный цикл AppKit и отдельную группу отмены. Не снимать экранированные или неоднозначные маркеры, не создавать встроенное оформление через несколько абзацев и не менять блоки кода блочными командами. Во время marked text и для недоступного редактирования команды не применяются.
- Команды создания списков, fenced-блока и горизонтального разделителя используют тот же путь форматирования и одну отмену. Для списков добавлено преобразование подтверждённых однострочных siblings общего cmark list: bullet/ordered/task, сохранность source content и UTF-16 selection, same-type без изменений. Многострочные родители пока не преобразуются, чтобы изменение ширины marker не разрушило вложенность; fenced/разделитель продолжают работать с обычными строками. В оформленном виде подтверждённый task-флажок рисуется поверх исходного маркера; щелчок меняет только пробел/x через обычный цикл отмены с проверкой версии, документа, доступности, IME и единственного выделения. Клик по флажку при запрещённой операции не передаётся обычной обработке и не сбрасывает множественное выделение. В этих новых блочных преобразованиях границы Markdown-строк — CR, LF и CRLF; U+2028/U+2029 остаются содержимым по правилам cmark, а индекс строк редактора сохраняет собственную обработку Unicode-разделителей. Проверка кода учитывает пересечение диапазона и незакрытое ограждение в конце файла; не ослаблять её ради новых команд.
- Оглавление — раскрываемый раздел существующей боковой панели, не индекс файлов библиотеки. Один результат Markdown-разбора обслуживает оформление и видимое оглавление; в исходном виде оглавление не меняет атрибуты редактора. `markdownHeadings` и `isMarkdownOutlineCurrent` временные: правка и внешняя замена текста немедленно отменяют актуальность. Переход проверяет выбранный документ и принадлежность текущему списку, раскрывает сворачивание также для позиции курсора без выделения. Раскрытие оглавления не записывается в сессию. Перенос раздела выполняет чистый `MarkdownSectionMoveService` (UTF-16, CR/LF/CRLF дословно, только `MarkdownHeading.isTopLevel`; раздел — до следующего заголовка того же или более высокого уровня; уровень не меняется, setext-заголовок получает пустую строку перед собой), применение — `AppState.moveMarkdownSection` через `EditorRangeReplacementRequest` с одной отменой, после `synchronizedSnapshot()`, при актуальном оглавлении, вне режима чтения и marked text; результат сообщает, состоялся ли перенос, чтобы фокус оглавления не ждал несостоявшийся. При суррогатах data URI отказ приходит из `Coordinator.apply` общим сообщением о смене позиции. Перетаскивание использует собственный тип `com.laceditor.outline-section`; источник — статический `OutlineSectionDrag` с проверкой идентификатора документа.
- Встроенный `[toc]` пока распознаётся как точный отдельный абзац верхнего уровня. Использовать заголовки того же разбора, не записывать развёрнутый список в текст. Выделение показывает исходный маркер, клик проверяет текущий документ/версию/IME и использует обычный revealSelection. Геометрия и hit-test ограничены видимой областью; не раскладывать все удалённые маркеры при каждом клике. HTML и нативный PDF получили отдельную подготовленную реализацию по тому же дереву cmark; допустимы только сгенерированные известные ID текущей страницы, unsafe HTML не включать. Для Pandoc подготовлена подстановка подтверждённых TOC-маркеров через существующее дерево вывода.
- `MarkdownTableEditingService` изменяет GFM-таблицы, включая неполные строки и таблицы внутри цитат/списков: строки, столбцы и выравнивание. Нативная сетка использует один NSTextView активной ячейки, поддерживает Tab/Shift-Tab, перенос строк/столбцов мышью и многострочный текст через подтверждённые `<br>`. Отображаемый текст и исходные диапазоны переводятся в обе стороны в UTF-16; неизменённые фрагменты сохраняются дословно. Одна подтверждённая операция — одна замена основного текста и одна отмена. Незавершённый системный ввод попадает в существующий live provider через составной снимок и не подменяется текстом модели. Для отсутствующих ячеек разделители создаются только после принятия ввода; отмена диалога ничего не добавляет. Ссылки и изображения проверяют идентификатор активной ячейки, документ, версию и выделение после диалога. При вводе переразбирать активную строку, смещая остальные диапазоны без копирования всех строк таблицы. Сохранность соседнего оформления проверять сразу, до фонового разбора. Полная клавиатурная матрица, буфер обмена и сложная разметка остаются в работе. Геометрия строки таблицы хранится в кэше `FoldLayoutManager`; строка со сдвинутыми диапазонами даёт промах, а не чужой результат.
- Cmd-клик по подтверждённой ссылке использует общий cmark-результат; при отсутствии готового результата допустим один отменяемый разбор по явному клику. Клик без Cmd сохраняет редактирование. Проверять объект документа, текущий ввод, версию и смену выделения, в том числе уход и возврат. До переходов по сноскам и ссылкам обрабатывать выход из активной ячейки; незавершённый ввод дочернего NSTextView нельзя обойти проверкой только родителя. Ячейки используют одинаковую локальную TextKit-разметку для рисования и попадания, диапазон ссылки хранится относительно исходника ячейки; картинки формул не меняют исходные координаты.
- Разборы в `EditorCoordinator` идут через `MarkdownPresentationBuilder`. Фоновые (ссылка по Cmd-клику, блоки кода при детаче) — `MarkdownPresentationBuilder.parse(...)` в `Task.detached` с `isCancelled: { Task.isCancelled }`. Синхронные по явной команде пользователя (форматирование, правки CriticMarkup, ячейка и Tab/строки таблицы) — `explicitCommandPresentation`: модель текущей версии (`document.markdownModel(forRevision:)`, если совпали длина, синтаксис и флаги `editorIncludes()`), иначе один синхронный разбор; после правки текста модель устаревшая, берётся свежий разбор. Признак заметки хранилища (`MarkdownObsidianComment.appliesTo(documentURL:)`) учитывается и при выборе модели, и в запасном разборе, и в Cmd-клике: команды в vault-заметке учитывают `%%`.
- `MarkdownHeadingAnchors` задаёт единые ID и псевдонимы заголовков для редактора и HTML. Сохранять прежние правила Unicode и конфликтов имён. `MarkdownLinkNavigationService` декодирует фрагмент один раз, разрешает относительный файл от URL документа и не выбирает рабочий каталог для несохранённого файла. Внешние http/https/mailto открываются системным приложением только по явному действию. Открытие другого поддерживаемого файла идёт через существующий WindowManager с проверкой идентичности и ожиданием чтения; перед переходом проверяются исходный запрос, активное целевое окно и точный снимок назначения. Диапазоны голых GFM email восстанавливаются общим захватом исходных TEXT-узлов до autolink; неоднозначное соответствие не угадывается. Именованные HTML-якоря сравниваются по точным UTF-8, без объединения канонически эквивалентных Unicode-строк. Ссылки предпросмотра проходят текущий DOM nonce и существующий путь открытия; отсутствующий Markdown создаётся только после подтверждения и повторных проверок актуальности.
- Сноски используют `CMARK_OPT_FOOTNOTES` в общем разборе и предпросмотре; заголовки внутри определений не попадают в оглавление. Подсказки и Cmd-переходы временные, проверяют актуальность и очищаются при смене документа/представления. HTML-предпросмотр допускает только свои якоря fn-/fnref- без ослабления остальных правил URL.
- Генерация скрытых глифов для уже установленного блочного Markdown-изображения использует быстрый путь для пакетов, полностью находящихся внутри его исходного диапазона; не выполнять полный набор Markdown-проверок для каждого символа Base64 data URI.
- `DocumentStatistics` считает составные символы и строки исходного текста, слова Markdown — по `MarkdownReadableText` из того же дерева cmark, что оформление. Один Han-знак — одно слово; остальные слова разделяет Foundation. Скорость чтения и краткий показатель задаются в существующих настройках, по умолчанию 200 слов/мин и число слов.
- `EditorDocument` принимает читаемую проекцию только после сверки с актуальным синхронизированным снимком; ввод, внешняя замена и смена языка снимают её актуальность. Выделение, версия, отмена и поколение расчёта проверяются до публикации. Не подставлять исходный подсчёт слов вместо отсутствующего результата Markdown. Неподдержанная HTML-разметка и неоднозначная часть преобразованного токена пока дают недоступную статистику. Разбор делается по экранному тексту (с media-токенами), поэтому при непустой карте контроллер передаёт `MarkdownReadableText.inSource(_:sourceLength:)` (диапазоны фрагментов, их `pieces` и `unsupportedRanges` в координатах файла; участок (и фрагмент `pieces`, и заголовок), пересекающий токен (`MarkdownMediaMap.intersectsToken`), получает `matchesSource == false`) и файловый текст `mediaTable.restore(...)`; иначе установка не проходила бы сверку и статистика слов не появлялась.
- `MarkdownPresentationController` запускает общий разбор также для включённой статистики в исходном представлении при закрытом оглавлении; это не разрешает применять атрибуты оформления. Незавершённый системный ввод, включая редактор ячейки, откладывает публикацию. Переключение документа передаёт сохранённую скорость чтения, даже если сама настройка не менялась.
- `markdownMaximumWidth` ограничивает ширину обоих представлений Markdown при переносе строк; по умолчанию `AppPreferences.defaultMarkdownMaximumWidth` = 760 pt. Явное «без ограничения» хранится как 0 (nil в модели); при отсутствии сохранённого ключа и при неверном значении берётся 760, поэтому один раз 760 получают и пользователи, у которых прежнее «без ограничения» было записано отсутствием ключа. `markdownTypography` считает ширину заданной пользователем только при сохранённом ключе. Горизонтальный inset редактора не меньше `EditorTextView.minimumHorizontalInset` (16 pt), текст при переносе не шире области минус 32 pt. Существующий `applyLayout` центрирует контейнер горизонтальным inset; перенос отключён — сохраняется горизонтальная прокрутка без ограничения ширины. Вертикальный inset/typewriter остаётся независимым. Во время marked text изменение ждёт существующей отсрочки метрик родителя/ячейки. `MarkdownTypography.usesCustomFontMetrics` сохраняет прежний шрифт preview, когда пользователь изменил только ширину; печать ограничивает ширину доступной областью бумаги.
- GFM email-координаты восстанавливаются из `MarkdownTextSourceCapture` до/после штатного postprocess того же cmark-разбора. Общий `MarkdownSourcePositions` обслуживает переходы и статистику (копирование с оформлением идёт через модель документа, U4.5); не искать совпадающий адрес по всему документу. Сопоставлять полный literal, учитывать entities, UTF-16 и одну карту на ячейку.
- `markdownLightColors` и `markdownDarkColors` хранят необязательные проверенные RGBA-значения текста, фона, ссылки, фона кода и цитаты. Пустое значение сохраняет системный цвет. Цвет текста применяется временными атрибутами, фон — свойством представления; исходник, атрибуты ввода и отмена не меняются. Снимок передаётся предпросмотру и PDF; изменения родителя и ячейки ждут окончания marked text.
- `markdownTOCMaxLevel` (1–6, по умолчанию 6) ограничивает видимые уровни бокового и встроенного оглавлений, предпросмотра и PDF. Полный список заголовков и адреса переходов сохраняются. Изменение уровня не включает пользовательские метрики шрифтов и не требует нового разбора Markdown.
- Подтверждённые emoji-shortcodes разрешаются общим локальным resolver. Оглавление получает отдельное отображаемое название, не меняя исходное название и якорь. Статистика и оформленное копирование используют ту же проекцию исходных диапазонов; выделение части преобразованного токена не угадывается. Подсказки после `:` (`EmojiShortcodeResolver.popularCompletions`) показывают не больше 20 имён: сначала список `popular` по данным Unicode о частоте эмодзи, затем порядок каталога Gemoji. Ruby, у которого в основе или подписи есть имя известного эмодзи (`containsShortcode`), `provenRuby` не подтверждает: он остаётся исходником в редакторе, предпросмотре и копировании.
- Emoji разрешаются локальным каталогом `Resources/Gemoji` (gemoji v4.1.0, закреплённая ревизия и MIT LICENSE в ресурсе); отдельный процесс Pandoc для поиска имени не используется. Полное совпадение закрытого каталога Typora этим не утверждается.
- Меню Markdown вставляет встроенную и блочную формулы через общий MarkdownFormattingService и обычную одну undo-группу. Пробный текст подтверждает общий Math parser, исходник не меняется до принятого edit. Блочная формула поддерживает целиком выбранный paragraph в quote/list/task (обход `MarkdownDocumentModel`, не cmark): префикс продолжения считается по тексту слева от маркера (`>`, пробелы и табы остаются, остальное — пробел), а корректность держит проверка пробой — candidate math range/literal и остальная структура сравниваются повторным разбором. Выноска и алерт считаются цитатой; цель формулы — абзац тела, заголовок выноски (`inlines`) целью не бывает. CR/LF/CRLF нормализуются лишь для сравнения literal, исходное выделенное содержимое остаётся прежним. Пустой leaf EOF quote `> ` и list/task с маркером и 1–4 пробелами создают пустое тело (`>⇥- ` тоже даёт пустую формулу с префиксом `>⇥␣␣`, а `-⇥- ` отказывает) и сохраняют структуру. Partial/lazy/неподтверждённый пустой контейнер/table и неподтверждённые task пока отказываются. Встроенная формула в цитате доступна; полная контейнерная поддержка остаётся открытой.
- Обычные bullet/ordered list markers подтверждаются тем же cmark и хранят точный source range/физическую строку. Ordered отображает start+sibling, bullet — •; source не переписывается. Control glyph резервирует измеренную ширину номера, рисование ограничено видимой областью; выделение редактируемой строки возвращает исходный marker. Continuation не создаёт новый marker, task checkbox остаётся отдельным. Source switch, fold и marked input должны вернуть прежние glyphs.
- Выбранные уровни заголовков могут использовать small caps (малые прописные) только при подтверждённой CoreText-функции шрифта; иначе редактор сохраняет начертание и настройки показывают индикатор. CSS предпросмотра может синтезировать начертание. Источник, anchors и размеры выбранного уровня не заменяются текстовой конвертацией.
- Направление RTL, выравнивание и интервалы абзацев входят в снимок оформления; нативные значения применяются к подтверждённым абзацам с восстановлением исходных атрибутов. HTML без оформления не получает эти декоративные правила. Вертикальная раскладка подключена к layout/линейке/блокам/дочерним представлениям.
- Incremental shift обычного текста внутри абзаца с inline-изображением подтверждается полным `MarkdownImage.paragraphRange`, даже если общий список paragraph ranges этот абзац не содержит. Диапазон самого media token остаётся запрещённой зоной: сдвиг допустим только для правки окружающего текста, которую можно однозначно перенести во все связанные media/formula/emoji диапазоны.
- `markdownNumberHeadings` выключен по умолчанию. Общий счётчик назначает поддержанным H1–H6 номера с точкой/пробелом, включая нулевые пропущенные уровни; определения сносок исключены как прежде. Raw title, source ranges, slug и anchors неизменны. - При раскрытии пронумерованного заголовка отступ номера снимается с новой строки и возвращается на ранее раскрытую. Если viewport временно недоступен, перестраивается объединение прежней и новой раскрытой строки; нельзя оставлять номер под выделением только из-за `visibleRange() == nil`.
- Изменение inline selection инвалидирует layout только для владельцев inline-маркеров и text replacements. Блочные контейнеры и paragraph separators не входят в этот индекс: каретка в обычном тексте не должна сбрасывать уже готовую раскладку.

- Преобразование существующего списка использует один исходный cmark tree и проверочный разбор результата явной команды. Выбранные пункты одного уровня меняют marker и подтверждённые отступы продолжений; вложенные пункты двигаются вместе с родителем. Checkbox не входит в block indentation. Текст, код, ссылки, принадлежность пунктов родителям, плотность списков и отображаемые номера невыбранных пунктов должны совпасть; иначе команда оставляет исходник. Top-level marker в начале строки допускает tab-stop4 в padding и continuation; остаточные колонки частично потреблённого tab сохраняются пробелами, body tabs не меняются. Checkbox принимается как задача, если он есть у пункта модели (`ListItem.task`); доказательство префикса контейнеров заменено проверкой пробой (результат не принимается, если структура изменилась). Применение остаётся одной editor replacement и undo-группой.
- Прописные заголовки включаются отдельно для H1–H6 и меняют только отображение. Source pieces сохраняют свои шрифты и стили, группы курсора объединяются по составным символам результата; доля TextKit между соседними позициями ввода не является числом UTF‑16 units. Для ß→SS, combining/emoji, вложенного оформления и вложений использовать ту же projection/геометрию; после раскрытия обычный NSTextView обрабатывает мышь и выделение. Исходник, anchors, undo, IME и raw title сохраняются.
- Задача в цитате в модели отличается от обычной тем, что флажок остаётся в тексте первого абзаца (`paragraph.range.location == task.markerRange.location`); у обычной задачи абзац начинается после флажка. Formatting для пункта с quote ancestor дополнительно доказывает начальный TEXT prefix и bodyRange: снимается только этот prefix при сравнении AST, пустой исходный TEXT не создаёт лишний узел. Math callback проверяет исходные байты/offset, не меняя тип cmark node; checkbox остаётся в исходнике. Не применять getter checked к обычному item как доказательство состояния и не менять глобальные callbacks библиотеки.
- `MarkdownSourcePositions.taskCheckbox` проверяет именно cmark item, байтовые block coordinates переводит в UTF-16 и считает marker padding по абсолютным tab-stop4 колонкам. Допустимы 1–4 колонки; Tab после checkbox или внутри body не означает автоматический отказ. Для нового quoted-tab fallback дополнительно подтверждаются первый paragraph/TEXT и точный marker/trivia prefix. Общий `MarkdownSourcePositions.range` и неоднозначные inline tab positions не расширяются этим правилом.
- При HTML-sensitive правке активной ячейки не переустанавливать старый полный snapshot: после завершения marked text используется временный снимок только текущей таблицы с raw cell text без runs. Старые HTML/link/image/media/SMART результаты и outline не считаются актуальными. Свежий background parse возвращает полное оформление после прежних generation/revision guards; обычный ввод не обходит документ.
- Настройки встроенных формул и прежних правил их границ используют существующие `markdownInlineMath`/`markdownLegacyInlineMath` и единый syntax snapshot. Defaults true/false не меняются; выключение встроенных формул не сбрасывает выбранные совместимые правила и не отключает формулы в отдельных блоках.
- `markdownStrictMode` сохраняется в общих preferences и по умолчанию true. Свободный режим изменяет только подтверждённые правила no-space heading и недостаточного отступа списка через публичный API того же дерева. Диапазоны новых/расширенных владельцев находятся в документ-локальной карте `MarkdownSourcePositions` и учитываются `range`/`wholeLines`/`firstPosition`; tasklist не считать обычным item только по numeric type. Format, Copy, outline, anchor и export получают один syntax snapshot; перед применением фонового anchor сверять также текущий syntax. Export вправе точечно менять отдельную временную копию, но не документ/live text/dirty/undo. Whole-tree CommonMark roundtrip не применять: он меняет alerts/subscript. Неподтверждённые сложные случаи сохраняют строгий разбор.
- Markdown → Fountain: `FountainLint` — единый классификатор блоков (используется и для защиты `!` в экспортёре, и для проверки ответа ИИ), своя трактовка fountain.io. Экспортёр ставит `!` перед блоком, который по `FountainLint.classifyBlock` не действие и не размечен сознательно. Соответствие: заголовки → `#`×уровень (в проекте со сдвигом), абзацы → действие (мягкий перенос склеивается пробелом, между иероглифами без него), `---` и page-break → `===`, `<center>` → `> … <`, комментарий HTML → `/* */`, таблицы/код/формулы → текстовые строки с предупреждением, список — один блок действия без предупреждения, проза с ведущим `!` получает ещё один `!`, ведущая `.` считается принудительной сценой только перед распознанным префиксом (`.INT.`, `.ИНТ.`, `.内景`), иначе (`.NET is great`, заголовок `# .NET Tips`) это проза: строка идёт в защиту `!`, заголовок остаётся `#`-секцией, картинки и сноски → заметки `[[ ]]`, вики-ссылки → псевдоним или цель, `[[`/`]]` в тексте разводятся. Служебные символы U+E010/U+E011 для заметок на время преобразования; если они уже есть в тексте, комментарии не переносятся.
- Выноски Obsidian `> [!тип]±` выводит HTML-адаптер из узлов модели (`MarkdownCalloutRender` разбирает только маркер и подпись), в редакторе оформляются как алерт: span `.callout(label:kind:)` (маркер `[!тип]±` целиком скрыт вне курсора, вместо него цветная подпись «знак + название типа» по группе цвета `FoldLayoutManager.calloutColor`, без полосы), заголовок жирным, тело остаётся цитатой; свёрнутая выноска раскрыта. Комментарии `%%…%%` в заметках хранилища (`appliesTo(documentURL:)`; в остальных документах не обрабатываются) в редакторе — span `.obsidianComment` (признак заметки хранилища — `MarkdownParseOptions.isVaultNote`, смена адреса = смена опций = полный разбор) и приглушаются цветом `lacCommentText` тем же `reapplyDecorationColors`; знаки `%%` — маркеры (скрываются вне курсора), текст комментария остаётся видимым; предела по длине документа нет (разбор в фоне). В таблицах `%%` и CriticMarkup не оформляются. `![[…]]` в редакторе — запись `MarkdownWikiLink(isEmbed: true)` и span `.link` (знаки `![[`, `]]` — маркеры; Cmd-клик идёт общим путём `follow` → `followWikiLink`, неразрешённая цель приглушается, как у `[[…]]`); обратные ссылки и переименование встраивания не учитывают.
- Строка внутри абзаца, целиком занятая комментарием `%%…%%`, не рвёт абзац: число строк сохраняется, признак «не рвёт абзац» ставит маска `MarkdownSourceMask`, невидимых знаков в HTML нет. Между блоками (пустая строка сверху или снизу) остаётся пустая строка.

- Страница хранилища с рабочей зоной (`VaultPageMode.ownerZone`): всё вне раздела «Owner Notes» (включая метки и шапку) приглушается `lacMutedText` временным `.foregroundColor` поверх подсветки (`reapplyVaultPageDim`, вызывается сразу после `reapplyDecorationColors`, общий флаг очистки `hasCriticColors`); без прохода по тексту — две арифметические операции над кэшем зоны. Страницы «только чтение» (`.noZone`, `.damaged`, `.serverReport`) не приглушаются. Режим пересчитывается при внешней замене текста; серверная пересборка, убравшая метки, переводит вкладку в только чтение.

- Правка шапки заметки хранилища из панели (этап 6, `VaultFrontmatterEditor`, чистый модуль): меняется только строка поля («заплатка» — минимальный диапазон UTF-16 и замена), остальное остаётся байт в байт (порядок, кавычки соседей, комментарии, пустые строки, окончания строк, BOM). Границы шапки — `MarkdownFrontMatter.frontMatter`. Перед применением Yams перечитывает результат и сравнивает дерево до и после; расхождение — отказ «写入未通过检查». Значение пишется без кавычек, только если Yams читает его как ту же строку. Правятся однострочные скаляры и список `tags`; многострочное и сложное не трогается. Одна правка — одно действие отмены (`EditorRangeReplacementRequest.groupsUndo`, «修改属性»); на собранных сервером страницах форма только читает. `access_count` входит в служебные поля (`VaultServerRules.systemFrontmatterFields`). Исходящие ссылки панели (`VaultLinks`) строятся через `MarkdownWikiLinkExtractor` и `MarkdownWikiLinkResolver` по каталогу хранилища: без псевдонимов и обратных ссылок. «Показать изменения сервера» сравнивает текст с версией сервера, которую держит движок (`heldServerVersions`), либо с текстом до последнего серверного обновления (`VaultServerUpdateMemory`, до 2 МиБ, только пока вкладка открыта).
- Ядро (`MarkdownDocumentParser`, `MarkdownSourcePositions`): у пункта задачи колонка продолжения считается от `[` (отметка входит в содержимое), таблица внутри пункта задачи (`tasklist`) поддержана как во вложенном списке; незакрытый fenced-блок не скрывает свой открывающий маркер; табуляция в тексте заголовка оглавления заменяется пробелом (длина не меняется); `MarkdownSourcePositions.range` принимает однострочный узел, если от начала строки до его конца нет табуляции (табуляция дальше по строке не делает его колонки неоднозначными); хвостовые пробелы перед жёстким переносом не входят в диапазон текста при сверке. После жёсткого переноса `\` cmark не переходит на новую строку: текст сразу после `\` сопоставляется по сохранённым строкам абзаца, а узлы, чья строка «отстаёт» после последующих мягких переносов (`laggedNodes`), не получают диапазона и остаются исходником. Эмодзи внутри подтверждённой пары `<a href>…</a>` ищутся так же, как внутри `<u>`. Табуляция в начале строки контейнера или сразу после маркера (`>⇥`, `-⇥`, `[x]⇥`) частично входит в отступ: такие строки не скрывают пробелы и не заменяют мягкий перенос; в абзаце после определения ссылки табуляция внутри текста при такой табуляции префикса оставляет весь абзац без диапазонов, а `editingTextRange` не подтверждает узлы абзаца с определением ссылки, если в нём есть табуляция. Отступ после отметки вложенной задачи считается по колонкам от маркера пункта (те же 1–4 колонки).
- Позиции cmark принимаются только подтверждённые. Строки блока, где у strong, emph, strikethrough, link, code, цитаты или пункта нет подтверждённого диапазона (элемент остался исходником), ядро записывает в `MarkdownDocumentModel.unreliableRanges`, адаптер переносит их в `MarkdownPresentation.unreliableRanges` (целые строки блока, слитые и отсортированные). `shift`, `shiftMediaOnly`, `replacingTable`, `numberingHeadings` и `resolvingHeadingEmoji` поле сохраняют; участок, задетый правкой, растёт вместе с ней. `MarkdownDisplayMap` (`Models/MarkdownDisplayMap.swift`, «текст редактора ↔ видимый текст») не гадает внутри таких участков: перевод позиции строго внутри даёт `unreliableRegion`, правка — `forbidden(.unreliableRegion)`. Что скрыто и чем заменено, карта берёт из полей презентации; новые потребители (T2–T4) не должны дублировать логику скрытия. Заголовок без span не помечается: его маркер `#` не скрывается, позиции верны. Раскрытие маркеров (`Reveal`) повторяет `FoldLayoutManager.touches`: при смене правил там менять и карту.
- `MarkdownDocumentModelCorpusTests` (U2.6) сверяет модель единого разбора с cmark на корпусе: 702 примера GFM 0.29 (`LacEditorTests/Fixtures/GFMSpec`, CC BY-SA 4.0, файлы не менять: хеши в `SOURCE.txt`) и документы `BaselineCorpus`, каждый текст в LF и CRLF, наборы настроек `editor`, `editorLoose`, `minimal`. Тест сам обходит дерево cmark и сравнивает: тело, info и ограждённость блоков кода (склейка `bodySegments` по исходнику равна `literal` cmark), текст и уровень заголовков, адреса ссылок и картинок, выравнивание, строки и текст простых ячеек таблиц; маркеры лежат внутри узла и не пересекаются; модель CRLF-текста равна LF-модели со сдвигом позиций на число `\n` слева; маска сохраняет длину и места переводов строк. Исключений нет, пропуск допустим только для узлов на строках маски (front matter, `%%`, CriticMarkup) и для ячеек не из простого набора; нижние планки «сравнено не меньше N» записаны в тесте константами. Читаемый текст при CRLF: многострочный фрагмент кода (литерал cmark с `\n`) находится в исходнике как литерал с `\r\n`, его `sourceRange` — мой диапазон со сдвигом, `matchesSource == false` (текст не равен исходнику побуквенно), `pieces` построчно: строка (`matchesSource == true`) и кусок `\r\n` длиной 2 с текстом `\n` (`matchesSource == false`); при LF кусков нет. HTML/media и wiki-ссылки в сверку не входят. `MarkdownSemanticRoundTripTests` проверяет, что переключение исходный текст → оформленный вид → исходный текст без правок не меняет ни байта текста.
- `MarkdownDocumentModel` (`Models/MarkdownDocumentModel.swift`) — общая модель документа единого слоя (`docs/markdown-unified-model-plan.md`): дерево блоков `MarkdownBlockNode` и строчных `MarkdownInlineNode` (диапазоны UTF-16 исходника, `markerRanges`, префиксы контейнеров по строкам листовых блоков, `isUnreliable`), `unreliableRanges`, индексы и необязательные данные по флагам `Includes` (`readableText`, `emoji`, `uppercaseRuns`, `elementIndex`, `blockIndex`, `editorContext`, `wikiLinks`, `noteEmbeds`, `criticMarkup`). Модель не импортирует cmark, AppKit, WebKit и SwiftUI. Блок кода хранит `bodySegments` (отрезки тела без префиксов контейнеров), `isClosed`, `literal`; диаграмма — поле `diagram` блока кода. Типы HTML-медиа берутся из `MarkdownHTMLMediaService` и `MarkdownPresentation`, не копируются. Модель пока никем не используется: разбор строит её с U2.3, адаптеры — с U3 и U5. Правило для новых возможностей: узел в модели, затем вывод в оба адаптера, затем эталон. Строчные узлы единого разбора (`Preview/MarkdownDocumentParser+Inline.swift`): wiki-ссылки, эмодзи и `![[…]]` ищутся по исходнику и текстовым узлам; эмодзи и wiki гасятся, если у родителя или предков есть неподтверждённый `html_inline` (кроме пар `<u>` и `<a>`), как в `MarkdownEmojiCandidateExtractor`; `![[…]]`, край которого попадает внутрь не-текстового узла (`![[a **b]] c**`), встраиванием не считается — отличие от панели, которая подставляет его до cmark. HTML (`+HTML.swift`): неподтверждённые строчные теги, ruby и `<br>` (с атрибутом, внутри script/template) попадают в `MarkdownDocumentModel.blockedHTML`.
- Блоки кода единого разбора (`Preview/MarkdownDocumentParser+CodeBlock.swift`, `codeBlockLayout`): число строк тела определяет `literal` cmark, а не конец узла (у ограждённого блока `end_line` cmark стоит на строке закрытия, даже если блок оборвала цитата, пункт или конец текста). Отрезок каждой строки ищется как конец исходной строки, всё слева — только пробелы, табы и `>` по числу цитат; закрыт блок, только если `end_line` узла указывает на строку сразу после тела, она внутри родителя и содержит ограждение не короче открывающего. Строки только по `\n`, `\r`, `\r\n`. Не сошлось (NUL, неожиданный `end_line`, закрытие) — `nil`: узел `isUnreliable` без отрезков и ограждений, позиции не выдумываются. Диапазон узла не включает последний перевод строки; `MarkdownCodeBlock.range` у незакрытого блока его включает. Разбор ограждений не вызывает `source.fenceRange`; `fenceRange` остаётся только у буфера обмена (соседние контейнеры).

Верна панель, поэтому: маркеры эмфазы/strong полные; закрывающие `#` ATX-заголовка входят в range заголовка; у вложенных цитат маркеры свои без дублей; блоки кода с отступом не включают хвостовые пустые строки; код в табах получает `codeBlock`-span; ссылки и автоссылки (в т. ч. голые URL и `www.`) имеют точный диапазон без `<>`; `<audio>/<video>` отдельной строкой — HTML-блок, а не абзац; `spans` идут в порядке документа; маркеры `***текст***` разводятся, как у cmark. `<kbd>` в ячейке таблицы редактор оформляет, а панель выводит тегом (старое расхождение). `smartRawHTMLRanges` равен `nil` («не запрошено») без флага `.emoji` (`includeEmojiCandidates`). Известные потери оформления — spec 9 (`\t - baz`) и spec 518 (многострочная ссылка с заголовком); список — в разделе «Изменения оформления в редакторе» `docs/markdown-unified-model-plan.md`.
- Абзац на строке с табом, помеченный ненадёжным, подтверждается по первому и последнему подтверждённому строчному узлу (`MarkdownDocumentParser.confirmedParagraphRange`), иначе остаётся ненадёжным; многострочная ссылка (адрес или заголовок на нескольких строках) получает диапазон через ту же сверку с исходником, что и картинка (`MarkdownSourcePositions.range`). Сервисы правки (`MarkdownEditingNode.model`) разбирают без умной пунктуации: подпись и заголовок картинки берутся буквально; проба подписи в `MarkdownImageEditingService.isComplexAlt` идёт без формул (внутри картинки их нет и в панели) и с CriticMarkup (alt модели уже без разметки, правка потеряла бы её).
- HTML предпросмотра, экспорта и PDF строит адаптер `MarkdownHTMLRenderer` (`Preview/MarkdownHTMLRenderer*.swift`) по `MarkdownDocumentModel`; подготовки текста перед cmark и правки готового HTML нет. Страница и её данные (`MarkdownRenderedPage`) лежат в `Preview/MarkdownRenderedPage.swift`.

## Единый слой Markdown

- Один разбор на версию текста: маска (`MarkdownSourceMask`: front matter, `%%`, wiki, CriticMarkup) → ядро (`Preview/MarkdownDocumentParser*.swift`, cmark) → модель `MarkdownDocumentModel` (`Models/`, значение `Sendable`, диапазоны UTF-16 исходника) → два адаптера: HTML (`Preview/MarkdownHTMLRenderer*.swift`) и TextKit (`Editor/MarkdownPresentationBuilder*.swift`, вход `MarkdownPresentationBuilder.parse`). Копирование с оформлением идёт по модели (`Services/MarkdownClipboardProjector*.swift`; RTF и картинки — `MarkdownClipboardCopyService`). Подтверждение HTML и медиа — в ядре (`MarkdownHTMLProof`, `MarkdownHTMLConfirmation`), одинаково для панели и редактора.
- Новая возможность: узел в модели → вывод в оба адаптера → эталоны (`Fixtures/RenderBaseline`, `Fixtures/PresentationBaseline`) → правила в `docs/agents/`. Второй разбор текста вне ядра и правку готового HTML не добавлять. Эталоны перезаписываются (`LAC_RECORD_BASELINE=1`) только вместе с правилом (`testing.md`). Сборка на Mac и прогон эталонов пока не выполнялись.

- Заменитель `MarkdownSourceMask` выбирается только из отсутствующих в исходнике символов U+E000…U+F8FF или U+FFFF. Если все заняты, маска возвращает исходный текст без сегментов: CriticMarkup и комментарии в этом редком случае остаются исходником, пользовательские символы не удаляются.
