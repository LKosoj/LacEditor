# Окна, вкладки и запуск

Читать при изменении окон, системных вкладок, закрытия и выхода, боковой панели как части окна, открытия из Finder, Dock и командной строки, папки запуска.

- Начинать изменения жизненного цикла с `App/WindowManager.swift`, `App/LacEditorApp.swift` и `App/AppState.swift`. Окна редактора, включая первое, создаёт и удерживает AppKit через `WindowManager`; сцена SwiftUI используется для настроек. Не добавлять второй независимый путь создания окна редактора.
- В обычном интерфейсе системная вкладка — отдельное `NSWindow` со своим `AppState`. При этом модель `AppState.documents` остаётся массивом для существующих операций; не заменять это предположением, что массив всегда содержит ровно один документ.
- Окна редактора восстанавливаются через `WindowManager` и снимки сессии; системное AppKit state restoration для создаваемых вручную окон отключено, чтобы не запускать второй путь восстановления.
- Сохранять общий экземпляр `AppPreferences` для состояний окон и направлять команды в активное состояние через `WindowManager`. Не подменять его состоянием первого созданного окна.
- Последняя выбранная пользователем видимость боковой панели хранится в `UserDefaults` и имеет приоритет над полем старого снимка рабочей сессии. Восстановление документов и вкладок не должно снова открывать панель или перезаписывать это значение, в том числе после остановки приложения из Xcode без штатного завершения.
- Наблюдение за нативным `NSSplitViewItem.isCollapsed` и фактическим изменением геометрии split view отражает пользовательское переключение, включая штатную кнопку AppKit; перед демонтажем split view наблюдение отключать, чтобы служебное изменение при закрытии окна не записывало панель как открытую.
- Кнопка боковой панели в toolbar использует собственный идентификатор и вызывает `AppState.toggleSidebar`; не возвращать системный `NSToolbarToggleSidebarItem`, который сворачивает split view в обход сохраняемого состояния. Старую сохранённую конфигурацию toolbar мигрировать заменой только этого идентификатора.
- Начальная установка ширины боковой панели не должна вызывать `setPosition` для уже свёрнутого `NSSplitViewItem`: AppKit при этом раскрывает панель и ошибочно сохраняет новое состояние.
- Открытие файла проверяет `DocumentFileIdentity` среди окон и активирует уже открытый документ. Сохранять эти проверки также для «Сохранить как» и сохранения при закрытии. Идентичность определяется ресурсом файла либо каноническим путём с разрешением символических ссылок, а не одним отображаемым именем.
- Системный диалог импорта фильтрует поддерживаемые форматы через `allowedContentTypes` и содержит выпадающий список «Все поддерживаемые форматы»/конкретное расширение; расширение дополнительно проверяет `PandocImportService` после выбора. Не дублировать полный список расширений длинным сообщением в окне.
- PDF с текстовым слоем импортируется отдельно через PDFKit: текст сохраняется постранично, поддерживаемые растровые PDF XObject-изображения встраиваются в Markdown как data URI без записи файлов рядом с исходником. Сканированные PDF без текстового слоя не импортируются; векторная графика и неподдерживаемые маски не подменяются снимками страниц.
- Перенос вкладки между окнами выполняет AppKit: системная вкладка переходит вместе со своим `NSWindow` и `AppState`. Собственной полосы вкладок и переноса `EditorDocument` между состояниями окон нет; не создавать документ заново только из строки текста.
- Сохранять различие между закрытием документа, окна и завершением приложения. При закрытии последнего заполненного документа в единственной системной вкладке окно заменяет его пустым документом; пустая вкладка либо вкладка в группе может закрыть своё окно. Повторное открытие через Dock и открытие файла через Finder проходят существующую координацию окна.
- Закрытие и выход ожидают текущие сохранения. Подтверждения несохранённых документов обрабатываются последовательно, отмена останавливает дальнейшее закрытие; не обходить эти пути прямым удалением состояния или вызовом завершения приложения.
- `WindowManager.openFilesFromFinder` и ранняя очередь используют одинаковую маршрутизацию каталога/файла. Явно открытая папка меняет только `folderWorkspace` текущего состояния, не текст и не массив документов. Для нового файла родитель назначается только после фактического начала открытия, если root ещё отсутствует; отмена предупреждения и активация уже открытого файла папку не меняют.
- `startupFolderPath` — путь в общих настройках, пусто по умолчанию. Выбор пути не открывает папку немедленно. Первый register сначала применяет восстановление и затем выбирает default только при root=nil и пустой ранней очереди Finder. Одноразовый флаг ставится до восстановления вкладок, которое само может регистрировать окна. Dock reopen не применяет default повторно. Поздняя папка Finder меняет root обычным открытием, поздний файл следует прежним правилам выбранной папки/автоматического родителя.
- Прямой запуск binary с позиционными путями передаёт их из `LacEditorApp.init` в общую раннюю очередь WindowManager до первого register. `-psn_…` пропускается, `--` разрешает имя с дефисом, неизвестная опция прекращает разбор путей; cwd фиксируется при запуске. Одинаковые ранние CLI/Finder пути объединяются, последующие явные открытия не подавляются. Существующий объект открывается обычным путём; отсутствующий CLI target создаётся только после NSAlert и повторной проверки состояния/диска. Отсутствующие родители не создаются; конкурентно появившийся объект не перезаписывается. Сессия/recovery/default-folder сохраняют прежний порядок, pending CLI также подавляет startup default.
- Схема `laceditor://open?path=…[&line=…[&column=…]]` и `laceditor://stdin?id=<UUID>` (команда `lacedit`) принимается `AppDelegate.handleGetURL` (свой обработчик Apple Event `kAEGetURL`) и передаётся в `WindowManager.openLaceditURL`; разбор — `LaceditRequest`, строгий: абсолютный путь без `..` и нуля, `line`/`column` — десятичные числа 1…999 999 999, лишние поля, повторы и чужие хосты отклоняются. Очередь холодного запуска общая с Finder/CLI (`PendingOpen` несёт `line`/`column`, id stdin ждут в `pendingStdinIDs`). Адрес открывает только существующий файл или папку (с папкой строка игнорируется; скрипт `lacedit --line N папка` тоже открывает папку), ничего не создаёт; если в активном окне уже есть рабочая папка, папка из адреса открывается только после подтверждения `NSAlert` с путём (`PendingOpen.confirmsFolderReplacement`, `presentLaceditFolderConfirmation`), отказ ничего не меняет, файл открывается без вопроса; неверный адрес и отсутствующий путь молча игнорируются. Строка и столбец считаются по тексту файла (`space: .source`), столбец — в `Character`, строка за концом файла — конец файла. Текст stdin читается только из `NSTemporaryDirectory()/lacedit-stdin/<UUID>.txt` (`LaceditStdinInbox.take`): свой обычный файл не больше 50 МиБ в UTF-8, файл всегда удаляется; результат открывается несохранённой вкладкой. Прямой запуск binary с путями не меняется.
- История переходов (`NavigationHistory` в `WindowManager`) общая для всех окон, не сохраняется в сессию и хранит `documentID`, строку и столбец (до 50 записей в каждом из двух стеков). Возврат фокусирует окно документа через `focus`; закрытые и ещё читаемые документы (заглушка открытия, `ioState != .idle`) пропускаются и отбрасываются. При незавершённом вводе (marked text) команды ничего не делают.
- `WindowManager` владеет единственным `OpenFileWatcher` (`openFileWatcher`). Набор наблюдаемых каталогов пересчитывается по `objectWillChange` состояний окон (пауза 0,2 с, подписки хранятся по `windowID` и снимаются в `unregister`), а также в конце `register`/`unregister`; проверка всех документов идёт из `applicationDidBecomeActive`.
- Порядок документов для поиска по всем открытым (`WindowManager.openDocumentSearchSources`): сначала группа вкладок активного окна (`tabGroup.windows`), затем остальные группы в порядке `NSApp.orderedWindows`, внутри окна — `AppState.documents`; состояния без окна идут последними. `revealOpenDocumentMatch` активирует вкладку через `focus` и переносит панель поиска в её окно.
- Писательский режим вкладки: `AppState.writerSession` (`WriterSession`) — общая на корень проекта, реестр `WindowManager.writerSessions[стандартизованный путь]` (`WindowManager+Writer.swift`); вкладки привязываются через `attachWriter`/`detachWriter`, пустая сессия удаляется, окно проекта закрывается вместе с ней. Режим включается кнопкой панели инструментов или меню «Вид»: если у вкладки открыта рабочая папка, берётся она (`enableWriterMode` → `startWriterProject`), окно выбора папки показывается только без папки: есть `.laceditor/project.json` — привязка, нет — мастер `ManuscriptProjectWizardView`, лист `writerWizardSheet`), выключается «Выйти из режима» (вкладка обычная, папка и документы остаются) или «Закрыть проект» (все вкладки проекта). Новая вкладка из писательской наследует проект, если файл внутри корня (`inheritedWriterSession`, `openFile(inheritsWriter:)`); результат сборки книги открывается в обычной вкладке с наследованием. В сессию пишется `WriterProjectSession` (корень и `projectID`, необязательное поле, старые сессии читаются); при восстановлении проект с тем же `projectID` привязывается, иначе вкладка обычная с плашкой «Проект не найден» (третий accessory окна, `WriterProjectBanner`), запись хранится до решения пользователя. Повреждённый манифест при восстановлении считается ненайденным.
- Результат экспорта в Fountain без записи в файл открывается в новой несохранённой вкладке «Обычный текст» (`openNativeTab(from:with:inheritsWriter:)`, `inheritsWriter: true` при сессии проекта). Лист `fountainSheet`/`fountainStorage` закрывается в `closeAuxiliaryWindows()` вместе с остальными листами.
- Автосохранение: у каждого `AppState` (окна) свой `AutosaveController` и свой таймер (создаётся только при включённой настройке). Пока идёт подтверждение закрытия (`confirmClosing`, счётчик `closeConfirmationDepth`, `isClosingDocument`) и после `WindowManager.terminationApproved` оно не пишет; общий флаг `WindowManager.isConfirmingClose` (счётчик `beginCloseConfirmation`/`endCloseConfirmation`) держится на всё время `confirmClosingAllWindows` и `windowShouldClose` до фактического закрытия, поэтому автосохранение других окон тоже стоит. Таймер сам завершается, когда окно освобождено, иначе выбор «Не сохранять» был бы нарушен. Закрытие документа вызывает `autosave.forget(id)`.
- Окна доски и сводного просмотра немодальные, принадлежат `WriterSession` (`boardWindow`, `combinedWindow`), регистрируются через `registerAuxiliaryWindow`; `detach()` отменяет фоновые задачи обоих контроллеров. Позднее закрытие окна не должно применять результаты.
- `WriterSession.world` (`StoryCardWorld`): каталог карточек, AI-контроллер и окно кандидатов проекта; `detach()` последнего окна вызывает `world.cancelAll()` (отмена сканирования и AI, закрытие листа кандидатов).

- Окно ментальной карты хранится в `AppState` (`mindMapController`, `mindMapWindowController`), закрывается в `closeAuxiliaryWindows()` через `closeMindMapWindow()`; контроллер держит `appState`/`windowManager` слабо. Виды «Проект» и «Связи» доступны только в писательской вкладке (`MindMapController.unavailableReason`).
- Режим хранилища (этап 4): одна `VaultSession` на приложение (`WindowManager.activeVaultSession`), вкладки привязываются через `AppState.vaultSession`/`vaultNote` (`attachVault`/`detachVault`), взаимоисключение с писательской сессией в одной вкладке. Запуск идемпотентен (`ensureVaultSession`, общий `vaultStartTask`). «Закрыть хранилище» (`leaveVault`) закрывает вкладки заметок обычным `performClose` (с вопросом о сохранении), сессию останавливает, файлы `Vaults/<id>/open/` оставляет. Снимок сессии хранит `VaultNoteBinding` (id подключения и путь на сервере); при восстановлении вкладка привязывается заново (`restoreVaultNote`), без связи работает локальная копия. Старые снимки без поля читаются.
- Режим хранилища, уточнения: `ensureVaultSession` ставит `activeVaultSession` до конца запуска; при изменении настроек того же подключения старая сессия останавливается, вкладки переходят к новой, другое хранилище при работающем не открывается (только `enterVault` с подтверждением). `leaveVault` по очереди закрывает вкладки заметок, ждёт ответа на вопрос о сохранении (отмена оставляет сессию и вкладку), затем `waitForClosings()` и `stop()`. Повторное открытие заметки ждёт её закрытия в движке (`closingTasks`). При первом запуске сессии за сеанс вызывается `cleanupAfterCrash(restoredPaths:)` по привязкам из файла сессии. В вкладке писателя `attachVault` сначала спрашивает о выходе из режима.
