# LacEditor

中文 · [English](README.en.md) · [Русский](README.ru.md)

一款安静、快速、真正属于 macOS 的文本与代码编辑器。

LacEditor 为日常文本、Markdown、JSON 和代码编辑而生：打开即写，标签切换顺手，预览只在需要时出现，复杂功能藏在原生菜单和快捷键里。本地编辑无需登录或云端；可选 AI 和 Jina 功能启用并运行后，会向所选服务发送所需内容。

## 为什么是 LacEditor？

- **打开就能写**：没有账号、工作区向导和多余的项目配置，启动后直接进入编辑区。
- **专注但不简陋**：多标签、查找替换、语法高亮、Markdown 预览和 JSON 工具都在手边，界面仍保持克制。
- **像 macOS 应用一样自然**：原生窗口、菜单、文件选择器、快捷键、深色模式和拖拽行为全部遵循系统习惯。
- **大文件也能继续工作**：针对长代码和日志文件采用可视区布局、后台任务和分级保护策略，优先保证输入与滚动流畅。
- **本地处理文字**：编辑、预览和恢复无需登录或联网；导出时 Pandoc 可能下载文档中引用的资源。

## 核心体验

### 写作助手

命令位于「AI 写作助手」菜单及其侧边面板。「设置 → 人工智能」中每个功能都有独立开关，默认全部关闭，后台处理另有开关。拼写与语法使用 macOS 系统检查，可分别设置，不向 AI 模型发送文本，也不自动替换单词。语言支持和质量由 macOS 决定。

提供清晰表达、重写（改写/缩短/扩写/调整语气）、翻译、一致性检查（术语与矛盾）、读者视角（语气与难懂之处）、结构、摘要、任务与决策、表格，以及「向文档提问」（仅依据当前文档/选区、当前窗口已打开的文档或所选文件作答，附可核对、可定位的引用，对话仅保存在当前窗口内存中；启用 Jina 搜索后可勾选「在互联网上搜索」，由模型通过函数调用（需服务器支持）每个回答最多搜索 3 次，启用 Reader 时按网页内容核对引用，网络来源单独列出且仅在点击时打开，「解释所选内容」为其菜单命令）。每项功能在菜单提示、AI 面板和设置中都有「需要／结果」说明，图片右键菜单有「使用 AI 描述图片」。接受前可比较原文与修改，接受后可正常撤销；编辑会使旧结果失效。一致性报告分为术语和矛盾两部分，可跳转到两个片段，摘要通过独立按钮插入。灰色续写用 Tab 接受、Esc 或继续输入取消；大文件不自动续写。元数据在面板中给出，可手动修改，并可在保存后更新，仅保留在当前文档对象。

选区翻译支持选择 13 种语言或输入其他语言，先预览再接受，并可正常撤销。AI 设置可为每项 AI 功能（包括翻译）及每条自定义检查选择独立模型；留空继承默认模型，服务地址、密钥和协议沿用对应类型的连接。

插图需主动生成并预览，可另存文件或作为内嵌 Markdown 图片插入选区之后。图片说明会发送所选图片的实际数据，需要支持图片输入的文本模型。

文本、Decisions 和图像分别配置地址、模型和协议，密钥存于系统钥匙串。OpenAI 使用 `https://api.openai.com/v1`，兼容的自定义服务可手动设置。来源搜索和网页读取使用 Jina，搜索与读取有独立开关、完整接口地址和密钥，默认为 `https://s.jina.ai/search`、`https://r.jina.ai/`。关闭 Reader 时仅显示未经验证的候选链接；启用后检查引文是否存在于获取的正文中，不保证语义正确。生成的二进制图片正常下载，Jina 用于读取网页。

另有六个手动工具：根据所选文档审阅（含其他窗口未保存的标签页）、两个版本的精确比较和解释、保存自定义检查、图片/PDF 识别、语音草稿和 Mermaid 生成。各工具单独启用后在同一助手面板选择。上下文结果提供经过核对的引文和来源跳转，不自动扫描目录；每条自定义规则也有独立开关。

识别和音频有独立配置。Gateway PDF 通过 `/v1/pdf/convert` 请求 `output=docx`，再由内置 Pandoc 转换；兼容图片输入的模型可使用 Responses/Chat Completions。音频使用 `/v1/audio/transcriptions`。请填写自己的地址和可用模型，相邻网关配置中的例子是 `llmgateway/pdf-converter`、`llmgateway/whisper-large-v3`。

可主动录音或选择现有音频文件，单独运行才发送；拒绝麦克风权限不影响导入。识别文本、转录和 Mermaid 块需点击后才插入并支持撤销；比较不修改源文件。识别和语音也支持空文档。

请求最多等待 10 分钟。网络错误区分超时、无网络、找不到服务器和安全连接失败，并提供手动「重试」（不会自动重试）。模型回复可带 ```json 代码围栏；无法核对的条目会被跳过并提示数量。手动发送超过 50 KB（去除内嵌媒体后按 UTF-8 计）时不会直接发送，面板会显示来源和大小，确认「仍然发送」后才发送；后台处理和自动续写超过 50 KB 时不运行。发送后面板显示来源和大小。图片、OCR 和音频不受此限制。

### 编辑文本与代码

支持 TXT、Markdown、JSON、HTML、JavaScript、TypeScript、CSS、Python、Swift、Shell、YAML、C/C++、SQL 等常见格式。提供行号、当前行高亮、自动缩进、Tab 缩进、撤销重做、基础折叠和括号配对高亮。

可分别选择正文和代码的字体族；修改后的字号与行距会传递到预览、PDF 和 PNG。本地音频由内置播放器播放，不自动播放。格式化编辑器可复制为纯文本、HTML 和 RTF，并在粘贴时转换 HTML/RTF；另有单独的复制 Markdown、复制 HTML 代码及粘贴为源文本命令。

查找与替换是编辑器上方的内嵌栏：匹配计数、正则表达式、整词，`⌘E` 用选区查找，`Esc` 关闭。`⌘L` 和状态栏中的光标位置可打开跳转到行。行号靠右对齐，标尺宽度随位数变化。编辑器水平边距至少 16 pt，Markdown 最大宽度默认 760 pt，可在设置中取消限制。

### Markdown 双栏预览

编辑与预览左右并排，实时渲染标题、段落、列表、引用、分割线、链接、行内代码、代码块、表格和 GFM 扩展。预览可随时关闭，长文档不会被迫进入笔记式工作流。

Mermaid、flow 和 sequence 图表显示在预览（`⌥⌘P`）和格式化编辑器中。引擎随应用本地提供，语法错误时保留源码和提示。图表右键菜单可复制 PNG 或保存 SVG、PNG、JPG；SVG 来自同一次渲染的矢量结果。支持的导出配置会为 Pandoc 准备临时图片，不修改文档 Markdown。

```mermaid
flowchart LR
    A[Start] --> B[End]
```

另支持数学公式及其在 HTML、DOCX 和 EPUB 中的图片、PDF 页面设置和 HTML 附加内容。浅色与深色配色可自定义，目录可限制标题层级，emoji 来自本地目录。

预览跟随编辑器滚动，显示加载状态和带「重试」的错误提示。提示块按类型着色，代码块按语言高亮（也用于 PDF 和打印），引用条、复选框和选区使用系统强调色。打印与 PDF 始终使用浅色主题。

### Markdown 源码与格式化编辑

「显示 → Markdown 编辑方式」可切换「Markdown 源码」和「格式化文本」。两种视图编辑同一份文档，切换不会转换正文。格式化视图支持标题、粗体、斜体、删除线、行内代码、链接、引用和代码块。已确认的行内标记按所选元素显示，同一行相邻元素保留排版。复制生成纯文本和 HTML，保真度已确认时附加 RTF；单独命令复制 Markdown 源码。已确认的普通列表标记以原生方式显示，编辑所在行时恢复源码。GFM 表格（包括不完整行及列表/引用中的表格）提供网格、单元格编辑、Tab 导航、多行文本，以及用鼠标拖动行列。本地、网络和 data URI 图片可在编辑器中显示，包括行内、嵌套和表格图片，以及 GIF 动画和 SVG。选择仅适用于当前标签页，恢复会话后显示源码。

### 格式命令和大纲

「Markdown 格式」菜单可在两种视图中添加或移除粗体（`⌘B`）、斜体（`⌘I`）、删除线、行内代码、1–6 级标题和引用；另有 `⌘K`（链接）、`⇧⌘K`（行内代码）、`⇧⌘X`（删除线）和 `⌥⌘1–6`（标题），图片操作归入「图片管理」子菜单。未选中文本时，行内命令插入成对标记；标题和引用作用于选中行。每个命令可单独撤销。不会移除未确认或已转义的标记。行内格式跨越多个段落，以及代码块内的块级命令不会修改正文。

另有从普通文本行创建无序列表、有序列表、任务列表、围栏代码块和分隔线的命令。

侧边栏的「文档大纲」显示当前 Markdown 文档的标题。点击可将光标移至标题并展开折叠区域。修改后在后台更新列表，过期条目不能用于跳转。大纲在源码和格式化视图中均可使用，后者复用同一解析结果。此部分默认收起，重启后不保留展开状态。

任务框可点击，列表自动续行与缩进。普通 GFM 表格有行列命令，行内链接有对话框，脚注有提示和 Cmd 跳转。设置中可分别开启括号/引号和 Markdown 标记的自动配对，默认均关闭。另有相邻段落淡化和打字机模式。Markdown 词数按可读内容计算，字符和行数按源码或选区计算。可在设置中选择状态栏统计项和阅读速度。

### 文档导入和导出

「文件 → 导出」可将 Markdown 转换为 HTML、Word（DOCX）、ODT、RTF、EPUB、FB2、LaTeX、纯文本、PDF、MediaWiki、RST、Textile 和 OPML。应用内置 Pandoc 3.13，无需单独安装或在启动时下载。PDF 通过 WebKit 和系统打印生成，无需额外 LaTeX。导出使用当前正文，包括未保存修改和没有路径的新文档，不改变源文档。新文档需要先选择 Markdown 语言。Pandoc 按 GFM 转换，排版可能与预览不同；导出时可能下载文档中引用的网络资源。HTML 内嵌图片；LaTeX 的相对路径以源文件所在文件夹为准。

「文件 → 导入…」支持 DOCX、ODT、RTF、EPUB、FB2、HTML、LaTeX 和带文字层的 PDF，创建新的未保存 Markdown 标签页，不修改源文件。识别出的内嵌和本地图片会写入文档正文；网络图片保留链接，导入过滤器不会下载它们。复杂排版和图片尺寸可能无法保留；复杂 LaTeX 命令中的图片也可能丢失。内嵌 HTML 页面不会被下载或显示在预览中；文件的相对链接保持相对形式。没有文字层的扫描 PDF 不会被导入；TXT 和 Markdown 使用普通的「打开」命令。

### JSON 工具不打乱内容

格式化和压缩只调整结构空白，保留对象字段顺序、重复键、数值字面量和字符串转义写法；无效 JSON 会尽量报告行号与列号。所有修改都可以用一次撤销恢复。

### 文件与窗口管理

支持多窗口、多标签、标签拖动排序、标签拖出成窗口、最近文件、收藏夹和自定义分组。同一个磁盘文件在多个窗口中只会打开一个可编辑实例，外部文件发生变化时默认不会静默覆盖。

快速打开 `⌘⇧O` 以编辑器上方的浮动面板显示，在当前文件夹、固定文件夹和最近文件夹中搜索，并高亮匹配字符。通过 Finder 传入或拖入窗口的文件夹在同一窗口中打开；新文件在还没有选择工作文件夹时，会加载其父文件夹。空文档提供「打开文件夹…」和最近文件。标题栏提供路径菜单（⌘ 点击）。

工作文件夹以目录树或列表显示，并在标签页中打开文件。支持创建、复制、移动、重命名和废纸篓（可撤销最近一次操作），四种排序，以及对展开目录的变更监听；文件夹状态按标签页分别保存。同一面板中的名称、正文和 YAML 标签搜索会计入已打开文档的未保存文本，并在跳转前验证结果。侧栏支持键盘操作、输入定位和 VoiceOver；收藏和分组的右键菜单有「上移」「下移」。

可通过「显示」菜单、工具栏按钮或 `⌃⌘B` 显示/隐藏左侧栏。「显示 → 进入专注模式」（`⇧⌘J`）让编辑器占满窗口工作区，隐藏侧栏、预览、行号、状态栏和工具栏。再次执行命令会恢复之前状态，不改变共享设置；`⌃⌘B` 也可退出此模式并显示侧栏。系统标签页和窗口按钮仍保留，不会进入系统全屏。此模式仅属于当前窗口，重启后不恢复。

设置带有搜索框，可滚动到匹配项并高亮。工具栏可通过 macOS 自定义，使用系统强调色。

在「设置 > 文件关联」查看常见格式的默认打开应用，按需将其设为 LacEditor；不会在安装或启动时自动更改。

### 笔记与编辑增强

- **命令面板**（`⇧⌘A`，「显示 → 命令面板…」）：编辑器上方的浮动面板，列出主菜单中所有可用命令，按名称和菜单路径搜索，显示快捷键，`Return` 执行、`Esc` 关闭。不显示不可用、隐藏及系统菜单项（服务、窗口）；与快速打开不会同时出现。不使用 `⇧⌘P`，因其已用于「页面设置…」。
- **行操作与注释**：「编辑 → 行操作」提供复制当前行（`⇧⌘D`）、上移当前行/下移当前行（`⌃⌘↑`/`⌃⌘↓`）、删除当前行（`⌃⇧K`）、合并行（`⌃⌘J`）和升序/降序排序（自然顺序，稳定；只选一行时排序整篇文档）。「切换注释」（`⌘/`）支持 Swift、JS/TS、C、Python、Shell、YAML、SQL（行注释）及 HTML、Markdown、CSS（逐行块注释）；JSON 和纯文本不支持。每个命令为一次撤销。
- **历史版本与磁盘比较**：每次成功保存后写入 macOS 文件版本（失败不影响保存）。「文件 → 浏览版本…」逐行比较所选版本与当前文本，「恢复此版本」作为一次可撤销的替换，文档保持未保存；「与磁盘文件比较…」按文档编码比较磁盘文件。无路径文档不可用，版本由系统管理，无删除界面。
- **换行符与编码**：状态栏显示 LF、CRLF、CR 或「混合」，菜单显示计数并可转换为 LF/CRLF/CR（也在「编辑 → 换行符」）。转换为一次替换、一次撤销，U+2028/U+2029 不算换行。「文件 → 以编码保存…」仅修改写入编码（文档变为未保存，无法表示的字符会拒绝保存）；「以编码重新打开…」按所选编码重新读取磁盘文件（有未保存修改时先确认，撤销历史会重置）。
- **Wiki 链接**：Markdown 支持 `[[名称]]`、`[[名称#标题]]`、`[[名称|文字]]`。按文件名在已打开的文件夹中查找（无文件夹则在文档所在目录）；同名多个时不猜测，需写路径。格式化视图中隐藏括号，未解析的链接为暗淡色；`⌘` 点击跳转（找不到时询问是否创建）；输入 `[[` 后给出文件名补全；预览与导出中替换为普通链接。表格和标题内的 Wiki 链接不识别，不支持嵌入 `![[…]]`。
- **反向链接**：打开文件夹后，侧栏「反向链接」分区列出其他 Markdown 文件中指向当前文件的普通链接和 Wiki 链接及行片段，点击跳转；包含已打开文档的未保存修改。该分区不写入会话。
- **标签**：文件夹标签搜索同时匹配 YAML front matter 标签和正文中的 `#标签`（标题、列表、引用、表格中也可），按完整标签、不区分大小写匹配（`#a` 匹配 `a` 与 `a/b`，不匹配 `ab`）。数字、`C#`、标题、代码、链接、Wiki 链接、HTML、公式和 `\#` 不算标签。侧栏「标签」分区显示标签及文件数，展开、换文件夹或「刷新标签」时读取，点击标签启动搜索；格式化视图中正文标签使用专门颜色。标签为平铺列表（不构建 `a/b` 层级），在展开、换文件夹和执行命令时更新；表格内标签不上色。
- **模板与每日笔记**：「文件 → 从模板新建笔记…」从模板文件夹选择 Markdown 模板并输入名称，在当前目录（否则工作文件夹根目录）创建且不覆盖已有文件，并打开它；模板中的 `{{title}}`、`{{date}}`（yyyy-MM-dd）、`{{time}}`（HH:mm）会被替换。「文件 → 每日笔记」打开或创建今天的笔记（模板文件夹中的 `daily.md`，没有则为空文件）。在「设置 → 文件与恢复 → 模板与每日笔记」设置模板文件夹、每日笔记文件夹和日期格式。每日笔记文件夹不存在时不会自动创建；没有工作文件夹时提示先打开。
- **在文件夹中替换**：文件夹内容搜索有区分大小写、正则、整词开关和「替换」模式：显示「原文 → 新文」预览、逐条勾选（默认全选）、「替换所选」，替换前确认匹配与文件数。未打开的文件直接以 UTF-8 原子写入，「撤销」无法还原；搜索后被修改的文件、非纯 UTF-8（如含 BOM）文件和符号链接会跳过并在结果中说明。已打开的文档作为编辑器中的一次替换（一次撤销），不会保存文件。名称与标签搜索没有替换功能。
- **阅读模式**（`⌥⌘R`，「显示 → 阅读模式」）：禁止编辑，保留选择、复制、查找和链接跳转。Markdown 以格式化视图显示，退出后恢复原视图。该模式只作用于当前标签页，不跨启动保留，状态栏显示其标识。
- **状态栏显示当前元素**：显示光标所在的 Markdown 元素路径，例如「标题 2 › 加粗」「引用 › 列表项 › 链接」。普通文本、选区、大文件、其他语言及宽度小于约 700 pt 的窗口不显示。
- **清晰的保存状态**：状态栏区分已保存、未保存（已有或尚无确认的恢复副本）、恢复副本写入失败和尚无文件的新文档；提示中显示上次保存时间。
- **写作目标**：设置项「每日字数目标」（0 为关闭）在状态栏显示「已写 / 目标」。按文档统计当日字数净增量，已关闭文档的贡献保留到当天结束；不发送通知。
- **在大纲中移动章节**：可拖动顶层标题，或用右键菜单的「上移章节」「下移章节」及 `⌥↑`/`⌥↓` 移动。章节连同子章节一起移动，一次撤销；标题级别不变。
- **固定与最近命令**：空查询时命令面板按「已固定」「最近使用」（最多 5 条）「所有命令」分组；行内图钉按钮或 `⌥↩` 固定/取消固定命令。命令以菜单名称路径识别，切换界面语言后旧记录不显示，但不删除。
- **聚焦当前句子**：「显示 → 聚焦当前句子」只保留当前句子高亮。表格、块级图片和竖排文字使用段落范围。
- **合并为文稿**：打开文件夹后，「文件 → 合并为文稿…」把选中的 `.md`/`.markdown` 合并到新的未保存标签页，可拖动或用按钮调整顺序。已打开文件的未保存修改会计入，未打开文件按 UTF-8 读取（其他文件跳过并提示）。元数据只保留第一个文件的，图片和链接的相对地址改为绝对地址，因此结果不能移到其他电脑使用。`[a][ref]` 写法、HTML 链接和媒体不转换并计入汇总；相同脚注标签会显示警告，需手动修改。文件末尾未闭合的代码块会吞掉下一个文件。源文件不变。
- **重命名时更新链接**：在已打开的文件夹内重命名或移动 Markdown 文件时，应用查找指向它的 Wiki 链接和普通链接并请求确认，默认不更新。已打开文档作为一次可撤销编辑修改，未打开文件（仅限无 BOM 的 UTF-8）直接写入磁盘；撤销重命名不会还原链接。文件夹、`file:` 地址、引用式链接、有歧义的名称、含 `# | [ ]` 的名称以及被移动文件自身的相对链接不会更新。
- **CriticMarkup 修订**：在源码和格式化视图中高亮 `{++ ++}`、`{-- --}`、`{~~ ~> ~~}`、`{>> <<}`、`{== ==}`；「Markdown → 修订」可建议插入、删除和添加批注，接受或拒绝当前或全部修订，并跳到下一处或上一处。表格、代码和 HTML 中的修订不识别，预览和导出按普通文本显示这些标记。

### 退出后继续工作

默认退出时保留完整工作区，下次启动恢复窗口、标签、正文、未保存状态、选区、滚动位置和界面状态。工作区快照与异常退出恢复分开保存，磁盘文件不会被自动改写；也可以在设置中切换为传统的退出前保存确认。

这也包括从未保存为文件的新文档。异常退出后恢复最后一次完成的恢复快照：写入延迟为 2 秒，大文档为 5 秒，因此最后的修改可能还没有写入。关闭文档时明确放弃保存会删除该文档的恢复数据。

退出时等待文件读取和保存；若写入工作区期间发生更改，会重新写入最新快照。若启动时无法安全恢复会话，应用会报告错误并停止启动，保留磁盘上的恢复数据。首次读取还没完成或已失败的文档，在成功读取前不能覆盖保存到原文件，也不能移到其他窗口。

### 界面语言

在「设置 > 外观 > 语言」中可选择跟随系统、中文、英语或俄语。更改将在重新启动应用后生效。

## 下载使用

在 [Releases](https://github.com/LKosoj/LacEditor/releases) 下载最新的 arm64 ZIP，退出旧版后解压，将 `LacEditor.app` 拖入“应用程序”并替换。需要 Apple Silicon 和 macOS 26 或更高版本。设置和工作区会保留。每个版本的内容见 [CHANGELOG.md](CHANGELOG.md)；本 README 描述的是仓库当前代码。

首次打开本机 ad-hoc 签名版本时，如果 macOS 阻止启动，请前往“系统设置 > 隐私与安全性”允许打开。

## 从源码构建

`LacEditor` scheme 的 Debug 使用独立开发身份及数据；正式安装包通过 `zsh Scripts/package-release.sh` 生成。
`LacEditor-UI-Experiment` scheme 保留独立实验身份。
正式安装包沿用正式数据，独立实验包的数据不会自动迁移。

环境要求：

- macOS 26+
- Apple Silicon Mac
- Xcode 26+

```bash
git clone https://github.com/LKosoj/LacEditor.git
cd LacEditor
sh Scripts/prepare-pandoc.sh
swift build
swift test
```

准备步骤从 `Vendor/Pandoc` 解压已验证的官方归档，无需联网。Xcode 自动执行此步骤。解压后的 Pandoc 使应用增加约 186 MiB，仓库中的归档约为 41 MiB。版本、许可证和源码分发说明见 [Vendor/Pandoc/README.md](Vendor/Pandoc/README.md)。

需要运行完整发布验收时：

```bash
./Scripts/run-acceptance.sh
```

也可以用 Xcode 打开 `LacEditor.xcodeproj`，选择 `LacEditor` scheme 后按 `Command+R`。

### 脚本

脚本位于 `Scripts` 文件夹，在 macOS 上运行。它们只使用仓库中的文件：源码、Pandoc 和版本号均取自本地，不会从 Git 下载任何内容，也不会向任何地方发送。Swift 依赖由 Swift Package Manager 按 `Package.swift` 中的地址下载。

| 脚本 | 作用 |
| --- | --- |
| `prepare-pandoc.sh` | 校验 `Vendor/Pandoc` 中归档的校验和，将 Pandoc 解压到 `LacEditor/Resources/Pandoc` 并允许其运行。通过 Swift Package Manager 构建前需要执行；Xcode 会自动执行此步骤。 |
| `verify-release.sh` | 发布前检查：版本号一致性、Debug 和 Release 构建、XCTest、独立的核心检查，以及 Xcode 中的 Release 构建。 |
| `run-acceptance.sh` | 完整验收：包含 `verify-release.sh` 的全部内容，以及 Xcode 代码分析、1、10、20、50 和 100 MB 文件检查、架构和验收应用检查。结束后会取消构建副本作为文件处理程序的注册。 |
| `verify-bundled-pandoc.sh` | 检查已构建 `.app` 内的 Pandoc：是否存在、arm64 架构、版本 3.13、许可证文件、导入过滤器和签名。应用路径作为参数传入。 |
| `package-candidate.sh` | 构建发布候选版；带 `--release` 时构建正式包：Release 构建、签名、ZIP 归档、归档及解压副本的检查。不安装、不发布，也不写入 Git。 |
| `package-release.sh` | 调用 `package-candidate.sh --release`。 |
| `build-production.sh` | 构建可发布版本：运行 `verify-release.sh` 和 `package-release.sh`，并在 `dist` 中生成 `LacEditor-<版本>-arm64.zip` 压缩包及其 `.sha256` 校验文件。最后输出把这两个文件上传到 GitHub Release 的命令。版本取自 `VERSION`，脚本不会修改它；新版本需先用 `prepare-release.sh` 设置。 |
| `package-experiment.sh` | 构建独立的实验版「LacEditor 实验版.app」，不会替换正式版。 |
| `prepare-release.sh` | 接受形如 `1.2.3` 的新版本号，要求 `CHANGELOG.md` 中有对应条目，检查该标签不存在，修改 `VERSION` 以及项目中的版本和构建号，并运行 `verify-release.sh`。不创建提交和标签，只打印相应命令。 |
| `clean-build-artifacts.sh` | 显示 `.build`、`.swiftpm`、`build` 和 `DerivedData` 的大小。仅在带 `--confirm` 参数和项目的确切路径时才删除它们。 |
| `file-associations.sh` | 不带参数时显示已注册为文件处理程序的应用副本。`--unregister-build <路径>` 取消单个构建副本的注册，`--clean` 取消除安装在「应用程序」中的副本之外的所有副本。不会更改默认应用。 |

## 技术方向

从 0.14.0 起使用 macOS 原生窗口标签，支持系统拖动、拆出与合并。旧版工作区会按原顺序恢复为原生标签组，继续保留未保存内容、正式文件路径和 Finder 打开方式。

LacEditor 使用 SwiftUI 构建界面，AppKit `NSTextView` 负责编辑，TextKit 负责可视区布局，WebKit 配合 `cmark-gfm` 负责本地 Markdown 预览。文件读写、语法扫描、搜索替换、JSON、预览和恢复各自保持独立，后台任务通过文档 revision 校验，过期结果不会覆盖较新的编辑内容。编辑器的基础仍是 TextKit 1。

后续优化方向见 [NEXT_OPTIMIZATIONS.md](NEXT_OPTIMIZATIONS.md)。Git、插件系统和云同步不属于 LacEditor 的主要规划。
