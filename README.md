# LacEditor

中文 · [English](README.en.md) · [Русский](README.ru.md)

一款安静、快速、真正属于 macOS 的文本与代码编辑器。

LacEditor 为日常文本、Markdown、JSON 和代码编辑而生：打开即写，标签切换顺手，预览只在需要时出现，
复杂功能藏在原生菜单和快捷键里。本地编辑无需登录或云端；可选 AI 和 Jina 功能启用并运行后，会向所选服务发送所需内容。

## 为什么是 LacEditor？

- **打开就能写**：没有账号、工作区向导和多余的项目配置，启动后直接进入编辑区。
- **专注但不简陋**：多标签、查找替换、语法高亮、Markdown 预览和 JSON 工具都在手边，界面仍保持克制。
- **像 macOS 应用一样自然**：原生窗口、菜单、文件选择器、快捷键、深色模式和拖拽行为全部遵循系统习惯。
- **大文件也能继续工作**：针对长代码和日志文件采用可视区布局、后台任务和分级保护策略，优先保证输入与滚动流畅。
- **本地处理文字**：编辑、预览和恢复无需登录或联网；导出时 Pandoc 可能下载文档中引用的资源。

## 核心体验

### 写作助手

当前源码分支提供「AI 写作助手」菜单和侧边面板。「设置 → 人工智能」中每个功能都有独立开关，默认全部关闭，后台处理另有开关。拼写与语法使用 macOS 系统检查，可分别设置，不向 AI 模型发送文本，也不自动替换单词。语言支持和质量由 macOS 决定；关闭拼写时语法检查的实际行为仍需在 Mac 上验证。

源码已接入清晰表达、改写、缩短、扩写、翻译、术语、语气、结构、摘要、矛盾、行动项、决策、表格和读者审阅。接受前可比较原文与修改，接受后可正常撤销；编辑会使旧结果失效。术语和矛盾报告可跳转到两个片段，摘要通过独立按钮插入。灰色续写用 Tab 接受、Esc 或继续输入取消；大文件不自动续写。元数据可在保存后更新并手动修改，仅保留在当前文档对象。来源记录只追踪启用后的本地事件，不猜测未知来源，重启后不保留。

插图需主动生成并预览，可另存文件或作为内嵌 Markdown 图片插入选区之后。图片说明会发送所选图片的实际数据，需要支持图片输入的文本模型。判断问题和提取笔记中的决策是独立功能。

文本、Decisions 和图像分别配置地址、模型和协议，密钥存于系统钥匙串。OpenAI 使用 `https://api.openai.com/v1`，兼容的自定义服务可手动设置。来源搜索和网页读取使用 Jina，搜索与读取有独立开关、完整接口地址和密钥，默认为 `https://s.jina.ai/search`、`https://r.jina.ai/`。关闭 Reader 时仅显示未经验证的候选链接；启用后检查引文是否存在于获取的正文中，不保证语义正确。生成的二进制图片正常下载，Jina 用于读取网页。

构建、XCTest、输入、系统检查和界面仍需在 Mac 上验证。本环境未运行真实模型或 Jina 请求，也未评估模型的三语质量。[计划与限制](docs/plans/2026-10-28-ai-editor-design.md)。

源码另接入七个手动工具：根据所选文档审阅（含其他窗口未保存的标签页）、两个版本的精确比较和解释、保存自定义检查、图片/PDF 识别、语音草稿、Mermaid 生成及解释选区。各工具单独启用后在现有助手面板选择。上下文结果提供经过核对的引文和来源跳转，不自动扫描目录；每条自定义规则也有独立开关。

识别和音频有独立配置。Gateway PDF 通过 `/v1/pdf/convert` 请求 `output=docx`，再由内置 Pandoc 转换；兼容图片输入的模型可使用 Responses/Chat Completions。音频使用 `/v1/audio/transcriptions`。请填写自己的地址和可用模型，相邻网关配置中的例子是 `llmgateway/pdf-converter`、`llmgateway/whisper-large-v3`。编辑器不会安装或修改网关。

可主动录音或选择现有音频文件，单独运行才发送；拒绝麦克风权限不影响导入。识别文本、转录和 Mermaid 块需点击后才插入并支持撤销；比较与解释不修改源文件。识别和语音也支持空文档。真实模型、录音、PDFKit、构建和 XCTest 仍需在 Mac 上验证。[七项功能计划](docs/plans/2026-10-28-selected-ai-tools.md)。


### 编辑文本与代码

支持 TXT、Markdown、JSON、HTML、JavaScript、TypeScript、CSS、Python、Swift、Shell、YAML、C/C++、SQL
等常见格式。提供行号、当前行高亮、自动缩进、Tab 缩进、撤销重做、基础折叠和括号配对高亮。

### Markdown 双栏预览

编辑与预览左右并排，实时渲染标题、段落、列表、引用、分割线、链接、行内代码、代码块、表格和 GFM
扩展。预览可随时关闭，长文档不会被迫进入笔记式工作流。

当前源码分支可在预览（`⌥⌘P`）中显示标记为 `mermaid` 的代码块。内置本地 Mermaid 12.2.0，无需联网。图表随浅色/深色主题更新，语法错误时显示源码和错误提示。已在 Chromium 中检查流程图和时序图，仍需在 Mac 上验证 WebKit。这仅用于预览；Pandoc 导出目前保留 Mermaid 代码。

```mermaid
flowchart LR
    A[Start] --> B[End]
```

### Markdown 源码与格式化编辑

当前源码分支可在「显示 → Markdown 编辑方式」中切换「Markdown 源码」和「格式化文本」。两种视图编辑同一份文档，切换不会转换正文。格式化视图支持标题、粗体、斜体、删除线、行内代码、链接、引用和代码块。已确认的语法标记在编辑段落以外隐藏，选中相应区域时显示；复制仍使用 Markdown 源码。列表标记、表格、图片及无法确定的语法暂时保留源码。选择仅适用于当前标签页，恢复会话后显示源码。这是格式化编辑的第一阶段，并非 Typora 的全部功能；构建、光标、撤销、中文输入和性能仍需在 Mac 上验证，此功能尚未包含在 0.15.0 发布版中。

### 格式命令和大纲

当前源码分支可通过「Markdown 格式」在两种编辑视图中添加或移除粗体（`⌘B`）、斜体（`⌘I`）、删除线、行内代码、1–6 级标题和引用。未选中文本时，行内命令插入成对标记；标题和引用作用于选中行。每个命令可单独撤销。不会移除未确认或已转义的标记。行内格式跨越多个段落，以及代码块内的标题或引用命令不会修改正文。

侧边栏的「文档大纲」显示当前 Markdown 文档的标题。点击可将光标移至标题并展开折叠区域。修改后在后台更新列表，过期条目不能用于跳转。大纲在源码和格式化视图中均可使用，后者复用已有解析结果。此部分默认收起，重启后不保留展开状态。这些功能仍需在 Mac 上验证构建和界面。

### 文档导入和导出

当前源码分支的「文件 → 导出」可将 Markdown 转换为 HTML、Word（DOCX）、ODT、RTF、EPUB、FB2、LaTeX、纯文本和 PDF。应用内置 Pandoc 3.13，无需单独安装或在启动时下载。PDF 仍需额外的生成引擎，默认使用 LaTeX。导出使用当前正文，包括未保存修改和没有路径的新文档，不改变源文档。新文档需要先选择 Markdown 语言。Pandoc 按 GFM 转换，排版可能与预览不同；导出时可能下载文档中引用的网络资源。HTML 内嵌图片；LaTeX 的相对路径以源文件所在文件夹为准。

「文件 → 导入…」支持 DOCX、ODT、RTF、EPUB、FB2、HTML 和 LaTeX，创建新的未保存 Markdown 标签页，不修改源文件。识别出的内嵌和本地图片会写入文档正文；网络图片保留链接，导入过滤器不会下载它们，本地预览也不会显示它们。复杂排版和图片尺寸可能无法保留；复杂 LaTeX 命令中的图片也可能丢失。内嵌 HTML 页面不会被下载或显示在预览中；文件的相对链接保持相对形式。暂不支持导入 PDF；TXT 和 Markdown 使用普通的「打开」命令。这些功能尚未包含在已发布的 0.15.0 中，仍需在 Mac 上验证构建和界面。

### JSON 工具不打乱内容

格式化和压缩只调整结构空白，保留对象字段顺序、重复键、数值字面量和字符串转义写法；无效 JSON 会
尽量报告行号与列号。所有修改都可以用一次撤销恢复。

### 文件与窗口管理

支持多窗口、多标签、标签拖动排序、标签拖出成窗口、最近文件、收藏夹和自定义分组。同一个磁盘文件
在多个窗口中只会打开一个可编辑实例，外部文件发生变化时默认不会静默覆盖。

当前源码分支可通过「显示」菜单、工具栏按钮或 `⌃⌘B` 显示/隐藏左侧栏。「显示 → 进入专注模式」（`⇧⌘J`）让编辑器占满窗口工作区，隐藏侧栏、预览、行号、状态栏和工具栏。再次执行命令会恢复之前状态，不改变共享设置；`⌃⌘B` 也可退出此模式并显示侧栏。系统标签页和窗口按钮仍保留，不会进入系统全屏。此模式仅属于当前窗口，重启后不恢复。仍需在 Mac 上验证构建和界面。

在「设置 > 文件关联」查看常见格式的默认打开应用，按需将其设为 LacEditor；不会在安装或启动时自动更改。

### 退出后继续工作

默认退出时保留完整工作区，下次启动恢复窗口、标签、正文、未保存状态、选区、滚动位置和界面状态。
工作区快照与异常退出恢复分开保存，磁盘文件不会被自动改写；也可以在设置中切换为传统的退出前保存确认。

这也包括从未保存为文件的新文档。异常退出后恢复最后一次完成的恢复快照：写入延迟为 2 秒，大文档为 5 秒，因此最后的修改可能尚未写入。关闭文档时明确放弃保存会删除该文档的恢复数据。

当前源码分支在退出时等待文件读取和保存；若写入工作区期间发生更改，会重新写入最新快照。若启动时无法安全恢复会话，应用会报告错误并停止启动，保留磁盘上的恢复数据。首次读取尚未完成或失败的文档，在成功读取前不能覆盖保存到原文件，也不能移到其他窗口。

### 界面语言

当前源码分支支持在「设置 > 外观 > 语言」中选择跟随系统、中文、英语或俄语。更改将在重新启动应用后生效；此功能尚未包含在已发布的 0.15.0 中。

## 从源码构建

当前分支使用现有 SwiftUI + AppKit，无需安装 Flutter。
`LacEditor` scheme 的 Debug 使用独立开发身份及数据；正式安装包通过 `zsh Scripts/package-release.sh` 生成。
`LacEditor-UI-Experiment` scheme 保留独立实验身份，详情见 [实验版说明](docs/UI_EXPERIMENT_README.md)。
正式安装包沿用正式数据，独立实验包的数据不会自动迁移。RC 候选阶段的打包与验证说明保留在 [候选阶段文档](docs/RELEASE_CANDIDATE.md)。

环境要求：

- macOS 26+
- Apple Silicon Mac
- Xcode 26+

```bash
git clone https://github.com/kolmh/LacEditor.git
cd LacEditor
sh Scripts/prepare-pandoc.sh
swift build
swift test
```

准备步骤从 `Vendor/Pandoc` 解压已验证的官方归档，无需联网。Xcode 自动执行此步骤。解压后的 Pandoc 使应用增加约 186 MiB，仓库中的归档约为 41 MiB。版本、许可证和源码分发说明见 [Vendor/Pandoc/README.md](Vendor/Pandoc/README.md)。

需要运行完整发布验收时：

```bash
./Scripts/run-acceptance.sh
```

也可以用 Xcode 打开 `LacEditor.xcodeproj`，选择 `LacEditor` scheme 后按 `Command+R`。

## 技术方向

从 0.14.0 起使用 macOS 原生窗口标签，支持系统拖动、拆出与合并。旧版工作区会按原顺序恢复为原生标签组，继续保留未保存内容、正式文件路径和 Finder 打开方式。

LacEditor 使用 SwiftUI 构建界面，AppKit `NSTextView` 负责编辑，TextKit 负责可视区布局，WebKit 配合
`cmark-gfm` 负责本地 Markdown 预览。文件读写、语法扫描、搜索替换、JSON、预览和恢复各自保持独立，
后台任务通过文档 revision 校验，过期结果不会覆盖较新的编辑内容。

## 路线图

完整的性能与架构路线记录在 [docs/ROADMAP.md](docs/ROADMAP.md)，当前规划分为三阶段：

- 第一阶段：减少 Markdown 预览全文复制、完善搜索缓存、补齐行号和末尾空行回归测试。
- 第二阶段：按脏范围剪枝 Tree-sitter，拆分高亮/折叠任务，减少长代码文件的主线程工作。
- 第三阶段：基于外部资料完成架构评估，保留 TextKit 1 与当前文档生命周期；取消 TextKit 2 实验，推迟通用渲染适配层和大型类拆分。
当前工作代码补充了可取消的预览、统计和折叠任务、侧栏键盘选择与批量操作，以及优先加载选中标签的渐进工作区恢复。这些改动尚未发布：Mac 构建、XCTest、实际界面检查和前后性能对比仍待完成。详见[完成计划](docs/plans/roadmap-completion-plan.md)及[后续优化清单](NEXT_OPTIMIZATIONS.md)。

Git、插件系统、云同步和双向链接暂不属于 LacEditor 的核心路线。
