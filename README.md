# LacEditor

中文 · [English](README.en.md) · [Русский](README.ru.md)

一款安静、快速、真正属于 macOS 的文本与代码编辑器。

LacEditor 为日常文本、Markdown、JSON 和代码编辑而生：打开即写，标签切换顺手，预览只在需要时出现，
复杂功能藏在原生菜单和快捷键里。本地编辑无需登录或云端；可选 AI 和 Jina 功能启用并运行后，会向所选服务发送所需内容。

## 为什么是 LacEditor？

- **打开就能写**：没有账号、工作区向导和多余的项目配置，启动后直接进入编辑区。
- **专注但不简陋**：多标签、查找替换、语法高亮、Markdown 预览和 JSON 工具都在手边，界面仍保持克制。
- **像 macOS 应用一样自然**：原生窗口、菜单、文件选择器、快捷键、深色模式和拖拽行为全部遵循系统习惯。
- **大文件也能继续工作**：针对长代码和日志文件采用可视区布局、后台任务和分级保护策略，优先保证输入与滚动流畅。
- **本地处理文字**：编辑、预览和恢复无需登录或联网；导出时 Pandoc 可能下载文档中引用的资源。

## 核心体验

### 写作助手

当前源码分支提供「AI 写作助手」菜单和侧边面板。「设置 → 人工智能」中每个功能都有独立开关，默认全部关闭，后台处理另有开关。拼写与语法使用 macOS 系统检查，可分别设置，不向 AI 模型发送文本，也不自动替换单词。语言支持和质量由 macOS 决定；关闭拼写时语法检查的实际行为仍需在 Mac 上验证。

源码已接入清晰表达、重写（改写/缩短/扩写/调整语气）、翻译、一致性检查（术语与矛盾）、读者视角（语气与难懂之处）、结构、摘要、任务与决策、表格，以及「向文档提问」（仅依据当前文档/选区、当前窗口已打开的文档或所选文件作答，附可核对、可定位的引用，对话仅保存在当前窗口内存中；启用 Jina 搜索后可勾选「在互联网上搜索」，由模型通过函数调用（需服务器支持）每个回答最多搜索 3 次，启用 Reader 时按网页内容核对引用，网络来源单独列出且仅在点击时打开，「解释所选内容」为其菜单命令；旧的「解释」与「判断问题」设置自动迁移到此功能）。每项功能在菜单提示、AI 面板和设置中都有「需要／结果」说明；旧的 AI 设置会自动迁移到合并后的功能，图片右键菜单新增「使用 AI 描述图片」。接受前可比较原文与修改，接受后可正常撤销；编辑会使旧结果失效。一致性报告分为术语和矛盾两部分，可跳转到两个片段，摘要通过独立按钮插入。灰色续写用 Tab 接受、Esc 或继续输入取消；大文件不自动续写。元数据可在保存后更新并手动修改，仅保留在当前文档对象。

插图需主动生成并预览，可另存文件或作为内嵌 Markdown 图片插入选区之后。图片说明会发送所选图片的实际数据，需要支持图片输入的文本模型。

文本、Decisions 和图像分别配置地址、模型和协议，密钥存于系统钥匙串。OpenAI 使用 `https://api.openai.com/v1`，兼容的自定义服务可手动设置。来源搜索和网页读取使用 Jina，搜索与读取有独立开关、完整接口地址和密钥，默认为 `https://s.jina.ai/search`、`https://r.jina.ai/`。关闭 Reader 时仅显示未经验证的候选链接；启用后检查引文是否存在于获取的正文中，不保证语义正确。生成的二进制图片正常下载，Jina 用于读取网页。

构建、XCTest、输入、系统检查和界面仍需在 Mac 上验证。本环境未运行真实模型或 Jina 请求，也未评估模型的三语质量。[计划与限制](docs/plans/2026-10-28-ai-editor-design.md)。

源码另接入六个手动工具：根据所选文档审阅（含其他窗口未保存的标签页）、两个版本的精确比较和解释、保存自定义检查、图片/PDF 识别、语音草稿和 Mermaid 生成（解释选区改由「向文档提问」完成）。各工具单独启用后在现有助手面板选择。上下文结果提供经过核对的引文和来源跳转，不自动扫描目录；每条自定义规则也有独立开关。

识别和音频有独立配置。Gateway PDF 通过 `/v1/pdf/convert` 请求 `output=docx`，再由内置 Pandoc 转换；兼容图片输入的模型可使用 Responses/Chat Completions。音频使用 `/v1/audio/transcriptions`。请填写自己的地址和可用模型，相邻网关配置中的例子是 `llmgateway/pdf-converter`、`llmgateway/whisper-large-v3`。编辑器不会安装或修改网关。

可主动录音或选择现有音频文件，单独运行才发送；拒绝麦克风权限不影响导入。识别文本、转录和 Mermaid 块需点击后才插入并支持撤销；比较不修改源文件。识别和语音也支持空文档。真实模型、录音、PDFKit、构建和 XCTest 仍需在 Mac 上验证。[七项功能计划](docs/plans/2026-10-28-selected-ai-tools.md)。


### 编辑文本与代码

支持 TXT、Markdown、JSON、HTML、JavaScript、TypeScript、CSS、Python、Swift、Shell、YAML、C/C++、SQL
等常见格式。提供行号、当前行高亮、自动缩进、Tab 缩进、撤销重做、基础折叠和括号配对高亮。

当前分支还准备了正文/代码字体选择、将修改后的字号与行距传递至预览/PDF/PNG，以及不自动播放的初步本地音频播放器。格式化编辑新增初步的纯文本/HTML/RTF 复制和 HTML/RTF 粘贴转换，并提供单独的复制 Markdown、复制 HTML 代码及粘贴为源文本命令。复杂剪贴板内容和资源尚未完成。这些代码仍需在 Mac 上构建、运行 Swift 测试并验证。

当前分支还加入界面体验改进：查找替换改为编辑器上方的内嵌查找栏（匹配计数、正则、整词、⌘E 用选区查找、Esc 关闭），新增跳转到行（⌘L）和可点击的状态栏光标位置；侧栏支持键盘导航、输入定位和 VoiceOver；标题栏支持路径菜单（⌘ 点击）并使用系统强调色；行号靠右对齐并按位数调整宽度；设置新增搜索框、AI 分段页和删除确认；Markdown 预览跟随编辑器滚动；菜单重新归类，默认工具栏精简（已保存的工具栏配置不变）；编辑器水平边距至少 16 pt，Markdown 最大宽度默认 760 pt（可在设置中改为不限制）。后续界面打磨：Markdown 格式菜单新增 ⌘K 链接、⇧⌘K 行内代码、⇧⌘X 删除线和 ⌥⌘1–6 标题快捷键，图片操作归入「图片管理」子菜单，并新增「帮助」菜单；拖入文件夹即可打开该文件夹；空文档提供「打开文件夹…」和最近文件；快速打开高亮匹配字符；预览显示加载状态和带「重试」的错误提示，打印与 PDF 始终使用浅色主题；设置搜索会滚动并高亮匹配项，图片设置独立成页；AI 面板的运行/停止位于同一位置，修改输入只将结果标为过期，写作建议支持逐词高亮、「全部接受」和「全部拒绝」。随后的细节打磨：预览中的提示块按类型着色，代码块按语言高亮（也用于 PDF 和打印），引用条、复选框和选区跟随系统强调色；收藏和分组可通过右键菜单上移/下移；查找框新增清除按钮。当前分支还准备了 Markdown 宽度限制、本地 flow/sequence 和数学公式、HTML/DOCX/EPUB 图形导出、PDF 页面设置和 HTML 附加内容。Finder 传入的目录沿用已有窗口路径打开；新文件在尚未选择工作目录时加载父目录。完整功能与 Mac 验证仍在进行。

### Markdown 双栏预览

编辑与预览左右并排，实时渲染标题、段落、列表、引用、分割线、链接、行内代码、代码块、表格和 GFM
扩展。预览可随时关闭，长文档不会被迫进入笔记式工作流。

当前源码分支已准备在预览（`⌥⌘P`）和格式化编辑器中显示 Mermaid、flow 和 sequence 图表。引擎随应用本地提供，语法错误时保留源码和提示。图表右键菜单可复制 PNG 或保存 SVG、PNG、JPG；SVG 来自同一次渲染的矢量结果。支持的导出配置会为 Pandoc 准备临时图片，不修改文档 Markdown。已准备 Swift 测试及静态检查，WebKit、系统对话框和最终文件仍需在 Mac 上验证。

```mermaid
flowchart LR
    A[Start] --> B[End]
```

### Markdown 源码与格式化编辑

当前源码分支可在「显示 → Markdown 编辑方式」中切换「Markdown 源码」和「格式化文本」。两种视图编辑同一份文档，切换不会转换正文。格式化视图支持标题、粗体、斜体、删除线、行内代码、链接、引用和代码块。已确认的行内标记按所选元素显示，同一行相邻元素保留排版；格式化复制准备纯文本和 HTML，通过保真检查后附加 RTF；单独命令复制 Markdown 源码。已确认的普通列表标记以原生方式显示，编辑所在行时恢复源码；GFM 表格（包括不完整行及列表/引用中的表格）已准备可编辑网格、Tab 导航、多行单元格与行列拖动；本地、data URI 和网络图片可在编辑器中显示，包括行内、嵌套和表格图片。GIF 动画及 SVG 显示已准备，实际运行仍需 Mac 验证。选择仅适用于当前标签页，恢复会话后显示源码。这是格式化编辑的第一阶段，并非 Typora 的全部功能；构建、光标、撤销、中文输入和性能仍需在 Mac 上验证，此功能尚未包含在 0.15.0 发布版中。

### 格式命令和大纲

当前源码分支可通过「Markdown 格式」在两种编辑视图中添加或移除粗体（`⌘B`）、斜体（`⌘I`）、删除线、行内代码、1–6 级标题和引用。未选中文本时，行内命令插入成对标记；标题和引用作用于选中行。每个命令可单独撤销。不会移除未确认或已转义的标记。行内格式跨越多个段落，以及代码块内的标题或引用命令不会修改正文。

新增从普通文本行创建无序列表、有序列表、任务列表、围栏代码块和分隔线的命令。已有列表标记的转换仍是单独的后续任务。补充 UTF-16、CRLF、代码块和撤销的 XCTest；构建、测试及界面行为仍需在 Mac 上验证。

侧边栏的「文档大纲」显示当前 Markdown 文档的标题。点击可将光标移至标题并展开折叠区域。修改后在后台更新列表，过期条目不能用于跳转。大纲在源码和格式化视图中均可使用，后者复用已有解析结果。此部分默认收起，重启后不保留展开状态。这些功能仍需在 Mac 上验证构建和界面。

### 文档导入和导出

当前分支还准备了可点击任务框、列表续行与缩进、普通 GFM 表格的行列命令、行内链接对话框以及带提示和 Cmd 跳转的脚注。设置可分别开启括号/引号和 Markdown 标记配对，默认均关闭。另有当前段落聚焦与打字机模式；Markdown 词数按可读内容计算，字符和行数按源码或选区计算；可设置状态栏统计项和阅读速度。尚未支持的 HTML 内容暂不返回统计值。工作文件夹提供可展开目录树并沿用既有标签打开文件；已准备创建、复制、移动、重命名、废纸篓及最近操作的撤销；已准备每个标签页独立的文件夹状态保存、四种排序、树形/列表视图和展开目录的变更监听。同一侧栏已连接文件名/正文/YAML 标签搜索，使用打开文档的未保存快照，并在跳转前验证结果。已添加 Swift 测试，但构建、XCTest 与 Mac 行为尚未验证；完整 Typora 计划仍在开发中，CSS 主题已排除。

当前源码分支的「文件 → 导出」可将 Markdown 转换为 HTML、Word（DOCX）、ODT、RTF、EPUB、FB2、LaTeX、纯文本、PDF、MediaWiki、RST、Textile 和 OPML。应用内置 Pandoc 3.13，无需单独安装或在启动时下载。PDF 现改用 WebKit 和系统打印，无需额外 LaTeX；分页、图片、取消和输出仍待 Mac 验证。导出使用当前正文，包括未保存修改和没有路径的新文档，不改变源文档。新文档需要先选择 Markdown 语言。Pandoc 按 GFM 转换，排版可能与预览不同；导出时可能下载文档中引用的网络资源。HTML 内嵌图片；LaTeX 的相对路径以源文件所在文件夹为准。四种新增格式及其 XCTest 仍需在 Mac 上使用内置 Pandoc 验证。

「文件 → 导入…」支持 DOCX、ODT、RTF、EPUB、FB2、HTML 和 LaTeX，创建新的未保存 Markdown 标签页，不修改源文件。识别出的内嵌和本地图片会写入文档正文；网络图片保留链接，导入过滤器不会下载它们。复杂排版和图片尺寸可能无法保留；复杂 LaTeX 命令中的图片也可能丢失。内嵌 HTML 页面不会被下载或显示在预览中；文件的相对链接保持相对形式。暂不支持导入 PDF；TXT 和 Markdown 使用普通的「打开」命令。这些功能尚未包含在已发布的 0.15.0 中，仍需在 Mac 上验证构建和界面。

### JSON 工具不打乱内容

格式化和压缩只调整结构空白，保留对象字段顺序、重复键、数值字面量和字符串转义写法；无效 JSON 会
尽量报告行号与列号。所有修改都可以用一次撤销恢复。

### 文件与窗口管理

支持多窗口、多标签、标签拖动排序、标签拖出成窗口、最近文件、收藏夹和自定义分组。同一个磁盘文件
在多个窗口中只会打开一个可编辑实例，外部文件发生变化时默认不会静默覆盖。

当前源码分支可通过「显示」菜单、工具栏按钮或 `⌃⌘B` 显示/隐藏左侧栏。「显示 → 进入专注模式」（`⇧⌘J`）让编辑器占满窗口工作区，隐藏侧栏、预览、行号、状态栏和工具栏。再次执行命令会恢复之前状态，不改变共享设置；`⌃⌘B` 也可退出此模式并显示侧栏。系统标签页和窗口按钮仍保留，不会进入系统全屏。此模式仅属于当前窗口，重启后不恢复。仍需在 Mac 上验证构建和界面。

在「设置 > 文件关联」查看常见格式的默认打开应用，按需将其设为 LacEditor；不会在安装或启动时自动更改。

### 笔记与编辑增强

以下为当前源码分支的功能，不在已发布的 0.15.0 中；Mac 构建、XCTest 与界面均未验证。

- **命令面板**（`⇧⌘A`，「显示 → 命令面板…」）：编辑器上方的浮动面板，列出主菜单中所有可用命令，按名称和菜单路径搜索，显示快捷键，`Return` 执行、`Esc` 关闭。不显示不可用、隐藏及系统菜单项（服务、窗口）；与快速打开不会同时出现。不使用 `⇧⌘P`，因其已用于「页面设置…」。
- **行操作与注释**：「编辑 → 行操作」提供复制当前行（`⇧⌘D`）、上移当前行/下移当前行（`⌃⌘↑`/`⌃⌘↓`）、删除当前行（`⌃⇧K`）、合并行（`⌃⌘J`）和升序/降序排序（自然顺序，稳定；只选一行时排序整篇文档）。「切换注释」（`⌘/`）支持 Swift、JS/TS、C、Python、Shell、YAML、SQL（行注释）及 HTML、Markdown、CSS（逐行块注释）；JSON 和纯文本不支持。每个命令为一次撤销。
- **历史版本与磁盘比较**：每次成功保存后写入 macOS 文件版本（失败不影响保存）。「文件 → 浏览版本…」逐行比较所选版本与当前文本，「恢复此版本」作为一次可撤销的替换，文档保持未保存；「与磁盘文件比较…」按文档编码比较磁盘文件。无路径文档不可用，版本由系统管理，无删除界面。
- **换行符与编码**：状态栏显示 LF、CRLF、CR 或「混合」，菜单显示计数并可转换为 LF/CRLF/CR（也在「编辑 → 换行符」）；转换为一次替换、一次撤销，U+2028/U+2029 不算换行。「文件 → 以编码保存…」仅修改写入编码（文档变为未保存，无法表示的字符会拒绝保存）；「以编码重新打开…」按所选编码重新读取磁盘文件（有未保存修改时先确认，撤销历史会重置）。
- **Wiki 链接**：Markdown 支持 `[[名称]]`、`[[名称#标题]]`、`[[名称|文字]]`。按文件名在已打开的文件夹中查找（无文件夹则在文档所在目录）；同名多个时不猜测，需写路径。格式化视图中隐藏括号，未解析的链接为暗淡色；`⌘` 点击跳转（找不到时询问是否创建）；输入 `[[` 后给出文件名补全；预览与导出中替换为普通链接。表格、标题和 `![[…]]` 暂不支持。
- **反向链接**：打开文件夹后，侧栏「反向链接」分区列出其他 Markdown 文件中指向当前文件的普通链接和 Wiki 链接及行片段，点击跳转；包含已打开文档的未保存修改。该分区不写入会话。
- **标签**：文件夹标签搜索同时匹配 YAML front matter 标签和正文中的 `#标签`（标题、列表、引用、表格中也可），按完整标签、不区分大小写匹配（`#a` 匹配 `a` 与 `a/b`，不匹配 `ab`）。数字、`C#`、标题、代码、链接、Wiki 链接、HTML、公式和 `\#` 不算标签。侧栏「标签」分区显示标签及文件数，展开、换文件夹或「刷新标签」时读取，点击标签启动搜索；格式化视图中正文标签使用专门颜色。限制：标签为平铺列表（不构建 `a/b` 层级）；表格内标签不上色；列表不会随文件变化自动更新。
- **模板与每日笔记**：「文件 → 从模板新建笔记…」从模板文件夹选择 Markdown 模板并输入名称，在当前目录（否则工作文件夹根目录）创建且不覆盖已有文件；模板中的 `{{title}}`、`{{date}}`（yyyy-MM-dd）、`{{time}}`（HH:mm）会被替换。「文件 → 每日笔记」打开或创建今天的笔记（模板文件夹中的 `daily.md`，没有则为空文件）。在「设置 → 文件与恢复 → 模板与每日笔记」设置模板文件夹、每日笔记文件夹和日期格式。每日笔记文件夹不存在时不会自动创建；没有工作文件夹时提示先打开。
- **在文件夹中替换**：侧栏文件夹内容搜索新增区分大小写、正则、整词开关和「替换」模式：显示「原文 → 新文」预览、逐条勾选（默认全选）、「替换所选」，替换前确认匹配与文件数。未打开的文件直接以 UTF-8 原子写入，「撤销」无法还原；搜索后被修改的文件、非纯 UTF-8（如含 BOM）文件和符号链接会跳过并在结果中说明。已打开的文档作为编辑器中的一次替换（一次撤销），不会保存文件。名称与标签搜索没有替换功能。

### 退出后继续工作

默认退出时保留完整工作区，下次启动恢复窗口、标签、正文、未保存状态、选区、滚动位置和界面状态。
工作区快照与异常退出恢复分开保存，磁盘文件不会被自动改写；也可以在设置中切换为传统的退出前保存确认。

这也包括从未保存为文件的新文档。异常退出后恢复最后一次完成的恢复快照：写入延迟为 2 秒，大文档为 5 秒，因此最后的修改可能尚未写入。关闭文档时明确放弃保存会删除该文档的恢复数据。

当前源码分支在退出时等待文件读取和保存；若写入工作区期间发生更改，会重新写入最新快照。若启动时无法安全恢复会话，应用会报告错误并停止启动，保留磁盘上的恢复数据。首次读取尚未完成或失败的文档，在成功读取前不能覆盖保存到原文件，也不能移到其他窗口。

### 界面语言

当前源码分支支持在「设置 > 外观 > 语言」中选择跟随系统、中文、英语或俄语。更改将在重新启动应用后生效；此功能尚未包含在已发布的 0.15.0 中。

## 从源码构建

当前分支使用现有 SwiftUI + AppKit，无需安装 Flutter。
`LacEditor` scheme 的 Debug 使用独立开发身份及数据；正式安装包通过 `zsh Scripts/package-release.sh` 生成。
`LacEditor-UI-Experiment` scheme 保留独立实验身份，详情见 [实验版说明](docs/UI_EXPERIMENT_README.md)。
正式安装包沿用正式数据，独立实验包的数据不会自动迁移。RC 候选阶段的打包与验证说明保留在 [候选阶段文档](docs/RELEASE_CANDIDATE.md)。

环境要求：

- macOS 26+
- Apple Silicon Mac
- Xcode 26+

```bash
git clone https://github.com/kolmh/LacEditor.git
cd LacEditor
sh Scripts/prepare-pandoc.sh
swift build
swift test
```

准备步骤从 `Vendor/Pandoc` 解压已验证的官方归档，无需联网。Xcode 自动执行此步骤。解压后的 Pandoc 使应用增加约 186 MiB，仓库中的归档约为 41 MiB。版本、许可证和源码分发说明见 [Vendor/Pandoc/README.md](Vendor/Pandoc/README.md)。

需要运行完整发布验收时：

```bash
./Scripts/run-acceptance.sh
```

也可以用 Xcode 打开 `LacEditor.xcodeproj`，选择 `LacEditor` scheme 后按 `Command+R`。

## 技术方向

从 0.14.0 起使用 macOS 原生窗口标签，支持系统拖动、拆出与合并。旧版工作区会按原顺序恢复为原生标签组，继续保留未保存内容、正式文件路径和 Finder 打开方式。

LacEditor 使用 SwiftUI 构建界面，AppKit `NSTextView` 负责编辑，TextKit 负责可视区布局，WebKit 配合
`cmark-gfm` 负责本地 Markdown 预览。文件读写、语法扫描、搜索替换、JSON、预览和恢复各自保持独立，
后台任务通过文档 revision 校验，过期结果不会覆盖较新的编辑内容。

## 路线图

完整的性能与架构路线记录在 [docs/ROADMAP.md](docs/ROADMAP.md)，当前规划分为三阶段：

- 第一阶段：减少 Markdown 预览全文复制、完善搜索缓存、补齐行号和末尾空行回归测试。
- 第二阶段：按脏范围剪枝 Tree-sitter，拆分高亮/折叠任务，减少长代码文件的主线程工作。
- 第三阶段：基于外部资料完成架构评估，保留 TextKit 1 与当前文档生命周期；取消 TextKit 2 实验，推迟通用渲染适配层和大型类拆分。
当前工作代码补充了可取消的预览、统计和折叠任务、侧栏键盘选择与批量操作，以及优先加载选中标签的渐进工作区恢复。这些改动尚未发布：Mac 构建、XCTest、实际界面检查和前后性能对比仍待完成。详见[完成计划](docs/plans/roadmap-completion-plan.md)及[后续优化清单](NEXT_OPTIMIZATIONS.md)。

Git、插件系统和云同步暂不属于 LacEditor 的核心路线。
